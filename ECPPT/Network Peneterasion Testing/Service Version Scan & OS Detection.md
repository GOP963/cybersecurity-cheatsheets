## 1️⃣ Service Version Scan — `-sV`

### 🎯 هدف

وقتی پورت باز رو پیدا کردی، فقط شماره پورت کافی نیست. باید بفهمی:

- چه سرویسی روش هست (HTTP, FTP, SSH, …)
    
- نسخه دقیق اون سرویس (Apache 2.4.52, OpenSSH 8.2p1, …)
    

این اطلاعات می‌تونه بهت کمک کنه تا:

- اکسپلویت مناسب پیدا کنی.
    
- آسیب‌پذیری‌های نسخه خاص رو شناسایی کنی.
    

---

### ⚙️ دستور پایه

```bash
nmap -sV 192.168.1.10
```

یا برای پورت‌های خاص:

```bash
nmap -sV -p 21,22,80 192.168.1.10
```

---

### 🔍 جزئیات عملکرد

- Nmap بعد از کشف پورت باز، **Probe**‌های مخصوص سرویس رو می‌فرسته.
    
- پاسخ رو با دیتابیس داخلی (`nmap-service-probes`) مقایسه می‌کنه.
    
- نتیجه رو به صورت:
    
    ```
    80/tcp open  http     Apache httpd 2.4.52 ((Ubuntu))
    ```
    

---

### 🛠 نکات پیشرفته

- افزایش دقت:
    
    ```bash
    nmap -sV --version-intensity 9 192.168.1.10
    ```
    
- محدود کردن زمان:
    
    ```bash
    nmap -sV --version-light 192.168.1.10
    ```

## 2️⃣ OS Detection Scan — `-O`

### 🎯 هدف

شناسایی سیستم‌عامل هدف (Windows, Linux, BSD, Router OS, …) و حتی نسخه تقریبی.

---

### ⚙️ دستور پایه

```bash
nmap -O 192.168.1.10
```

---

### 🔍 جزئیات عملکرد

- Nmap چندین تست TCP/IP fingerprinting انجام میده:
    
    - تفاوت در TTL
        
    - اندازه پنجره TCP
        
    - ترتیب بسته‌ها
        
    - پاسخ به بسته‌های غیرعادی (مثل FIN بدون SYN)
        
- نتیجه رو با دیتابیس `nmap-os-db` مقایسه می‌کنه.
    
- خروجی نمونه:
    
    ```
    OS details: Linux 5.4 - 5.10
    Network Distance: 1 hop
    ```
    

---

### 🛠 نکات پیشرفته

- ترکیب با Version Scan برای اطلاعات کامل:
    
    ```bash
    nmap -sV -O 192.168.1.10
    ```
    
- فعال کردن تشخیص تهاجمی (همراه اسکریپت‌ها و traceroute):
    
    ```bash
    nmap -A 192.168.1.10
    ```
    

---

## ⚠️ نکات از دید Attacker

- **Service Version Scan** ممکنه سرویس رو در لاگ‌ها ثبت کنه (probe غیرعادی).
    
- **OS Detection** گاهی نتیجه اشتباه میده، مخصوصاً پشت فایروال یا با stackهای سفارشی.
    
- بعضی سیستم‌ها با IDS/IPS ممکنه اسکن رو بلاک کنن یا حتی IP رو موقت قطع کنن.

## 1️⃣ `-sS` — **TCP SYN Scan (Half-Open Scan)**

### 🎯 هدف

- شناسایی پورت‌های باز بدون برقراری کامل ارتباط TCP (سه‌مرحله‌ای یا 3-way handshake).
    
- به همین دلیل بهش **Half-Open Scan** یا **Stealth Scan** میگن.
    

---

### ⚙️ نحوه کار

1. Nmap یک بسته **SYN** به پورت هدف می‌فرسته.
    
2. اگر پورت **باز** باشه، سیستم هدف با **SYN/ACK** جواب میده.
    
3. Nmap بلافاصله یک **RST** می‌فرسته تا اتصال کامل نشه.
    
4. اگر پورت **بسته** باشه → RST دریافت میشه.
    

---

### 📌 مزایا

- سریع‌تر از روش کامل `-sT`.
    
- کمتر در لاگ سرویس ثبت میشه (ولی همچنان در لاگ فایروال ممکنه بیفته).
    
- امکان استفاده از raw packet برای کنترل دقیق.
    

### ⚠️ معایب

- نیاز به دسترسی **Root / Administrator** برای ارسال بسته‌های raw.
    
- روی سیستم‌هایی با IDS مدرن هنوز هم قابل شناساییه.
    

---

### 🔹 مثال

```bash
nmap -sS 192.168.1.10
nmap -sS -p 22,80,443 192.168.1.10
```

## 2️⃣ `-T4` — **Timing Template (Aggressive Speed)**

### 🎯 هدف

تنظیم سرعت اسکن و فاصله بین ارسال بسته‌ها.

Nmap دارای 6 سطح زمان‌بندی است:

```
-T0 → Paranoid (خیلی آهسته، برای دور زدن IDS)
-T1 → Sneaky (آهسته)
-T2 → Polite (کندتر از معمول، برای کاهش بار روی شبکه)
-T3 → Default (حالت پیش‌فرض)
-T4 → Aggressive (سریع، مناسب شبکه‌های مطمئن)
-T5 → Insane (خیلی سریع، احتمال از دست دادن پورت‌ها)
```

---

### 📌 ویژگی `-T4`

- مناسب وقتی که شبکه لوکال یا ارتباط سریع داری.
    
- کاهش فاصله بین probeها → سرعت بالا.
    
- ممکنه روی شبکه‌های با latency بالا باعث **miss شدن بعضی پورت‌ها** بشه.
    
- از دید Attacker: برای LAN عالیه ولی در اینترنت ممکنه پر سروصدا بشه.
    

---

### 🔹 مثال

```bash
nmap -sS -T4 192.168.1.10
nmap -sS -T4 -p- 192.168.1.10
```

ترکیب SYN Scan با سرعت aggressive.

---

💡 **ترفند Red Team:**  
وقتی مطمئنی IDS یا فایروال خیلی حساس نیست و میخوای سریع نتیجه بگیری، `-sS -T4` رو بزن.  
ولی اگه میخوای stealth باشی، `-sS -T2` یا حتی `-T1` بهتره.
