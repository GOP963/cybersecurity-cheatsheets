## 🔹 فرمت‌های خروجی در Nmap

### 1. **Normal Output (`-oN`)**

- فرمت پیش‌فرضه، شبیه همون چیزی که توی ترمینال می‌بینی.
    
- برای مرور سریع و خواندن توسط انسان خوبه.
    
- ساختار ساده، ولی برای اسکریپت‌نویسی زیاد کاربردی نیست.
    

مثال:

```bash
nmap -oN result.txt 192.168.1.10
```

---

### 2. **XML Output (`-oX`)**

- خروجی به فرمت **XML** میده.
    
- خیلی کاربردیه چون میشه راحت با ابزارهای دیگه (مثل SIEM یا Splunk) ایمپورت کرد.
    
- برای پردازش خودکار (Automated Parsing) عالیه.
    

مثال:

```bash
nmap -oX result.xml 192.168.1.10
```

---

### 3. **Grepable Output (`-oG`)**

- فرمت ساده‌شده برای **grep** یا ابزارهای Command Line.
    
- هر خط مربوط به یک هاسته و میشه با `grep`, `awk`, `cut` و ... راحت پردازش کرد.
    
- الان رسمی دیگه deprecated شده، ولی هنوز خیلی از پنتسترها استفاده می‌کنن.
    

مثال:

```bash
nmap -oG result.gnmap 192.168.1.10
```

---

### 4. **Script Kiddie Output (`-oS`)**

- یک خروجی فان و سرگرمی 😅
    
- شبیه به استایل “leet speak” (جایگزین حروف با اعداد/علامت‌ها).
    
- کاربرد جدی نداره، فقط برای شوخی/استایل.

## leet speak

==یک نوع نوشتار جایگزین است که در آن حروف با اعداد و نمادهای مشابه جایگزین می‌شوند==. این نوع نوشتار در ابتدا توسط هکرها و گروه‌های کامپیوتری برای مخفی کردن محتوای خود و جلوگیری از شناسایی توسط فیلترهای ساده استفاده می‌شد [10، 8]. امروزه، لیت‌اسپیک بیشتر به عنوان یک سرگرمی یا راهی برای ابراز تمایز و عضویت در یک گروه خاص مورد استفاده قرار می‌گیرد

مثال:

```bash
nmap -oS result.txt 192.168.1.10
```

---

### 5. **All Formats (`-oA`)**

- همه فرمت‌های اصلی (Normal, XML, Grepable) رو همزمان ذخیره می‌کنه.
    
- پس سه فایل می‌سازه:
    
    - `result.nmap` (Normal)
        
    - `result.xml` (XML)
        
    - `result.gnmap` (Grepable)
        

مثال:

```bash
nmap -oA result 192.168.1.10
```

---

## 🔹 خلاصه کاربردی

- **-oN** → خوندن دستی
    
- **-oX** → ایمپورت به ابزارهای دیگه / پردازش خودکار
    
- **-oG** → grep و پردازش سریع توی لینوکس
    
- **-oA** → همه‌ی بالا با هم
    

---

برای این‌که نتایج **Nmap** رو به **Metasploit** وارد کنیم، معمولا از **فرمت XML (`-oX`)** استفاده می‌کنیم.

## 🔹 چرا XML برای Metasploit؟

- متاسپلویت ابزار `db_import` داره که خروجی **XML نَمپ** رو می‌گیره و به دیتابیس خودش وارد می‌کنه.
    
- بعدش می‌تونی هاست‌ها، پورت‌های باز و سرویس‌ها رو توی **msfconsole** ببینی و روی همونا اکسپلویت اجرا کنی.
    

---

## 🔹 روش کار

### 1. گرفتن خروجی Nmap در فرمت XML

```bash
nmap -sS -p- -T4 -oX scan.xml 192.168.1.0/24
```

اینجا:

- `-sS` → اسکن SYN
    
- `-p-` → همه پورت‌ها
    
- `-oX scan.xml` → خروجی XML برای استفاده در متاسپلویت
    

---

### 2. وارد کردن خروجی به Metasploit

توی `msfconsole` اینو می‌زنی:

```bash
db_import scan.xml
```

---

### 3. بررسی داده‌ها در Metasploit

بعد از ایمپورت، می‌تونی این دستورات رو بزنی:

```bash
hosts        # لیست هاست‌ها
services     # لیست سرویس‌ها و پورت‌ها
vulns        # اگر چیزی شناخته شده باشه
```

## 🔹 نکته مهم

اگر دیتابیس Postgres متاسپلویت فعال باشه، داده‌ها ذخیره می‌شن و می‌تونی بعداً هم ازشون استفاده کنی.  
برای همین خیلی‌ها همیشه با `-oA` خروجی می‌گیرن که هم برای خودشون نگه دارن، هم **scan.xml** برای متاسپلویت داشته باشن.

مثال:

```bash
nmap -sS -p- -T4 -oA pentest_scan 192.168.1.0/24
```

اینجا سه فایل ساخته می‌شه:

- `pentest_scan.nmap`
    
- `pentest_scan.gnmap`
    
- `pentest_scan.xml` → اینو میدی به Metasploit
