## 1️⃣ WinRM چیست؟

**WinRM** یا **Windows Remote Management** یک پروتکل مایکروسافت است که بر پایه‌ی **WS-Management** ساخته شده و برای **مدیریت و اجرای دستورات روی سیستم‌های ویندوزی از راه دور** استفاده می‌شود.

- از پورت‌های پیش‌فرض زیر استفاده می‌کند:
    
    - **HTTP → پورت 5985**
        
    - **HTTPS → پورت 5986**
        
- پروتکلش XML-based است و از SOAP استفاده می‌کند.
    
- می‌توان با آن PowerShell، CMD یا حتی اسکریپت‌ها را از راه دور روی سیستم اجرا کرد.
    

---

## 2️⃣ کارکرد اصلی

WinRM دو کار اصلی انجام می‌دهد:

1. **مدیریت راه دور** (Remote Administration)  
    مثل اجرای دستورات PowerShell، چک کردن سرویس‌ها، گرفتن لاگ‌ها.
    
2. **انتقال داده و تنظیمات مدیریتی**  
    مثلاً برای پیکربندی فایروال، نصب نرم‌افزار یا اعمال GPO.
    

---

## 3️⃣ نحوه فعال‌سازی و استفاده

🔹 **فعال‌سازی WinRM روی یک سیستم**

```powershell
Enable-PSRemoting -Force
```

این دستور WinRM را فعال کرده، لیسنرها را روی پورت‌های پیش‌فرض ایجاد و فایروال را تنظیم می‌کند.

🔹 **اتصال به یک سیستم دیگر**

```powershell
Enter-PSSession -ComputerName TargetPC -Credential UserName
```

یا اجرای یک دستور بدون ورود به شل:

```powershell
Invoke-Command -ComputerName TargetPC -ScriptBlock { ipconfig } -Credential UserName
```

---

## 4️⃣ امنیت WinRM

- **احراز هویت**: معمولا از **Kerberos** (در دامنه) یا **NTLM** (خارج از دامنه) استفاده می‌شود.
    
- **رمزگذاری**: روی HTTP هم، حتی بدون SSL، داده‌ها معمولاً رمزگذاری می‌شوند اگر Kerberos/NTLM استفاده شود. ولی در محیط‌های حساس بهتر است از HTTPS روی پورت 5986 استفاده شود.
    
- **کنترل دسترسی**: با گروه‌هایی مثل `Remote Management Users` یا تنظیمات ACL محدود می‌شود.
    

---

## 5️⃣ استفاده در تست نفوذ

در حملات Red Team و Post-Exploitation، WinRM پرکاربرد است چون:

- نسبت به SMB یا RDP سروصدای کمتری در لاگ‌ها ایجاد می‌کند.
    
- اجازه می‌دهد بدون باز کردن Session گرافیکی، دستورها را از راه دور اجرا کنیم.
    
- ابزارهایی مثل **Evil-WinRM** در کالی لینوکس برای سوءاستفاده از آن وجود دارند:
    

```bash
evil-winrm -i 10.10.10.5 -u administrator -p 'P@ssw0rd!'
```

## 1️⃣ XML-based یعنی چی؟

- **XML** مخفف **eXtensible Markup Language** هست.
    
- ساختارش شبیه HTML ولی برای ذخیره و انتقال **داده** طراحی شده، نه نمایش.
    
- داده‌ها در قالب **تگ‌ها** ذخیره می‌شوند و به راحتی توسط سیستم‌های مختلف (حتی روی پلتفرم‌ها و زبان‌های متفاوت) خوانده می‌شوند.
    
- وقتی می‌گیم WinRM **XML-based** هست، یعنی داده‌هایی که بین کلاینت و سرور رد و بدل می‌شوند، به شکل XML فرمت‌بندی می‌شوند.
    

🔹 مثال ساده یک درخواست XML:

```xml
<Request>
    <Command>ipconfig</Command>
    <Arguments>/all</Arguments>
</Request>
```

این ساختار باعث میشه هر سیستمی که XML رو می‌فهمه بتونه درخواست رو تفسیر کنه.

---

## 2️⃣ SOAP چیست؟

- **SOAP** مخفف **Simple Object Access Protocol** هست.
    
- یک **پروتکل پیام‌رسانی** است که معمولاً روی **HTTP/HTTPS** سوار می‌شود.
    
- قالب پیام‌ها در SOAP هم **XML** است، ولی SOAP یک سری قوانین خاص برای ساخت پیام، هدر، بدنه و خطا دارد.
    
- در WinRM، SOAP استفاده می‌شود تا عملیات مدیریتی (مثل اجرای دستور یا گرفتن وضعیت سرویس‌ها) در قالب **پیام‌های استاندارد** ارسال شود.
    

🔹 ساختار کلی یک پیام SOAP:

```xml
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
    <soap:Header>
        <!-- اطلاعات احراز هویت، Session و غیره -->
    </soap:Header>
    <soap:Body>
        <ExecuteCommand>
            <Command>ipconfig</Command>
        </ExecuteCommand>
    </soap:Body>
</soap:Envelope>
```

- **Envelope**: کل پیام رو می‌پوشونه.
    
- **Header**: متادیتا و اطلاعات کنترلی (مثلاً auth).
    
- **Body**: دستور اصلی یا داده‌ای که می‌خوای ارسال کنی.

## 3️⃣ ارتباطشون با WinRM

وقتی تو با WinRM یک دستور اجرا می‌کنی:

1. **PowerShell یا ابزار مدیریت**، درخواست رو به یک **پیام SOAP** می‌پیچه.
    
2. محتوا (Body) شامل داده‌ها به فرمت **XML** است (مثلاً دستور و پارامترها).
    
3. این پیام SOAP روی HTTP یا HTTPS به سیستم مقصد ارسال می‌شود.
    
4. سیستم مقصد پیام را از SOAP باز کرده، XML را می‌خواند و دستور را اجرا می‌کند.
    
5. نتیجه اجرا دوباره در قالب XML داخل یک پیام SOAP برگشت داده می‌شود.

## 1️⃣ XML — **زبان نشانه‌گذاری برای داده**

- **هدف:** ذخیره و تبادل داده به شکلی ساخت‌یافته.
    
- **کار:** فقط داده رو نگه می‌داره، بدون این‌که مشخص کنه چطور نمایش داده بشه.
    
- **مثال:**
    

```xml
<person>
    <name>Ali</name>
    <age>30</age>
</person>
```

این XML فقط میگه:

- یک `person` وجود داره
    
- اسمش Ali هست
    
- سنش 30 هست  
    ولی نمیگه این رو قرمز کن، یا در جدول نشون بده.
    

---

## 2️⃣ XSL — **زبان سبک‌دهی و تبدیل برای XML**

- **هدف:** تعیین نحوه **نمایش** یا **تبدیل** داده‌های XML.
    
- **کار:** می‌تونه XML رو به HTML، متن ساده یا حتی XML دیگری تبدیل کنه.
    
- **XSLT** (XSL Transformations) بخش مهم XSL هست که برای **تبدیل ساختار** استفاده میشه.
    
- **مثال:**
    

```xml
<xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform" version="1.0">
  <xsl:template match="/person">
    <html>
      <body>
        <h1><xsl:value-of select="name"/></h1>
        <p>Age: <xsl:value-of select="age"/></p>
      </body>
    </html>
  </xsl:template>
</xsl:stylesheet>
```

این XSL میگه:

- وقتی XML یک `person` باشه، اسم رو در عنوان (`<h1>`) و سن رو در یک پاراگراف نشون بده.
    

---

## 3️⃣ خلاصه فرق

|ویژگی|XML|XSL|
|---|---|---|
|**کار اصلی**|ذخیره و تبادل داده|تغییر/نمایش داده|
|**نوع**|فرمت داده|زبان سبک‌دهی و تبدیل|
|**خروجی**|داده خام|داده پردازش‌شده یا قالب‌بندی‌شده|
|**وابستگی**|می‌تونه مستقل باشه|به XML نیاز دارد|

## 1️⃣ **WinRM Authentication** — احراز هویت در WinRM

این یعنی وقتی می‌خوای از طریق WinRM به یک سیستم وصل بشی، چه روشی برای تأیید هویت کاربر استفاده میشه.

WinRM از چند روش پشتیبانی می‌کنه:

|روش|توضیح|سناریوی معمول|
|---|---|---|
|**Kerberos**|پیش‌فرض در محیط Domain. امن‌تره چون پسورد رو روی شبکه نمی‌فرسته.|وقتی هر دو سیستم عضو یک دامنه Active Directory باشن.|
|**NTLM**|وقتی Kerberos در دسترس نیست. هش NTLM رد و بدل میشه.|اتصال بین سیستم‌های خارج از دامنه یا بدون DC.|
|**Basic**|یوزر و پسورد رو به صورت Base64 (نه رمزنگاری واقعی) ارسال می‌کنه.|معمولاً همراه HTTPS (پورت 5986) برای رمزگذاری.|
|**CredSSP**|پسورد رو کامل به سیستم مقصد می‌فرسته.|برای سناریوهایی که نیاز به دوباره احراز هویت روی مقصد داری.|

📌 نکته امنیتی:

- در محیط‌های Domain، Kerberos بهترین گزینه‌ست.
    
- NTLM ممکنه در برابر حملات Pass-the-Hash یا Relay آسیب‌پذیر باشه.
    
- Basic بدون HTTPS خیلی خطرناکه.

## 2️⃣ **WinRM Privilege** — سطح دسترسی در WinRM

این یعنی وقتی با موفقیت وصل شدی، چه کارهایی **اجازه داری** انجام بدی.

- WinRM به طور پیش‌فرض فقط به کاربرانی اجازه اتصال می‌ده که:
    
    1. عضو گروه **Administrators** باشن (دسترسی کامل).
        
    2. یا عضو گروه **Remote Management Users** باشن (دسترسی محدود).
        
- حتی اگر احراز هویت بشی، اگه پرمیژن لازم رو نداشته باشی، نمی‌تونی دستوری اجرا کنی.
    
- سطح دسترسی روی مقصد می‌تونه توسط **WinRM service ACLs** یا Group Policy تغییر کنه.
    

📌 مثال‌ها:

- اگر کاربر **Administrator** باشه → می‌تونه PowerShell کامل اجرا کنه، فایل‌ها رو بخونه/بنویسه، سرویس‌ها رو کنترل کنه.
    
- اگر کاربر فقط **Remote Management Users** باشه → ممکنه فقط اجازه اجرای یک سری Script محدود رو داشته باشه.
    
- اگه دسترسی به **SeRemoteInteractiveLogonRight** نداشته باشی → حتی بعد از auth هم Session ایجاد نمی‌شه.
    

---

## 3️⃣ ارتباط Authentication و Privilege

- **Authentication** = کی هستی؟ (احراز هویت)
    
- **Privilege** = چه اجازه‌ای داری؟ (سطح دسترسی)
    
- ممکنه تو Authentication رو بگذرونی ولی Privilege لازم رو نداشته باشی → یعنی وارد شدی ولی کاری نمی‌تونی بکنی.
    
- یا برعکس، اگه Privilege بالا داری ولی Auth موفق نباشه → اصلاً به Session نمی‌رسی.
