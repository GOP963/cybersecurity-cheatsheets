---

## 1️⃣ ایده کلی ReGeorg

**ReGeorg** یک ابزار (معمولاً به شکل یک اسکریپت کوچک وب) است که می‌توان آن را روی یک **وب‌سرور آسیب‌پذیر** آپلود کرد تا از طریق آن یک تونل SOCKS بسازی و مثل یک **پروکسی به شبکه داخلی سرور** دسترسی پیدا کنی.

به زبان ساده:

- یک Webshell خاص (مثلاً `tunnel.aspx`, `tunnel.jsp`, `tunnel.php`) روی سایت قربانی قرار می‌دی.
    
- این Webshell درخواست‌های تو رو می‌گیره و به مقصد در شبکه داخلی قربانی می‌فرسته.
    
- روی سیستم خودت، یک کلاینت ReGeorg رو اجرا می‌کنی که از طریق این Webshell یک SOCKS Proxy ایجاد می‌کنه.
    
- بعد می‌توانی با ابزارهایی مثل ProxyChains یا Burp Suite به شبکه داخلی قربانی وصل بشی.
    

---

## 2️⃣ سناریوی Pivoting با ReGeorg

تصور کن:

- سیستم قربانی یک وب‌سرور داره (`example.com`) که روی شبکه عمومی هست.
    
- این وب‌سرور به شبکه داخلی (`192.168.10.0/24`) دسترسی داره.
    
- تو تونستی فایل `tunnel.jsp` رو روی سرور آپلود کنی.
    

---

## 3️⃣ مراحل اجرا

### **قدم ۱ – آپلود وب‌شل تونل**

فایل `tunnel.jsp` یا `tunnel.php` رو روی مسیر قابل دسترسی سایت آپلود می‌کنی، مثلاً:

```
http://example.com/upload/tunnel.jsp
```

---

### **قدم ۲ – اجرای کلاینت ReGeorg روی سیستم خودت**

دستور معمول:

```bash
python reGeorgSocksProxy.py -u http://example.com/upload/tunnel.jsp -p 1080
```

اینجا:

- `-u` → آدرس کامل وب‌شل
    
- `-p 1080` → پورتی که روی سیستم خودت برای SOCKS Proxy باز می‌شود.
    

---

### **قدم ۳ – استفاده از ProxyChains**

اضافه کردن به `/etc/proxychains.conf`:

```
socks4 127.0.0.1 1080
```

(یا socks5 بسته به تنظیمات ReGeorg)

حالا مثلاً اسکن پورت سرور داخلی:

```bash
proxychains nmap -sT 192.168.10.5 -p 80,445
```

## 4️⃣ تفاوت Pivoting با ReGeorg نسبت به متاسپلویت

|ویژگی|Metasploit Pivoting|ReGeorg Pivoting|
|---|---|---|
|مسیر اولیه|Session Meterpreter|وب‌شل روی وب‌سرور|
|پروتکل|مستقیم TCP/Metasploit|HTTP(S) Tunnel|
|کاربرد|نیازمند Exploit یا دسترسی مستقیم|وقتی فقط وب‌سرور در دسترسه|
|ابزارهای قابل استفاده|ماژول‌های متاسپلویت و ابزارهای سازگار|هر ابزاری که از SOCKS پشتیبانی کنه|

---

## 5️⃣ نکته امنیتی

- ترافیک بین تو و ReGeorg از طریق HTTP(S) میره، پس اگر HTTPS باشه، شناسایی سخت‌تره.
    
- اگر Webshell لو بره، سریع حذف میشه.
    
- معمولاً IDS/IPS می‌تونه رفتار غیرعادی HTTP Tunnel رو شناسایی کنه مگر اینکه Payload رو تغییر بدی.
