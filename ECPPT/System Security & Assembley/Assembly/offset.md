## 📌 آدرس مطلق (Absolute Address)

یعنی یه **آدرس دقیق و ثابت توی حافظه** که همیشه همونه.  
مثال:  
می‌گیم داده‌مون دقیقاً توی آدرس `0x7FFDE000` قرار داره.

یعنی بدون هیچ محاسبه‌ای مستقیم می‌ریم سراغ همون آدرس.  
این می‌شه **مطلق** چون هیچ وابستگی به جای دیگه‌ای نداره.

---

## 📌 آدرس نسبی (Relative Address)

برعکس، گاهی آدرس دقیق معلوم نیست یا ممکنه تغییر کنه.  
مثلاً متغیرهای محلی توی **stack**:

- هر بار برنامه اجرا بشه، stack ممکنه جای دیگه‌ای توی حافظه قرار بگیره.
    
- پس اگه بگیم «متغیر x دقیقاً توی `0x7FFDE000` هست» اشتباه می‌شه چون دفعه‌ی بعد ممکنه جای دیگه باشه.
    

راه‌حل اینه که بگیم:  
«x توی `[EBP-4]` هست.»  
یعنی **نسبت به یه نقطه‌ی مرجع** (اینجا `EBP`) مشخص می‌کنیم.

این می‌شه **آدرس نسبی**.

---

## 🔹 مثال واقعی

تصور کن یه خونه داری:

- **آدرس مطلق**: تهران، خیابان انقلاب، پلاک ۱۰۲ → همیشه همونه.
    
- **آدرس نسبی**: "از میدان آزادی ۲ کیلومتر به سمت شرق" → بستگی داره تو کجا باشی، اما همیشه نسبت به آزادی تعریف می‌شه.
    

---

✅ پس خلاصه:

- **آدرس مطلق**: یه مکان دقیق و ثابت توی حافظه (مثلاً 0x00400000).
    
- **آدرس نسبی**: یه مکان متغیر که نسبت به یه مرجع مشخص می‌شه (مثلاً `[EBP-8]`).
    

---


---

## 🔹 اول: اگه offset نداشتیم چی می‌شد؟

فرض کن یه تابع داری که ۳ تا متغیر محلی (local variables) داره:

```c
void func(int a, int b) {
    int x = 10;
    int y = 20;
    int z = a + b;
}
```

وقتی این تابع اجرا می‌شه، توی **stack** یه بخش بهش داده می‌شه.  
حالا متغیرهای `x, y, z` باید توی اون بخش نگه‌داری بشن.

ولی نکته اینجاست:

- بار اول که برنامه اجرا می‌شه، ممکنه stack از آدرس `0x7FFE1000` شروع بشه.
    
- بار دوم از `0x7FFD9000` شروع بشه.
    

پس اگه قرار بود با آدرس مطلق کار کنیم، اصلاً نمی‌فهمیدیم `x` کجاست!

---

## 🔹 دوم: نقش **EBP (Base Pointer)**

برای حل این مشکل، پردازنده یه ترفند داره:

- وقتی تابع صدا زده می‌شه، آدرس فعلی ESP (یعنی بالای stack) رو می‌ریزیم توی **EBP**.
    
- از اون لحظه به بعد، EBP مثل یه "نقطه مرجع" عمل می‌کنه.
    

یعنی می‌گیم:  
«از این نقطه (EBP) به اندازه‌ی فلان offset برو، اونجا متغیرتو پیدا می‌کنی.»

---

## 🔹 سوم: offset‌های مثبت و منفی

حالا دقت کن:

- **آرگومان‌های تابع** (مثل `a` و `b`) بالای EBP قرار می‌گیرن → پس با **offset مثبت** صدا زده می‌شن.
    
    - مثلاً `[EBP+8]` = مقدار `a`
        
    - `[EBP+12]` = مقدار `b`
        
- **متغیرهای محلی** (مثل `x, y, z`) پایین‌تر از EBP ذخیره می‌شن → پس با **offset منفی** صدا زده می‌شن.
    
    - مثلاً `[EBP-4]` = `x`
        
    - `[EBP-8]` = `y`
        
    - `[EBP-12]` = `z`
        

---

## 🔹 چهارم: مزیت این کار

به جای اینکه آدرس مطلق داشته باشیم، همیشه می‌گیم:

- `a` → `[EBP+8]`
    
- `x` → `[EBP-4]`
    

حتی اگه هر بار stack جای دیگه‌ای باشه، باز هم با همین offset‌ها می‌تونیم داده رو پیدا کنیم.

📌 یعنی **offset انعطاف‌پذیری میاره و برنامه‌هارو قابل اجرا روی هر سیستم و هر بار اجرا می‌کنه.**

---

## 🔹 پنجم: در آرایه‌ها و ساختارها

بذار با یه آرایه هم نشونت بدم:

```c
int arr[3] = {11, 22, 33};
```

فرض کن `arr` از آدرس `0x1000` شروع می‌شه.

- arr[0] → offset = 0 → آدرس = `0x1000 + 0*4 = 0x1000`
    
- arr[1] → offset = 1 → آدرس = `0x1000 + 1*4 = 0x1004`
    
- arr[2] → offset = 2 → آدرس = `0x1000 + 2*4 = 0x1008`
    

باز هم می‌بینی offset به ما کمک می‌کنه "نسبت به شروع" بگیم عنصر دوم یا سوم کجاست.

---

✅ پس جمع‌بندی:  
**offset = فاصله‌ی نسبی از یه نقطه‌ی مرجع (مثل EBP یا آدرس شروع آرایه)**  
→ به درد **دسترسی مطمئن و قابل‌انتقال به داده‌ها** می‌خوره، بدون اینکه آدرس مطلق رو بدونیم.

---

خیلی خوب داری جلو میای 👌 حالا بذار **تعریف مفهومی** offset رو برات ردیف کنم:

---

### 🔹 تعریف ساده‌ی Offset

**Offset یعنی فاصله‌ی نسبی (relative address) از یک نقطه‌ی مرجع (base address).**

- نقطه مرجع می‌تونه:
    
    - ابتدای حافظه (absolute base)
        
    - یا ابتدای یک ساختار (مثل آرایه)
        
    - یا ابتدای یک فریم در استک (مثل EBP) باشه.
        

وقتی می‌گی:

```asm
[EBP-4]
```

یعنی: "۴ بایت پایین‌تر از جایی که EBP الان ایستاده → این همون متغیر محلی منه."

یا:

```asm
[EBP+8]
```

یعنی: "۸ بایت بالاتر از EBP → این آرگومان اول تابع منه."

---

### 🔹 فرق آدرس مطلق و Offset

- **آدرس مطلق (absolute address):** همون شماره خونه توی حافظه‌ست. مثل اینکه بگی "برو به آدرس 0x00403010".
    
- **Offset:** فقط فاصله‌ست. می‌گی "از اینجا ۸ بایت برو جلو" یا "۴ بایت برو عقب".
    

---

### 🔹 تعریف کتابی (برای جزوه‌ت)

> Offset به معنی "جابه‌جایی" یا "فاصله‌ی نسبی" است که نشان می‌دهد یک داده یا دستور، چند بایت دورتر از یک نقطه مرجع (base address) قرار دارد. در اسمبلی، offset معمولاً نسبت به ثباتی مانند **EBP** یا ابتدای یک سگمنت محاسبه می‌شود و به جای اشاره مستقیم به یک آدرس مطلق، موقعیت نسبی داده را مشخص می‌کند.

## 🔹 دیدن مقدار ESP و EBP

این دوتا ثبات (Register) رو نمی‌تونی مثل متغیرهای پایتون چاپ کنی 😅، ولی می‌تونی توی **دیباگر** یا با **دستور اسمبلی** ببینیشون:

1. **توی GDB (لینوکس):**
    
    ```bash
    info registers
    ```
    
    یا برای فقط یکی‌شون:
    
    ```bash
    info registers esp ebp
    ```
    
    خروجی مثلاً میشه:
    
    ```
    esp            0xbffff2c0
    ebp            0xbffff2e8
    ```
    
2. **توی WinDbg یا x64dbg (ویندوز):**  
    معمولاً پنجره‌ی Registers داری، اونجا مستقیم EAX, EBX, ESP, EBP رو می‌بینی.
    

---

## 🔹 مقداردهی یا کپی کردن بین ESP و EBP

در اسمبلی خودت می‌تونی دستور مستقیم بدی:

- ذخیره‌ی ESP توی EBP (خیلی رایجه موقع ورود به تابع):
    
    ```asm
    mov ebp, esp
    ```
    
- یا برعکس، تغییر دادن ESP از روی EBP:
    
    ```asm
    mov esp, ebp
    ```
    
- حتی می‌تونی محتواشونو **push/pop** کنی:
    
    ```asm
    push esp    ; مقدار ESP رو بذار روی استک
    pop ebp     ; حالا مقدار ESP میره داخل EBP
    ```
    

---

## 🔹 چرا این کار مهمه؟

- وقتی تابع شروع میشه:
    
    ```asm
    push ebp
    mov ebp, esp
    ```
    
    این کار باعث میشه EBP نقش **پایه (base pointer)** رو بگیره. بعدش اگه ESP تغییر کنه (مثلاً push/pop بشه)، EBP ثابت می‌مونه و میشه مرجع مطمئن برای دسترسی به آرگومان‌ها و متغیرهای محلی.
    

---

🔥 پس جمع‌بندی:

- برای دیدن: `info registers` (GDB) یا رجیستر پنجره توی دیباگرها.
    
- برای دادن مقدار ESP به EBP: `mov ebp, esp`.
    
- برای برعکس: `mov esp, ebp`.
    

---

## 🔹 مفهوم اصلی

`push` و `pop` دو دستور پایه برای کار با **استک (Stack)** هستن.  
استک یه ناحیه از حافظه‌ست که مثل یه **لیست پشته‌ای (LIFO: Last In, First Out)** کار می‌کنه:

- هر چیزی رو بذاری روش (push)، بالاترین عنصر جدید میشه.
    
- هر چیزی رو برداری (pop)، آخرین چیزی که گذاشتی برمی‌گرده.
    

---

## 🔹 دستور `push`

- کاری که می‌کنه:
    
    1. مقدار **ESP** رو ۴ تا (در معماری 32bit) کم می‌کنه → چون استک رو به سمت آدرس‌های پایین رشد می‌کنه.
        
    2. مقدار رو توی اون آدرس جدید می‌نویسه.
        

📌 مثال:

```asm
push eax
```

- مقدار داخل `EAX` میره روی استک.
    
- ESP = ESP - 4
    
- `[ESP] = EAX`
    

---

## 🔹 دستور `pop`

- کاری که می‌کنه:
    
    1. مقدار `[ESP]` (یعنی بالاترین داده روی استک) رو برمی‌داره و می‌ریزه توی رجیستر مقصد.
        
    2. مقدار **ESP** رو ۴ تا زیاد می‌کنه (یعنی اون خانه از استک دیگه آزاد حساب میشه).
        

📌 مثال:

```asm
pop ebx
```

- مقدار بالای استک → وارد `EBX`
    
- ESP = ESP + 4
    

---

## 🔹 یک مثال ترکیبی

```asm
mov eax, 1234h   ; EAX = 0x1234
push eax         ; مقدار 1234 میره روی استک
pop ebx          ; حالا EBX = 0x1234
```

نتیجه:

- مقدار داخل EAX از طریق استک منتقل شد به EBX.
    

---

## 🔹 نکته مهم

- **push** و **pop** همیشه روی **ESP** کار می‌کنن (top of stack).
    
- برای ذخیره و بازیابی مقادیر (مثل موقع ورود/خروج از تابع) استفاده میشن:
    
    ```asm
    push ebp       ; ذخیره ebp قبلی
    mov ebp, esp   ; تنظیم frame جدید
    ...
    mov esp, ebp   ; برگردوندن esp
    pop ebp        ; بازیابی ebp قبلی
    ret            ; برگشت از تابع
    ```
    

---

🔥 پس به طور خلاصه:

- `push X` → مقدار X رو بذار بالای استک، ESP رو کم کن.
    
- `pop X` → بالای استک رو بذار توی X، ESP رو زیاد کن.
