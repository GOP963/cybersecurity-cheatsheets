## 🔹 چرا رجیسترها برای چاپ لازم هستن؟

وقتی می‌خوای چیزی روی صفحه چاپ بشه:

1. باید به **سیستم‌عامل** بگی چه کاری انجام بده (اینجا یعنی write روی صفحه).
    
2. این درخواست رو به شکل **سیستم‌کال (syscall)** یا **interrupt** به سیستم‌عامل میدی.
    
3. شمارهٔ syscall و آدرس داده‌ها و طولش رو باید توی رجیسترها قرار بدی.
    

---

## 🔹 مثال در لینوکس (x86 - 32bit)

```asm
section .data
    msg db 'Hello, World!', 0xA ; متن + newline
    len equ $ - msg             ; طول متن

section .text
    global _start

_start:
    mov eax, 4      ; شماره syscall = 4 (sys_write)
    mov ebx, 1      ; فایل‌دسکریپتور = 1 (stdout)
    mov ecx, msg    ; آدرس متن
    mov edx, len    ; طول متن
    int 0x80        ; فراخوانی سیستم‌عامل

    ; خروج از برنامه
    mov eax, 1      ; شماره syscall = 1 (sys_exit)
    xor ebx, ebx    ; کد خروج = 0
    int 0x80
```

---

## 🔹 اینجا هر رجیستر چه کاری می‌کنه؟

- **EAX** → شمارهٔ syscall (اینجا 4 برای write و 1 برای exit)
    
- **EBX** → اولین آرگومان (اینجا شمارهٔ فایل: 1 = stdout)
    
- **ECX** → آدرس داده (متن ما "Hello, World!")
    
- **EDX** → طول داده (تعداد بایت‌هایی که باید نوشته بشه)
    

---

📌 پس می‌بینی که این رجیسترها فقط برای محاسبات ساده نیستن، بلکه نقش **پل ارتباطی بین برنامه و سیستم‌عامل** رو دارن.

## 🔹 syscall چیه؟
- وقتی یه برنامهٔ **User Mode** می‌خواد یه کار سیستمی انجام بده (مثل نوشتن روی صفحه، خوندن از فایل، ساختن پروسس، یا خروج از برنامه)، خودش مستقیم به سخت‌افزار دسترسی نداره.  
- باید از **سیستم‌عامل** کمک بگیره.  
- این کمک گرفتن از طریق یه "درخواست ویژه" به اسم **System Call (syscall)** انجام میشه.  

یعنی syscall = **درخواست مستقیم از هستهٔ سیستم‌عامل**.  

---

## 🔹 شمارهٔ syscall یعنی چی؟
هر کاری که سیستم‌عامل می‌تونه برات انجام بده، یک شمارهٔ منحصربه‌فرد داره.  
این شماره‌ها مثل "کد عملیات" هستن.  

مثلاً در لینوکس (x86 - 32bit):
- `1` → exit (خروج از برنامه)  
- `3` → read (خواندن از فایل/ورودی)  
- `4` → write (نوشتن روی فایل/صفحه)  

پس وقتی می‌خوای چیزی چاپ کنی باید به سیستم‌عامل بگی:  
> "سلام، من syscall شماره 4 رو می‌خوام، یعنی **write**"  

---

## 🔹 رجیستر EAX و شمارهٔ syscall
توی معماری 32 بیتی، همیشه شمارهٔ syscall رو داخل **EAX** می‌ذاری.  
مثال:
```asm
mov eax, 4    ; شماره syscall = 4 → write
```

---

## 🔹 آرگومان‌های syscall
خود syscall به جز شماره، معمولاً چندتا آرگومان هم می‌خواد (مثل تابع‌های زبان‌های برنامه‌نویسی).  
این آرگومان‌ها هم داخل رجیسترهای دیگه می‌رن:  

برای `write(fd, buf, len)`:
- `EBX` → شماره فایل (fd) → اینجا `1` یعنی stdout  
- `ECX` → آدرس متن (buf)  
- `EDX` → طول متن (len)  

---

## 🔹 نمونه
```asm
mov eax, 4      ; syscall = write
mov ebx, 1      ; fd = 1 (stdout)
mov ecx, msg    ; آدرس متن
mov edx, len    ; طول متن
int 0x80        ; اجرای syscall
```

اینجا ما گفتیم:  
- "سیستم‌عامل جان، من شماره 4 (write) رو می‌خوام"  
- "می‌خوام روی fd شماره 1 (stdout) بنویسی"  
- "متن من اینجاست (آدرس msg)"  
- "اندازه متن هم len هست"  

---

✅ پس:  
**شمارهٔ syscall = همون کدی که می‌گه سیستم‌عامل چه کاری باید انجام بده.**  
رجیستر **EAX** همیشه این شماره رو نگه می‌داره (توی 32 بیتی).

## 🔹 حالت‌های مختلف کاراکتر

1. **ASCII** (قدیمی‌ترین و ساده‌ترین)
    
    - هر کاراکتر = 1 بایت (8 بیت)
        
    - مثلاً `'A' = 0x41`
        
2. **UTF-8** (امروزه پرکاربردترین)
    
    - هر کاراکتر می‌تونه 1 تا 4 بایت باشه.
        
    - حروف انگلیسی = 1 بایت
        
    - بعضی نمادها و شکلک‌ها (Emoji) = 2 تا 4 بایت
        
3. **UTF-16**
    
    - بیشتر زبان‌ها (مثل فارسی، چینی) → کاراکترها معمولاً 2 بایت هستن.
        
    - بعضی نمادها خاص = 4 بایت
        
4. **UTF-32**
    
    - هر کاراکتر دقیقاً 4 بایت (ولی خیلی پرحجم میشه، کمتر استفاده میشه).
        

---

## 🔹 در اسمبلی چی؟

- وقتی توی اسمبلی معمولاً رشته‌ی `"Hello"` رو تعریف می‌کنی، هر حرفش = 1 بایت (چون ASCII یا UTF-8 ساده).
    
- یعنی `"Hello"` دقیقاً 5 بایت طول داره (+1 بایت برای `\0` اگه C-style باشه).
    

---

## 🔹 مثال

```asm
msg db 'H','e','l','l','o',0
```

اینجا:

- H = 0x48 (1 بایت)
    
- e = 0x65 (1 بایت)
    
- l = 0x6C (1 بایت)
    
- l = 0x6C (1 بایت)
    
- o = 0x6F (1 بایت)
    
- 0 = 0x00 (Null Terminator)
    

پس کلش = 6 بایت.

---

✅ پس جواب کوتاه:

- نه، **هر کاراکتر همیشه 2 بایت نیست**.
    
- توی ASCII و UTF-8 (برای انگلیسی) هر کاراکتر = 1 بایت.
    
- ولی توی UTF-16 (مثل ویندوز برای فارسی) هر کاراکتر معمولاً 2 بایت میشه.
