## ✅ رجیستر EBP (Extended Base Pointer) چیه؟

- **EBP**
- هم مثل ESP یک **Pointer (آدرس)** نگه می‌داره.
    
- اما تفاوتش اینه که:
    
    - **ESP
    - همیشه به بالای استک اشاره می‌کنه (دائماً تغییر می‌کنه).
        
    - **EBP معمولاً ثابت‌تره** و به عنوان 
    - **مرجع (Base)** برای دسترسی به داده‌های داخل استک استفاده میشه.
        

---

## ✅ کاربرد اصلی EBP

در **فریم تابع (Stack Frame)** به کار میره.

وقتی یه تابع صدا زده میشه:

1. آدرس برگشت (`Return Address`) روی استک ذخیره میشه.
    
2. رجیستر **EBP فعلی push میشه** تا بعداً برگردونده بشه.
    
3. مقدار ESP فعلی در EBP کپی میشه.
    
    - یعنی:
        
        ```asm
        push ebp
        mov  ebp, esp
        ```
        
    
    این کار باعث میشه EBP مرجع ثابتی برای اون تابع بشه.
    

بعدش کامپایلر می‌تونه راحت‌تر به متغیرهای محلی و آرگومان‌ها دسترسی داشته باشه.

---

## ✅ چرا EBP مهمه؟

چون اگه بخوای به متغیرهای محلی یا پارامترهای تابع دسترسی پیدا کنی، ESP هی تغییر می‌کنه و غیرقابل پیش‌بینی میشه.  
ولی EBP در طول اجرای تابع **ثابت می‌مونه** (تا وقتی تابع تموم بشه).

---

## ✅ دسترسی به داده‌ها با EBP

فرض کن تابعی مثل این داری (زبان C):

```c
int add(int a, int b) {
    int c = a + b;
    return c;
}
```

روی استک اینطوری ذخیره میشه:

```
[EBP+8] → آرگومان اول (a)
[EBP+12] → آرگومان دوم (b)
[EBP-4] → متغیر محلی (c)
```

یعنی:

- مقادیر **بالاتر از EBP (+)** معمولاً آرگومان‌ها هستن.
    
- مقادیر **پایین‌تر از EBP (-)** معمولاً متغیرهای محلی تابع هستن.
    

---

## ✅ جمع‌بندی ساده

- **ESP → بالای استک (دائماً تغییر می‌کنه)**
    
- **EBP → نقطهٔ مرجع ثابت در استک (برای دسترسی راحت به متغیرها و آرگومان‌ها)**

## 🔹 مشکل بدون EBP

رجیستر **ESP** مدام تغییر می‌کنه:

- وقتی `push` می‌کنی → ESP کم میشه.
    
- وقتی `pop` می‌کنی → ESP زیاد میشه.
    
- وقتی متغیر محلی بسازی → ESP تغییر می‌کنه.
    

حالا فرض کن می‌خوای به یک متغیر محلی یا آرگومان دسترسی پیدا کنی.  
اگر فقط از ESP استفاده بشه، چون مقدارش دائم در حال تغییره، موقعیت اون متغیر هم مرتب تغییر می‌کنه → دسترسی سخت و پرریسک میشه.

---

## 🔹 راه‌حل → استفاده از EBP

اینجا **EBP** وارد میشه:

1. وقتی تابع شروع میشه:
    
    ```asm
    push ebp        ; ذخیره EBP قدیمی
    mov ebp, esp    ; EBP = ESP (ثابت کردن نقطه‌ی مرجع)
    ```
    
    حالا EBP یک **پایه ثابت** از استک برای این تابع میشه.
    
2. از این به بعد، کامپایلر می‌تونه راحت بنویسه:
    
    - `[ebp+8]` ← آرگومان اول
        
    - `[ebp+12]` ← آرگومان دوم
        
    - `[ebp-4]` ← متغیر محلی
        
3. وقتی تابع تموم میشه:
    
    ```asm
    mov esp, ebp    ; استک رو برمی‌گردونه
    pop ebp         ; مقدار قبلی EBP رو بازیابی می‌کنه
    ret             ; به آدرس برگشت میره
    ```

## 🔹 مزایای استفاده از EBP

1. **ثبات (Stability):**  
    EBP در طول اجرای تابع تغییر نمی‌کنه → دسترسی به متغیرها ساده و مطمئن.
    
2. **قابلیت اشکال‌زدایی (Debugging):**  
    چون EBP همیشه یک "Base ثابت" برای هر تابع داره، ابزارهای دیباگر (مثل gdb, OllyDbg, WinDbg) راحت می‌تونن call stack رو بازسازی کنن و بگن تابع‌ها به چه ترتیبی صدا زده شدن.
    
3. **مدیریت بهتر پارامترها و متغیرهای محلی:**
    
    - پارامترها همیشه بالای EBP هستن.
        
    - متغیرهای محلی همیشه پایین‌تر از EBP هستن.  
        → این نظم، نوشتن و کامپایل کردن کد رو ساده‌تر می‌کنه.
        
4. **هک و اکسپلویت (Exploitation):**  
    چون EBP مرجع ثابت هر تابع محسوب میشه، مهاجم‌ها در حملات buffer overflow از اون استفاده می‌کنن تا مسیر اجرای برنامه رو تغییر بدن.
    

---

## 🔹 تصویر ذهنی (Stack Frame)

وقتی تابع صدا زده میشه، استک اینطوری میشه:

```
[EBP+12] → آرگومان دوم
[EBP+8]  → آرگومان اول
[EBP+4]  → آدرس برگشت (Return Address)
[EBP]    → EBP قبلی
[EBP-4]  → متغیر محلی اول
[EBP-8]  → متغیر محلی دوم
...
```

رجیستر **EBP** در اصل برای این ساخته شده که:

- استک تابع مرتب و قابل پیش‌بینی بشه.
    
- کامپایلر راحت‌تر به متغیرها و پارامترها دسترسی بده.
    
- دیباگرها بتونن call stack رو بازسازی کنن.
    
- برنامه‌نویس یا هکر راحت بفهمه چه چیزی کجای استکه.

# 🔹 چرا باید از push و pop استفاده کنیم؟

استک مثل یک قفسه یا ستون کتابه:

- **push →** گذاشتن چیزی روی استک
    
- **pop →** برداشتن چیزی از استک
    

حالا کاربردهاش:

---

## 1. ذخیره‌سازی موقت (Save / Restore)

فرض کن داری با رجیستر `EAX` کار می‌کنی، ولی قبلش مقدار مهمی توشه. نمی‌خوای مقدارش از دست بره.

```asm
push eax    ; مقدار فعلی EAX رو موقتاً روی استک می‌ذاریم
mov eax, 5  ; حالا EAX رو آزادانه تغییر می‌دیم
; ...
pop eax     ; مقدار قبلی EAX رو برمی‌گردونیم
```

🔹 این تکنیک خیلی پرکاربرده چون رجیسترها تعداد محدودی دارن.

---

## 2. ذخیره آدرس برگشت توابع (Function Calls)

وقتی یک تابع رو صدا می‌زنی (`call func`):

- پردازنده به‌طور خودکار آدرس دستور بعد از `call` رو **push** می‌کنه روی استک.
    
- وقتی تابع تموم شد (`ret`):
    
    - CPU اون آدرس رو **pop** می‌کنه و برمی‌گرده سراغ ادامه برنامه.
        

📌 بدون push/pop آدرس برگشت، اصلاً فراخوانی توابع امکان‌پذیر نبود!

---

## 3. نگهداری فریم تابع (Stack Frame)

در ابتدای هر تابع:

```asm
push ebp        ; EBP فعلی رو ذخیره کن
mov ebp, esp    ; فریم جدید بساز (EBP = مرجع ثابت)
```

در انتهای تابع:

```asm
mov esp, ebp    ; استک رو به حالت قبلی برگردون
pop ebp         ; EBP قدیمی رو بازیابی کن
ret             ; آدرس برگشت رو از استک pop کن
```

🔹 این مکانیزم باعث میشه **هر تابع استک مخصوص به خودش** داشته باشه.

---

## 4. تبادل داده بین توابع (Passing Arguments)

در بسیاری از زبان‌های برنامه‌نویسی سطح پایین یا قراردادهای فراخوانی (Calling Conventions)، پارامترهای تابع از طریق استک **push** می‌شن:

```asm
push 5       ; آرگومان دوم
push 3       ; آرگومان اول
call add     ; فراخوانی تابع
```

داخل تابع `add`:

- `[ebp+8] = 3`
    
- `[ebp+12] = 5`
    

---

## 5. امنیت و اکسپلویت

مهاجم‌ها در حملات **Buffer Overflow** از همین push/pop و استک سوءاستفاده می‌کنن:

- داده مخرب رو push می‌کنن روی استک.
    
- وقتی تابع `ret` میزنه، آدرس جعلی pop میشه → کنترل اجرای برنامه دست مهاجم میفته.

- **push:** گذاشتن مقدار روی استک (ESP کاهش پیدا می‌کنه).
    
- **pop:** برداشتن مقدار از استک (ESP افزایش پیدا می‌کنه).

### 🔹 شباهت EBP به Pointer

بله، **EBP هم یک Pointer هست** (مثل ESP).

- هر دو **آدرس حافظه** نگه می‌دارن.
    
- هر دو به ناحیه‌ای در **استک** اشاره می‌کنن.
    

---

### 🔹 تفاوت نقش EBP و ESP

- **ESP**: همیشه به **بالای استک (Top of Stack)** اشاره می‌کنه و مدام تغییر می‌کنه (با هر `push` و `pop`).
    
- **EBP**: وقتی تابع شروع میشه، مقدار ESP در EBP کپی میشه. از این به بعد EBP **ثابت می‌مونه** (تا آخر تابع) و به عنوان **مرجع (Base)** استفاده میشه.
    

پس می‌شه گفت:

- ESP → پویاتر و لحظه‌ایه.
    
- EBP → مرجع ثابت برای دسترسی به آرگومان‌ها و متغیرهای محلیه.
    

---

### 🔹 مثال تصویری

فرض کن وارد یه تابع شدی:

```asm
push ebp
mov  ebp, esp
```

الان:

- **EBP = ESP** (هر دو یکسان هستن)
    
- بعدش اگه `push` یا ساختن متغیر محلی انجام بشه، **ESP تغییر می‌کنه** ولی **EBP ثابت می‌مونه**.
    

برای دسترسی به داده‌ها:

- `[ebp+8]` = آرگومان اول
    
- `[ebp+12]` = آرگومان دوم
    
- `[ebp-4]` = متغیر محلی
    

---

✅ نتیجه:  
بله، می‌تونی بگی **EBP یه جور Pointer ثابته که مقدار لحظه‌ای ESP رو در شروع تابع نگه می‌داره، تا وقتی ESP تغییر کرد ما هنوز یک مرجع ثابت برای دسترسی به داده‌ها داشته باشیم.**
