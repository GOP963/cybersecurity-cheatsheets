## 🔹 سلسله‌مراتب رجیسترها
توی معماری x86 (۳۲ بیتی):  
- **EAX** → رجیستر 32 بیتی کامل  
- **AX** → نصف پایینی EAX (16 بیت)  
- **AH** → 8 بیت بالایی AX  
- **AL** → 8 بیت پایینی AX  

📌 یعنی:  
```
EAX = 32 بیت
 └─ AX = 16 بیت پایینی
     ├─ AH = 8 بیت بالایی AX
     └─ AL = 8 بیت پایینی AX
```

---

## 🔹 مثال تصویری
فرض کن بنویسیم:
```asm
mov eax, 0x12345678
```

الان:
- `EAX = 12345678h` (کل 32 بیت)  
- `AX  = 5678h` (فقط نصف پایینی)  
- `AH  = 56h` (بخش بالا از AX)  
- `AL  = 78h` (بخش پایین از AX)  

---

## 🔹 چرا این‌طوری طراحی شده؟
چون توی گذشته (قبل از 80386) پردازنده‌ها 8 بیتی بودن → فقط AL داشتیم.  
بعد شدن 16 بیتی → AX اضافه شد (که شامل AL و AH میشه).  
بعد شدن 32 بیتی → EAX اضافه شد.  
بعد 64 بیتی → RAX اضافه شد.  

یعنی اینا یه جور **سازگاری عقبگرد (Backward Compatibility)** هستن.  

---

## 🔹 کاربرد عملی
- **AL** → خیلی وقت‌ها برای کار با کاراکترها (یک بایت) استفاده میشه.  
- **AH** → گاهی توی عملیات‌هایی مثل تقسیم یا کارهای خاص استفاده میشه.  
- **AX** → وقتی با مقادیر 16 بیتی کار داریم.  
- **EAX** → مقدار کامل 32 بیتی.  

---

## 🔹 مثال
```asm
mov eax, 0x00001234
```

- `EAX = 00001234h`  
- `AX  = 1234h`  
- `AH  = 12h`  
- `AL  = 34h`  

---

- **EAX** = 32 بیت کامل  
- **AX** = 16 بیت پایینی  
- **AH** = 8 بیت بالایی از AX  
- **AL** = 8 بیت پایینی از AX
