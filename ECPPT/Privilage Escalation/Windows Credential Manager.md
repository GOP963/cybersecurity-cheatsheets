

مدیریت اعتبارنامه (Windows Credential Manager) داخل ویندوز یه **محل ذخیره‌سازی امن** برای اطلاعات ورود (credentials) مثل **نام کاربری، رمز عبور و حتی توکن‌ها** هست.

🔹 ساده بگم:  
وقتی شما توی ویندوز به یه وب‌سایت، نرم‌افزار یا حتی شبکه (مثل یک share در شبکه یا ریموت دسکتاپ) وصل میشید و گزینه **"Remember me" / "Save password"** رو می‌زنید، اون اطلاعات داخل Credential Manager ذخیره میشه.

---

### 📌 انواع Credentialها

Credential Manager معمولاً اینا رو ذخیره می‌کنه:

1. **Web Credentials** → برای ذخیره اطلاعات ورود به وب‌سایت‌ها (در مرورگرهایی مثل Internet Explorer یا Edge قدیمی).
    
2. **Windows Credentials** → برای شبکه‌ها، سرویس‌ها، RDP، SMB و...
    
3. **Generic Credentials** → اپلیکیشن‌ها یا سرویس‌های شخص ثالث (مثلاً GitHub، SQL Server، یا VMware).
    

---

### 📌 محل ذخیره

- به‌صورت **رمزگذاری‌شده** (با DPAPI = Data Protection API) در سیستم ذخیره میشه.
    
- فایل‌های اصلی داخل مسیر زیر هستند:
    
    ```
    %Systemdrive%\Users\<Username>\AppData\Local\Microsoft\Credentials
    %Systemdrive%\Users\<Username>\AppData\Roaming\Microsoft\Credentials
    ```
    
- رجیستری هم برای رفرنس استفاده میشه:
    
    ```
    HKEY_CURRENT_USER\Software\Microsoft\IdentityCRL
    ```
    

---

### 📌 برای کاربر عادی چه کاربردی داره؟

- راحتی کار → نیاز نیست هر بار پسورد وارد کنید.
    
- امنیت نسبی → رمزها با کلید کاربر در سیستم رمزگذاری میشن.
    

---

### 📌 از دید **یک Attacker**

برای **Privilege Escalation یا Lateral Movement** خیلی ارزشمنده چون:

- اگه بتونه به Credential Manager دسترسی بگیره (مثلاً با ابزارهایی مثل **Mimikatz** یا **cmdkey /list** یا PowerShell)، می‌تونه یوزرنیم/پسورد ذخیره‌شده رو استخراج کنه.
    
- اینجوری به سرویس‌ها، شبکه‌ها یا حتی سیستم‌های دیگه وصل میشه بدون نیاز به دانستن پسورد واقعی.
    


****

، ابزار **`cmdkey.exe`** یک برنامه خط فرمان (CLI) داخلی ویندوز هست که برای **مدیریت Credentialها** (یعنی همون نام کاربری و رمز عبورهایی که سیستم ذخیره می‌کنه) استفاده میشه.  

### 🎯 وظایف اصلی `cmdkey`
- اضافه کردن یک credential (ذخیره نام کاربری و پسورد برای یک مقصد خاص)  
- لیست کردن credentialهایی که ذخیره شدن  
- حذف کردن credentialها  

---

### 🛠️ کاربردها
1. **اتصال به منابع شبکه‌ای (Shareها، Remote Desktop و...)**  
   → مثلا اگه بخوای به یک فایل‌سرور وصل بشی و نمی‌خوای هر بار رمز بزنی، می‌تونی با `cmdkey` credential رو ذخیره کنی.  

2. **کار با Remote Desktop (RDP)**  
   → با استفاده از `cmdkey` می‌تونی یوزرنیم و پسورد یک سیستم رو ذخیره کنی و بعد با `mstsc` بدون درخواست رمز وصل بشی.  

3. **مدیریت Security Context در اسکریپت‌ها**  
   → اگه داری اسکریپتی می‌نویسی که نیاز به دسترسی یک یوزر دیگه داره، می‌تونی با `cmdkey` اون credential رو ست کنی.  

---

### 📌 مثال‌ها
🔹 اضافه کردن credential:  

```cmd
cmdkey /add:192.168.1.10 /user:Administrator /pass:P@ssw0rd
```
→ از این به بعد هر بار به `192.168.1.10` وصل بشی، ویندوز اتومات با این یوزر/پسورد وارد میشه.  

🔹 لیست credentialهای ذخیره‌شده:  
```cmd
cmdkey /list
```

🔹 حذف credential:  
```cmd
cmdkey /delete:192.168.1.10
```

---

### ⚠️ از دید مهاجم (Attacker View)
- اگر مهاجم بتونه روی یک سیستم دسترسی پیدا کنه، می‌تونه با دستور `cmdkey /list` credentialهای ذخیره‌شده رو بگیره.  
- بعدش می‌تونه از اون credentialها برای حرکت جانبی (Lateral Movement) به سیستم‌های دیگه استفاده کنه.

در ویندوز، دستور **`runas`** برای اجرای یک برنامه یا دستور با کاربر دیگر استفاده می‌شود.  
یکی از سوییچ‌های مهم آن **`/savecred`** است.

---

🔹 **کارکرد `/savecred` در runas**  
وقتی شما برای اولین بار یک دستور را با `runas /savecred` اجرا می‌کنید، ویندوز از شما پسورد کاربر مورد نظر را می‌پرسد و آن را در **Windows Credential Manager** ذخیره می‌کند.

از آن به بعد، اگر دوباره همان دستور (با همان کاربر) را اجرا کنید، دیگر نیازی به وارد کردن پسورد ندارید، چون از Credential Manager خوانده می‌شود.

---

🔹 **مثال:**

```powershell
runas /user:Administrator /savecred "cmd.exe"
```

- بار اول: از شما پسورد ادمین می‌خواهد و ذخیره می‌کند.
    
- بار دوم به بعد: بدون پرسیدن پسورد، مستقیم `cmd.exe` را با دسترسی ادمین اجرا می‌کند.
    

---

⚠️ **ریسک امنیتی:**

- اگر attacker یک بار پسورد را با `/savecred` ذخیره کند، بعدش می‌تواند بارها بدون داشتن پسورد واقعی به آن کاربر دسترسی بگیرد.
    
- این باعث می‌شود **Privilege Escalation** ساده‌تر شود.
    
- خیلی از سازمان‌ها این قابلیت را غیرفعال می‌کنند چون می‌تواند به مهاجم کمک کند.
