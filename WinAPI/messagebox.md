## 2️⃣ Wide چیست؟

### تعریف ساده:

**Wide یعنی کاراکتر چندبایتی (معمولاً ۲ بایت)**

```c++
wchar_t
```

```c++
wchar_t text[] = L"سلام";
```

ویژگی‌ها:

- هر کاراکتر = 2 بایت (در ویندوز)
    
- می‌تواند زبان‌های غیرانگلیسی را پشتیبانی کند
    
- پایه‌ی Unicode در ویندوز

به چه دردی میخورد ؟ 

ما توی کامپیوتر یک استانداردی داریم برای اینکه بتونیم به واسطه این استاندارد بیایم و اون مقداری که تخصیص دادیم به برنامه مون بره داخل CPU و پردازش بشه، برای اینکه CPU اون مقدار که حالا میتونه عدد باشه یا حروف رو باید تبدیل به متن unicode بکنه مثلا ascii که بتونه از طریق اون کدی کهascii به ما میده بیایم و در قدم بعدی به CPU معرفی کنیم و بره پردازش شه 

مثلا 

c ----> 99
p ----> 112

همونطور که میبینید این عدد ها کد ascii مربوط به کلمات هستند و کامپیوتر بتونه این کلامت رو به CPU معرفی کنه باید این حروف رو تبدیل به کد ascii کنه یعنی unicode بشه تا در قدم بعدی این unicode بره و تبدیل به binery بشه تا CPU بتونه پردازشش کنه 

اما اینیو که گفتیم مربوط میشه به کلامت انگلیسی، اگر ما بخواهیم که داخل متغیر مون که یک رشته میگیره بیایم و یه مقدار string رو بهش بدیم و اون مقدار string کلمه انگلیسی باشه مقداری رو که میگیرد تک بایتی هست م با datatype char میتونیم بهش معرفی میکنیم حالا کلمات انگلیسی تو API های ویندوز به ANSI معروف هستند که ANSI رو هم توضیح دادیم (یعنی متن تک‌بایتی) اما اگر اون مقداری رو که میدیم یه متنی غیر از انگلیسی باشد تک بایتی محسوب نمیشود و چون متن تک بایتی محسوب نمیشود ANSI به حساب نمیاد و بیشتر از تک بایت جا میگیرد و Wide به حساب می آید مثلا یه متن فارسی یا ایموجی یا هر چیزی که ANSI نیست 

تو windows API ها موقعی که داریم از یه API استفاده میکنیم اگر بعد از اسم API کلمه A بود به معنای ANSI یا اگر کلمه یی به اسم W به معنای Wide 


حالا ما همه اینارو گفتیم که از اون رشته شروع میشه تا باینری ولی نحوه ذخیره سازیش رو نگفتیم 
ما به واسطه Unicode میایم دیتایی که داریم یعنی همون String رو تبدیل به یک code Code Point میکنیم تا در قدم بعدی این Code Point بره داخل CPU و پردازش بشه اما چطوری ؟ 
از طریق  UTF ها اینکار انجام میشود 

در UTF همون روش ذخیره سازی Unicode

یعنی:

- Unicode می‌گوید «این کاراکتر چیست»
    
- UTF می‌گوید «این کاراکتر چطور در حافظه ذخیره شود»


## Unicode چیست (یادآوری سریع)

Unicode به هر کاراکتر یک **Code Point** می‌دهد:
## UTF یعنی چی؟

**UTF = Unicode Transformation Format**

یعنی:

> تبدیل Code Point به بایت


## UTF-8 چیست؟

### تعریف:

**UTF-8 یک Encoding متغیر طول است**


| کاراکتر | بایت   |
| ------- | ------ |
| A       | 1 بایت |
| س       | 2 بایت |
| 😄      | 4 بایت |

|کاراکتر|Code Point|
|---|---|
|A|U+0041|
|س|U+0633|
|😄|U+1F604|

### ویژگی‌ها:

✔ سازگار با ASCII  
✔ کم‌حجم برای انگلیسی  
✔ استاندارد وب و لینوکس  
✔ Endianness ندارد



```shell
"Hello" → 48 65 6C 6C 6F
"سلام"  → D8 B3 D9 84 D8 A7 D9 85
```

## UTF-16 چیست؟

### تعریف:

**UTF-16 اغلب 2 بایت است (گاهی 4 بایت)**


|کاراکتر|بایت|
|---|---|
|A|2|
|س|2|
|😄|4 (Surrogate Pair)|


### ویژگی‌ها:

✔ مورد استفاده ویندوز  
✔ پایه WinAPI  
❌ Endianness دارد (LE / BE)

در ویندوز:


```c++
wchar_t == UTF-16
```

## 3️⃣ Unicode چیست؟

### تعریف ساده:

**Unicode یک استاندارد جهانی برای نمایش تمام زبان‌هاست**

Unicode می‌گوید:

> هر کاراکتر در دنیا → یک Code Point

مثال:

- 'A' → U+0041
    
- 'س' → U+0633
    
- 😄 → U+1F604

فرمت‌ها:

- UTF-8
    
- UTF-16
    
- UTF-32

# 1️⃣ اول یک مدل ذهنی درست بسازیم

در WinAPI، پسوندها **تزئینی نیستند**  
هرکدوم به یک «نیاز واقعی» پاسخ می‌دهند:

```
A / W   → نوع داده متنی
Ex      → قابلیت‌های اضافه
Ex2     → معماری جدید / امنیتی‌تر
```

این‌ها **لایه‌های مستقل** هستند، نه جایگزین هم.

# 2️⃣ تفاوت دقیق A و W با Ex و Ex2

## A / W به چه درد می‌خورند؟

### مشکل اصلی:

ویندوز باید:

- هم برنامه‌های قدیمی (ANSI)
    
- هم برنامه‌های مدرن (Unicode)
    

را پشتیبانی کند.

### راه‌حل:

دو نسخه از API:

|پسوند|حل چه مشکلی؟|
|---|---|
|A|سازگاری با Legacy|
|W|پشتیبانی کامل Unicode|

📌 A/W فقط **نوع داده** را عوض می‌کنند  
هیچ قابلیت جدیدی اضافه نمی‌کنند

---

## Ex به چه درد می‌خورد؟

### مشکل:

نسخه‌ی اولیه‌ی API:

- ساده است
    
- پارامتر کم دارد
    
- کنترل امنیتی محدود دارد
    

### راه‌حل:

> API جدید بدون شکستن قدیمی

یعنی:

- تابع قدیمی دست‌نخورده می‌ماند
    
- تابع جدید با پارامترهای بیشتر معرفی می‌شود
    

---

## مثال واقعی: CreateWindow vs CreateWindowEx

### CreateWindow:

```c
HWND CreateWindow(...);
```

❌ کنترل محدود روی Window Style

### CreateWindowEx:

```c
HWND CreateWindowEx(
  DWORD dwExStyle,
  ...
);
```

✔ کنترل Z-Order  
✔ Layered Window  
✔ TopMost  
✔ Transparency

📌 این‌ها بدون Ex اصلاً ممکن نبود

---

## مثال امنیتی: RegCreateKey vs RegCreateKeyEx

### RegCreateKey:

- ساده
    
- بدون Security Descriptor
    
- بدون Access Control
    

### RegCreateKeyEx:

- تعیین Permission
    
- تعیین Option
    
- کنترل رفتار رجیستری
    

📌 برای بدافزار و EDR حیاتی

---

> **ASCII پایه‌ی همه‌چیزه**  
> هم ANSI

> همه از ASCII شروع می‌شن.

## 1️⃣ ASCII دقیقاً چیست؟

### تعریف رسمی:

**ASCII = American Standard Code for Information Interchange**

- یک جدول **۷ بیتی**
    
- فقط **۱۲۸ کاراکتر**
    
- مخصوص انگلیسی
    

---

## 2️⃣ جدول ASCII شامل چی‌هاست؟

|بازه|معنی|
|---|---|
|0–31|Control Characters|
|32–126|حروف، اعداد، علائم|
|127|DEL|

مثال:

```
'A' → 65 (0x41)
'a' → 97 (0x61)
'0' → 48 (0x30)
```

---

## 3️⃣ ASCII چه ربطی به ANSI دارد؟

### ANSI در واقع:

> **ASCII + 128 کاراکتر اضافه (بسته به Code Page)**

مثلاً:

- CP1252 (اروپایی)
    
- CP1256 (عربی/فارسی)
    

📌 نکته مهم:

- 0–127 → ASCII
    
- 128–255 → وابسته به سیستم
    

پس:

> ANSI = ASCII + منطقه‌ای

---

## 4️⃣ ASCII چه ربطی به UTF-8 دارد؟

### نکته طلایی 🧠:

> UTF-8 کاملاً با ASCII سازگار است

یعنی:

```
UTF-8("A") == ASCII("A")
```

|کاراکتر|بایت|
|---|---|
|A|0x41|
|1|0x31|
|!|0x21|

📌 به همین دلیل:

- فایل‌های قدیمی هنوز کار می‌کنند
    
- وب به UTF-8 مهاجرت کرد
    

---

## 5️⃣ ASCII چه ربطی به UTF-16 دارد؟

در UTF-16:

- ASCII به صورت **2 بایتی** ذخیره می‌شود
    

مثال:

```
'A' → 0x0041
```

یعنی:

> معنی یکی است، شکل ذخیره فرق می‌کند

---

## 6️⃣ ASCII در WinAPI کجاست؟

|حالت|استفاده|
|---|---|
|ANSI API|مستقیم|
|Unicode API|غیرمستقیم|

مثال:

```c
MessageBoxA("Hello"); // ASCII
MessageBoxW(L"Hello"); // UTF-16 ولی همچنان ASCII-range
```

چون خیلی از توابع ویندوز از **ساختارهایی استفاده می‌کنن که بخشی از اون‌ها ورودی هستند و بخشی خروجی**  
و ویندوز **انتظار داره بعضی فیلدها از قبل مقدار مشخص (معمولاً صفر یا اندازه ساختار) داشته باشن**

```c++

```
هر عددی می‌تونه باشه چون:

- حافظه قبلاً استفاده شده
    
- داده‌های قدیمی هنوز توش هستن
    

📌 این داده‌ها همون **Garbage** هستند.
