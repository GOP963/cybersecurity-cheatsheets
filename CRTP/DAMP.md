## 🛠️ ابزار DAMP چیست؟

**DAMP** 
مخفف **Discretionary ACL Modification Project** هست. این ابزار توسط متخصصان امنیتی مثل [@harmj0y](https://github.com/HarmJ0y/DAMP) ساخته شده و هدفش ایجاد **Persistence (ماندگاری دسترسی)** در سیستم‌های ویندوزی از طریق **تغییر ACLها و Security Descriptorها** هست.

### 🎯 هدف اصلی DAMP:

ایجاد راه‌های مخفی برای دسترسی به سیستم، بدون نیاز به عضویت در گروه Administrators، با استفاده از تغییر مجوزهای دسترسی به سرویس‌ها، رجیستری، WMI، DCOM و غیره.

link : https://github.com/HarmJ0y/DAMP

| فایل                           | توضیح                                                 |
| ------------------------------ | ----------------------------------------------------- |

| `Get-RemoteMachineAccountHash` | دریافت هش حساب ماشین از راه دور                       |
| `Get-RemoteLocalAccountHash`   | دریافت هش حساب‌های محلی از راه دور                    |
| `Get-RemoteCachedCredential`   | دریافت اعتبارنامه‌های کش‌شده دامنه                    |

## 🔑 دستور `Add-RemoteRegBackdoor` و سوییچ‌های مهم

این دستور برای ایجاد backdoor رجیستری استفاده می‌شه. مهم‌ترین سوییچ‌هاش:

|سوییچ|توضیح|
|---|---|
|`-ComputerName`|نام یا IP سیستم هدف|
|`-Trustee`|نام کاربری که می‌خوای بهش دسترسی بدی (مثلاً student1)|
|`-Verbose`|نمایش جزئیات اجرای دستور برای دیباگ و بررسی|

### ✅ عملکرد:

این دستور ACLهای کلیدهای رجیستری زیر رو تغییر می‌ده:

- `HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg`
- `HKLM\SAM\SAM\Domains\Account`
- `HKLM\SECURITY\Policy\Secrets`

و به کاربر `student1` اجازه می‌ده که از راه دور به این کلیدها دسترسی داشته باشه، حتی اگر ادمین نباشه.

## 🔍 تحلیل کلی دستور:

```powershell
Add-RemoteRegBackdoor -ComputerName dcorp-dc -Trustee student1 -Verbose
```

### 🧠 چی می‌گه؟

- روی سیستم `dcorp-dc`، ACLهای رجیستری رو طوری تغییر بده که کاربر `student1` بتونه به کلیدهای حساس دسترسی داشته باشه.
- این یعنی ایجاد یک **دسترسی دائمی و مخفی** برای استخراج اطلاعات مثل هش‌ها، بدون نیاز به اجرای کد یا نصب ابزار روی سیستم هدف.

این نوع دستکاری ACLها معمولاً توسط آنتی‌ویروس‌ها شناسایی نمی‌شن چون رفتاری مخرب ندارن، فقط مجوزها رو تغییر می‌دن. برای مقابله با این نوع حملات باید:

- تغییرات ACLها رو مانیتور کرد.
- از ابزارهایی مثل Sysmon، Windows Event Logs و SIEM استفاده کرد.
- دسترسی ادمین رو محدود کرد.

## 🧠 پیش‌نیازهای دسترسی ریموت به رجیستری

برای اینکه بتونی از راه دور به رجیستری یک سیستم ویندوزی دسترسی داشته باشی، باید چند شرط برقرار باشه:

1. **سرویس Remote Registry روی سیستم هدف فعال باشه**  
    این سرویس به‌طور پیش‌فرض در اکثر سیستم‌ها غیرفعاله. برای فعال‌سازی:
    
    ```powershell
    Set-Service -Name RemoteRegistry -StartupType Automatic
    Start-Service -Name RemoteRegistry
    ```
    
2. **دسترسی ادمین یا مجوز مناسب روی سیستم هدف داشته باشی**  
    اگر از ابزار DAMP استفاده می‌کنی، باید قبلاً با تغییر ACLها به کاربر مورد نظر (مثلاً `student1`) مجوز دسترسی داده باشی.
    
3. **پورت‌های مربوط به رجیستری و RPC باز باشن**  
    معمولاً پورت‌های `135` و `445` برای این نوع ارتباط استفاده می‌شن. باید مطمئن بشی که فایروال سیستم هدف این پورت‌ها رو بلاک نکرده باشه.

## 🔐 ACL و Security Descriptor یعنی چی؟

در ویندوز، هر منبع (مثل فایل، رجیستری، سرویس، WMI، DCOM) یک **Security Descriptor** داره که مشخص می‌کنه چه کسی می‌تونه به اون منبع دسترسی داشته باشه و چه کاری انجام بده.

بخش اصلی این Security Descriptor، چیزی به نام **DACL (Discretionary Access Control List)** هست که شامل لیستی از **ACEها (Access Control Entries)** می‌شه. هر ACE مشخص می‌کنه که یک کاربر یا گروه خاص چه نوع دسترسی‌ای داره (خواندن، نوشتن، اجرا و غیره).

---

## 🎯 چرا تغییر ACLها برای Persistence مهمه؟

وقتی مهاجم وارد سیستم می‌شه، می‌خواد راهی برای برگشت داشته باشه—even اگر رمزها عوض بشن یا سیستم ریستارت بشه. یکی از زیرکانه‌ترین روش‌ها اینه که:

✅ به جای نصب بک‌دور یا اجرای کد مخرب، فقط **مجوزهای دسترسی (ACL)** رو تغییر بده  
✅ به یک کاربر غیرادمین (مثلاً `student1`) اجازه بده به منابع حساس مثل رجیستری یا سرویس‌ها دسترسی داشته باشه  
✅ این دسترسی دائمی باقی می‌مونه و معمولاً توسط آنتی‌ویروس‌ها یا EDRها شناسایی نمی‌شه

---

## 🛠️ چطور ACLها رو تغییر می‌دن؟

### 🔸 با PowerShell مستقیم:

مثلاً برای دادن دسترسی به رجیستری:

```powershell
$acl = Get-Acl "HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg"
$rule = New-Object System.Security.AccessControl.RegistryAccessRule("student1","FullControl","Allow")
$acl.SetAccessRule($rule)
Set-Acl "HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg" $acl
```

### 🔸 با ابزار DAMP:

ابزار DAMP این کار رو اتوماتیک انجام می‌ده. دستور زیر:

```powershell
Add-RemoteRegBackdoor -ComputerName dcorp-dc -Trustee student1 -Verbose
```

میاد و ACLهای کلیدهای رجیستری حساس رو طوری تغییر می‌ده که کاربر `student1` بتونه از راه دور به رجیستری دسترسی داشته باشه—even اگر ادمین نباشه.

---

## 📌 نتیجه این تغییر چیه؟

بعد از تغییر ACLها، کاربر `student1` می‌تونه:

- با ابزارهایی مثل `Get-RemoteMachineAccountHash` هش حساب‌های ماشین رو بخونه
- با `Get-RemoteLocalAccountHash` هش حساب‌های محلی رو استخراج کنه
- حتی اعتبارنامه‌های کش‌شده دامنه رو با `Get-RemoteCachedCredential` دریافت کنه

و همه‌ی این‌ها بدون نیاز به اجرای کد روی سیستم هدف، فقط با دسترسی به رجیستری از راه دور.

## 🧭 سناریوی کلی: از Initial Access تا Privilege Escalation با رجیستری

### ✅ مرحله 1: Initial Access

تو به‌نوعی وارد سیستم هدف شدی—مثلاً با:

- کرک کردن رمز یک کاربر دامنه
- اجرای کد از طریق phishing
- استفاده از آسیب‌پذیری مثل EternalBlue یا PrintNightmare

حالا یه دسترسی محدود داری، مثلاً با کاربر `student1`.

---

### ✅ مرحله 2: اجرای ابزار DAMP برای تغییر ACL رجیستری

با استفاده از ابزار DAMP، دستور زیر رو اجرا می‌کنی:

```powershell
Add-RemoteRegBackdoor -ComputerName dcorp-dc -Trustee student1 -Verbose
```

این دستور میاد و **ACLهای کلیدهای رجیستری حساس** رو تغییر می‌ده، مثل:

- `HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg`
- `HKLM\SAM\SAM\Domains\Account`
- `HKLM\SECURITY\Policy\Secrets`

و به `student1` اجازه می‌ده که از راه دور به این کلیدها دسترسی داشته باشه—even اگر ادمین نباشه.

### ✅ مرحله 3: استفاده از دسترسی جدید برای استخراج اطلاعات حساس

حالا که `student1` دسترسی به رجیستری داره، می‌تونه با ابزارهای DAMP این اطلاعات رو بکشه بیرون:

|دستور|کاری که انجام می‌ده|

## 🧠 یعنی چی "backdoor با رجیستری"؟

در این روش، هیچ فایل اجرایی یا کد مخربی روی سیستم هدف اجرا نمی‌شه. فقط مجوزهای دسترسی به کلیدهای رجیستری مثل:

- `HKLM\SAM\SAM\Domains\Account` → برای هش حساب‌های محلی
- `HKLM\SECURITY\Policy\Secrets` → برای کش‌های دامنه
- `HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg` → برای دسترسی ریموت به رجیستری

تغییر داده می‌شن تا کاربر `student1` بتونه از راه دور این اطلاعات رو بخونه.

---

## 🔐 چرا این نوع backdoor خطرناک و زیرکانه‌ست؟

- چون هیچ آنتی‌ویروسی به‌راحتی متوجهش نمی‌شه
- چون مهاجم می‌تونه بعداً بدون نفوذ مجدد، فقط با همون کاربر وارد بشه و اطلاعات بکشه بیرون
- چون این دسترسی دائمی باقی می‌مونه حتی بعد از ریستارت یا تغییر رمزها

## 🧠 اول: Agent یعنی چی؟

در تست نفوذ، **Agent** معمولاً به یک برنامه یا اسکریپت گفته می‌شه که روی سیستم هدف نصب یا اجرا می‌شه تا ارتباط دائمی با مهاجم برقرار کنه (مثل reverse shell، beacon، یا implant).  
اما در روش‌هایی مثل DAMP/RACE، هیچ agentی نصب نمی‌شه. پس چطور کار می‌کنن؟

## 🔍 مکانیزم دقیق کار بدون Agent

### ✅ 1. استفاده از **Remote Registry Service**

ویندوز یک سرویس داخلی داره به نام **RemoteRegistry** که اگر فعال باشه، اجازه می‌ده از راه دور به رجیستری سیستم دسترسی پیدا کنی.  
ابزارهایی مثل DAMP از همین سرویس استفاده می‌کنن.

> نکته: این سرویس به‌طور پیش‌فرض در اکثر سیستم‌ها غیرفعاله، ولی اگر فعال باشه و مهاجم دسترسی ادمین داشته باشه، می‌تونه ازش استفاده کنه.

---

### ✅ 2. استفاده از **RPC و SMB**

دسترسی به رجیستری از راه دور از طریق پروتکل‌های **RPC (Remote Procedure Call)** و **SMB (Server Message Block)** انجام می‌شه.  
ابزار DAMP از PowerShell و WMI برای ارتباط با سیستم هدف استفاده می‌کنه، بدون اینکه چیزی روی اون نصب کنه.

---

### ✅ 3. تغییر ACLها از راه دور

وقتی مهاجم دسترسی ادمین داره، می‌تونه از راه دور ACLهای کلیدهای رجیستری رو تغییر بده. مثلاً:

```powershell
Invoke-Command -ComputerName dcorp-dc -ScriptBlock {
    $acl = Get-Acl "HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg"
    $rule = New-Object System.Security.AccessControl.RegistryAccessRule("student1","ReadKey","Allow")
    $acl.SetAccessRule($rule)
    Set-Acl "HKLM\SYSTEM\CurrentControlSet\Control\SecurePipeServers\winreg" $acl
}
```

این یعنی بدون نصب هیچ فایل یا اجرای کد روی سیستم هدف، فقط با تغییر مجوزها، راهی برای دسترسی بعدی ایجاد می‌شه.

---

### ✅ 4. استفاده از ابزارهای PowerShell Remoting

ابزارهایی مثل DAMP از **PowerShell Remoting** استفاده می‌کنن که خودش از WinRM بهره می‌بره. اگر WinRM فعال باشه، مهاجم می‌تونه از راه دور دستورات PowerShell اجرا کنه.

---

## 🔐 چرا این روش خطرناک و stealthy هست؟

- هیچ فایل اجرایی یا implant روی سیستم هدف نیست
- فقط از سرویس‌های داخلی ویندوز استفاده می‌شه
- تغییر ACLها معمولاً توسط آنتی‌ویروس‌ها شناسایی نمی‌شن
- مهاجم می‌تونه بعداً با یک کاربر غیرادمین مثل `student1` اطلاعات حساس رو استخراج کنه

## 🧠 4. `Get-RemoteCachedCredential -ComputerName dcorp-dc -Verbose`

### 📌 چی کار می‌کنه؟

اطلاعات کش‌شده‌ی مربوط به **کاربران دامنه** رو از سیستم هدف استخراج می‌کنه. ویندوز برای ورود آفلاین، این اطلاعات رو نگه می‌داره.

### 🎯 کاربرد:

- استخراج هش‌های دامنه بدون نیاز به دسترسی به DC
- استفاده در حملات Pass-the-Hash یا Kerberoasting

---

## 🧩 جمع‌بندی کاربردها

| دستور                          | هدف اصلی          | کاربرد امنیتی                   |
| ------------------------------ | ----------------- | ------------------------------- |
| `Add-RemoteRegBackdoor`        | تغییر ACL رجیستری | ایجاد backdoor برای دسترسی بعدی |
| `Get-RemoteMachineAccountHash` | استخراج هش ماشین  | حملات lateral movement          |
| `Get-RemoteLocalAccountHash`   | استخراج هش محلی   | privilege escalation            |
| `Get-RemoteCachedCredential`   | دریافت کش دامنه   | حملات credential reuse          |
