📌 **Event ID 4688** در ویندوز مربوط به **ایجاد یک Process جدید** هست.  
این لاگ هر بار که یک برنامه یا دستور جدید اجرا بشه توسط **Windows Security Auditing** ثبت میشه.

---

### 🔹 جزئیات اصلی Event ID 4688:

- **Process Create** → هر بار یک پروسس جدید ساخته میشه.
    
- در لاگ مشخص میشه:
    
    - **Creator Process ID** → همون PID پروسس والد (Parent).
        
    - **New Process ID** → PID پروسس جدیدی که ساخته شده.
        
    - **New Process Name** → مسیر فایل اجرایی پروسس جدید (مثلاً `C:\Windows\System32\cmd.exe`).
        
    - **Token Elevation Type** → آیا پروسس با دسترسی ادمین یا کاربر عادی اجرا شده.
        
    - **Command Line** (اگه Audit Process Creation Command Line فعال باشه) → دقیقاً چه دستوری اجرا شده.
        
    - **Creator Process Name** → پروسس والد (مثلاً explorer.exe، services.exe، یا svchost.exe).
        

---

### 🔹 اهمیت امنیتی:

این Event یکی از **مهم‌ترین لاگ‌ها برای تحلیل تهدیدات** هست چون:

- میشه فهمید چه برنامه‌هایی در سیستم اجرا شدن.
    
- میشه تشخیص داد که یک مهاجم ابزار مخرب یا cmd/powershell مشکوک اجرا کرده.
    
- برای تحلیل حملات مثل:
    
    - **Malware Execution**
        
    - **Privilege Escalation**
        
    - **Lateral Movement**
        
    - **Persistence**
        
    - **Living off the Land Binaries (LOLBins)**
        

---

### 🔹 مثال از موقعیت واقعی:

فرض کن در لاگ ببینی:

```
New Process Name: C:\Windows\System32\cmd.exe
Command Line: cmd.exe /c whoami
Creator Process Name: outlook.exe
```

این می‌تونه نشونه اجرای یک **ماکرو مخرب از طریق ایمیل** باشه.

### 🔹 نمایش خروجی به Base64

داخل خود ابزار `mimikatz` یک دستور مخصوص برای کدگذاری وجود داره:

```mimikatz
base64 /in:<file> /out:<file> [/line:##]
```

- `/in` : فایل ورودی (مثلاً یک dump از رمزها یا تیکت‌ها).
    
- `/out` : فایل خروجی که نتیجه Base64 داخلش ذخیره میشه.
    
- `/line:##` : تعداد کاراکتر در هر خط Base64 (پیش‌فرض 64).
    

🔸 مثال:

```mimikatz
base64 /in:sekret.bin /out:sekret.b64
```

این میاد محتوای `sekret.bin` (مثلاً یه تیکت کر‌بروس یا هش) رو Base64 میکنه و داخل `sekret.b64` ذخیره میکنه.

---

### 🔹 استفاده مستقیم از Base64 برای ورودی

اگه خروجی رو قبلاً Base64 گرفتی، می‌تونی دوباره برگردونی (decode) تا Mimikatz بتونه استفاده کنه:

```mimikatz
base64 /in:sekret.b64 /out:sekret.bin /decode
```

اینجا `/decode` باعث میشه Base64 برگرده به باینری اصلی.

---

### 🔹 کاربرد واقعی

1. وقتی میخوای **تیکت Kerberos (Kirbi files)** یا **LSASS dump** رو منتقل کنی، میتونی اول Base64 کنی تا راحت‌تر داخل لاگ یا اسکریپت بذاری.
    
2. وقتی لاگ رو در محیط‌هایی داری که کاراکترهای باینری رو خراب می‌کنن، Base64 سالم‌تر منتقل میشه.
    

---

✅ خلاصه:

- در **Mimikatz** با دستور `base64` میشه ورودی/خروجی رو Base64 کرد یا از Base64 خارج کرد.
    
- خیلی وقت‌ها برای انتقال تیکت‌ها (Pass-the-Ticket) یا خروجی‌های حساس استفاده میشه.
