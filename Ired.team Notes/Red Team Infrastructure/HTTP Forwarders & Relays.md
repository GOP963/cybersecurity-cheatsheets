
**فورواردها / رله‌های HTTP**

پنهان‌سازی میزبان‌های مهاجم با استفاده از ری‌دایرکتورها / فوروارد کننده‌های ترافیک با `iptables` یا `socat`

**هدف**

ری‌دایرکتورها یا فوروارد کننده‌های ترافیک در واقع پروکسی‌هایی بین سرور رد تیمینگ (مثلاً همان سروری که ایمیل‌های فیشینگ یا یک C2 را می‌فرستد) و قربانی هستند — قربانی <> ری‌دایرکتور <> سرور تیم

هدف میزبان ری‌دایرکتور، همان‌طور که معمول است:

- پنهان کردن سرور رد تیمینگ با مخفی نگه‌داشتن آدرس IP آن. به عبارت دیگر — قربانی ترافیک را از سمت میزبان ری‌دایرکتور خواهد دید نه از سمت سرور تیم.
    
- اگر پاسخ‌دهندگان به حادثه تشخیص دهند که فعالیت مشکوکی از ری‌دایرکتور نشأت می‌گیرد، آن می‌تواند «به‌راحتی» از سرویس خارج شده و با یک مورد دیگر جایگزین شود، که این کار نسبت به بازسازی سرور تیم «راحت‌تر» است.
    

**فورواردینگ HTTP با iptables**

من قرار است فورواردرهای سادهٔ HTTP را بررسی کنم که دقیقاً همان کاری را انجام می‌دهند — روی یک اینترفیس و پورت مشخص گوش می‌دهند و تمام ترافیکی را که روی آن پورت دریافت می‌کنند، به یک پورت listener روی سرور تیم فوروارد می‌کنند.

محیط من در این آزمایشگاه:

- سرور تیم و یک پورت شنونده: `10.0.0.2:80`
    
- میزبان ری‌دایرکتور و یک پورت شنونده: `10.0.0.5:80`
    
- میزبان قربانی: `10.0.0.11`
    

یک راه ساده برای ساخت یک ری‌دایرکتور HTTP این است که از یک سیستم لینوکسی و قابلیت `iptables` آن استفاده کنید.

در ادامه نشان داده می‌شود چگونه یک ماشین لینوکسی را به یک ری‌دایرکتور HTTP تبدیل کنید. در این حالت، تمام ترافیک HTTP به `10.0.0.5:80` (ری‌دایرکتور) به `10.0.0.2:80` (سرور تیم) فوروارد خواهد شد.

---

```
iptables -I INPUT -p tcp -m tcp --dport 80 -j ACCEPT
iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 10.0.0.2:80
iptables -t nat -A POSTROUTING -j MASQUERADE
iptables -I FORWARD -j ACCEPT
iptables -P FORWARD ACCEPT
sysctl net.ipv4.ip_forward=1
```

---

```
iptables -I INPUT -p tcp -m tcp --dport 80 -j ACCEPT
```

این خط می‌گه:

> تمام بسته‌هایی که به پورت 80 (یعنی HTTP) میان، اجازه عبور داشته باشن.


| بخش          | معنی                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------- |
| `iptables`   | ابزار مدیریت فایروال لینوکس                                                                     |
| `-I INPUT`   | قانون را در ابتدای **chain** مربوط به بسته‌هایی که وارد سیستم می‌شوند (INPUT chain) درج می‌کند. |
| `-p tcp`     | فقط بسته‌های پروتکل TCP را در نظر بگیر.                                                         |
| `-m tcp`     | ماژول TCP را برای بررسی ویژگی‌های خاص TCP فعال می‌کند (مثل پورت‌ها).                            |
| `--dport 80` | یعنی اگر **پورت مقصد** بسته عدد 80 بود (HTTP)، این قانون اعمال شود.                             |
| `-j ACCEPT`  | اقدام (jump) نهایی: بسته را **بپذیر و عبور بده**.                                               |

---

```
iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 10.0.0.2:80
```

این قانون برای **Port Forwarding (تغییر مقصد بسته)** است.  
می‌گوید:

> هر بسته TCP که وارد سیستم می‌شود و پورت مقصدش 80 است، قبل از رسیدن به مقصد اصلی، به مقصد جدید **10.0.0.2:80** تغییر داده شود.

|بخش|معنی|
|---|---|
|`-t nat`|جدول NAT (Network Address Translation) را مشخص می‌کند. این جدول برای تغییر آدرس‌های IP استفاده می‌شود.|
|`-A PREROUTING`|این قانون را به زنجیره (chain) **PREROUTING** اضافه می‌کند — یعنی قبل از مسیردهی بسته‌ها اجرا شود.|
|`-p tcp`|فقط بسته‌های TCP.|
|`--dport 80`|پورت مقصد 80 باشد.|
|`-j DNAT`|**Destination NAT** — تغییر مقصد بسته.|
|`--to-destination 10.0.0.2:80`|مقصد جدید را مشخص می‌کند؛ یعنی بسته به جای اینکه به IP اصلی برود، به 10.0.0.2 روی پورت 80 ارسال می‌شود.|

تمام درخواست‌های HTTP که به این سرور میان، به سیستم دیگری (10.0.0.2) فوروارد می‌شن.

---

```
iptables -t nat -A POSTROUTING -j MASQUERADE
```

این خط برای **NAT خروجی** است؛ یعنی وقتی بسته‌ها از این سیستم به بیرون می‌روند، آدرس IP مبدأ آنها به **IP سیستم فعلی** تغییر کند.


|بخش|معنی|
|---|---|
|`-t nat`|جدول NAT را مشخص می‌کند.|
|`-A POSTROUTING`|قانون را بعد از تصمیم‌گیری مسیر بسته اضافه می‌کند (در خروجی).|
|`-j MASQUERADE`|یعنی از **ماسکریدینگ (Masquerading)** استفاده کن — مشابه SNAT ولی به صورت پویا.|
|برای سیستم‌هایی با IP متغیر (مثل اینترنت یا DHCP) کاربرد دارد.||

---

```
iptables -I FORWARD -j ACCEPT
```

هر بسته‌ای که قرار است **از سیستم عبور کند (Forwarding)** بدون محدودیت عبور کند.

---

```
iptables -P FORWARD ACCEPT
```

این دستور **policy پیش‌فرض** زنجیره FORWARD را روی **ACCEPT** قرار می‌دهد.  
یعنی اگر هیچ قانونی خاصی مطابقت نداشت، بسته‌ها **به‌صورت پیش‌فرض اجازه عبور دارند**.

---

```
sysctl net.ipv4.ip_forward=1
```

این دستور در سطح **کرنل لینوکس** ویژگی **IP forwarding** را فعال می‌کند.  
بدون این گزینه، حتی اگر iptables تنظیم شده باشد، بسته‌ها بین دو شبکه فوروارد نمی‌شن.

---

برای دائمی کردنش می‌تونی بنویسی:

```
echo "net.ipv4.ip_forward=1" >> /etc/sysctl.conf
sysctl -p
```

سیستم شما به‌صورت یک **روتر (gateway)** عمل می‌کند و بسته‌ها را بین دو شبکه (مثلاً LAN و WAN) عبور می‌دهد.

---

🧩 خلاصه‌ی کل دستورها

| خط  | عملکرد کلی                                             |
| --- | ------------------------------------------------------ |
| 1️⃣ | اجازه دادن به ترافیک ورودی HTTP                        |
| 2️⃣ | هدایت درخواست‌های HTTP به سرور داخلی (Port Forwarding) |
| 3️⃣ | تغییر IP مبدأ بسته‌های خروجی (Masquerade/NAT)          |
| 4️⃣ | اجازه عبور بسته‌ها بین شبکه‌ها                         |
| 5️⃣ | تنظیم سیاست پیش‌فرض FORWARD به ACCEPT                  |
| 6️⃣ | فعال کردن قابلیت فوروارد IP در کرنل                    |

حالا میتونیم این فرایند رو حرفه ایی ترش بکنیم مثلا داخل agent که به عنوان همون Malisious Payload روی سیستم قربانی هست ذکر کنیم که هر درخواستی از سمت سیستم تو داره ارسال میشه به Redirector مثلا با یک  user-agent خواص بیاد در غیر این صورت هر درخواستی ارسال بشه سرور Redirector ما پاسخ  404 بده
