# Evidence of Execution

در فورنزیک دیجیتال، **Evidence of Execution** به مجموعه آرتیفکت‌هایی گفته می‌شود که ثابت می‌کنند یک برنامه **واقعاً اجرا شده** — نه فقط روی دیسک وجود داشته.

---

## چرا مهم است؟

گاهی مهاجم فایل مخرب را پاک می‌کند، ولی ردپای اجرا باقی می‌ماند. این آرتیفکت‌ها آن ردپا هستند.

---

## مهم‌ترین آرتیفکت‌ها

| آرتیفکت            | مسیر                                                                                 | اطلاعات کلیدی                    |
| ------------------ | ------------------------------------------------------------------------------------ | -------------------------------- |
| **Prefetch (.pf)** | `C:\Windows\Prefetch\`                                                               | نام فایل، زمان اجرا، تعداد دفعات |
| **ShimCache**      | Registry: `SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache`          | آخرین زمان اجرا                  |
| **AmCache**        | `C:\Windows\AppCompat\Programs\Amcache.hve`                                          | Hash فایل، مسیر، زمان نصب/اجرا   |
| **UserAssist**     | Registry: `NTUSER.DAT\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist` | برنامه‌های اجراشده از GUI        |
| **BAM/DAM**        | Registry: `SYSTEM\CurrentControlSet\Services\bam\State\UserSettings`                 | آخرین زمان اجرا به ازای هر user  |
| **Jump Lists**     | `%AppData%\Microsoft\Windows\Recent\`                                                | فایل‌های اخیراً باز‌شده          |

---

## ارتباط با Prefetch

Prefetch که قبلاً بررسی کردیم یکی از **قوی‌ترین** evidence of execution هاست چون:
- زمان **اولین** و **آخرین** اجرا را دارد
- تعداد دفعات اجرا را ثبت می‌کند (Run Count)
- حتی اگر فایل اصلی حذف شده باشد، `.pf` ممکن است باقی بماند

---

## نتیجه در یک جمله

> Evidence of Execution = اثبات اینکه برنامه X در زمان Y توسط user Z **واقعاً اجرا شده**، حتی اگر فایل دیگر موجود نباشد.





بریم باهم چند تا از این artifact هارو ببینیم 


#### Evidence Acquisition - Running OS

· Memory
. Running Process, network connection and open sessions
· Shared storage

### Evidence Acquisition - Not Running OS

. File System Artifacts
. Registry Hives
. Hard Drives
. Logs

## Windows Prefetch چیست؟

**Prefetch** یک مکانیزم ویندوز است که توسط سرویس **SuperFetch/SysMain** مدیریت می‌شود. هدف آن بهبود سرعت اجرای برنامه‌هاست — ویندوز فایل‌ها و دایرکتوری‌هایی که یک برنامه به آن‌ها دسترسی داشته را ردیابی می‌کند تا دفعه بعد سریع‌تر لود شود.

**مسیر ذخیره‌سازی:**
C:\Windows\Prefetch\


**هر فایل .pf شامل این اطلاعات است:**

| فیلد | توضیح |
|------|-------|
| Run Count | تعداد دفعات اجرای برنامه |
| Full Path | مسیر کامل فایل اجرایی |
| Files/Dirs Accessed | فایل‌ها و پوشه‌هایی که برنامه به آن‌ها دسترسی داشته |
| Last Run Time | آخرین زمان اجرا (در Win8+ تا ۸ تایم‌استمپ) |
| Volume ID | شناسه درایو |

نام فایل‌ها به فرمت `PROGRAMNAME-HASH.pf` هستند، مثلاً `NOTEPAD.EXE-EB1B961A.pf` که hash بر اساس مسیر فایل اجرایی محاسبه می‌شود.

---

## PECmd.exe چیست؟

**PECmd** (Prefetch Explorer Command Line) ابزاری است ساخته **Eric Zimmerman** که برای **تحلیل فایل‌های Prefetch** در فورنزیک دیجیتال استفاده می‌شود.

### کاربردها:

- **فورنزیک و تحقیقات جنایی دیجیتال:** اثبات اینکه یک برنامه خاص روی سیستم اجرا شده
- **خواندن فایل‌های .pf** به صورت human-readable
- **استخراج تایم‌استمپ‌ها** برای تشخیص زمان اجرای برنامه‌ها
- **شناسایی بدافزار:** اگر malware اجرا شده باشد، اثر آن در Prefetch باقی می‌ماند

### نمونه استفاده:
```cmd
PECmd.exe -f "C:\Windows\Prefetch\NOTEPAD.EXE-EB1B961A.pf"
PECmd.exe -d "C:\Windows\Prefetch" --csv output_folder
```

به طور خلاصه، PECmd ابزار اصلی تحلیلگران فورنزیک برای بررسی تاریخچه اجرای برنامه‌ها روی یک سیستم ویندوزی است.

![[Pasted image 20260609110221.png]]

قابلیت، Prefetch فقط «زمان اجرا» را ثبت نمی‌کند. اطلاعاتی که ذخیره می‌شود:

- **زمان‌های اجرا** — آخرین ۸ بار اجرا (Win8+)
- **تعداد دفعات اجرا** — چند بار اجرا شده
- **مسیر کامل** — دقیقاً از کجا اجرا شده
- **فایل‌های دسترسی‌یافته** — هر فایلی که برنامه هنگام اجرا باز کرده (DLL‌ها، config‌ها، ...)
- **شناسه درایو** — روی کدام درایو بوده

---

هدف اصلی Prefetch **سرعت‌دهی به اجرای برنامه** است (نه ثبت لاگ)، اما چون این اطلاعات را ذخیره می‌کند، در فورنزیک به عنوان **شواهد دیجیتال** بسیار مفید است..

ویندوز قبل از اینکه کاربر برنامه را باز کند، فایل‌های موردنیازش را از دیسک به RAM منتقل می‌کند — وقتی برنامه اجرا می‌شود، منابع در حافظه آماده‌اند و نیازی به خواندن کند از دیسک نیست.

ما در تصویر بالا اومدیم و از این ابزار استفاده کردیم برای اینکه ببینیم برنامه ما دقیقا چه کاری رو کرده 
اگر به تصویر دقت کنید میبینید که Run Count  1 هست یعنی یک بار برنامه اجرا شده اینجا یه مقدار شک بر انگیز میشه 

و باید شک کنیم به 

Run Count 1
- intial Access 
- Credential Access

### دقیقاً چه اتفاقی می‌افتد؟

ویندوز هنگام **اولین اجرای** برنامه، رفتار واقعی آن را **مانیتور** می‌کند:
- کدام فایل‌ها از دیسک خوانده شدند
- کدام DLLها لود شدند
- به کدام دایرکتوری‌ها دسترسی داشت

این اطلاعات را در فایل `.pf` ذخیره می‌کند.

---

### دفعات بعدی اجرا:

ویندوز **فایل `.pf` را می‌خواند** (نه PE Header را) و همان فایل‌هایی که قبلاً استفاده شدند را **پیش‌بارگذاری (Prefetch)** می‌کند — دقیقاً همان چیزی که در تصویر می‌بینی:

- `NTDLL.DLL`
- `KERNEL32.DLL`
- `KERNELBASE.DLL`
- فایل‌های `.NLS` و ...

---

### پس خلاصه:

| | توضیح |
|---|---|
| **PE Header** | ساختار فایل اجرایی — می‌گوید برنامه چطور لود شود |
| **Prefetch (.pf)** | تاریخچه واقعی اجرا — می‌گوید چه فایل‌هایی در عمل استفاده شدند |

ویندوز از `.pf` استفاده می‌کند، نه از PE Header، برای پیش‌بارگذاری.

این فایل در ram بارگذاری میشه تا روند اجرای برنامه سریع تر جلو بره
