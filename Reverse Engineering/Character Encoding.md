
##### What is  Character Encoding 



### 1. کامپیوتر واقعاً Character را نمی‌فهمد

کامپیوتر در پایین‌ترین سطح با **Bit و Byte** کار می‌کند:

```text
01000001
```

این مقدار برای کامپیوتر فقط یک **عدد** است؛ خودش نمی‌داند که این یعنی `A`.

برای اینکه `01000001` را به `A` تبدیل کنیم، باید یک **قرارداد (Encoding)** داشته باشیم که بگوید:

> «این مقدار عددی، نمایانگر کدام Character است؟»

مثلاً در ASCII:

```text
01000001 = 65 = A
```

پس کامپیوتر به‌تنهایی نمی‌گوید `01000001` یعنی `A`؛ **Encoding تعیین می‌کند که این مقدار چگونه تفسیر شود.**

---

### 2. Encode یعنی چه؟

**Encoding** یعنی تبدیل یک Character یا متن به یک نمایش قابل ذخیره/انتقال برای کامپیوتر، یعنی معمولاً مجموعه‌ای از **Byteها**.

مثلاً:

```text
Character
   ↓
Encoding
   ↓
Bytes
```

برای مثال در ASCII:

```text
A
↓
65
↓
0x41
↓
01000001
```

برعکس این فرآیند را **Decoding** می‌گوییم:

```text
Bytes
 ↓
Decoding
 ↓
Character
```

---

### 3. پس Unicode چیست؟

اینجا یک مشکل بزرگ به وجود می‌آید.

ASCII برای تعداد محدودی از Characterها طراحی شده بود و برای زبان‌هایی مثل فارسی، چینی، ژاپنی و... کافی نبود.

بنابراین **Unicode** ایجاد شد تا برای Characterهای زبان‌ها و سیستم‌های نوشتاری مختلف، یک مجموعه استاندارد از **Code Point**ها تعریف شود.

مثلاً:

```text
A → U+0041
```

اینجا `U+0041` یک **Unicode Code Point** است.

نکته خیلی مهم:

> **Unicode خودش Encoding نیست.**

Unicode مشخص می‌کند **هر Character چه Code Pointی دارد**؛ سپس Encodingهایی مثل **UTF-8، UTF-16 و UTF-32** مشخص می‌کنند که آن Code Point چگونه به Byte تبدیل شود.

مثلاً:

```text
Character
   ↓
Unicode Code Point
   ↓
UTF-8 / UTF-16
   ↓
Bytes
```

---

### 4. UTF یعنی چه؟

**UTF = Unicode Transformation Format**

یعنی روشی برای تبدیل **Unicode Code Point**ها به یک توالی از Byteها.

سه مورد مهم:

```text
UTF-8
UTF-16
UTF-32
```

مثلاً یک Character ممکن است یک Code Point داشته باشد، اما در UTF-8 و UTF-16 به شکل متفاوتی در Memory ذخیره شود.

---

### 5. Localization کجای این داستان قرار می‌گیرد؟

وقتی وارد Unicode و Encoding شدیم، یک مفهوم دیگر به نام **Localization (L10n)** مطرح می‌شود.

Localization فقط «تبدیل Characterها» نیست؛ بلکه یعنی نرم‌افزار را برای **زبان، منطقه و فرهنگ خاص** آماده کنیم.

مثلاً یک برنامه ممکن است بر اساس Locale کاربر:

```text
Language:
English / Persian / Japanese

Date:
08/12/2026
یا
12/08/2026

Number:
1,234.56
یا
1.234,56

Currency:
$ / € / ¥
```

را متفاوت نمایش دهد.

پس:

> **Unicode/UTF → مشکل نمایش و ذخیره Characterها را حل می‌کنند.**

> **Localization → نرم‌افزار را با زبان، منطقه، قالب تاریخ، عدد، واحد پول و قواعد فرهنگی کاربر سازگار می‌کند.**

این تفکیک خیلی مهم است؛ چون در Reverse Engineering وقتی به **Stringها، Unicode، UTF-16، Locale و Windows APIها** می‌رسی، این مفاهیم مرتب کنار هم دیده می‌شوند.
