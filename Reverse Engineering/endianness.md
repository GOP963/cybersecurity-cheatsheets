

### Endianness چیست؟

**Endianness** 
مشخص می‌کند وقتی یک مقدار چندبایتی داریم، **Byteهای آن با چه ترتیبی در Memory قرار بگیرند.**

دو حالت اصلی داریم:

- **Little-Endian**
    
- **Big-Endian**
    

فرض کنیم مقدار زیر را داریم:

```text
0x12345678
```

این مقدار 4 Byte دارد:

```text
12 34 56 78
```

### Little-Endian

در **Little-Endian**، کم‌ارزش‌ترین Byte (**Least Significant Byte / LSB**) در آدرس پایین‌تر قرار می‌گیرد:

```text
Memory:

Address     Value
0x1000      78
0x1001      56
0x1002      34
0x1003      12
```

پس در Memory می‌بینیم:

```text
78 56 34 12
```

ولی مقدار واقعی:

```text
0x12345678
```

است.

### Big-Endian

در **Big-Endian**، پرارزش‌ترین Byte (**Most Significant Byte / MSB**) در آدرس پایین‌تر قرار می‌گیرد:

```text
Memory:

Address     Value
0x1000      12
0x1001      34
0x1002      56
0x1003      78
```

پس:

```text
12 34 56 78
```

### نکته خیلی مهم برای Reverse Engineering

وقتی در یک **Hex Dump** می‌بینی:

```text
78 56 34 12
```

نباید فوراً فکر کنی مقدار `0x78563412` است.

اگر داده **Little-Endian** باشد، مقدار واقعی:

```text
0x12345678
```

است.

به‌صورت خلاصه:

```text
Little-Endian → LSB first
Big-Endian    → MSB first
```

و در عمل، معماری‌های **x86/x86-64** که در مهندسی معکوس زیاد با آن‌ها سروکار داری، از **Little-Endian** استفاده می‌کنند.

به صورت کلی به این معنی هست که اون بایت هایی که قرار است در حافظه قرار بگیرند از سمت راست به چپ داخل page  حافظه ریخته می شوند یا برعکس از سمت چپ به راست 
بحث نظم هستش یعنی اون بایت ها به نحوی پردازش میشن، از سمت راست به چپ یا برعکس
پس یک نوع قرارداد برای پردازش دیتا هست 

### Endianness در فایل‌ها

این مفهوم فقط مخصوص RAM نیست. **فرمت‌های فایل باینری** هم برای ذخیره کردن Integerهای چندبایتی باید یک Endianness مشخص داشته باشند.

مثلاً اگر یک فایل بخواهد مقدار:

```text
0x12345678
```

را به صورت **Little-Endian** ذخیره کند:

```text
78 56 34 12
```

بنابراین وقتی یک Hex Editor باز می‌کنی، ممکن است Byteها برعکس چیزی باشند که به‌صورت منطقی مقدار را می‌نویسیم.

---

### PE File چگونه است؟

فرمت **PE (Portable Executable)** ویندوز، مثل فایل‌های:

```text
.exe
.dll
.sys
```

در ساختارهای اصلی خودش از **Little-Endian** استفاده می‌کند.

مثلاً در PE Header، فیلدهایی مثل `e_lfanew` یک مقدار چندبایتی هستند.

فرض کنیم مقدار:

```text
e_lfanew = 0x000000F0
```

باشد.

در فایل به شکل:

```text
F0 00 00 00
```

ذخیره می‌شود.

چون PE از **Little-Endian** استفاده می‌کند:

```text
File Offset

F0 00 00 00
↑
LSB
```

و هنگام خواندن فایل، Parser یا Loader این Byteها را طبق ساختار PE تفسیر می‌کند و مقدار واقعی را به دست می‌آورد:

```text
0x000000F0
```

---

### یک مثال واقعی‌تر

فرض کن در Hex Editor این را ببینی:

```text
50 45 00 00
```

این همان:

```text
"PE\0\0"
```

است که **PE Signature** است.

اما اگر یک مقدار عددی 4 بایتی داشته باشیم، مثلاً:

```text
34 12 00 00
```

با توجه به Little-Endian مقدار آن:

```text
0x00001234
```

است، نه:

```text
0x34120000
```



> **Endianness در فرمت فایل مشخص می‌کند Byteهای یک مقدار چندبایتی با چه ترتیبی در فایل ذخیره شوند. فرمت PE در ساختارهای عددی خود از Little-Endian استفاده می‌کند؛ بنابراین هنگام تحلیل Hex Dump باید ترتیب Byteها را در نظر گرفت.**


```
LSB 
Address		value
0x00001		56
0x00002		34
0x00003		12

Big-Endian
MSB
Address		value
0x00001		12
0x00002		34
0x00003		56

```
##### بریم باهم یه برنامه بنوسیم که به صورت لایو ببینیم اون دیتا به چه صورت تو حافظه میشینه 


```c
#include <stdio.h>

int main(void)
{
	int number = 0x1234567;
	char* cast = (char*)&number;
	int len = sizeof(number);
	for (int i= 0 ; i < len; i++)
	{
		printf("%.2x ", cast[i]);
	}
	getchar();
	printf("this is the end\n");
}
```

خب من یه متغیر دارم که یه مقداری به صورت هگز داره مهم نیست مقدار واقعا چیه ما میخواهیم به این درک برسیم که little endian چیه 
پس تو مرحله بعدی ادرس مربوط به متغیر مون رو به char تبدیل میکنیم و برای اینکه بتونه به درستی تبدیل بشه باید به اون ادرسه اشاره کنه دیگه پس به همین خاطر باید اون cast کردنه از نوع pointer باشه 
در نهایت هم حلقه درست میکنیم تا بتونیم به واسطه اون شمارنده حلقه مون اون دیتا رو تو کنسول نمایش بدیم
