# 🟦 Pass by Value  
### 🎒 تصور کن می‌خوای دفتر مشقت رو بدی به دوستت، ولی نمی‌خوای خرابش کنه  
پس چیکار می‌کنی؟  

👉 **از دفترت یک کپی می‌گیری و کپی رو می‌دی بهش.**

حالا:

- هرچی با کپی انجام بده فقط روی همون نسخه است  
- دفتر اصلی تو سالم می‌مونه  
- اگر کپی رو پاره کنه → به دفتر اصلی هیچ آسیبی نمی‌رسه

در برنامه‌نویسی دقیقاً همین اتفاق میفته:

### ✔ وقتی متغیری را "Pass by Value" می‌فرستی:
- از آن **یک کپی** ساخته می‌شود  
- تابع فقط با **کپی** کار می‌کند  
- **متغیر اصلی بدون تغییر می‌ماند**

### 🔹 نتیجه:
- **ایمن‌تره**
- **داده اصلی خراب نمی‌شه**
- ولی اگر داده بزرگ باشد → **کپی‌کردنش کند است**

---

# 🟩 Pass by Reference  
### 🎒 حالا تصور کن این دفعه خودِ دفتر اصلی را به دوستت می‌دهی  
در این حالت:

- اگر روی دفتر خط بکشه → روی دفتر اصلی‌ات خط کشیده  
- اگر چیزی اضافه کند → روی دفتر اصلی اضافه شده  
- هیچ کپی‌ای وجود ندارد

یعنی مستقیم روی نسخه واقعی کار می‌کند.

در برنامه‌نویسی:

### ✔ وقتی متغیری را "Pass by Reference" ارسال می‌کنی:
- تابع **کپی نمی‌گیرد**
- روی **خودِ متغیر اصلی** کار می‌کند
- هر تغییری → روی متغیر اصلی دیده می‌شود

### 🔹 نتیجه:
- **سریع‌تره** (چون کپی نمی‌سازد)
- **تابع می‌تواند مقدار اصلی را تغییر دهد**
- اما اگر حواست نباشد ممکن است داده اصلی خراب شود

# 🔥 جمع‌بندی خیلی ساده (در حد حفظ کردن)

| مفهوم | توضیح برای نوجوان |
|------|----------------------|
| **Pass by Value** | مثل اینکه از دفترت کپی بگیری و نسخه کپی را به کسی بدهی. هر کاری بکند فقط روی کپی است. |
| **Pass by Reference** | مثل اینکه دفتر اصلی‌ات را بدهی. هر کاری بکند روی نسخه واقعی انجام می‌شود. |

# 🧠 چرا دوتا روش داریم؟

### ✔ Value → برای امنیت و مطمئن شدن  
وقتی نمی‌خواهی کسی داده اصلی‌ات را تغییر دهد.

### ✔ Reference → برای سرعت و تغییر  
وقتی می‌خواهی تابع بتواند:

- مقدار اصلی را تغییر بدهد  
- چند مقدار برگرداند  
- یا با داده‌های بزرگ سریع‌تر کار کند

---


زمانی که ما میایم از علامت & برای اشاره به یک متغیر استفاده میکنیم یعنی داریم میگیم که از متغیر اصلا کپی نساز برو به خوده ادرس متغیر و برای من و مقداری رو که داره رو برای من انجام بده یعنی داریم در اصل با اضافه کردن این علامت میگیم که بیا برای من مقدار متغیر اصلیم داره رو کپی کن داخل اون value 
اما بدون این علامت داریم میگیم که مقدار متغیر اصلیم رو کپی کن داخل اون تابع  value 

---

# 🟦 مثال شماره 1 — Pass by Value

```cpp
void changeValue(int x) {
    x = 100;
}

int main() {
    int a = 5;
    changeValue(a);
}
```

## ✔ دقیقاً این‌ها یعنی چی؟ (قطعه‌قطعه و واضح)

### 🔹 این قسمت:

```cpp
void changeValue(int x)
```

اینجا **x یک متغیر value است**.  
چرا؟  
چون **هیچ علامت & ندارد** → پس یعنی _کپی ساخته می‌شود_.

---

### 🔹 این قسمت:

```cpp
int a = 5;
```

این **متغیر اصلی** است.

---

### 🔹 این قسمت:

```cpp
changeValue(a);
```

اینجا:

- `a` → **مقدار اصلی**
    
- به تابع ارسال می‌شود
    
- تابع یک **کپی از a** می‌سازد به اسم `x`
    

پس:

```
a = 5   → اصلی
x = 5   → کپی داخل تابع
```

📌 **اینجا "Pass by Value" اتفاق می‌افتد.**

---

# 🟩 مثال شماره 2 — Pass by Reference

```cpp
void changeValue(int &x) {
    x = 100;
}

int main() {
    int a = 5;
    changeValue(a);
}
```

## ✔ حالا دقیقاً ببین کجای کد Reference است

### 🔹 این قسمت:

```cpp
int &x
```

این دقیقاً یعنی:

- `x` **مرجع (Reference)** است
    
- `x` کپی نیست
    
- `x` همان **خودِ متغیر اصلی a** است
    

### 🔹 این قسمت:

```cpp
changeValue(a);
```

اینجا:

- `a` به تابع فرستاده می‌شود
    
- ولی **کپی ساخته نمی‌شود**
    
- اشاره‌گر آدرس `a` مستقیماً به `x` وصل می‌شود
    

پس:

```
x  → اشاره به a
x و a هر دو یک مکان در RAM هستند
```

📌 **این نقطه دقیقاً همان جایی است که Pass by Reference رخ می‌دهد.**

# 🟥 تشخیص دقیق داخل خود کد

## 🔥 کلید طلایی تشخیص:

### 1. اگر پارامتر تابع این شکلی بود:

```cpp
void func(int x)
```

✔ **Pass by Value**  
❌ Reference

---

### 2. اگر پارامتر تابع این شکلی بود:

```cpp
void func(int &x)
```

✔ **Pass by Reference**  
❌ Value

---

### 3. اگر این را در main ببینی:

```cpp
func(a);
```

این فقط _فراخوانی_ است.  
نوع Pass **کاملاً وابسته به تعریف تابع** است، نه اینجا.

# 🟧 تصویر ذهنی دقیق (خیلی مهم)

## Pass by Value:

```
a ----> 5
       |
       |----> 5  (x = copy)
```

## Pass by Reference:

```
a ----> 5
x ----^  (x و a یکی هستند)
```

---

# 🟩 مثال ترکیبی (کامل‌ترین مثال)

```cpp
#include <iostream>
using namespace std;

void byValue(int x) {   // ← اینجا x یک VALUE است
    x = 10;             // ← تغییر روی کپی
}

void byReference(int &y) {  // ← اینجا y یک REFERENCE است
    y = 20;                 // ← تغییر روی خودِ متغیر اصلی
}

int main() {
    int a = 5;  // ← متغیر اصلی

    byValue(a);     // ← ارسال با مقدار (کپی ساخته می‌شود)
    byReference(a); // ← ارسال با مرجع (بدون کپی)
}
```

# 🧠 خلاصه‌ی خلاصه برای تشخیص سریع

|قسمت کد|نشانه|یعنی چی؟|
|---|---|---|
|تعریف پارامتر بدون &|`int x`|Pass by Value|
|تعریف پارامتر با &|`int &x`|Pass by Reference|
|فراخوانی تابع|`func(a)`|فقط ارسال متغیر؛ نوع Pass در تعریف تابع مشخص می‌شود|
|داخل تابع تغییر می‌کنیم|`x = ...`|اگر value باشد → روی کپی است / اگر reference باشد → روی اصل|

# ✅ توضیح درست و دقیق (نسخه‌ی اصلاح‌شده و ساده)

## **📌 Pass by Value (ارسال با مقدار)**

وقتی می‌خواهیم **یک کپی** از متغیر را به تابع بدهیم  
از **pass by value** استفاده می‌کنیم.

🚨 یعنی:  
تابع روی «کپی» کار می‌کند  
نه روی متغیر اصلی.

بنابراین **متغیر اصلی هیچ تغییری نمی‌کند**.

✔️ درست فهمیدی.

---

## **📌 Pass by Reference (ارسال با مرجع)**

وقتی علامت `&` در تعریف تابع می‌گذاریم:

```cpp
void change(int& n)
```

این یعنی:

- تابع «کپی» نمی‌گیرد
    
- تابع «آدرس واقعی» متغیر اصلی را می‌گیرد
    
- تابع مستقیماً روی **همان متغیر اصلی** کار می‌کند
    
- بنابراین هر تغییری → در اصل روی خود متغیر اصلی است
    

✔️ درست فهمیدی: این روش به **حافظه اصلی** اشاره می‌کند.

---


## ✔️ در Reference مقدار تابع **ثابت نمی‌ماند**

بلکه **تابع همان مقدار اصلی را تغییر می‌دهد.**

این مزیت اصلی Pass by Reference است.

---

# 🎯 خلاصهٔ ساده‌تر:

## **Pass by Value**

- کپی فرستاده می‌شود
    
- تغییرات فقط روی کپی است
    
- متغیر اصلی دست‌نخورده می‌ماند
    

## **Pass by Reference**

- آدرس متغیر اصلی فرستاده می‌شود
    
- تابع مستقیم به متغیر اصلی دسترسی دارد
    
- تغییرات روی خود متغیر اصلی اعمال می‌شود
    

---

# 🧠 یک تصویر ذهنی:

### Value = کپی کردن کلید خانه

تو کلید اصلی را داری  
تابع یک کلید کپی می‌گیرد  
هر کاری با آن کند → اصلش تغییر نمی‌کند

### Reference = دادن کلید اصلی خانه به تابع

تابع می‌تواند وارد خانه واقعی شود  
و همه‌چیز را تغییر دهد

---



به صورت کلی ما در  pass_by_refrence میایم یک alias تعریف میکنیم به اون متغیر محلی 


وقتی داریم refrence پاس میدیم یعنی داریم میگیم که من میخوام محتوای اون متغیر محلی  رو عوض کنم


---

تعریف کردن یک کلاس یعنی تعریف کردن یک datatype کاستوم
