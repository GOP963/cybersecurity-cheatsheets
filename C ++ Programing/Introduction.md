## Advanced man Use Cases

### Accessing and Extracting Specific Sections

- **Filtering by section number:** To access specific sections of man pages, For example, man 3 printf retrieves the documentation for the printf function in the C standard library. Here is a list of the numerical section numbers for man pages:
    - **1:** User commands (executable programs or shell commands)
    - **2:** System calls (functions provided by the kernel)
    - **3:** Library calls (functions within program libraries)
    - **4:** Special files (usually found in /dev)
    - **5:** File formats and conventions (e.g., /etc/passwd)
    - **6:** Games and screensavers
    - **7:** Miscellaneous (including macro packages and conventions)
    - **8:** System administration commands (usually only for root)
    - **9:** Kernel routines (non-standard)

## **مثال‌های پیشرفته**

### **۱. دسترسی به بخش‌های خاص از man page‌ها**

برخی فرمان‌ها چندین بخش در مستندات خود دارند:

- `man 5 passwd` → فرمت فایل پیکربندی passwd (بخش ۵)
    
- `man 1 passwd` → فرمان passwd که کاربران اجرا می‌کنند (بخش ۱)
    

### **۲. جستجو بر اساس کلیدواژه**

دستور زیر همهٔ man pageهایی که یک کلمه در توضیحاتشان آمده را پیدا می‌کند:

```
man -k [keyword]
```

مثلاً:

```
man -k network
```

تمام موارد مرتبط با شبکه را فهرست می‌کند.

## **نکات مهم برای تسلط بر man**

### **۱. ترکیب man با دستورات دیگر**

خروجی man را می‌توان با ابزارهای دیگر فیلتر کرد:

```

```

فقط خطوط حاوی کلمهٔ "sort" را نمایش می‌دهد.

### **۲. سفارشی‌سازی فرمت نمایش**

با تغییر متغیرهای محیطی می‌توان نحوهٔ نمایش صفحات را تغییر داد. مثلاً:

```

```

اسکرول افقی را فعال می‌کند.

## **ساختار یک man page**

صفحات man معمولاً شامل بخش‌های زیر هستند:

- **NAME** – توضیح مختصر فرمان
    
- **SYNOPSIS** – ساختار، سینتکس و نحوهٔ استفاده
    
- **DESCRIPTION** – توضیح کامل عملکرد فرمان
    
- **OPTIONS** – لیست تمام گزینه‌ها و توضیح آن‌ها
    
- **EXAMPLES** – مثال‌هایی از کاربردهای عملی
    

این ساختار استاندارد باعث می‌شود اطلاعات سریع‌تر یافت شود.

## **موارد پیشرفته**

### **۱. دسترسی به بخش‌های خاص با شماره‌بندی**

لیست شماره بخش‌های man:

1. فرمان‌های کاربر
    
2. فراخوانی‌های سیستمی (kernel system calls)
    
3. توابع کتابخانه‌ای
    
4. فایل‌های خاص مثل `/dev`
    
5. فرمت فایل‌ها مثل `/etc/passwd`
    
6. بازی‌ها
    
7. مباحث متفرقه
    
8. فرمان‌های مدیریتی (root)
    
9. روتین‌های هسته (غیر استاندارد)
    

مثال:

```
man 3 printf
```

توضیح تابع printf از کتابخانه C را نشان می‌دهد.

### **۲. استخراج بخش‌های خاص از man page**

مثلاً استخراج بخش EXAMPLES از ls:

```
man ls | sed -n '/^EXAMPLES/,/^$/p'
```

## Virtual Memory 

این مکانیزم Virtual Memory یک لایه‌ی ترجمه است که بین برنامه و حافظه‌ی واقعی (RAM) قرار می‌گیرد
به کمک Virtual Memory، هر برنامه:

- حافظه‌ی خودش را دارد (ایزوله می‌شود)
    
- نمی‌تواند حافظه‌ی برنامه‌ی دیگر را ببینید
    
- می‌تواند فراتر از حجم واقعی RAM کار کند
    
- می‌تواند در آدرس‌های زیبا و مرتب کار کند، نه آدرس‌های واقعی و شلوغ RAM

# 🟣 آدرس مجازی (Virtual Address) چیه؟

این **آدرسی است که برنامه‌ها با آن کار می‌کنند.**

وقتی یک برنامه (مثلاً یک exe یا یک DLL) در حال اجراست، تمام pointer ها، stack، heap، متغیرها و کدها **با آدرس مجازی** آدرس‌دهی می‌شوند.

برنامه‌ها اصلاً به آدرس واقعی RAM دسترسی مستقیم ندارند!

 ```shell
 0x7ffd12340000
 ```

این آدرس مجازی است — فقط داخل فضای آدرس‌دهی برنامه معنی دارد.

# 🟣 آدرس فیزیکی (Physical Address) چیه؟

این **آدرس واقعی داخل RAM** است.  
واقعاً نشان می‌دهد یک بایت در کدام سلول RAM ذخیره شده.

برنامه‌ها این آدرس را نمی‌توانند ببینند.  
فقط **CPU + MMU + OS (کرنل)** به آن دسترسی دارند.

# 🟣 چه چیزی Virtual Address را به Physical Address تبدیل می‌کند؟

این کار توسط **MMU = Memory Management Unit** انجام می‌شود.  
یک سخت‌افزار داخل CPU که با جدول‌های سیستم‌عامل (Page Tables) همکاری می‌کند.

وقتی برنامه می‌گوید:  
"برو آدرس 0x7ffd12340000 را بخوان!"

MMU می‌گوید:  
🔄 «بذار ببینم این آدرس به کدام صفحه فیزیکی map شده…»  
بعد تبدیل می‌کند به یک آدرس فیزیکی.

به این فرایند می‌گویند:

# 🟣 Page و Page Table یعنی چی؟ (مهم‌ترین بخش)

حافظه مجازی و فیزیکی هر دو به تکه‌های ۴ کیلوبایتی تقسیم می‌شوند که به آن‌ها می‌گوییم:

- **Page (صفحه مجازی)**
    
- **Frame (صفحه فیزیکی)**
    

سیستم‌عامل جدول‌هایی دارد که به آن‌ها می‌گویند:  
**Page Table**

در Page Table نوشته شده:



```shell
Virtual Page 5 → Physical Frame 20
Virtual Page 6 → Physical Frame 99
Virtual Page 7 → روی دیسک ذخیره شده (Page Out)
```


حالا هرقت  برنامه یی  اجرا می‌شه، سیستم‌عامل برایش یک بخش از **Virtual Memory** به اسم **Stack** می‌سازه.

Stack در واقع یک "بخش مجازی" از حافظه‌ست که:

- داخل Virtual Memory قرار داره
    
- برای ذخیره‌ی **متغیرهای محلی**، **آدرس برگشت تابع**، **آرگومان‌ها** و … استفاده می‌شه
    
- اندازه‌ی آن محدود است (مثلاً 1MB یا 8MB)
    

Stack 
یک بخش **کاملاً مجازی** است.  
یعنی آدرس‌هایش **Virtual Address** هستند (نه فیزیکی).

# 🟣 Stack Overflow یعنی چی؟

به زبان ساده:

وقتی برنامه بیش از حد ظرفیت Stack، داده داخلش بنویسه  
➡ **Stack پر می‌شود**  
➡ داده‌ها از محدوده‌ی مجاز بیرون می‌زنند  
➡ و **متغیرها، آدرس‌ها یا ساختارهای مهم حافظه را overwrite می‌کنند**


```c
void func() {
    char buf[10];
    gets(buf);  // خطرناک
}
```

اگر کاربر 50 بایت وارد کند، چه می‌شود؟  
→ در Virtual Memory، داده بیش از حد داخل buf نوشته می‌شود  
→ وارد بخش‌های بعدی Stack می‌شود  
→ متغیرها و حتی **return address** را خراب می‌کند

اگر return address خراب شود و ما مقدار دلخواه بگذاریم  
→ کنترل کامل اجرای برنامه را می‌گیریم.

این پایه‌ی **Buffer Overflow Exploit** است.


## Overflow یعنی دستکاری کردن Virtual Addressهای حساس

پر شدن بافر باعث می‌شود داده به جاهایی نوشته شود که:

- return address (آدرس برگشت تابع)
    
- saved EBP
    
- متغیرهای دیگر
    
- ساختارهای stack frame
    

همه‌ی این‌ها **آدرس‌های مجازی هستند** و می‌توانیم آن‌ها را کنترل کنیم.


# 🟣 چرا Stack Overflow برای Exploit حیاتی است؟

چون:

- روی return address دسترسی مستقیم پیدا می‌کنی
    
- می‌تونی EIP/RIP را hijack کنی
    
- می‌تونی shellcode inject کنی
    
- می‌تونی ROP chain بسازی
    
- می‌تونی اجرای برنامه را 180 درجه تغییر بدهی
    

همه‌ی این‌ها روی Virtual Memory اتفاق می‌افتد.


# 🟢 **تفاوت Stack Overflow و Buffer Overflow**

## ✨ خلاصهٔ خیلی ساده:

**Buffer Overflow یک نوع آسیب‌پذیری است.**  
**Stack Overflow فقط یکی از جاهایی است که این آسیب‌پذیری می‌تواند اتفاق بیفتد.**

به بیان ساده‌تر:

✔ **Buffer Overflow = سرریز شدن یک بافر در هر جای حافظه**  
✔ **Stack Overflow = سرریز شدن بافر _روی استک_**

پس:  
🔸 هر **Stack Overflow** یک **Buffer Overflow** هست.  
🔸 اما هر **Buffer Overflow** لزوماً **Stack Overflow** نیست.

# 🟣 تعریف فنی — دقیق و مرحله‌به‌مرحله

## 1️⃣ Buffer Overflow چیست؟

Buffer Overflow یعنی:

> نوشتن داده بیشتر از اندازه‌ی واقعی یک بافر  
> و overwrite کردن حافظه‌ی اطراف آن.

این بافر می‌تواند:

- روی **Stack** باشد → Stack-based Buffer Overflow
    
- روی **Heap** باشد → Heap Overflow
    
- در **Data section** باشد
    
- حتی در حافظه‌ی GPU یا Kernel باشد


## Stack Overflow چیست؟

Stack Overflow یک حالت خاص از Overflow است:

> وقتی متغیر (بافر) روی Stack باشد و overflow شود،  
> به این خاص می‌گوییم **Stack-based Buffer Overflow**  
> که تلفظ کوتاه شده‌اش می‌شه "Stack Overflow".


|نوع|کجا رخ می‌دهد؟|
|---|---|
|Buffer Overflow|هر جای حافظه (Stack / Heap / Global)|
|Stack Overflow|فقط و فقط روی Stack|

|نوع|تاثیر روی exploit|
|---|---|
|Stack Overflow|بهترین حالت برای کنترل EIP/RIP و کنترل کامل اجرای برنامه|

# 🟣 1. `auto`

(پیش‌فرض همه متغیرهای داخل تابع)

**کجا ذخیره می‌شود؟**  
✔ روی **Stack**  
✔ فقط وقتی تابع اجرا می‌شود وجود دارد

**چطور ذخیره می‌شود؟**  
فقط یک فضای موقتی روی Stack می‌گیرد، بعد از خروج تابع پاک می‌شود.

### مثال:

```c
void func() {
    auto int x = 5;   // auto اختیاری است
    int y = 10;       // دقیقا مثل auto
}
```

x و y:

- داخل Stack هستند
    
- بعد از خروج از func از بین می‌روند
    

**نکته:** نوشتن `auto` ضروری نیست، چون پیش‌فرض است.

---

# 🟣 2. `register`

**هدف:** سریع‌تر بودن، نگهداری در رجیستر CPU (اگر امکان داشته باشد).

**کجا ذخیره می‌شود؟**  
✔ در رجیستر CPU  
⛔ یا اگر جا نبود → Stack

**چطور ذخیره می‌شود؟**  
compiler _سعی می‌کند_ متغیر را در رجیستر CPU قرار دهد.

### مثال:

```c
void func() {
    register int i;
    for(i = 0; i < 100000; i++) {
        // ...
    }
}
```

i ممکن است در یک رجیستر CPU ذخیره شود ← سرعت بیشتر  
ولی هیچ تضمینی نیست.

⛔ نکته مهم:  
نمی‌توان از یک register variable **آدرس** گرفت:

```c
register int x;
int *p = &x;   // ERROR
```

# 🟣 3. `static`

**دو نقش اصلی دارد:**

## ✨ a) Static در داخل تابع

- فقط **یکبار** ساخته می‌شود
    
- مقدارش بین اجرای تابع **حفظ می‌شود**
    
- روی **Data Segment** ذخیره می‌شود (نه روی Stack)
    

### مثال:

```c
void func() {
    static int counter = 0;
    counter++;
    printf("%d\n", counter);
}
```

اگر تابع را ۵ بار صدا بزنی، خروجی:

```
1
2
3
4
5
```

که یعنی مقدارش حفظ می‌شود.

---

## ✨ b) Static برای متغیر‌های global

- فقط در **همان فایل** قابل دسترسی هستند
    
- به فایل‌های دیگر export نمی‌شوند
    
- در **Data segment** ذخیره می‌شوند
    

### مثال:

```c
static int secret = 42;

void func() {
    printf("%d", secret);
}
```

فایل دیگری نمی‌تواند به secret دسترسی داشته باشد.

---

# 🟣 4. `extern`

**هدف:** اعلام کردن یک متغیر که در فایل دیگری تعریف شده.

یعنی:

- اینجا فقط _اعلام_ می‌کنیم (declaration)
    
- در فایل دیگر _تعریف_ (definition) انجام شده
    

### مکان ذخیره:

در **global / data segment** (جایی که متغیر اصلی تعریف شده)

### مثال:

### file1.c

```c
int x = 10;   // تعریف
```

### file2.c

```c
extern int x;  // اعلام
printf("%d", x);
```

x فقط یک بار در file1.c ساخته می‌شود اما در file2.c قابل استفاده است.

---

# 🟣 5. Global Variables (بدون static یا extern)

متغیرهای global:

- در **Data Segment** ذخیره می‌شوند
    
- در کل برنامه قابل مشاهده هستند
    
- در تمام فایل‌های دیگر قابل دسترسی‌اند (تا وقتی static نشده باشند)
    

### مثال:

```c
int score = 0;

void func() {
    printf("%d", score);
}
```

score در کل پروژه قابل دسترسی است.

---

# 🟣 جدول جمع‌بندی فوق‌مفید

|Storage Class|کجا ذخیره می‌شود؟|طول عمر|Scope|نکته مهم|
|---|---|---|---|---|
|`auto`|Stack|تا پایان تابع|بلوک|پیش‌فرض|
|`register`|Register یا Stack|تا پایان تابع|بلوک|نمی‌توان آدرس گرفت|
|`static` داخل تابع|Data Segment|کل عمر برنامه|بلوک تابع|مقدارش حفظ می‌شود|
|`static` global|Data Segment|کل عمر برنامه|فقط در همان فایل|مخفی از فایل‌های دیگر|
|`extern`|همان‌جایی که variable تعریف شده|کل عمر|فایل‌های دیگر|فقط declaration|
|Global|Data Segment|کل عمر|همه فایل‌ها|مگر static شود|

# 🟣 مثال کامل از همه‌ی Storage Classها در یک برنامه

```c
#include <stdio.h>

int g = 10;            // global

static int s = 20;     // static global (فقط در این فایل)

void func() {
    auto int a = 1;    // stack
    register int r = 2; // register
    static int st = 3; // data segment, مقدار حفظ می‌شود

    a++;
    r++;
    st++;

    printf("a=%d, r=%d, st=%d\n", a, r, st);
}

extern int ext;        // اعلام
```
