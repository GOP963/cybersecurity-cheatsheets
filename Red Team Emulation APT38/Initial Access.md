مهاجمان ممکن است **ایمیل‌های اسپیر فیشینگ** را همراه با **یک فایل مخرب** ارسال کنند تا به سیستم قربانی دسترسی پیدا کنند.  
_Spearphishing Attachment_ یک نوع خاص از اسپیر فیشینگ است. تفاوت آن با دیگر انواع اسپیر فیشینگ در این است که **بدافزار به‌صورت یک فایل پیوست‌شده در ایمیل** قرار می‌گیرد.

همه انواع اسپیر فیشینگ نوعی **مهندسی اجتماعی الکترونیکی** هستند که به‌طور خاص یک فرد، شرکت یا صنعت را هدف می‌گیرند.  
در این سناریو، مهاجم یک فایل را به ایمیل ضمیمه می‌کند و معمولاً با تکیه بر **اجرای کاربر (User Execution)**، به اجرای کد مخرب دست پیدا می‌کند.
سپر فیشینگ همچنین ممکن است شامل تکنیک‌های مهندسی اجتماعی باشد، مانند اینکه مهاجم **خود را به‌عنوان فرد یا منبع قابل‌اعتماد جا بزند**.

### **انواع فایل‌های قابل استفاده در پیوست مخرب**

امکان استفاده از انواع مختلف فایل وجود دارد، مثلاً:

- **فایل‌های Microsoft Office** (ماکرو، OLE، VBA، Excel 4.0)
    
- **فایل‌های اجرایی (exe)**
    
- **PDFهای مخرب**
    
- **فایل‌های آرشیوی** (zip، rar، 7z)


بریم برای شبیه سازی این اتک، ما از ابزار Caldera  استفاده میکنیم برای شبیه سازی اما از سایر فریمورک ها هم میشود استفاده کرد از جمله Cobalt یا Empire  و سایر موارد یا اصلا خودمون بیایم اون فایل رو بسازیم

خلاصه: این لیست، مجموعه payloadهای پیش‌فرض Caldera + payloadهایی که از Atomic Red Team اضافه شدن هست. Caldera به صورت پیش‌فرض تعدادی payload داره، ولی وقتی پلاگین Atomic رو نصب کنی، صدها payload جدید از Atomic Red Team به‌طور خودکار اضافه می‌شه.

بخش Command چیه و چرا نوشته «از Atomic Test برداریم»؟وقتی یک Ability از Atomic Red Team میاد (یعنی با پلاگین atomic نصب شده)، Caldera دو راه داره:

1. Command 
2. رو خودش به‌صورت خودکار پر کنه (اگر input arguments درست باشه)
3. یا بگه «من دقیقاً نمی‌دونم چطور این تست رو روی این سیستم اجرا کنم، خودت از Atomic Test کپی کن»
