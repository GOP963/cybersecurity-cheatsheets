## ✅ `iptables` چیست؟

**`iptables`** یک ابزار خط فرمان در لینوکسه که برای:

> **مدیریت ترافیک شبکه و فایروال سطح پایین (packet filtering)**

استفاده میشه.

🔒 با `iptables` می‌تونی تعیین کنی که:

- چه ترافیکی **اجازه عبور** داشته باشه
    
- چه ترافیکی **ممنوع یا مسدود** بشه
    
- چه ترافیکی **مسیردهی (routing)** یا **log** بشه
    

---

## 🧠 `iptables` چطور کار می‌کند؟

`iptables` بر پایه‌ی **netfilter** در کرنل لینوکس کار می‌کنه.  
این ابزار ترافیک شبکه رو در قالب **زنجیره‌هایی (chains)** و **جدول‌هایی (tables)** بررسی می‌کنه.

---

## 📦 ساختار اصلی `iptables`:

### 1. 🔹 جدول‌ها (Tables)

|جدول|کاربرد|
|---|---|
|`filter`|پیش‌فرض – فیلتر کردن ترافیک (قبول یا رد)|
|`nat`|تغییر آدرس (برای NAT، مثلاً ماسک کردن IP)|
|`mangle`|تغییر در بسته‌ها (مانند TTL)|
|`raw`|برای قوانین خاص قبل از پردازش connection tracking|

---

### 2. 🔸 زنجیره‌ها (Chains)

|زنجیره|توضیح|
|---|---|
|`INPUT`|ترافیکی که به خود سیستم وارد میشه|
|`OUTPUT`|ترافیکی که از خود سیستم خارج میشه|
|`FORWARD`|ترافیکی که از سیستم رد میشه (نه برای خودش)|
|`PREROUTING`|قبل از تعیین مسیر – مخصوص nat و mangle|
|`POSTROUTING`|بعد از تعیین مسیر – مخصوص nat و mangle|

---

## 🛠 مثال‌های ساده برای درک بهتر:

### 💥 1. بلاک کردن یک IP خاص:

```bash
iptables -A INPUT -s 192.168.1.100 -j DROP
```

→ هر ترافیکی که از IP 192.168.1.100 به این سیستم برسه، بلاک میشه.

---

### 🛡️ 2. اجازه دادن به پورت SSH:

```bash
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

→ اجازه می‌ده ترافیک TCP روی پورت 22 (SSH) وارد سیستم بشه.

---

### 🛑 3. رد کردن تمام ترافیک ورودی:

```bash
iptables -P INPUT DROP
```

→ پالیسی پیش‌فرض ورودی‌ها را روی رد (DROP) می‌ذاره.

---

### 📜 4. نمایش قوانین فعال:

```bash
iptables -L -n -v
```

## ⚙️ نسخه‌های جدید: `nftables`

در نسخه‌های جدید لینوکس (مثل Ubuntu 22+)، ابزار جدیدتری به نام `nftables` جایگزین `iptables` شده. ولی هنوز هم `iptables` پرکاربرد و قدرتمند هست.

### ✅ هدف از رمزنگاری در شبکه دوربین‌ها چیه؟

1. **محرمانگی (Confidentiality):** جلوگیری از اینکه افراد غیرمجاز تصویر و ویدیوها رو ببینن.
    
2. **تمامیت داده (Integrity):** جلوگیری از تغییر ویدیوها یا دستکاری در مسیر.
    
3. **احراز هویت (Authentication):** مطمئن بشیم که فقط افراد مجاز به ویدیوها دسترسی دارن یا دستگاه‌های قانونی به شبکه وصل هستن.
    

---

### ✅ رایج‌ترین الگوریتم‌های رمزنگاری پیشنهادی:

|کاربرد|الگوریتم پیشنهادی|توضیح|
|---|---|---|
|**رمزنگاری داده‌های در حال انتقال** (مثلاً بین دوربین و NVR)|**TLS (با AES-256)**|استفاده از HTTPS یا RTSP over TLS برای رمزنگاری جریان ویدیو.|
|**رمزنگاری ذخیره‌سازی محلی** (روی هارد NVR یا سرور)|**AES-256 یا ChaCha20**|برای رمزنگاری فایل‌های ویدیویی ذخیره‌شده.|
|**رمزنگاری بین دستگاه‌ها** (مثلاً بین دوربین و سوئیچ هوشمند)|**IPSec یا VPN با AES**|برای ایجاد تونل امن در بستر شبکه خصوصی.|
|**احراز هویت و کنترل دسترسی**|**RSA/ECC + HMAC یا SHA-256**|برای تأیید هویت کاربران و دستگاه‌ها.|

---

### ✅ توصیه‌ها برای پیاده‌سازی:

1. **از دوربین‌هایی استفاده کن که از TLS/SSL پشتیبانی می‌کنن.**
    
2. **اگه NVR داری، حتماً ذخیره‌سازی رو با AES رمزنگاری کن.**
    
3. **در صورت امکان از VPN برای ارتباط از راه دور استفاده کن.**
    
4. **دسترسی به ویدیوها رو فقط با احراز هویت قوی (مثلاً رمز دو مرحله‌ای یا گواهی دیجیتال) انجام بده.**
    
5. **حتماً firmware دوربین‌ها رو به‌روز نگه دار.**
    

---

### ✅ جمع‌بندی ساده:

- **برای رمزنگاری جریان ویدیو (Streaming):** از **TLS با AES-256** استفاده کن.
    
- **برای رمزنگاری ذخیره‌سازی:** از **AES-256** یا اگر منابع کمی داری، **ChaCha20** استفاده کن.
    
- **برای احراز هویت و امنیت بیشتر:** از **RSA یا ECC** برای تبادل کلید استفاده کن.

## 🔐 تفاوت بین RSA و AES چیست؟

|ویژگی|RSA|AES|
|---|---|---|
|**نوع الگوریتم**|**رمزنگاری نامتقارن** (Asymmetric)|**رمزنگاری متقارن** (Symmetric)|
|**کلیدها**|از **دو کلید** استفاده می‌کند: یک کلید عمومی (public) و یک کلید خصوصی (private)|فقط از **یک کلید** برای رمزنگاری و رمزگشایی استفاده می‌کند|
|**سرعت اجرا**|**کندتر** است چون محاسبات ریاضی سنگینی دارد|**خیلی سریع‌تر** است|
|**اندازه کلید پیشنهادی**|حداقل 2048 بیت|معمولاً 128 یا 256 بیت (اما امنیت بالایی دارد)|
|**کاربرد معمول**|تبادل کلید، امضای دیجیتال، احراز هویت|رمزنگاری داده‌های حجیم مثل فایل، ویدیو، شبکه|
|**مثال واقعی**|رمزنگاری تبادل کلید در TLS، ایمیل، VPN|رمزنگاری فایل‌های سیستم، استریم ویدیو، دیسک‌های سخت|

---

## 📌 مثال ساده برای درک بهتر:

فرض کن می‌خوای برای کسی یک پیام رمزنگاری‌شده بفرستی:

- با **RSA**:
    
    - تو پیام رو با **کلید عمومی طرف مقابل** رمز می‌کنی.
        
    - فقط خودش با **کلید خصوصی خودش** می‌تونه رمز رو باز کنه.
        
- با **AES**:
    
    - تو و طرف مقابل **هر دو یک کلید مشترک** دارید.
        
    - با همون کلید پیام رمزگذاری و رمزگشایی میشه.
        

---

## 💡 پس چرا باید از هر دو استفاده کنیم؟

در دنیای واقعی، ما معمولاً این دو الگوریتم رو **با هم ترکیب می‌کنیم** چون:

### 1. **RSA برای تبادل کلید امن**

- چون کلید AES قراره محرمانه باشه، اونو با RSA ارسال می‌کنیم.
    
- وقتی طرف مقابل کلید AES رو دریافت کرد، دیگه ارتباط ادامه پیدا می‌کنه با AES که سریع‌تره.
    

### 2. **AES برای رمزنگاری داده‌های حجیم**

- مثلاً ویدیو دوربین‌ها یا فایل‌های سیستمی.
    
- AES خیلی سریع‌تر عمل می‌کنه و مصرف CPU پایین‌تری داره.

## ✅ چرا در شبکه دوربین مداربسته مهمه؟

|الگوریتم|چرا استفاده کنیم؟|
|---|---|
|**RSA**|برای اطمینان از اینکه فقط گیرنده اصلی (مثلاً NVR یا سرور) می‌تونه کلید رمز AES رو باز کنه.|
|**AES**|برای رمزنگاری جریان زنده ویدیوها (live stream)، چون سریع و امنه.|

## 🔐 ترکیب پیشنهادی برای امنیت بالا:

- در ابتدا، RSA برای تبادل کلید AES.
    
- سپس تمام ارتباط بین دوربین و ضبط‌کننده با **AES-256** رمزنگاری بشه.
    
- این ساختار، هم **محرمانگی**، هم **امنیت کلید** و هم **سرعت بالا** رو تضمین می‌کنه.

## ✅ سناریو ۱: استفاده از الگوریتم‌ها در شبکه (مثلاً شبکه دوربین مداربسته)

### ۱. **در سطح شبکه از پروتکل‌هایی استفاده کن که رمزنگاری داخلی دارن**:

مثل:

|پروتکل|رمزنگاری داخلی|
|---|---|
|**HTTPS** یا **RTSP over TLS**|استفاده از **TLS = RSA + AES**|
|**VPN (مثل OpenVPN یا WireGuard)**|تبادل کلید با **RSA/ECDH** و انتقال داده با **AES یا ChaCha20**|
|**IPSec**|استفاده از RSA و AES برای رمزنگاری در لایه شبکه|

**مثال کاربردی برای دوربین:**

- تنظیمات دوربین رو طوری پیکربندی کن که از **HTTPS یا RTSP over TLS** استفاده کنه.
    
- اگر ارتباط از راه دور داری، حتماً بین شبکه‌ها **VPN** راه بنداز.
    
- **NVR یا سرور ضبط ویدیو** هم باید قابلیت رمزنگاری ذخیره‌سازی با AES رو داشته باشه.

### 🔐 مرحله ۱: نصب کتابخانه موردنیاز

```bash
pip install cryptography
```

---

### 🔐 مرحله ۲: رمزنگاری متقارن با AES (برای داده‌های حجیم)

```python
from cryptography.fernet import Fernet

# تولید کلید AES
key = Fernet.generate_key()
cipher = Fernet(key)

# رمزنگاری داده
plaintext = b"video stream data or message"
ciphertext = cipher.encrypt(plaintext)

# رمزگشایی
original = cipher.decrypt(ciphertext)

print("رمز شده:", ciphertext)
print("رمزگشایی شده:", original)
```

---

### 🔐 مرحله ۳: رمزنگاری نامتقارن با RSA (برای انتقال کلید AES)

```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import serialization, hashes

# تولید جفت کلید
private_key = rsa.generate_private_key(public_exponent=65537, key_size=2048)
public_key = private_key.public_key()

# کلید AES فرضی
aes_key = Fernet.generate_key()

# رمزنگاری کلید AES با کلید عمومی RSA
encrypted_key = public_key.encrypt(
    aes_key,
    padding.OAEP(mgf=padding.MGF1(algorithm=hashes.SHA256()),
                 algorithm=hashes.SHA256(), label=None)
)

# رمزگشایی کلید با کلید خصوصی RSA
decrypted_key = private_key.decrypt(
    encrypted_key,
    padding.OAEP(mgf=padding.MGF1(algorithm=hashes.SHA256()),
                 algorithm=hashes.SHA256(), label=None)
)

print("کلید AES رمز شده:", encrypted_key)
print("کلید رمزگشایی شده:", decrypted_key)
```

## 📌 ساختار کلی دستور iptables

```bash
iptables [CHAIN] [CONDITION] [ACTION]
```

مثلاً:

```bash
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

یعنی به زنجیره INPUT یک قانون اضافه کن که اگر بسته TCP به پورت 22 (SSH) بود، اجازه عبور بده.

---

## 🔗 زنجیره‌های اصلی (Chains)

|Chain|کاربرد|
|---|---|
|`INPUT`|برای بسته‌هایی که به سیستم وارد می‌شن|
|`OUTPUT`|برای بسته‌هایی که از سیستم خارج می‌شن|
|`FORWARD`|برای بسته‌هایی که از روی سیستم عبور می‌کنن (مثل روتر)|

---

## 🧱 کامندهای پرکاربرد iptables

### 1. **نمایش قوانین فعلی**

```bash
iptables -L -n -v
```

- `-L` → لیست قوانین
    
- `-n` → نمایش IP به جای نام‌ها (سریع‌تر)
    
- `-v` → نمایش با جزئیات
    

---

### 2. **اجازه دادن به پورت خاص**

```bash
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
```

- اجازه به پورت 80 (HTTP)
    

---

### 3. **بستن یک پورت خاص**

```bash
iptables -A INPUT -p tcp --dport 21 -j DROP
```

- جلوگیری از دسترسی به پورت 21 (FTP)
    

---

### 4. **اجازه دادن فقط به IP خاص**

```bash
iptables -A INPUT -s 192.168.1.10 -j ACCEPT
```

- فقط IP خاص اجازه ورود دارد.
    

---

### 5. **بلاک کردن یک IP خاص**

```bash
iptables -A INPUT -s 10.0.0.5 -j DROP
```

---

### 6. **پاک کردن یک قانون خاص**

```bash
iptables -D INPUT -p tcp --dport 22 -j ACCEPT
```

---

### 7. **پاک‌سازی تمام قوانین**

```bash
iptables -F
```

- تمام قوانین زنجیره‌ها پاک می‌شن (Flush)
    

---

### 8. **تنظیم سیاست پیش‌فرض برای بلاک کردن**

```bash
iptables -P INPUT DROP
```

- یعنی اگر قانونی نبود، بسته‌ها بلاک شوند.
    

---

### 9. **ذخیره قوانین برای بوت بعدی (در اوبونتو)**

```bash
sudo iptables-save > /etc/iptables/rules.v4
```

---

### 10. **بازنشانی به حالت اولیه**

```bash
iptables -F

iptables -t nat -X
```

- تمام قوانین و زنجیره‌های تعریف‌شده کاربر پاک می‌شن.

## 🧠 دسته‌بندی دستورات پیشرفته

---

### ✅ 1. **استفاده از ماژول Connection Tracking (`conntrack` یا `state`)**

برای پیگیری وضعیت اتصال (Established, New, Related)

#### اجازه به اتصالات موجود:

```bash
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

- اجازه می‌ده بسته‌هایی که به اتصالات قبلی تعلق دارن (مثلاً پاسخ از سرور وب) عبور کنن.
    
- **بسیار مهم برای اجازه به ترافیک برگشتی.**
    

#### فقط اجازه به اتصال جدید از پورت خاص:

```bash
iptables -A INPUT -p tcp --dport 443 -m conntrack --ctstate NEW -j ACCEPT
```

---

### 🔁 2. **NAT و فورواردینگ - جدول nat**

#### تغییر IP مبدأ (Source NAT = SNAT)

```bash
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

- برای اشتراک‌گذاری اینترنت بین چند دستگاه (مثلاً در مودم یا روتر).
    
- `MASQUERADE` برای آدرس‌های پویا مفیده.
    

#### تغییر IP مقصد (Destination NAT = DNAT)

```bash
iptables -t nat -A PREROUTING -p tcp --dport 2222 -j DNAT --to-destination 192.168.1.10:22
```

- ترافیک پورت 2222 رو به پورت 22 روی IP داخلی بفرست.
    

---

### 📌 3. **ساخت زنجیره سفارشی**

#### ایجاد زنجیره جدید:

```bash
iptables -N MYCHAIN
```

#### اضافه کردن قوانین به اون:

```bash
iptables -A MYCHAIN -s 10.0.0.0/8 -j DROP
```

#### فراخوانی زنجیره در INPUT:

```bash
iptables -A INPUT -j MYCHAIN
```

---

### ⏱️ 4. **محدود کردن نرخ (Rate Limiting)**

#### محدود کردن ICMP (پینگ):

```bash
iptables -A INPUT -p icmp -m limit --limit 1/second --limit-burst 5 -j ACCEPT
```

- فقط اجازه می‌ده ۱ پینگ در ثانیه رد بشه (با حداکثر ۵ تا پشت سر هم)
    

---

### 🚫 5. **محافظت در برابر اسکن پورت با TCP Flags**

```bash
iptables -A INPUT -p tcp --tcp-flags ALL NONE -j DROP
iptables -A INPUT -p tcp --tcp-flags SYN,FIN SYN,FIN -j DROP
iptables -A INPUT -p tcp --tcp-flags SYN,RST SYN,RST -j DROP
```

- برای جلوگیری از انواع اسکن پورت‌های stealth توسط ابزارهایی مثل `nmap`
    

---

### 🔍 6. **لاگ کردن بسته‌ها**

#### لاگ قبل از بلاک کردن:

```bash
iptables -A INPUT -s 10.10.10.10 -j LOG --log-prefix "Blocked IP: "
iptables -A INPUT -s 10.10.10.10 -j DROP
```

- لاگ در `/var/log/syslog` یا `/var/log/messages`

### 🧹 7. **زمان‌دار کردن قوانین (اگر از ماژول time پشتیبانی بشه)**

```bash
iptables -A INPUT -m time --timestart 09:00 --timestop 17:00 --weekdays Mon,Tue,Wed,Thu,Fri -j ACCEPT
```

- فقط در ساعات کاری اجازه دسترسی بده

### 🧩 8. **بر اساس MAC Address**

```bash
iptables -A INPUT -m mac --mac-source 00:11:22:33:44:55 -j ACCEPT
```

### 🗂️ 9. **فیلتر بر اساس نام کاربری (برای OUTPUT)**

```bash
iptables -A OUTPUT -m owner --uid-owner 1001 -j ACCEPT
```

- فقط اجازه به برنامه‌هایی که توسط کاربر UID=1001 اجرا می‌شن

### 🧮 10. **محدود کردن تعداد اتصال به یک پورت (مثلاً جلوگیری از DoS)**

```bash
iptables -A INPUT -p tcp --dport 22 -m connlimit --connlimit-above 3 -j REJECT
```

- بیش از 3 اتصال همزمان به SSH رو رد می‌کنه.
