# Idle Scanning (Zombie Scan) — توضیح کامل و شفاف

## 0️⃣ مسئله‌ای که Idle Scan حل می‌کند

فرض کن می‌خوای بفهمی:

> «روی سیستم Target چه پورت‌هایی باز هستند؟»

اما:

- نمی‌خوای IP خودت دیده شود
    
- نمی‌خوای IDS / Firewall بفهمد
    
- نمی‌خوای لاگ‌ها به تو برسند
    

👉 Idle Scan می‌گه:

> «اصلاً خودت با Target حرف نزن»

---

# 1️⃣ سه نقش در Idle Scan

|نقش|توضیح|
|---|---|
|Attacker|تو|
|Zombie|سیستم بی‌خبر و Idle|
|Target|هدف اسکن|

Zombie مهم‌ترین بخش حمله است.

---

# 2️⃣ IP ID چیست؟ (خیلی ساده و کاربردی)

### تعریف رسمی

**IP ID** یک عدد **16 بیتی** در هدر IPv4 است.

### کاربرد واقعی

وقتی یک Packet بزرگ Fragment می‌شود:

- همه Fragmentها **IP ID یکسان** دارند
    
- مقصد می‌فهمد این‌ها متعلق به یک پکت هستند
    

### نکته حیاتی

حتی وقتی **Fragment نداریم**:

- سیستم‌عامل باز هم برای هر Packet یک IP ID می‌گذارد
    

📌 بعضی OSها این عدد را:

- برای **هر پکت خروجی یکی زیاد می‌کنند**
    
- این یعنی: قابل شمارش، قابل پیش‌بینی
    

همین «قابل شمارش بودن» اساس Idle Scan است.

---

# 3️⃣ Zombie مناسب چه ویژگی دارد؟

Zombie باید:

- تقریباً هیچ ترافیکی نداشته باشد (Idle)
    
- IP ID آن **Global Incremental** باشد
    

مثلاً:

```
Packet 1 → IPID = 500
Packet 2 → IPID = 501
Packet 3 → IPID = 502
```

اگر وسطش ترافیک بیاد → اسکن خراب می‌شود.

---

# 4️⃣ منطق اصلی Idle Scan (ایده ذهنی)

Attacker نمی‌داند Target چه پاسخی می‌دهد  
اما می‌تواند **ببیند Zombie چند Packet فرستاده**

و چون:

> هر Packet = IPID +1

پس:

> با شمردن IPID می‌فهمیم چه اتفاقی افتاده

---

# 5️⃣ مراحل Idle Scan — دقیق و خطی

فرض کن:

- Zombie IPID = 1000
    

---

## مرحله 1: اندازه‌گیری اولیه IPID

Attacker → Zombie  
یک Probe ساده می‌فرستد

Zombie → Attacker  
پاسخ می‌دهد با:

```
IPID = 1000
```

Attacker یادداشت می‌کند.

---

## مرحله 2: تحریک Target (بدون دیده شدن)

Attacker → Target

```
SYN
Source IP = Zombie
```

⚠️ Attacker مستقیم با Target صحبت نمی‌کند.

---

## مرحله 3: واکنش Target

### اگر پورت Target **باز باشد**

Target → Zombie

```
SYN/ACK
```

Zombie گیج می‌شود:

> «من SYN نفرستادم!»

پس Zombie:

```
RST → Target
```

📌 Zombie **یک Packet فرستاده**  
📌 IPID می‌شود:

```
1001
```

---

### اگر پورت Target **بسته باشد**

Target → Zombie

```
RST
```

Zombie:

- کاری نمی‌کند
    
- هیچ Packetی نمی‌فرستد
    
- IPID تغییر نمی‌کند
    

---

## مرحله 4: اندازه‌گیری دوباره IPID

Attacker دوباره از Zombie Probe می‌گیرد:

### نتایج:

|IPID جدید|نتیجه|
|---|---|
|1001|پورت بسته|
|1002|پورت باز|

📌 چرا 1002؟

- +1 برای پاسخ به Probe دوم
    
- +1 برای RST به Target
    

---

# 6️⃣ نقش IP ID (این قسمت کلیدی است)

Idle Scan اصلاً به محتوای Packet نگاه نمی‌کند.  
فقط می‌پرسد:

> Zombie چند بار «مجبور شده» Packet بفرستد؟

و چون:

- هر Packet = IPID +1
    

پس:

- RST فرستاده؟ → IPID بالا رفته
    
- RST نفرستاده؟ → ثابت مانده
    

📌 IPID در این حمله:

> مثل **شمارنده ضربان قلب Zombie** است

---

# 7️⃣ چرا RST حیاتی است؟

Zombie فقط در یک حالت Packet می‌فرستد:

- وقتی **SYN/ACK ناخواسته** دریافت کند
    

این Packet = RST

بدون RST:

> هیچ سیگنالی برای اندازه‌گیری وجود ندارد  
> Idle Scan شکست می‌خورد

---

# 8️⃣ چرا Idle Scan امروزه سخت شده؟

|دلیل|توضیح|
|---|---|
|Random IPID|OSهای جدید|
|NAT|تغییر IPID|
|IPv6|حذف IPID|
|Noise|ترافیک Zombie|

---

# 9️⃣ جمع‌بندی خیلی کوتاه (جزوه‌ای)

- Idle Scan = اسکن پورت بدون تماس مستقیم
    
- مبتنی بر **IPID قابل پیش‌بینی**
    
- RST = تنها نشانه پورت باز
    
- Zombie = حسگر غیرمستقیم حمله
    
- تکنیک کلاسیک ولی آموزشی-عمیق
    

> **داخل IPID هیچ اطلاعاتی درباره پورت یا اتصال نیست.  
> ما فقط از «تغییر عدد IPID» به عنوان یک شمارنده استفاده می‌کنیم.**

حالا بیایم دقیق، اما خیلی شفاف.

---

# 1️⃣ داخل IPID واقعاً چی هست؟

### پاسخ کوتاه:

**هیچی به‌جز یک عدد 16 بیتی.**

- IPID = **Identification Number**
    
- هیچ فلگی
    
- هیچ بیت معنایی برای «پورت باز»
    
- هیچ ارتباطی با TCP
    

📌 کار اصلی IPID:

> برچسب‌زدن Fragmentها برای Reassembly

---

# 2️⃣ پس ما چی رو از IPID می‌خوانیم؟

### فقط این سؤال:

> «Zombie چند Packet فرستاده؟»

چون:

- در بعضی سیستم‌ها
    
- **هر Packet خروجی → IPID +1**
    

---

# 3️⃣ چرا Zombie Packet می‌فرستد؟

Zombie فقط در یک حالت **ناخواسته** Packet می‌فرستد:

### دریافت SYN/ACK بدون اینکه SYN فرستاده باشد

این یعنی:

```
Target → Zombie : SYN/ACK
Zombie → Target : RST
```

📌 این RST باعث افزایش IPID می‌شود.

---

# 4️⃣ تفاوت رفتار در پورت باز و بسته

## اگر پورت بسته باشد

```
Attacker → Target : SYN (Src=Zombie)
Target → Zombie  : RST
Zombie           : هیچ کاری نمی‌کند
```

📌 Zombie Packet نمی‌فرستد  
📌 IPID تغییر نمی‌کند

---

## اگر پورت باز باشد

```
Attacker → Target : SYN (Src=Zombie)
Target → Zombie  : SYN/ACK
Zombie → Target  : RST
```

📌 Zombie مجبور به ارسال Packet می‌شود  
📌 IPID افزایش می‌یابد

---

# 5️⃣ عددها چگونه معنی پیدا می‌کنند؟

فرض کن:

```
IPID اولیه = 3000
```

بعد از اسکن:

|IPID جدید|تحلیل|
|---|---|
|3001|فقط پاسخ Probe → پورت بسته|
|3002|پاسخ Probe + RST → پورت باز|

📌 این **اختلاف عدد** معنی‌دار است، نه خود عدد.

---

# 6️⃣ تشبیه خیلی ساده 🧠

Zombie = دستگاه کارت‌زن  
IPID = شماره بلیت

- هر بار که Zombie مجبور به ارسال Packet می‌شود → یک بلیت جدید صادر می‌کند
    
- Attacker فقط شماره بلیت‌ها را می‌بیند
    
- از اختلاف شماره‌ها نتیجه می‌گیرد
    

---

# 7️⃣ نکته فوق‌مهم

Idle Scan:

- **IPID را تفسیر نمی‌کند**
    
- **TCP Payload را نمی‌بیند**
    
- فقط از **Side-Effect شبکه** استفاده می‌کند
    

🎯 این دقیقاً فلسفه حملات Red Team است:

> سوءاستفاده از رفتارهای جانبی، نه از داده اصلی

---

# 8️⃣ جمع‌بندی نهایی (جواب سؤال تو)

> داخل IPID هیچ چیزی درباره باز یا بسته بودن پورت نیست.  
> ما فقط از افزایش IPID می‌فهمیم Zombie مجبور شده Packet بفرستد یا نه،  
> و تنها دلیلی که Zombie Packet می‌فرستد، دریافت SYN/ACK از یک پورت باز است.
