## UWP (Universal Windows Platform)

انقلاب دستگاه‌های موبایل، روش‌های جدیدی را برای تهیه و اجرای نرم‌افزار ایجاد کرد. دستگاه‌های موبایل معمولاً برنامه‌های خود را از یک فروشگاه مرکزی دریافت می‌کنند؛ جایی که نصب و به‌روزرسانی‌ها به صورت خودکار و با کمترین دخالت کاربر انجام می‌شود. هنگامی که کاربر برنامه‌ای را از فروشگاه انتخاب می‌کند، می‌تواند مجوزهایی را که آن برنامه برای عملکرد صحیح نیاز دارد، مشاهده کند. این مجوزها، «قابلیت‌ها» (Capabilities) نامیده می‌شوند و هنگام ارسال بسته برنامه به فروشگاه، به عنوان بخشی از آن تعریف می‌گردند. بدین ترتیب، کاربر می‌تواند تصمیم بگیرد که آیا این قابلیت‌ها قابل قبول هستند یا خیر.

شکل ۷-۱۶ مثالی از لیست قابلیت‌های یک بازی UWP (نسخه بتای ویندوز ۱۰ بازی ماینکرفت) را نشان می‌دهد. این بازی به دسترسی اینترنت (به عنوان کلاینت و سرور) و دسترسی به شبکه خانگی یا کاری نیاز دارد. کاربر با دانلود بازی، به‌صورت ضمنی توافق می‌کند که بازی ممکن است از این قابلیت‌ها استفاده کند. در مقابل، کاربر اطمینان دارد که بازی فقط از همین قابلیت‌های تاییدشده استفاده می‌کند و هیچ راهی وجود ندارد که برنامه از قابلیت‌های غیرمجاز دیگری (مانند دسترسی به دوربین دستگاه) استفاده کند.

- **اجرایی‌ها:** برنامه‌های UWP می‌توانند فایل‌های اجرایی معمولی (مشابه دسکتاپ) تولید کنند. فایل `wwahost.exe` برای میزبانی برنامه‌های UWP مبتنی بر HTML/JavaScript استفاده می‌شود، زیرا خروجی آن‌ها DLL است، نه یک فایل اجرایی.
- **ویندوز ران‌تایم (WinRT):** پلتفرم UWP توسط APIهای Windows Runtime پیاده‌سازی شده که مبتنی بر نسخه پیشرفته‌ای از COM هستند. برای زبان‌های ++C (از طریق C++/CX)، دات‌نت (NET.) و جاوااسکریپت، زبان‌های واسط (Projections) ارائه شده است تا دسترسی به WinRT آسان‌تر شود.
- **فناوری‌های پل (Bridging):** ابزارهایی برای تبدیل سایر انواع برنامه‌ها به UWP وجود دارد.
- **ساختار لایه‌ای:** ویندوز ران‌تایم مشابه فریم‌ورک دات‌نت، بر روی DLLهای زیرسیستم ویندوز قرار دارد. این پلتفرم فاقد اجزای کرنل مستقل است و از همان APIهای Win32 استفاده می‌کند. با این حال، برخی سیاست‌ها در سطح کرنل و برای پشتیبانی از AppContainerها پیاده‌سازی می‌شوند.
- **محل قرارگیری:** APIهای WinRT در فایل‌هایی با الگوی `Windows.Xxx.Yyy.Dll` در پوشه `%SystemRoot%\System32` قرار دارند.


### مفهوم AppContainer

فرآیندهای UWP داخل یک محیط ایزوله به نام **AppContainer** اجرا می‌شوند. ویژگی‌های فرآیندهای بسته‌بندی شده در AppContainer عبارتند از:

1. **سطح یکپارچگی (Integrity Level):** سطح دسترسی فرآیند روی `Low` تنظیم شده است که دسترسی به بسیاری از اشیاء و APIها را محدود می‌کند.
2. **مدیریت با Job:** فرآیندهای UWP همیشه درون یک «Job» (یک Job برای هر برنامه) ایجاد می‌شوند تا مدیریت چرخه حیات (تعلیق/ازسرگیری) توسط Process State Manager (PSM) انجام شود.
3. **هویت (SID):** توکن فرآیند UWP دارای یک AppContainer SID است که از هش SHA-2 نام بسته برنامه مشتق شده و با پیشوند `S-1-15-2` آغاز می‌شود.
4. **قابلیت‌ها (Capabilities):** لیست قابلیت‌های برنامه در مانیفست تعریف شده و به فرمت SID تبدیل می‌شود تا سیستم بتواند دسترسی‌ها را کنترل کند.
5. **سطح دسترسی (Privileges):** این توکن‌ها فقط به مجموعه‌ای محدود از مجوزهای استاندارد (مانند `SeChangeNotifyPrivilege`) دسترسی دارند.
6. **ویژگی‌های امنیتی (Security Attributes):** توکن شامل حداکثر چهار ویژگی امنیتی است (مانند `WIN://PKG` برای هویت بسته و `WIN://SYSAPPID` برای شناسه‌های برنامه) که توسط سرویس `DcomLaunch` تزریق می‌شوند.
7. **فلگ TOKEN_LOWBOX:** با تنظیم این فلگ، اجزای ویندوز متوجه می‌شوند که با یک فرآیند AppContainer سروکار دارند.

_نکته: نوع دوم AppContainer، یعنی «Child AppContainer» نیز وجود دارد که برای لایه‌های امنیتی بیشتر و تو در تو استفاده می‌شود._
