

**wmiexec.py**  
`wmiexec.py` از یک **shell نیمه‌تعاملی (semi-interactive)** استفاده می‌کند که دستورات از طریق **Windows Management Instrumentation (WMI)** اجرا می‌شوند.

ویژگی‌ها:

- هیچ فایل یا اجرایی روی سیستم هدف ریخته نمی‌شود.
    
- نسبت به سایر ماژول‌ها، **تعداد کمتری لاگ تولید می‌کند**.
    
- بعد از اتصال، دستورات با **امتیاز کاربر محلی که با آن وارد شدیم** اجرا می‌شوند (این روش نسبت به اجرای دستورها با SYSTEM، کمتر برای کسانی که دنبال نفوذ هستند قابل مشاهده است).
    

💡 نکته: این روش نسبت به ابزارهای دیگر، **روش مخفیانه‌تری برای اجرای دستورات روی میزبان‌ها** است، اما همچنان توسط اکثر سیستم‌های مدرن آنتی‌ویروس و EDR قابل شناسایی است.

- در مثال، همان حسابی که با `psexec.py` استفاده شد، برای دسترسی به هاست مورد استفاده قرار می‌گیرد:
    

```bash
psexec.py inlanefreight.local/wley:'transporter@4'@172.16.5.125
```



- توجه داشته باشید که این **محیط shell به‌طور کامل تعاملی نیست**؛ هر دستوری که اجرا می‌کنید، **یک cmd.exe جدید از طریق WMI ایجاد می‌کند و دستور شما را اجرا می‌کند**.
    
- نقطه ضعف: اگر یک مدافع دقیق لاگ‌ها را بررسی کند و به Event ID **4688: A new process has been created** نگاه کند، مشاهده می‌شود که **یک پروسه جدید برای اجرای cmd.exe و اجرای دستور ایجاد شده است**.
    
    - این همیشه فعالیت مخرب نیست، زیرا بسیاری از سازمان‌ها از WMI برای مدیریت سیستم‌ها استفاده می‌کنند، اما می‌تواند **نشانه‌ای برای تحقیقات امنیتی** باشد.
        
- در تصویر نمونه، مشخص است که پروسه تحت **کاربر wley** روی میزبان اجرا می‌شود، نه SYSTEM.
