## 🧠 ۱. مفهوم کلی Stack در C

هر برنامه در C — وقتی اجرا می‌شود — حافظه‌اش معمولاً به چند بخش تقسیم می‌شود:

|ناحیه حافظه|توضیح|
|---|---|
|**Text / Code segment**|محل ذخیره کد برنامه (دستورات کامپایل‌شده)|
|**Data segment**|متغیرهای global و static|
|**Heap**|حافظه‌ی دینامیکی (با malloc/free)|
|**Stack**|محل نگهداری متغیرهای محلی (local) و پارامترهای توابع|

---

## 🧩 ۲. Stack چگونه کار می‌کند؟

Stack دقیقاً مانند یک **پشته (LIFO)** است:  
آخرین چیزی که وارد آن می‌شود، اولین چیزی است که بیرون می‌آید.

وقتی تابعی فراخوانی می‌شود:

1. اطلاعات لازم برای بازگشت (return address) در استک ذخیره می‌شود.
    
2. پارامترهای تابع روی استک قرار می‌گیرند.
    
3. برای متغیرهای محلی حافظه‌ای در استک رزرو می‌شود.
    
4. سپس کنترل به بدنه‌ی تابع منتقل می‌شود.
    

وقتی تابع تمام شد:

- **Stack Frame** مخصوص آن تابع از بین می‌رود.
    
- حافظه‌ی متغیرهای محلی آزاد می‌شود.
    
- CPU به آدرسی که قبل از فراخوانی ذخیره کرده بود (return address) برمی‌گردد.
    

---

## 🧭 ۳. مفهوم Stack Frame

هر بار که تابعی صدا زده می‌شود، **یک Stack Frame جدید** روی پشته ساخته می‌شود.

هر Stack Frame معمولاً شامل موارد زیر است:

|بخش|توضیح|
|---|---|
|Return Address|آدرسی که CPU باید بعد از تمام شدن تابع به آن برگردد|
|Saved Frame Pointer|وضعیت استک تابع قبلی (برای بازگردانی)|
|Function Arguments|مقادیر پارامترهایی که به تابع داده‌ای|
|Local Variables|متغیرهای محلی همان تابع|

---

## 🧮 ۴. مثال مرحله‌به‌مرحله (تحلیل دقیق کد کتاب)

```c
int foo(int x, int y)
{
    return x + y;
}

int main(void)
{
    int a = 13, b = 42;
    int c = foo(a, b);
    return 0;
}
```

### مرحله ۱ — اجرای `main()`

- یک Stack Frame برای `main()` ساخته می‌شود.
    
- متغیرهای محلی `a` و `b` روی استک قرار می‌گیرند.
    
- فرض کنیم آدرس استک از بالا به پایین کاهش می‌یابد (stack grows downward).
    

```
|----------------|
|  b = 42        |
|----------------|
|  a = 13        |
|----------------|
|  return addr   | ← FP (Frame Pointer)
|----------------|
```

---

### مرحله ۲ — فراخوانی `foo(a, b)`

وقتی `foo()` صدا زده می‌شود:

1. مقادیر `a` و `b` به عنوان آرگومان روی استک قرار می‌گیرند.
    
2. return address (آدرس بعد از `foo`) هم ذخیره می‌شود.
    
3. stack pointer پایین‌تر می‌رود تا فضای جدید بسازد.
    

```
|----------------|
|  y = 42        |
|----------------|
|  x = 13        |
|----------------|
|  return addr   |
|----------------|
|  saved FP      |
|----------------|
```

---

### مرحله ۳ — اجرای `foo()`

- متغیرهای محلی (در اینجا x و y) در همین Stack Frame هستند.
    
- `x + y` محاسبه شده و مقدار در یک رجیستر (مثلاً EAX) قرار می‌گیرد.  
    (نتیجه معمولاً در رجیستر بازگشتی CPU ذخیره می‌شود، نه روی استک.)
    

---

### مرحله ۴ — بازگشت از `foo()`

- مقدار برگشتی (مثلاً 55) در رجیستر قرار دارد.
    
- Stack Frame مربوط به `foo` پاک می‌شود (sp ← fp).
    
- CPU از آدرس return address به ادامه‌ی `main()` برمی‌گردد.
    

---

### مرحله ۵ — ادامه‌ی `main()`

- مقدار برگشتی `foo()` در متغیر `c` ذخیره می‌شود.
    
- در پایان `main()`، Stack Frame آن نیز حذف می‌شود.
    
- کل برنامه خاتمه می‌یابد.
    

---

## ⚠️ ۵. Lifetime متغیرهای محلی

متغیرهای محلی فقط **در زمان اجرای تابعی که در آن تعریف شده‌اند** وجود دارند.

به محض اینکه تابع تمام شود:

- Stack Frame حذف می‌شود.
    
- حافظه‌ای که در آن متغیرها بودند، **ممکن است دوباره استفاده شود**.
    
- دسترسی به آن متغیر پس از return، **رفتار تعریف‌نشده (undefined behavior)** است.
    

مثلاً:

```c
int* foo(void) {
    int x = 5;
    return &x; // ❌ اشتباه بزرگ!
}
```

در اینجا اشاره‌گر `&x` به حافظه‌ای اشاره می‌کند که بعد از پایان تابع آزاد می‌شود.  
استفاده از آن باعث خطاهای مرموز (Segmentation Fault) خواهد شد.

---

## 🧩 ۶. سه Pointer مهم در اجرای تابع

|Pointer|نقش|
|---|---|
|**IP (Instruction Pointer)**|آدرس دستور فعلی در حال اجرا|
|**SP (Stack Pointer)**|آدرس بالاترین بخش آزاد استک|
|**FP (Frame Pointer / Base Pointer)**|آدرس شروع فریم تابع فعلی|

کامپایلر با FP و offsetها موقعیت متغیرهای محلی را در استک پیدا می‌کند.

---

## 🧱 ۷. مدل ذهنی از حرکت استک

وقتی تابعی صدا زده می‌شود، استک رشد می‌کند ⬇️  
وقتی تابعی برمی‌گردد، استک کوچک می‌شود ⬆️

```
Before foo():
|    a, b, main() frame    |

Call foo():
| foo() frame |
| a, b, main() frame |

Return from foo():
|    a, b, main() frame    |
```

---

## 💡 نکته مهم برای امنیت

گاهی داده‌های حساس (مثل پسورد) در استک ذخیره می‌شوند.  
اگر تابعی اشتباه حافظه را مدیریت کند (مثلاً **buffer overflow**)،  
ممکن است داده‌های دیگر یا حتی return address را **overwrite** کند.

این همان چیزی است که منجر به حملات **Stack Overflow Exploit** می‌شود.
