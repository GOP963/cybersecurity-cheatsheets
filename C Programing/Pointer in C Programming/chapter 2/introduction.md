
در بالاتر از آن، حافظه‌ای وجود دارد که برنامه در زمان اجرا **درخواست و آزاد (allocate / deallocate)** می‌کند.  
به این بخش حافظه **heap** گفته می‌شود.  
در فصل ۹ توضیح داده می‌شود که چطور در C می‌توانی از heap حافظه بگیری.  
وقتی فرآیند به حافظه‌ی بیشتری نیاز دارد، heap به سمت بالا رشد می‌کند.  
اما آزاد کردن حافظه در heap کمی پیچیده‌تر است.

نمی‌توانیم یک بلوک وسط heap را حذف کنیم و همه‌ی داده‌های بالاتر را به پایین منتقل کنیم، چون این کار بسیار زمان‌بر است و همچنین نمی‌توانیم اشیایی را جابه‌جا کنیم که **آدرس** آن‌ها را قبلاً گرفته‌ایم — چون اگر جابه‌جا شوند، آدرسی که در اختیار داریم دیگر به داده‌ی درست اشاره نخواهد کرد.  
البته نگران نباش، سیستم اجرایی (runtime) زبان C خودش این مسائل را مدیریت می‌کند.

در بالاترین بخش، **stack** قرار دارد.  
stack 
برای **فراخوانی توابع (function calls)** استفاده می‌شود و جایی است که **متغیرهای محلی (local variables)** و **آرگومان‌های توابع** در آن زندگی می‌کنند.  
stack معمولاً **به سمت پایین رشد می‌کند**.

بین stack و heap معمولاً یک ناحیه‌ی ممنوعه وجود دارد که برنامه اجازه‌ی دسترسی به آن را ندارد.  
این ناحیه برای جلوگیری از آن است که stack و heap در هم تداخل پیدا کنند.

## virtual memory

حافظه‌ای که یک فرآیند می‌بیند، به‌ندرت همان **حافظه‌ی فیزیکی واقعی** سیستم است.  
بین فرآیند در حال اجرا و حافظه‌ی فیزیکی، CPU یک حافظه‌ی **مجازی (virtual memory)** ایجاد می‌کند.  
برنامه در همین فضای مجازی کار می‌کند و هر بار که لازم است به حافظه دسترسی پیدا کند، سخت‌افزار آدرس مجازی را به یک آدرس فیزیکی **نگاشت (map)** می‌کند.

در گذشته، حافظه‌ی فیزیکی و مجازی یکی بودند و هر برنامه‌ای می‌توانست داده‌ها را از هر جای حافظه بخواند یا بنویسد و هر کدی را از هر جایی اجرا کند — که واضح است **بسیار ناامن** بود.  
حافظه‌ی مجازی باعث شد فرآیندها از یکدیگر جدا بمانند و رابط ساده‌تری برای آدرس‌دهی در اختیار برنامه‌ها قرار گیرد.


برنامه‌ها باید برای استفاده از **stack** و **heap**، حافظه‌ای درخواست کنند، و این معمولاً از طریق سیستم‌عامل انجام می‌شود.  
سیستم‌عامل در پاسخ، نگاشت بین حافظه‌ی فیزیکی و مجازی را تنظیم می‌کند.

گرچه در تئوری می‌توانی به کل فضای آدرس‌دهی دسترسی داشته باشی، در عمل اگر خارج از محدوده‌ی حافظه‌ی تخصیص‌داده‌شده چیزی را بخوانی یا بنویسی، سخت‌افزار یک **وقفه (interrupt)** ایجاد می‌کند و سیستم‌عامل احتمالاً فرآیند را خاتمه می‌دهد.  
بنابراین اگر بدون مجوز بخواهی از جایی بخوانی یا در آن بنویسی، نتیجه‌اش معمولاً **مرگ برنامه‌ات (crash)** خواهد بود.

---

اگر می‌خواهی **آدرس حافظه‌ی** یک متغیر را بدانی،  
کافی است علامت `&` را قبل از نام آن بنویسی:

```
#include <stdio.h>
int main(void)
{
    char c = 1;
    printf("%d %p\n", c, (void *)&c);

    int i = 2;
    printf("%d %p\n", i, (void *)&i);

    double d = 3.0;
    printf("%f %p\n", d, (void *)&d);

    return 0;
}
```

این برنامه مقدار متغیرها (`char`، `int` و `double`) را همراه با **آدرس حافظه‌ی آن‌ها** چاپ می‌کند.  
در تابع `printf()`، فرمت `%p` برای نمایش آدرس حافظه استفاده می‌شود.  
عملگر `(void *)` نیز برای تبدیل آدرس به **نوع اشاره‌گر void** است،  
چون `%p` مخصوص این نوع است.  
(در فصل بعدی بیشتر درباره‌ی اشاره‌گرهای `void *` صحبت می‌شود.)


![[Pasted image 20251015042754.png]]


```
1 0x7ffee0d888ff
2 0x7ffee0d888f8
3.000000 0x7ffee0d888f0
```

این خروجی نشان می‌دهد که `double` زودتر از بقیه در حافظه قرار گرفته،  
بعد از آن `int` و در آخر `char`.  

آدرس‌های حافظه از پایین به بالا مرتب شده‌اند.  
مثلاً عدد صحیح (`int`) در آدرس‌های `0x7ffee0d888f8` (پایین) تا `0x7ffee0d888fb` (بالا) قرار دارد.

۸ بایت از آدرس `0x7ffee0d888f0` به متغیر `double` اختصاص دارد.  
بلافاصله بعد از آن، متغیر `int` قرار دارد.  
از خروجی `sizeof(int)` در برنامه‌ی قبلی می‌دانیم که `int` در سیستم من ۴ بایت فضا می‌گیرد.

با این حال، بین `int` و `char` **یک فاصله (gap)** وجود دارد (منطقه‌ی خاکستری در شکل).  
C می‌تواند متغیرها را هر طور که خواست در حافظه قرار دهد  
و هیچ تضمینی وجود ندارد که دو متغیر پشت سر هم ذخیره شوند.

این چیدمان حافظه مخصوص کامپایلر و تنظیمات من است.  
اگر تنظیمات کامپایلر را تغییر دهم (مثلاً حالت بهینه‌سازی را عوض کنم)،  
چیدمان حافظه ممکن است کاملاً متفاوت شود.

بنابراین **هیچ‌وقت فرض نکن** متغیرها پشت سر هم در حافظه قرار می‌گیرند.  
استاندارد C فقط تضمین می‌کند که هر شیء:

- **یک آدرس دارد**
    
- و **اندازه‌ای دارد که توسط نوع آن تعیین می‌شود**

## 🧠 مفهوم کلی Memory Allocation

زمانی که برنامه‌ای در حال اجراست، تمام داده‌ها و متغیرها باید **جایی در حافظه RAM یا کش یا رجیسترها** قرار بگیرند تا CPU بتواند با آن‌ها کار کند.  
اما سؤال اینجاست:  
«این حافظه چطور و توسط چه کسی تخصیص داده می‌شود؟»

---

## 🧩 سه نوع اصلی تخصیص حافظه در C

### 1. **Static / Global Allocation (اختصاص ایستا یا سراسری)**
وقتی متغیری **خارج از تابع** یا با کلیدواژه‌ی `static` تعریف می‌شود،  
حافظه‌اش در بخش **data segment** رزرو می‌شود و تا پایان اجرای برنامه باقی می‌ماند.

```c
int counter = 0;  // global variable
```

- عمر: تا پایان اجرای برنامه  
- محل ذخیره: data segment  
- آزادسازی: خودکار در پایان برنامه  

---

### 2. **Stack Allocation (اختصاص در پشته)**
وقتی متغیر درون تابعی تعریف می‌کنی:

```c
void func() {
    int x = 5;
}
```

- حافظه برای `x` در **پشته (stack)** تخصیص می‌یابد.  
- وقتی تابع تمام می‌شود، این حافظه آزاد می‌شود.  
- این تخصیص توسط **کامپایلر و CPU** انجام می‌شود (اتوماتیک).

🔹 **نکته مهم:**  
نمی‌توانی آدرس متغیر محلی را بعد از پایان تابع استفاده کنی، چون حافظه‌اش آزاد می‌شود (dangling pointer).

---

### 3. **Dynamic Allocation (اختصاص پویا)**
در این حالت خودت حافظه را به‌صورت دستی از **heap** می‌گیری:

```c
int *arr = malloc(5 * sizeof(int));
```

- حافظه تا زمانی که خودت آن را `free()` نکنی باقی می‌ماند.  
- برای آرایه‌ها یا ساختارهایی که اندازه‌شان در زمان اجرا مشخص می‌شود، از این روش استفاده می‌کنی.

---

## 📦 مثال آرایه‌ها (Arrays)

در این مثال:
```c
int array[5];
```

- کامپایلر حافظه‌ای برای ۵ عدد `int` در **پشته** می‌گیرد.  
- این ۵ مقدار **پشت سر هم** (contiguous) در حافظه ذخیره می‌شوند.  
- `array` در واقع آدرس اولین عدد است (`&array[0]`).

خروجی `printf` در کد بالا نشان می‌دهد که:
هر عنصر `sizeof(int)` بایت با عنصر بعدی فاصله دارد.

---

## ⚙️ ساختار `union` و تخصیص حافظه آن

در `union`، همه‌ی اعضا **در یک آدرس** ذخیره می‌شوند و فقط یکی از آن‌ها در لحظه قابل استفاده است.

```c
union data {
    char c;
    int i;
    double d;
};
```

در این حالت، حافظه‌ی union برابر است با **بزرگ‌ترین نوع داده** (در اینجا `double` یعنی 8 بایت).  
تمام اعضا آدرس یکسان دارند چون در یک بلوک مشترک هستند.

📌 کاربرد اصلی:
زمانی که چند نوع داده ممکن است در یک متغیر ذخیره شود (مثلاً برای مفسرها یا ساختارهای داده سطح پایین).

---

## 🧱 ساختار `struct` و تخصیص حافظه آن

برخلاف union، در `struct` همه‌ی اعضا **به‌صورت همزمان** وجود دارند:

```c
struct data {
    char c;
    int i;
    double d;
};
```

در این مثال:
- `c` در آدرس شروع ساختار است.
- `i` بعد از آن می‌آید.
- `d` بعد از `i` قرار می‌گیرد.  

اما اندازه‌ی کلی `struct` معمولاً **بیشتر از مجموع اندازه‌ی اعضا** است، چون بین آن‌ها **padding (فضای خالی)** اضافه می‌شود.

---

## 🔍 Padding و Alignment چیست؟

CPU معمولاً داده‌ها را بهتر می‌خواند اگر **در آدرس‌های خاصی (مثل مضرب 4 یا 8)** قرار داشته باشند.  
به همین دلیل کامپایلر بین اعضای struct **فضای خالی اضافه می‌کند** تا داده‌ها هم‌تراز شوند.

مثلاً:
```
char (1 byte)
int (4 bytes)
double (8 bytes)
```

اگر ترتیبشان این باشد:
```c
char c;
int i;
double d;
```
ممکن است ساختار به جای 13 بایت، **16 بایت** فضا بگیرد تا `int` و `double` در آدرس‌های مناسب قرار بگیرند.

ولی اگر ترتیب را عوض کنیم:
```c
int i;
double d;
char c;
```
ساختار حتی ممکن است **24 بایت** شود (به خاطر فضای خالی انتهایی بعد از char).

## 📘 خلاصه تفاوت Struct و Union

| ویژگی | Struct | Union |
|--------|--------|--------|
| تخصیص حافظه | برای تمام اعضا همزمان | فقط بزرگ‌ترین عضو |
| آدرس اعضا | پشت سر هم | یکسان |
| اندازه کل | مجموع اندازه‌ها + padding | اندازه بزرگ‌ترین عضو |
| کاربرد | نگهداری چند داده مختلف همزمان | نگهداری یکی از چند نوع داده |
