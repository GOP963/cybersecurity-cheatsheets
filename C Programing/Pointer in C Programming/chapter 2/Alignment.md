## 🔹 مفهوم Memory Alignment (تراز حافظه)

وقتی CPU داده‌ها را از RAM می‌خواند یا در آن می‌نویسد، دوست دارد داده‌ها در آدرس‌هایی قرار داشته باشند که **برابر با مضربی از اندازه‌ی داده** باشند.

مثلاً اگر:

- نوع `int` اندازه‌اش ۴ بایت باشد، CPU ترجیح می‌دهد آن در آدرسی قرار گیرد که **بر ۴ بخش‌پذیر** است (مثل 0x100, 0x104, 0x108, …).
    
- نوع `double` اندازه‌اش ۸ بایت است، پس باید در آدرس‌هایی باشد که **بر ۸ بخش‌پذیرند**.
    

اگر داده در آدرسی قرار بگیرد که به درستی تراز نشده (unaligned)، ممکن است:

- اجرای CPU **کندتر** شود، یا
    
- در برخی معماری‌ها (مثل ARM قدیمی) **باعث خطای سخت‌افزاری** شود!
    

---

## 🔹 مثال ساده از alignof و sizeof

```c
#include <stdio.h>
#include <stdalign.h>

int main(void) {
    printf("char: alignof=%zu, sizeof=%zu\n", alignof(char), sizeof(char));
    printf("int: alignof=%zu, sizeof=%zu\n", alignof(int), sizeof(int));
    printf("double: alignof=%zu, sizeof=%zu\n", alignof(double), sizeof(double));
}
```

📘 خروجی معمولی:

```
char: alignof=1, sizeof=1
int: alignof=4, sizeof=4
double: alignof=8, sizeof=8
```

یعنی:

- `char` می‌تواند در هر جایی از حافظه قرار گیرد (alignment=1)
    
- `int` باید در مضرب‌های ۴ باشد
    
- `double` باید در مضرب‌های ۸ باشد

## 🔹 چرا padding در structها وجود دارد؟

فرض کنید داریم:

```c
struct data {
    char c;   // 1 byte
    int i;    // 4 bytes
    double d; // 8 bytes
};
```

در ظاهر جمع اندازه‌ها می‌شود `1 + 4 + 8 = 13` بایت،  
ولی در واقع `sizeof(struct data)` معمولاً می‌شود **16 بایت**.

چرا؟  
چون کامپایلر بین متغیرها **فضای خالی (padding)** اضافه می‌کند تا تراز مناسب حفظ شود.

نمای حافظه مثلاً این‌طوری است:

|فیلد|اندازه (بایت)|آدرس شروع|توضیح|
|---|---|---|---|
|c|1|0|اولین بایت|
|padding|3|1–3|تا عدد 4 بخش‌پذیر شود|
|i|4|4|شروع در آدرس 4|
|d|8|8|شروع در آدرس 8|

جمع = 16 بایت ✅

---

## 🔹 چرا گاهی struct از جمع اندازه اعضایش بزرگ‌تر است؟

دلیلش این است که:  
اگر چند struct پشت‌سرهم در حافظه (مثلاً در آرایه‌ای از struct) قرار بگیرند،  
کامپایلر می‌خواهد **هر struct جدید هم در آدرس درست تراز شود**.

پس حتی اگر آخرین فیلد `char` باشد، باید فضای خالی بعد از آن (terminal padding) اضافه شود تا struct بعدی درست تراز شود.

## 🔹 چرا union هم padding دارد؟

در union، تمام اعضا در **یک محل حافظه مشترک** ذخیره می‌شوند،  
اما اندازه‌ی نهایی union باید بزرگ‌تر یا مساوی بزرگ‌ترین عضو باشد.

اگر تفاوت alignment اعضا زیاد باشد، union ممکن است **بزرگ‌تر از بزرگ‌ترین عضو** شود تا بتواند به درستی تراز شود.

مثلاً:

```c
union data {
    char c[9];   // 9 bytes
    double d;    // 8 bytes
};
```

جمع ساده‌ی اندازه‌ها ۹ است،  
ولی `sizeof(union data)` معمولاً **۱۶ بایت** می‌شود، چون `double` باید در آدرس مضرب ۸ باشد.

---

## 🔹 نکته‌ی کلیدی

در زبان C، لازم نیست معمولاً نگران alignment باشید، چون:

- کامپایلر به طور خودکار padding لازم را اضافه می‌کند.
    
- حافظه‌ای که از طریق `malloc()` یا `calloc()` می‌گیرید، **همیشه به درستی تراز شده است**.
    
- مشکل فقط زمانی پیش می‌آید که بخواهید **با cast کردن نادرست pointerها**، نوع داده را عوض کنید (مثلاً اشاره‌گر `char*` را به `double*` تبدیل کنید).
    

در این حالت ممکن است داده در آدرس نادرست قرار گیرد و برنامه crash کند.
