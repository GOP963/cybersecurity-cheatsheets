## 💡 مفهوم کلی `malloc()`

`malloc` مخفف عبارت **memory allocate** است، یعنی  
> «اختصاص دادن حافظه به‌صورت پویا (در زمان اجرا)».

---

### 🧠 تعریف ساده:
در زبان C، حافظه برنامه به چند بخش تقسیم می‌شود:

| بخش حافظه | توضیح                                                                                                            |
| --------- | ---------------------------------------------------------------------------------------------------------------- |
| **Stack** | برای متغیرهای معمولی (مثل `int a = 5;`) — به‌صورت خودکار مدیریت می‌شود.                                          |
| **Heap**  | ناحیه‌ای از حافظه که خودت باید به‌صورت دستی مدیریت کنی (یعنی با `malloc()`، `calloc()`، `realloc()` و `free()`). |

🔹 `malloc()` از Heap حافظه می‌گیرد.  
🔹 باید بعداً آن را با `free()` آزاد کنی.

---

## 🧩 فرم کلی استفاده:

```c
pointer = (type*) malloc(size_in_bytes);
```

### پارامترها:
- `size_in_bytes`: تعداد بایت‌هایی که می‌خواهی رزرو کنی.  
- خروجی تابع: آدرس شروع حافظه‌ای که رزرو شده.

---

## 🎯 مثال ۱: تخصیص حافظه برای یک عدد
```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int *ptr;                      // تعریف پوینتر
    ptr = (int*) malloc(sizeof(int));  // رزرو حافظه به اندازه‌ی یک عدد صحیح

    if (ptr == NULL) {             // بررسی اینکه حافظه واقعاً تخصیص داده شده یا نه
        printf("Memory not allocated!\n");
        return 1;
    }

    *ptr = 42;                     // ذخیره مقدار در آدرس رزروشده
    printf("Value: %d\n", *ptr);   // چاپ مقدار

    free(ptr);                     // آزاد کردن حافظه
    return 0;
}
```

📘 خروجی:
```
Value: 42
```

---

## 🎯 مثال ۲: تخصیص حافظه برای چند عدد (آرایه)
```c
int *arr = (int*) malloc(5 * sizeof(int));
```
این یعنی:
> ۵ عدد از نوع `int` در Heap ذخیره شود.

حالا می‌تونی ازش مثل آرایه استفاده کنی:
```c
for (int i = 0; i < 5; i++)
    arr[i] = i + 1;
```

و در آخر:
```c
free(arr);
```

---

## ⚙️ نکته‌های خیلی مهم:

| نکته | توضیح |
|------|--------|
| `malloc()` فقط حافظه رزرو می‌کنه، مقداردهی نمی‌کنه (ممکنه داده‌ی قبلی حافظه داخلش باشه). |
| همیشه بررسی کن `malloc()` مقدار `NULL` برنگردونه. |
| بعد از استفاده، همیشه `free()` یادت نره، چون باعث **memory leak** می‌شه. |

---

نکته اگر بخواهیم یه مقداری حافظه به malloc اختصصاص بدیم در حافظه heap میتونیم از این راه استفاده کنیم 

```
int *data = NULL;
data = malloc(20); ----> 20 byte
```

به  جای اینکار میتونیم اینطوری اختصاص بدیم 
```
data = malloc(sizeof(int) * 5); ----> 20 byte 
```


---

خطرات امنیتی malloc() در C
--------------------------
1️⃣ عدم بررسی مقدار بازگشتی → NULL Pointer Dereference
2️⃣ آزاد نکردن حافظه → Memory Leak
3️⃣ نوشتن خارج از محدوده → Buffer Overflow
4️⃣ استفاده بعد از free → Use-After-Free
5️⃣ آزاد کردن دوباره → Double Free
6️⃣ تخریب ساختار Heap → Heap Corruption

✅ راهکارها:
- همیشه مقدار برگشتی malloc را بررسی کن.
- پس از پایان کار، حتماً free() را صدا بزن.
- پس از free، مقدار pointer را NULL کن.
- اندازه‌ی دقیق حافظه و آرایه‌ها را رعایت کن.
- از ابزارهای امنیتی مثل Valgrind یا ASan استفاده کن.



---

## ⚠️ از دید امنیتی، `malloc()` چه خطرهایی داره؟

### 1️⃣ **عدم بررسی مقدار بازگشتی (NULL Pointer Dereference)**

اگر `malloc()` نتونه حافظه رزرو کنه (مثلاً سیستم رم کافی نداشته باشه)، مقدارش `NULL` میشه.

اگر برنامه بدون بررسی از اون استفاده کنه:

```c
int *ptr = (int*) malloc(sizeof(int));
*ptr = 5;  // 💥 اگر malloc شکست خورده باشه → Crash (Segmentation Fault)
```

📛 **نتیجه:**  
Crash یا حتی امکان **اجرای کد غیرمجاز (exploit)** در شرایط خاص.

✅ **راه حل:**

```c
if (ptr == NULL) {
    fprintf(stderr, "Memory allocation failed!\n");
    exit(1);
}
```

---

### 2️⃣ **Memory Leak (نشت حافظه)**

اگر بعد از `malloc()` حافظه رو با `free()` آزاد نکنی، اون فضا توی RAM باقی می‌مونه و هرگز بازگردونده نمی‌شه.

📛 **نتیجه:**

- مصرف رم به‌مرور زیاد می‌شه
    
- برنامه کند یا حتی از کار می‌افته
    
- در سرویس‌های دائمی (مثل سرور) باعث **Denial of Service (DoS)** می‌تونه بشه
    

✅ **راه حل:**  
همیشه بعد از اتمام کار با حافظه، `free(ptr);` رو فراخوانی کن.

---

### 3️⃣ **Buffer Overflow**

اگر با حافظه‌ای که `malloc()` رزرو کرده اشتباه برخورد کنی (بیش از حد بنویسی)، داده‌های دیگر حافظه را هم تخریب می‌کنی.

```c
int *arr = malloc(5 * sizeof(int));
for (int i = 0; i <= 5; i++) // 👈 اشتباه: باید i < 5 باشد
    arr[i] = i;
```

📛 **نتیجه:**

- آسیب به داده‌های مجاور
    
- Crash
    
- یا حتی اجرای کد دلخواه مهاجم (Code Injection)
    

✅ **راه حل:**  
مرز آرایه‌ها و طول حافظه تخصیص‌یافته را همیشه کنترل کن.

---

### 4️⃣ **Use After Free**

اگر حافظه‌ای را آزاد (`free()`) کنی ولی بعد دوباره ازش استفاده کنی:

```c
int *ptr = malloc(sizeof(int));
free(ptr);
*ptr = 10; // 💥 استفاده از حافظه آزادشده
```

📛 **نتیجه:**  
ممکنه داده‌های حساس دوباره‌نویسی بشن، یا حتی مهاجم با تکنیک‌هایی مثل **heap spraying** اون فضا رو کنترل کنه.

✅ **راه حل:**  
بعد از `free()` همیشه پوینتر را `NULL` کن:

```c
free(ptr);
ptr = NULL;
```

---

### 5️⃣ **Double Free**

اگر یک حافظه دوبار آزاد بشه:

```c
int *ptr = malloc(10);
free(ptr);
free(ptr); // 💥 دوبار آزاد کردن
```

📛 **نتیجه:**  
ممکنه باعث crash یا exploit بشه (در سیستم‌های قدیمی‌تر خیلی خطرناک بود — heap corruption).

✅ **راه حل:**  
هر حافظه فقط **یک‌بار** آزاد بشه و بعدش `ptr = NULL` تنظیم بشه.

---

### 6️⃣ **Heap Corruption**

اگر خطاهای بالا تکرار بشن (مثل نوشتن خارج از محدوده یا دوبار free کردن)، ساختار درونی Heap سیستم خراب میشه.  
در این حالت، رفتار برنامه غیرقابل پیش‌بینی میشه و مهاجم می‌تونه ازش برای حملات **Heap Exploitation** استفاده کنه.

## 🧰 ابزارهای امنیتی برای کشف مشکلات `malloc`

ابزارهایی هستن که بهت کمک می‌کنن چنین خطاهایی رو در حین تست شناسایی کنی:

|ابزار|توضیح|
|---|---|
|**Valgrind**|پیدا کردن memory leak، double free و use-after-free|
|**AddressSanitizer (ASan)**|ابزار کامپایلر برای کشف corruption و overflow|
|**ElectricFence**|دیباگر سبک برای memory overflow|

## نکته : Heap توسط developer کنترول میشه اما Stack توسط سیستم عامل 

---

![[Pasted image 20251015035013.png]]

حافظه heap یک حافظه ی است که برنامه های در حال اجرا **درخواست و آزاد (allocate / deallocate)** می‌کند.
وقتی فرآیند به حافظه‌ی بیشتری نیاز دارد، heap به سمت بالا رشد می‌کند.

نمی‌توانیم یک بلوک وسط heap را حذف کنیم و همه‌ی داده‌های بالاتر را به پایین منتقل کنیم، چون این کار بسیار زمان‌بر است و همچنین نمی‌توانیم اشیایی را جابه‌جا کنیم که **آدرس** آن‌ها را قبلاً گرفته‌ایم — چون اگر جابه‌جا شوند، آدرسی که در اختیار داریم دیگر به داده‌ی درست اشاره نخواهد کرد.  
البته نگران نباش، سیستم اجرایی (runtime) زبان C خودش این مسائل را مدیریت می‌کند.

در بالاترین بخش، **stack** قرار دارد.  
stack 
برای **فراخوانی توابع (function calls)** استفاده می‌شود و جایی است که **متغیرهای محلی (local variables)** و **آرگومان‌های توابع** در آن زندگی می‌کنند.  
stack معمولاً **به سمت پایین رشد می‌کند**.

بین stack و heap معمولاً یک ناحیه‌ی ممنوعه وجود دارد که برنامه اجازه‌ی دسترسی به آن را ندارد.  
این ناحیه برای جلوگیری از آن است که stack و heap در هم تداخل پیدا کنند.
