# `union` چیست؟

`union`
نوع داده‌ای ترکیبی است که **چند عضو با انواع متفاوت** را تعریف می‌کند ولی **همه اعضا در یک فضای حافظه مشترک (overlap)** قرار می‌گیرند. یعنی در هر لحظه فقط _یکی_ از اعضا «فعال» فرض می‌شود و تمام اعضا از همان آدرس شروع می‌شوند.

---

# ویژگی‌های کلیدی

- اندازه‌ی `union` برابر است با **حداکثر اندازه‌ی یکی از اعضا** (با توجه به alignment).
    
- همه‌ی اعضا از همان آدرس حافظه شروع می‌شوند — بنابراین تغییر یک عضو می‌تواند بیت‌های دیگر اعضا را تحت‌تأثیر قرار دهد.
    
- در استفاده صحیح، `union` برای صرفه‌جویی حافظه یا پیاده‌سازی «نوع متغیر» (variant) کاربرد دارد.
    
- دسترسی همزمان به عضو‌ای که آخرین‌بار نوشته نشده ممکن است **UB** (undefined behavior) یا implementation-defined باشد — به‌خصوص وقتی از انواع دارای representation متفاوت استفاده می‌کنی.
    

---

# تعریف ساده و مثال

```c
#include <stdio.h>

union U {
    int i;
    float f;
    char s[4];
};

int main(void) {
    union U u;
    u.i = 0x41424344;       // write as int
    printf("i = %d\n", u.i);
    printf("s = %.4s\n", u.s); // read same bytes as chars
    u.f = 3.14f;            // now f is the active member
    printf("f = %f\n", u.f);
    return 0;
}
```

توضیح: بیت‌هایی که در `u` نوشته می‌شوند، بسته به اینکه چگونه آن‌ها را بخوانی (به‌عنوان `int` یا `char[]` یا `float`) معنی متفاوتی خواهند داشت.

# نمونه‌ی رایج: tagged union (امن و عملی)

برای نگه‌داشتن مقادیر با انواع مختلف به‌صورت ایمن بهتر است از یک `enum` برای مشخص کردن نوع فعال استفاده کنی:

```c
enum Type { INT, FLOAT, STR };

struct Variant {
    enum Type tag;
    union {
        int i;
        float f;
        char s[32];
    } value;
};

void print_variant(const struct Variant *v) {
    switch (v->tag) {
    case INT:   printf("int: %d\n", v->value.i); break;
    case FLOAT: printf("float: %f\n", v->value.f); break;
    case STR:   printf("str: %s\n", v->value.s); break;
    }
}
```

این الگو (tag + union) یک پیاده‌سازی امن‌تر از «نوع متغیر» است.

# موارد کاربرد (جزوه‌ای)

- **صرفه‌جویی حافظه** در embedded systems وقتی مقادیر مختلف هرگز هم‌زمان نیاز نیستند.
    
- **انتِرپریتیشن بایت‌ها**: دیدن یک بلوک بایت به‌عنوان انواع مختلف (ولی با احتیاط؛ ممکن است UB باشد).
    
- **پیاده‌سازی variant/union-type** همراه با یک `enum` برای تشخیص نوع فعال.
    
- **پارس کردن پروتکل‌ها/فایل‌ها** در شرایطی که header/بدنه می‌تواند چند فرم داشته باشد (همیشه validate کن!).
    

---

# هشدارها و نکات امنیتی/پرتکل‌های ایمن

- **نوع‌پانینگ (type punning)** از طریق union ممکن است رفتار implementation-dependent یا UB باشد؛ اگر هدف فقط تبدیل بایت‌هاست بهتر است از `memcpy` استفاده کنی تا از UB جلوگیری شود.
    
- وقتی union را به‌عنوان reinterpretation بیت‌ها استفاده می‌کنی، به مسأله‌ی **endianness** و **alignment** توجه کن.
    
- همیشه در طراحی API واضح کن **کدام عضو فعال است** (مثلاً با یک `tag`) تا خواننده/کد بعدی اشتباه نکند.
    
- اگر برنامه‌ات به portability و استانداردسازی اهمیت می‌دهد از تکنیک‌های امن (memcpy یا tagged union) استفاده کن.
    

مثال امن برای reinterpret با `memcpy`:

```c
int i = 0x41200000;
float f;
memcpy(&f, &i, sizeof(f)); // امن‌تر از خواندن مستقیم از union برای تبدیل بیت‌ها
```

---

# خلاصه‌ی چند خطی برای جزوه

- `union` = چند عضو، یک آدرس مشترک.
    
- اندازه = اندازه‌ی بزرگ‌ترین عضو.
    
- مناسب برای صرفه‌جویی حافظه و نوع‌های متغیر؛ اما باید همراه با `tag` برای ایمنی استفاده شود.
    
- برای type-punning بهتر از `memcpy` استفاده کن تا از UB جلوگیری بشه.
    
- همیشه به alignment و endianness توجه کن.
