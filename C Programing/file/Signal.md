## 🧠 اول: Signal دقیقاً چیه؟
سیگنال‌ها در لینوکس نوعی **پیام یا وقفه نرم‌افزاری (software interrupt)** هستن که سیستم‌عامل یا processها می‌تونن برای هم بفرستن.  
هر سیگنال برای اطلاع دادن از یه **رویداد خاص** استفاده میشه — مثل:

| سیگنال | معنی | مثال کاربرد |
|--------|--------|--------------|
| `SIGINT` | قطع کردن (Interrupt) | وقتی Ctrl + C می‌زنی |
| `SIGTERM` | پایان دادن معمولی | دستور `kill <PID>` |
| `SIGKILL` | پایان فوری (Kill) | `kill -9 <PID>` |
| `SIGSEGV` | خطای حافظه (Segmentation fault) | دسترسی به آدرس نامعتبر |

---

## ⚙️ حالا مفهوم **manageable** و **unmanageable**

وقتی یه سیگنال برای یه process ارسال میشه، اون process ممکنه:

1. خودش **تصمیم بگیره با اون سیگنال چطور برخورد کنه** ✅  
2. یا **اجازه‌ی هیچ دخالتی نداشته باشه و باید فوراً تموم بشه** ❌  

بر این اساس سیگنال‌ها به دو گروه تقسیم می‌شن:

---

### 🟢 1. **Manageable (قابل مدیریت)**

این‌ها سیگنال‌هایی هستن که process می‌تونه اون‌ها رو **دریافت و مدیریت** کنه.

یعنی process می‌تونه:

- اون سیگنال رو **نادیده بگیره (ignore)**،
- براش **handler بنویسه** (یعنی یه تابع خاص برای زمانی که اون سیگنال رسید)،
- یا اجازه بده رفتار پیش‌فرض سیستم‌عامل اجرا بشه.

📘 مثال:
```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

void handle_sigint(int sig) {
    printf("Signal %d دریافت شد، اما برنامه هنوز ادامه دارد!\n", sig);
}

int main() {
    signal(SIGINT, handle_sigint); // تعریف handler برای Ctrl+C
    while(1) {
        printf("در حال اجرا...\n");
        sleep(1);
    }
}
```

حالا اگه توی ترمینال `Ctrl + C` بزنی،  
به جای اینکه برنامه بسته بشه، پیام چاپ میشه چون ما **سیگنال رو مدیریت کردیم**.

---

### 🔴 2. **Unmanageable (غیرقابل مدیریت)**

این‌ها سیگنال‌هایی هستن که **سیستم‌عامل اجازه نمی‌ده process اون‌ها رو کنترل یا نادیده بگیره**.  
یعنی وقتی این سیگنال برسه، **حتماً باید اقدام خاصی انجام بشه (معمولاً terminate شدن process)**.

📘 معروف‌ترین نمونه‌ها:

| سیگنال | توضیح |
|---------|--------|
| `SIGKILL` | هیچ processی نمی‌تونه اون رو بگیره یا نادیده بگیره. فوراً process رو می‌کشه. |
| `SIGSTOP` | هیچ processی نمی‌تونه اون رو نادیده بگیره یا مدیریت کنه. process فوراً متوقف (suspend) میشه. |

---

### ⚖️ تفاوت خلاصه:

| ویژگی | Manageable | Unmanageable |
|--------|-------------|---------------|
| قابل نادیده گرفتن؟ | بله | خیر |
| میشه handler نوشت؟ | بله | خیر |
| توسط کاربر کنترل میشه؟ | بله | خیر |
| مثال | SIGINT، SIGTERM | SIGKILL، SIGSTOP |

---

### 🧩 چرا unmanageable داریم؟

سیستم‌عامل باید **قدرت نهایی کنترل فرایندها** رو داشته باشه.  
فرض کن processی بنویسی که همه سیگنال‌ها رو نادیده بگیره، حتی سیگنال‌هایی که باید باعث توقفش بشن — در این حالت هیچ‌وقت نتونی اونو متوقف کنی 😅  
برای همین، لینوکس چند سیگنال رو "unmanageable" تعریف کرده تا **کنترل نهایی همیشه دست kernel** بمونه.

---

```
#include <stdio.h>
#include <stdlib.h>

int main(){
	int age;
	while(1){
		printf("Enter Your Age: \n");
		if(scanf("%d",&age)== 0){
			break;
		} else{
			scanf("%*[^\n]");
		}
	}
}
```
