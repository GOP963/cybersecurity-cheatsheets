





# 🧩 Symbols در WinDbg چیست؟

**Symbol** 
‌ها اطلاعاتی هستند که:

- نام توابع
    
- نام متغیرها
    
- ساختارهای داخلی
    
- Offsetها
    

را به WinDbg می‌دهند.

بدون Symbol:

- فقط آدرس می‌بینی ❌
    
- Call Stack بی‌معنی می‌شود
    
- Debugging تقریباً غیرممکن است
    

---

## 🧠 Symbolها از کجا می‌آیند؟

- فایل‌های **`.pdb`**
    
- Microsoft Symbol Server
    
- Symbol Server داخلی سازمان‌ها
    

---

# ⚙️ تنظیم Symbol Path در WinDbg

---

## 1️⃣ روش سریع و استاندارد (توصیه‌شده)

```text
.symfix
.reload
```

### توضیح:

- `.symfix` → Symbol Path پیش‌فرض مایکروسافت را تنظیم می‌کند
    
- `.reload` → Symbolها را بارگذاری می‌کند
    

📌 مسیر پیش‌فرض:

```
srv*C:\Symbols*https://msdl.microsoft.com/download/symbols
```

---

## 2️⃣ تنظیم دستی Symbol Path

```text
.sympath srv*C:\MySymbols*https://msdl.microsoft.com/download/symbols
```

📌 اجزا:

- `srv*` → استفاده از Symbol Server
    
- `C:\MySymbols` → مسیر Cache محلی
    
- URL → Symbol Server مایکروسافت
    

---

## 3️⃣ اضافه کردن مسیر (بدون حذف قبلی)

```text
.sympath+ C:\CustomSymbols
```

📌 برای زمانی که:

- PDB برنامه خودت را داری
    
- Symbol خصوصی داری
    

---

## 4️⃣ مشاهده Symbol Path فعلی

```text
.sympath
```

---

## 5️⃣ بارگذاری مجدد Symbolها

```text
.reload
```

یا برای همه ماژول‌ها:

```text
.reload /f
```

📌 `/f` = Force Reload

---

## 🔍 بررسی وضعیت Symbolها

### دیدن ماژول‌ها و وضعیت Symbol

```text
lm
```

خروجی:

- `PDB symbols loaded`
    
- یا `Export symbols only`
    
- یا `No symbols`
    

---

## 🔎 مثال خیلی مهم

```text
lm m nt
```

بررسی Symbol برای Kernel (`ntoskrnl.exe`)

## ⚠️ مشکلات رایج Symbol

### ❌ Symbol لود نمی‌شود

دلایل:

- اینترنت قطع
    
- Firewall
    
- نسخه PDB با Binary نمی‌خورد
    
- مسیر Cache مشکل دارد
    

---

### 🔧 حل مشکل

```text
!sym noisy
.reload
!sym quiet
```

📌 خروجی دقیق می‌دهد که Symbol از کجا Fail شده.

# 🧩 Symbols در WinDbg: مفهوم اصلی

**Symbolها (نشانه‌ها)** اطلاعات متنی و ساختاری هستند که دیباگر (مانند WinDbg) برای ترجمه **آدرس‌های خام حافظه** به **نام‌های خوانا** استفاده می‌کند.

| بدون Symbol | با Symbol |
| :--- | :--- |
| آدرس‌های هگز (مثلاً `00401000`) | نام توابع و متغیرها (مثلاً `MyFunction`, `g_counter`) |
| Call Stack نامفهوم | نمایش دقیق زنجیره فراخوانی توابع |

**منبع اصلی:** فایل‌های **`.pdb`** (Program Database) که حاوی نگاشت آدرس‌ها به نام‌ها هستند.

---

# ⚙️ تنظیم مسیر Symbol در WinDbg

تنظیم مسیر (Symbol Path) به WinDbg می‌گوید که فایل‌های `.pdb` مورد نیاز را از کجا پیدا کند.

| دستور | کاربرد | توضیح فشرده |
| :--- | :--- | :--- |
| **`.symfix`** | تنظیم اولیه | مسیر پیش‌فرض مایکروسافت (Local Cache + Server) را تنظیم می‌کند. |
| **`.reload`** | بارگذاری | پس از تنظیم مسیر، دستور می‌دهد Symbolها را مجدداً بارگذاری کند. |
| **`.sympath srv*C:\Cache*http://server/symbols`** | تنظیم دستی | تنظیم مسیر سفارشی با استفاده از سرور و کش محلی. |
| **`.sympath+ C:\MyPDBs`** | اضافه کردن | یک مسیر محلی دیگر (مثلاً PDB برنامه خودتان) را به مسیر فعلی اضافه می‌کند. |
| **`.sympath`** | مشاهده | مسیر Symbol فعلی تنظیم شده را نمایش می‌دهد. |

---

## 🔍 بررسی وضعیت

دستور `lm` (List Modules) حیاتی است:

```text
lm
```

این دستور نشان می‌دهد که برای هر ماژول (EXE/DLL) چه نوع Symbolهایی بارگذاری شده‌اند (مثلاً `Symbols loaded`, `Export symbols only` یا `No symbols`). **تطابق دقیق نسخه (Build Number) بین فایل اجرایی و PDB ضروری است.**

---

# 💡 چرا برنامه متوقف می‌شود (مثال Notepad)؟

هنگامی که یک برنامه را در WinDbg بارگذاری می‌کنید (مثلاً `notepad.exe`)، برنامه در **نقطه ورود اولیه (Entry Point)** متوقف می‌شود، نه اینکه اجرا شده باشد.

1.  **بارگذاری:** WinDbg برنامه را لود می‌کند و اغلب در یک نقطه اولیه (مثل تابع `mainCRTStartup` یا Entry Point) متوقف می‌شود.
2.  **دستور `g` (Go):** این دستور به دیباگر می‌گوید: "اجرا را ادامه بده تا به نقطه توقف بعدی برسی یا برنامه تمام شود."
3.  **اجرای کامل:** با زدن `g`، برنامه شروع به اجرای کد می‌کند، توابع را فراخوانی می‌کند، و شما می‌توانید از طریق دستورات دیگر (مانند `p` برای قدم زدن مرحله‌ای) آن را دنبال کنید.

---

# 📋 دستورات پرکاربرد WinDbg (فراخوانی شده بر اساس نیاز)

در اینجا چند دستور بسیار پرکاربرد دیگر در کنار مواردی که ذکر کردید آورده شده است:

| دستور | کاربرد | توضیح |
| :--- | :--- | :--- |
| **`g`** (Go) | اجرای برنامه | ادامه اجرای برنامه تا نقطه توقف بعدی یا پایان. |
| **`p`** (Step Over) | اجرای مرحله‌ای (Pass) | اجرای دستور فعلی و رفتن به دستور بعدی در **همان سطح** (از توابع فراخوانی شده عبور می‌کند). |
| **`t`** (Trace) | اجرای مرحله‌ای (Trace) | اجرای دستور فعلی و رفتن به دستور بعدی، **وارد توابع فراخوانی شده** می‌شود. |
| **`k`** (Kill/Crash) | نمایش Call Stack | نمایش زنجیره فراخوانی توابع (مهمترین دستور برای فهمیدن اینکه "چگونه به اینجا رسیدم؟"). |
| **`q`** (Quit) | خروج از دیباگر | بستن پنجره دیباگ. |
| **`dd <address>`** | نمایش داده | نمایش 32 بیتی (Dword) از حافظه در آدرس مشخص. |
| **`bp <address/name>`** | تنظیم Breakpoint | قرار دادن نقطه توقف (مثلاً `bp notepad!WinMain`). |
| **`bl`** | لیست Breakpointها | نمایش نقاط توقف فعال. |
| **`bc <ID>`** | پاک کردن Breakpoint | غیرفعال کردن یک نقطه توقف با استفاده از شناسه آن (از `bl` می‌گیرید). |
| **`dv`** | نمایش متغیرها | نمایش متغیرهای محلی (Local Variables) در Scope فعلی. |
