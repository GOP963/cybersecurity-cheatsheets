



# Protected Processes

## ترجمه

در مدل امنیتی ویندوز، هر پروسسی که با توکنی اجرا شود که **privilege دیباگ** داشته باشد  
(مثلاً اکانت Administrator)، می‌تواند:

- هر سطح دسترسی که بخواهد به پروسس‌های دیگر درخواست دهد
    
- حافظه آن‌ها را بخواند یا بنویسد
    
- کد تزریق کند
    
- تردها را متوقف یا اجرا کند
    
- اطلاعات داخلی آن‌ها را بخواند
    

ابزارهایی مثل:

- Process Explorer
    
- Task Manager
    

به همین دسترسی‌ها نیاز دارند.

---

## مشکل DRM

این رفتار منطقی است چون:

- ادمین باید کنترل کامل سیستم را داشته باشد
    

اما این موضوع با نیازهای **DRM (حفاظت از محتوای دیجیتال)** در تضاد است.

مثلاً برای پخش:

- Blu-ray
    
- محتوای ویدیویی با کیفیت بالا
    

باید جلوی دسترسی به حافظه پروسس‌های پخش‌کننده گرفته شود.

---

## معرفی Protected Process

برای حل این مشکل، در:

- Windows Vista
    
- Windows Server 2008
    

مفهوم **Protected Process** معرفی شد.

این پروسس‌ها:

- شبیه پروسس‌های معمولی هستند
    
- اما محدودیت شدید روی دسترسی سایر پروسس‌ها دارند
    
- حتی اگر آن پروسس Administrator باشد
    

---

## چه پروسسی می‌تواند Protected شود؟

هر برنامه‌ای می‌تواند درخواست Protected بودن بدهد  
اما سیستم فقط در صورتی اجازه می‌دهد که:

- فایل اجرایی آن
    
- با **Windows Media Certificate مخصوص**
    
- به صورت دیجیتال امضا شده باشد
    

---

## کاربرد واقعی Protected Process

ویندوز از Protected Process در مسیر زیر استفاده می‌کند:

### Protected Media Path (PMP)

برای حفاظت از محتوای ارزشمند مثل:

- DVD
    
- Blu-ray
    
- محتوای DRM
    

برنامه‌های پخش‌کننده می‌توانند از:

- Media Foundation API
    

برای اجرای پروسس محافظت‌شده استفاده کنند.

---

## مثال پروسس‌های Protected

### 1. Audiodg.exe

پروسس گراف صدای ویندوز  
چون محتوای صوتی DRM از آن عبور می‌کند.

### 2. Mfpmp.exe

Media Foundation Protected Pipeline  
برای پردازش محتوای محافظت‌شده

### 3. Werfaultsecure.exe

پروسس گزارش خطای ویندوز  
باید به Protected Processها دسترسی داشته باشد.

### 4. System Process

پروسس System هم Protected است چون:

- اطلاعات رمزنگاری داخل حافظه آن است
    
- جدول handleهای کرنل در آن نگهداری می‌شود
    
- درایورها ممکن است حافظه داخل آن map کنند
    

---

## پیاده‌سازی در سطح کرنل

در کرنل، پشتیبانی از Protected Process دو بخش دارد:

### 1. ساخت پروسس در کرنل

بیشتر مراحل ایجاد پروسس در kernel-mode انجام می‌شود  
تا جلوی injection گرفته شود.

### 2. فلگ‌های خاص در ساختار EPROCESS

در ساختار کرنلی EPROCESS:

- بیت‌های خاصی تنظیم می‌شود
    
- که رفتار سیستم امنیتی را تغییر می‌دهد
    
- و دسترسی‌ها را محدود می‌کند
    

---

## دسترسی‌های مجاز به Protected Process

فقط این دسترسی‌ها مجاز هستند:

- PROCESS_QUERY_LIMITED_INFORMATION
    
- PROCESS_SET_LIMITED_INFORMATION
    
- PROCESS_TERMINATE
    
- PROCESS_SUSPEND_RESUME
    

یعنی:

❌ خواندن حافظه  
❌ تزریق کد  
❌ گرفتن لیست DLLها

مجاز نیست.

---

## رفتار ابزارها

### Process Explorer

چون از APIهای user-mode استفاده می‌کند:

- نمی‌تواند اطلاعات کامل Protected Process را بخواند
    

### WinDbg در kernel mode

چون از زیرساخت کرنل استفاده می‌کند:

- می‌تواند اطلاعات کامل را نمایش دهد
    

---

## نکته مهم درباره Debug Mode

اگر سیستم در حالت:

```
bcdedit /debug on
```

بوت شود:

- پخش محتوای HD کار نمی‌کند
    
- چون این حالت امنیت Protected Process را تضعیف می‌کند
    

---

## آیا ادمین می‌تواند Protected بودن را دور بزند؟

از نظر تئوری:

- ادمین می‌تواند درایور کرنلی لود کند
    
- و فلگ Protected را تغییر دهد
    

اما:

- این کار خلاف مدل PMP است
    
- به عنوان رفتار مخرب شناخته می‌شود
    
- روی سیستم‌های ۶۴ بیتی معمولاً بلاک می‌شود
    

به دلیل:

- Code Signing Policy
    
- PatchGuard
    
- Peauth.sys
    

---

# Protected Process Light (PPL)

## معرفی

از:

- Windows 8.1
    
- Windows Server 2012 R2
    

مدل جدیدی معرفی شد:

### PPL = Protected Process Light

---

## تفاوت با Protected Process

PPL هم:

- جلوی code injection را می‌گیرد
    
- جلوی دسترسی به DLLها را می‌گیرد
    

اما یک تفاوت مهم دارد:

### سطح اعتماد (Signer Level)

پروسس‌ها بر اساس:

- نوع امضای دیجیتال
    
- سطح اعتماد signer
    

در سطوح مختلف قرار می‌گیرند.

---

## قانون دسترسی در PPL

قاعده:

- سطح بالاتر → دسترسی به پایین‌تر
    
- سطح پایین‌تر → دسترسی به بالاتر ندارد
    

---

## مثال دسترسی‌ها

به طور معمول فقط:

- QUERY/SET LIMITED
    
- SUSPEND/RESUME
    

مجاز است.

در بعضی سطوح:

- حتی TERMINATE هم ممنوع است
    

---

## جلوگیری از سوءاستفاده بدافزار

سوال مهم:

چرا بدافزار خودش را PPL نمی‌کند؟

پاسخ:

مایکروسافت از سیستم Code Integrity استفاده می‌کند  
و فقط گواهی‌هایی با EKU خاص اجازه PPL می‌گیرند.

دو EKU مهم:

```
1.3.6.1.4.1.311.10.3.22
1.3.6.1.4.1.311.10.3.20
```

---

## کنترل DLLهای لود شده

هر پروسس PPL:

- یک Signature Level دارد
    
- در EPROCESS ذخیره می‌شود
    

و فقط می‌تواند DLLهایی لود کند که:

- سطح امضای مجاز داشته باشند
    

مثال:

پروسس با signer = WinTcb  
فقط DLLهای:

- Windows signed
    
- یا بالاتر
    

را لود می‌کند.

---

## مثال پروسس‌های PPL در ویندوز

در Windows 10:

با سطح WinTcb-Lite اجرا می‌شوند:

- smss.exe
    
- csrss.exe
    
- services.exe
    
- wininit.exe
    

### lsass.exe

می‌تواند:

- به صورت PPL اجرا شود
    
- اگر در رجیستری یا policy فعال شود
    

---

## Minimum TCB List

برخی پروسس‌های سیستمی:

- همیشه باید با سطح خاصی اجرا شوند
    
- حتی اگر کاربر سطح دیگری تعیین کند
    

این لیست:

- Minimum TCB list  
    نام دارد.
    

---

# آزمایش در Process Explorer

اگر ستون Protection را فعال کنی:

- نوع Protected یا PPL را می‌بینی
    

اما:

در پایین صفحه، لیست DLLها خالی است  
چون دسترسی لازم وجود ندارد.

---

# پشتیبانی از PPL برای آنتی‌ویروس‌ها

یک آنتی‌ویروس معمولی شامل:

### 1. درایور کرنل

برای:

- مانیتور فایل‌ها
    
- مانیتور شبکه
    
- بلاک کردن عملیات مخرب
    

### 2. سرویس user-mode

برای:

- مدیریت سیاست‌ها
    
- دریافت هشدارها
    

### 3. رابط گرافیکی

برای تعامل با کاربر

---

## مشکل امنیتی

بدافزار می‌تواند:

- کد داخل سرویس آنتی‌ویروس تزریق کند
    
- آن را غیرفعال کند
    

---

## راه‌حل: اجرای آنتی‌ویروس به صورت PPL

اگر سرویس آنتی‌ویروس PPL باشد:

- injection ممکن نیست
    
- terminate هم ممکن نیست
    
- امنیت بالاتر می‌رود
    

---

## شرط اجرای آنتی‌ویروس به صورت PPL

باید:

- درایور ELAM داشته باشد
    
- با گواهی خاص مایکروسافت امضا شده باشد
    

اگر شرایط برقرار باشد:

پروسس می‌تواند با سطح:

```
PS_PROTECTED_ANTIMALWARE_LIGHT (0x31)
```

اجرا شود.

---

## مثال واقعی

Windows Defender:

- MsMpEng.exe
    
- NisSvc.exe
    

به صورت PPL اجرا می‌شوند.

---

# خلاصه خیلی کوتاه

## Protected Process

- برای DRM
    
- دسترسی بسیار محدود
    
- فقط فایل‌های امضاشده خاص
    

## PPL

- نسخه توسعه‌یافته
    
- دارای سطح اعتماد
    
- استفاده در:
    
    - lsass
        
    - defender
        
    - سرویس‌های مهم
