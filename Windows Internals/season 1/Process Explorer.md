## نکته : از **Windows 10 (Build 1703 به بعد)**، اگر میزان **RAM سیستم ۳٫۵ گیگابایت یا بیشتر** باشد، ویندوز تلاش می‌کند **هر Windows Service را در یک svchost.exe مجزا** اجرا کند، حتی اگر آن سرویس‌ها همگی تحت یک **Service Account** مثل  
**LocalService** یا **NetworkService** باشند.

اما اگر مقدار RAM **کمتر از ۳٫۵ گیگابایت** باشد، برای صرفه‌جویی در حافظه، ویندوز چندین سرویس را که در یک **Service Group** قرار دارند، داخل **یک svchost.exe مشترک** اجرا می‌کند.



خلاصه کلی :

# svchost.exe چیه؟

**svchost.exe = Service Host**

یعنی:

> یک **Process میزبان** برای اجرای **Windows Serviceها**  
> که خودشون به‌صورت **DLL** پیاده‌سازی شده‌اند، نه EXE مستقل.

📌 خیلی از سرویس‌های ویندوز:

- فایل اجرایی جدا ندارن
    
- داخل DLL نوشته شدن
    
- برای اجرا شدن، باید داخل یه Process لود بشن  
    👉 این Process میشه

## نکته :

من الان پروسه calculator رو اجرا میکنم و در process explorer برسیش میکنم 


![[Pasted image 20251218132745.png]]

همونطور که میبینید پروسه یی رو که از طریق run اومدم و اجراش کردم اما الان که دارم در process explorer میبینم نوشته parent پروسس svchost است چرا ؟
برنامه calculator بر اساس com نوشته شده و  **Parent Process همیشه کسی نیست که ظاهراً برنامه را اجرا کرده**

در ویندوز، مخصوصاً برای برنامه‌های **Modern / UWP / COM-based**،  
فرآیند اجرا می‌تونه **به سرویس‌های سیستمی delegate بشه**.

و این دقیقاً کاریه که **DCOM / COM** انجام می‌ده.
## DcomLaunch دقیقاً چیه؟

### 🔹 DcomLaunch = DCOM Server Process Launcher

- یک **سرویس حیاتی ویندوز**
    
- داخل این svchost اجرا می‌شود


### این سرویس مسئول:

- اجرای **COM Serverها**
    
- اجرای **DCOM Objectها**
    
- راه‌اندازی:
    
    - Shell components
        
    - UWP apps
        
    - Modern Windows Apps (مثل Calculator)
        
    - بعضی از GUI Infrastructureها
        

📌 اگر DcomLaunch بالا نیاد:

- ویندوز عملاً Boot نمی‌شود ❌
