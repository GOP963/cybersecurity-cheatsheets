# 1️⃣ Four-Level Paging چیه؟

**Four-Level Paging** 
یعنی معماری‌ای که CPU (در x64) برای ترجمه‌ی:

> **Virtual Address → Physical Address**

از **۴ جدول تو در تو** استفاده می‌کنه.

در سیستم‌های **۶۴ بیتی** ویندوز (x86-64):

```
Virtual Address
   ↓
PML4
   ↓
PDPT
   ↓
PD
   ↓
PT
   ↓
Physical Page (RAM)
```

---

## ساختار آدرس مجازی (x64)

یک Virtual Address 64 بیتی به این شکل تفسیر می‌شه:

```
| 9 | 9 | 9 | 9 | 12 |
 PML4 PDPT  PD  PT Offset
```

- 12 بیت آخر → Offset داخل صفحه (Page = 4KB)
- هر 9 بیت → اندیس یکی از جدول‌ها

📌 به همین دلیل بهش می‌گن **Four-Level Paging**

---

# 2️⃣ CR3 چیه؟

**CR3** یک **Register کنترلی CPU** هست که:

> آدرس فیزیکی **ریشه‌ی Page Table** (یعنی PML4) رو نگه می‌داره

### خیلی ساده:
- CR3 = «از کجا باید Page Table این Process رو بخونم؟»

---

## CR3 و Process

🔹 هر **Process**:
- یک **Address Space جدا**
- و در نتیجه یک **CR3 متفاوت**

وقتی CPU بین Processها **Context Switch** می‌کنه:
```text
CR3 عوض می‌شه
```

📌 یعنی:
> با عوض شدن CR3، کل Virtual Memory عوض می‌شه

---

# 3️⃣ ارتباط CR3 با Virtual Memory

### فرآیند ترجمه به‌صورت ساده:

1. CPU
2. یک Virtual Address می‌گیره
3. می‌ره سراغ CR3
4. از اونجا PML4 رو پیدا می‌کنه
5. جدول‌ها رو یکی‌یکی دنبال می‌کنه
6. به Physical Address می‌رسه

📌 Process:
- فقط Virtual Address می‌ده
- هیچ خبری از CR3 یا Physical Memory نداره

---

# 4️⃣ چرا این موضوع خیلی مهمه؟ (Security / EDR)

### 🔴 از دید Kernel / EDR:
- دسترسی به CR3 = دید کامل به حافظه‌ی Process
- می‌تونی:
  - Memory scan کنی
  - Hidden pages رو ببینی
  - Inject شده‌ها رو پیدا کنی

### 🔵 از دید Attacker:
- بازی با Page Table = مخفی‌سازی
- Shadow memory
- Unlinked pages

(که البته اینا خیلی advanced ـه)

---

# 5️⃣ Page Fault کجای این داستانه؟

اگر:
- صفحه در RAM نباشه
- یا Permission درست نباشه

CPU:
```text
Page Fault → Kernel (Memory Manager)
```

Memory Manager:
- Page رو از Disk بیاره
- یا Access رو deny کنه

---

# 6️⃣ خلاصه‌ی خیلی تمیز (برای جزوه)

> **Four-Level Paging مکانیزم ترجمه‌ی آدرس مجازی به فیزیکی در سیستم‌های ۶۴ بیتی است که از چهار جدول صفحه استفاده می‌کند. رجیستر CR3 آدرس فیزیکی ریشه‌ی این جداول (PML4) را نگه می‌دارد و با تغییر CR3، فضای آدرس مجازی پردازش تغییر می‌کند.**

# قبلش یک جمله‌ی خیلی مهم

> اینا **چهار نوع جدول (Table)** هستن، نه چهار تا رجیستر، نه چهار تا ساختار جادویی.  
> هر کدوم فقط می‌گن «مرحله‌ی بعدی کجاست».

---

# 1️⃣ PML4 – Page Map Level 4

### چی هست؟

**PML4** بالاترین سطح Page Table در x64 ـه.

📌 وظیفه‌اش:

> می‌گه **کدوم PDPT باید استفاده بشه**

---

### چند تا Entry داره؟

- 512 تا Entry
    
- هر Entry = 8 بایت
    

📌 چرا 512؟  
چون:

```
2^9 = 512
```

---

### PML4 Entry چی داره؟

هر Entry شامل:

- آدرس فیزیکی PDPT بعدی
    
- Flagها:
    
    - Present
        
    - Read/Write
        
    - User/Supervisor
        
    - NX
        

---

# 2️⃣ PDPT – Page Directory Pointer Table

### چی هست؟

**PDPT** مرحله‌ی دومه.

📌 وظیفه:

> اشاره می‌کنه به **Page Directory (PD)**

---

### نکته‌ی مهم:

PDPT می‌تونه:

- به PD اشاره کنه (حالت عادی)
    
- یا مستقیم به **1GB Page** اشاره کنه (Huge Page)
    

---

### PDPT Entry شامل:

- آدرس PD
    
- Flagهای دسترسی
    

---

# 3️⃣ PD – Page Directory

### چی هست؟

مرحله‌ی سوم ترجمه.

📌 وظیفه:

> مشخص می‌کنه **کدوم Page Table (PT)** استفاده بشه

---

### قابلیت خاص:

PD Entry می‌تونه:

- به PT اشاره کنه (4KB pages)
    
- یا مستقیم به **2MB Page** اشاره کنه (Large Page)
    

---

# 4️⃣ PT – Page Table

### چی هست؟

آخرین مرحله.

📌 وظیفه:

> نگاشت مستقیم **Virtual Page → Physical Page**

---

### PT Entry چی داره؟

- آدرس فیزیکی صفحه‌ی 4KB در RAM
    
- Flagها:
    
    - Read/Write
        
    - User/Supervisor
        
    - NX
        

---

# 🔍 حالا کل مسیر رو با مثال ببین

فرض کن CPU می‌خواد به این آدرس دسترسی پیدا کنه:

```
0x7FF6A1234567
```

### CPU چی کار می‌کنه؟

1. 9 بیت اول → اندیس PML4
    
2. از CR3 → آدرس PML4
    
3. Entry رو می‌خونه → PDPT
    
4. 9 بیت بعد → PDPT entry → PD
    
5. 9 بیت بعد → PD entry → PT
    
6. 9 بیت بعد → PT entry → Physical Page
    
7. 12 بیت آخر → Offset داخل صفحه

# جمع‌بندی خیلی تمیز

> **PML4، PDPT، PD و PT جداول سلسله‌مراتبی هستند که CPU در سیستم‌های ۶۴ بیتی برای ترجمه‌ی آدرس‌های مجازی به آدرس‌های فیزیکی از آن‌ها استفاده می‌کند. هر جدول فقط مرحله‌ی بعدی را مشخص می‌کند و آخرین جدول (PT) به صفحه‌ی واقعی حافظه اشاره می‌کند.**
