# System Idle Process 
### فرآیند بیکاری سیستم (System Idle Process - PID 0)

#### ۱. این فرآیند دقیقاً چیست؟
برخلاف نامش، این یک "Process" واقعی نیست. یعنی هیچ فایل اجرایی (مثل `idle.exe`) روی هارد دیسک وجود ندارد که این فرآیند از روی آن ساخته شده باشد.
*   **ماهیت:** این بخشی از خودِ کرنل ویندوز (`ntoskrnl.exe`) است.
*   **PID 0:** شناسه ۰ همیشه برای این فرآیند رزرو شده است.
*   **Parent:** این فرآیند پدر و مادر ندارد و اولین چیزی است که سیستم به صورت مجازی در نظر می‌گیرد.

#### ۲. چرا به آن نیاز داریم؟ (فلسفه وجودی)
پردازنده (CPU) طوری طراحی شده که **همیشه باید یک دستورالعمل را اجرا کند**. CPU نمی‌تواند "توقف" کند مگر اینکه کامپیوتر را خاموش کنید. تا زمانی که برق وصل است، چرخ‌دنده‌ها باید بچرخند.

حال سوال اینجاست: **وقتی کاربر هیچ کاری نمی‌کند و هیچ برنامه‌ای نیاز به پردازش ندارد، CPU چه کدی را باید اجرا کند؟**

اینجاست که **زمان‌بند (Scheduler)** ویندوز وارد عمل می‌شود. زمان‌بند همیشه به دنبال نخی (Thread) با بالاترین اولویت برای اجرا می‌گردد. اگر هیچ نخی در صف نباشد، زمان‌بند **"نخ‌های بیکاری" (Idle Threads)** را که درون System Idle Process قرار دارند، برای اجرا انتخاب می‌کند.

> **تعریف خلاصه:** System Idle Process **"پرکننده وقت خالی"** پردازنده است. نخی است که وقتی هیچ کار دیگری برای انجام دادن وجود ندارد، اجرا می‌شود.

#### ۳. داخل این فرآیند چه اتفاقی می‌افتد؟ (مدیریت انرژی)
در سیستم‌عامل‌های قدیمی، این فرآیند فقط یک حلقه بی‌نهایت ساده بود (مثل `while(1) {}`) که CPU را مشغول نگه می‌داشت. اما این کار باعث داغ شدن بیهوده پردازنده می‌شد.

در ویندوزهای مدرن، این فرآیند بسیار هوشمندتر است:
*   وقتی Idle Thread اجرا می‌شود، دستوراتی را به پردازنده می‌فرستد (معمولاً دستور اسمبلی **`HLT`** یا Halt).
*   این دستور به CPU می‌گوید که بخش‌های داخلی خود را خاموش کند و در حالت **کم‌مصرف (Low Power State)** قرار بگیرد تا زمانی که یک وقفه (Interrupt) جدید (مثل حرکت موس یا دریافت بسته شبکه) رخ دهد.
*   بنابراین، این فرآیند در واقع مسئول **خون‌رسانی به CPU** و **کاهش مصرف برق و حرارت** است.

#### ۴. ساختار نخ‌ها (Threads)
*   به ازای هر **هسته منطقی (Logical Core)** پردازنده، یک Idle Thread وجود دارد.
*   اگر CPU شما ۴ هسته دارد، PID 0 دارای ۴ نخ است که هر کدام روی یک هسته اجرا می‌شوند تا آن هسته را در زمان بیکاری مدیریت کنند.

#### ۵. چرا در Task Manager درصد بالایی دارد؟
اگر در Task Manager می‌بینید که System Idle Process حدود **۹۹٪** یا **۹۰٪** است، این **خبر خوبی** است!
*   این عدد نشان‌دهنده میزان **بیکاری** سیستم است، نه میزان مشغولیت.
*   ۹۰٪ یعنی: ۹۰ درصد از توان پردازنده شما آزاد است و در حال استراحت می‌باشد.
*   فرمول استفاده واقعی از CPU این است:
    $$ 100\% - (\text{System Idle Process \%}) = \text{Real CPU Usage} $$

---

### خلاصه برای جزوه:

> **System Idle Process (PID 0):**
> *   یک فرآیند مجازی درون کرنل است (فایل exe ندارد).
> *   **وظیفه:** اجرا شدن در زمانی که هیچ برنامه دیگری نیاز به CPU ندارد (Thread با کمترین اولویت).
> *   **کارکرد فنی:** با ارسال دستورات توقف (`HLT`) به CPU، پردازنده را به حالت کم‌مصرف می‌برد تا در مصرف برق صرفه‌جویی شود و حرارت کاهش یابد.
> *   **درصد CPU:** نشان‌دهنده مقدار ظرفیت **خالی** پردازنده است.

# SMSS.exe

همونطور که بالا هم بهش اشاره کردیم اولین پروسس kernel mode که به وجود میاد پروسس system هستش 

و اولین پروسس user mode که میاد بالا process smss.exe هستش
مدیریت کردن session های ویندوز بر عهده این پروسس هستش 
یعنی اگر یه کاربری میاد در سیستم لاگین میکنه  وظیفه این پروسس هستش که بیاد براش یک session بسازه 

بسیار عالی. این بخش در مورد **Session Manager Subsystem (smss.exe)** است که یکی از حیاتی‌ترین اجزای فرآیند بوت شدن ویندوز محسوب می‌شود. متن شما دقیقاً مراحل تولد دنیای User Mode (حالت کاربر) را توصیف می‌کند.

در اینجا توضیحات کامل و تشریحی این بخش برای جزوه شما آورده شده است:

---

### مدیر نشست‌ها (Session Manager - smss.exe)

#### ۱. هویت و جایگاه (`\windows\system32\smss.exe`)
*   **اولین فرآیند User Mode:** تا قبل از اجرای `smss.exe`، هر کدی که اجرا شده بود (مثل `ntoskrnl.exe` یا درایورها) در حالت Kernel Mode قرار داشت.
*   کرنل پس از اتمام مقداردهی‌های اولیه خود، این فایل را اجرا می‌کند. بنابراین `smss.exe` **اولین فرآیند واقعی غیر-کرنلی** است که در سیستم ساخته می‌شود. پدر این فرآیند خودِ سیستم (System process) است.

#### ۲. وظایف اصلی (Main Tasks)
این فرآیند مسئول "چیدن مقدمات" برای اجرای برنامه‌های ویندوز است:

*   **ایجاد متغیرهای محیطی سیستم (Environment Variables):**
    قبل از اینکه هر برنامه دیگری اجرا شود، `smss.exe` متغیرهای کلی سیستم (مثل `PATH`, `SystemRoot`, `TEMP`) را تعریف می‌کند تا سایر برنامه‌ها بتوانند از آنها استفاده کنند.

*   **اجرای زیرسیستم‌ها (Subsystems):**
    ویندوز برای اجرای برنامه‌ها نیاز به یک محیط اجرایی دارد. `smss.exe` مسئول اجرای فرآیند حیاتی **`csrss.exe`** (Client/Server Runtime Subsystem) است. بدون `csrss`، هیچ پنجره‌ای، کنسولی و یا گرافیکی وجود نخواهد داشت.

*   **مدیریت نشست‌های چندگانه (Multi-Session):**
    ویندوز سیستم‌عاملی است که از چندین نشست (Session) پشتیبانی می‌کند (مثلاً Session 0 برای سرویس‌ها، Session 1 برای کاربر اول، Session 2 برای کاربر دوم و غیره). `smss.exe` مسئول ایجاد و مدیریت این دنیاهای ایزوله است.

#### ۳. مکانیسم عجیب "اجرای خود" (Launching Itself)
این قسمت کمی پیچیده است و نیاز به دقت دارد:

1.  یک نسخه اصلی از `smss.exe` همیشه در حال اجراست (Master Instance).
2.  وقتی قرار است یک نشست جدید (مثلاً برای لاگین یک کاربر) ایجاد شود، نسخه اصلی `smss.exe`، **یک کپی جدید از خودش** را در آن نشست جدید اجرا می‌کند.
3.  **وظیفه آن کپی:** آن کپیِ جدید، در داخل نشست جدید، دو فرآیند حیاتی را اجرا می‌کند:
    *   **`csrss.exe`**: برای مدیریت گرافیک و APIهای آن نشست.
    *   **`winlogon.exe`**: برای مدیریت ورود کاربر و قفل صفحه.
4.  **پایان کار کپی:** به محض اینکه `csrss` و `winlogon` با موفقیت اجرا شدند، آن کپیِ `smss.exe` کارش تمام شده و **خاتمه می‌یابد (Terminates)**.

> **نکته:** به همین دلیل است که شما معمولاً در Task Manager فقط **یک** `smss.exe` می‌بینید، حتی اگر چندین کاربر لاگین کرده باشند. کپی‌های دیگر فقط برای "راه‌اندازی" می‌آیند و می‌روند.

#### ۴. نقش نگهبان (The Watchdog)
نسخه اصلی `smss.exe` که باقی می‌ماند، دو وظیفه حیاتی تا زمان خاموش شدن سیستم دارد:

*   **انتظار ابدی (Waits forever):** او منتظر می‌ماند تا ببیند آیا فرآیندهای حیاتی (`csrss.exe` یا `winlogon.exe`) بسته می‌شوند یا خیر.
*   **سقوط سیستم (BSOD):** اگر به هر دلیلی `csrss.exe` یا `winlogon.exe` متوقف شوند (Crash کنند یا ویروسی آنها را ببندد)، ویندوز دیگر نمی‌تواند به کار خود ادامه دهد. در این حالت `smss.exe` بلافاصله دستور ایست کامل سیستم را صادر می‌کند که منجر به **صفحه آبی مرگ (BSOD)** با کد خطایی مثل `CRITICAL_PROCESS_DIED` یا `0xC000021A` می‌شود.

*   **مدیریت Terminal Services:** همچنین گوش‌به‌زنگ است تا اگر درخواستی برای ریموت دسکتاپ (RDP) یا ورود کاربر جدید آمد، فرآیند ساخت نشست جدید را آغاز کند.

---

### خلاصه برای جزوه:

> **Session Manager (smss.exe):**
> *   اولین فرآیند User Mode که توسط کرنل اجرا می‌شود.
> *   **وظایف:** تنظیم متغیرهای محیطی، اجرای زیرسیستم ویندوز (`csrss.exe`).
> *   **مکانیسم نشست‌ها:** برای هر نشست جدید، یک نسخه از خود را اجرا می‌کند تا `winlogon` و `csrss` را در آن نشست بالا بیاورد و سپس آن نسخه کپی بسته می‌شود.
> *   **امنیت:** به عنوان یک نگهبان عمل می‌کند؛ اگر `csrss.exe` یا `winlogon.exe` بسته شوند، `smss.exe` سیستم را کرش می‌کند (Blue Screen)، چون ویندوز بدون آنها نمی‌تواند کار کند.

# winlogon.exe VS smss.exe

تفاوت این دو فرآیند مانند تفاوت **“سازنده ساختمان”** و **“نگهبان و مسئول پذیرش”** است. با اینکه هر دو در راه‌اندازی ویندوز نقش دارند، اما وظایف و سطح دسترسی آن‌ها کاملاً متفاوت است.

در اینجا تفاوت‌های کلیدی را به صورت ساختاریافته بررسی می‌کنیم:

### ۱. رابطه پدر و فرزندی (Hierarchy)

- **`smss.exe` (پدر):** این فرآیند **خالق** است. `smss` نشست (Session) را می‌سازد و سپس `winlogon.exe` را درون آن اجرا می‌کند.
- **`winlogon.exe` (فرزند):** این فرآیند توسط `smss` اجرا می‌شود و درون نشستی که `smss` ساخته، زندگی می‌کند.

### ۲. تفاوت در وظیفه اصلی (Core Responsibility)

- **`smss.exe` (مدیر زیرساخت):** کارش فنی و سیستمی است. او محیط را آماده می‌کند (متغیرها، حافظه مجازی، دیوایس‌مپ‌ها). او کاری به اینکه “چه کسی” پشت کامپیوتر نشسته ندارد، کارش این است که مطمئن شود “اتاق” (Session) آماده است.
- **`winlogon.exe` (مدیر ورود کاربر):** کارش تعامل با کاربر و امنیت است. او مسئول این است که بفهمد “چه کسی” می‌خواهد وارد شود، رمز عبور را بررسی کند و پروفایل شخصی او را لود کند.

### ۴. زنجیره اجرا (Execution Chain)

تفاوت آن‌ها در زنجیره بوت به وضوح دیده می‌شود:

1. **`smss.exe`** اجرا می‌شود ←\leftarrow← محیط نشست را می‌سازد.
2. `smss.exe` فرآیند **`winlogon.exe`** را اجرا می‌کند.
3. **`winlogon.exe`** پس از تایید هویت کاربر ←\leftarrow← فرآیند `userinit.exe` را اجرا می‌کند.
4. `userinit.exe` ←\leftarrow←
5. پوسته ویندوز (**`explorer.exe`**) را اجرا می‌کند (همان دسکتاپ و آیکون‌ها).

این سوال بسیار دقیقی است و نشان می‌دهد که شما عمیقاً وارد معماری داخلی ویندوز شده‌اید. تمایز بین **Master** و **Slave** (یا همان نمونه‌های موقت) در `smss.exe` برای درک نحوه مدیریت نشست‌ها (Sessions) حیاتی است.

در اینجا تفاوت دقیق این دو را توضیح می‌دهم:

---

### ۱. نمونه اصلی (Master Instance)

*   **زمان تولد:** این اولین فرآیند User Mode است که توسط کرنل (`ntoskrnl.exe`) در هنگام بوت شدن سیستم ایجاد می‌شود.
*   **عمر:** از لحظه بوت شدن تا لحظه خاموش شدن سیستم زنده است.
*   **محل زندگی:** همیشه در **Session 0** اجرا می‌شود.
*   **وظایف منحصر به فرد:**
    1.  **مالکیت:** این نسخه، "پدرخوانده" تمام نشست‌هاست.
    2.  **گوش به زنگ:** روی یک پورت LPC (Local Procedure Call) به نام `\SmApiPort` گوش می‌دهد. کرنل و سرویس‌ها درخواست‌های ایجاد نشست جدید (مثلاً وقتی شما RDP می‌زنید یا Switch User می‌کنید) را به این پورت می‌فرستند.
    3.  **مدیریت کلان:** او تصمیم می‌گیرد که چه زمانی یک نشست جدید ساخته شود و چه زمانی یک نشست خاتمه یابد.
    4.  **نظارت (Watchdog):** او کسی است که اگر فرآیند حیاتی `csrss.exe` در Session 0 بمیرد، سیستم را با صفحه آبی (BSOD) متوقف می‌کند.

### ۲. نمونه فرعی یا موقت (Slave Instance / Intermediate Instance)

*   **زمان تولد:** هر بار که نیاز به ایجاد یک **نشست جدید** (Session 1, Session 2, ...) باشد، نسخه Master یک کپی جدید از خودش (همان فایل `smss.exe`) را اجرا می‌کند. این کپی جدید، همان "Slave" است.
*   **محل زندگی:** این فرآیند در **Session جدید** (همان نشستی که قرار است ساخته شود) اجرا می‌شود.
*   **عمر:** بسیار کوتاه! (چند میلی‌ثانیه تا چند ثانیه). فقط تا زمانی زنده است که محیط نشست آماده شود.
*   **وظایف منحصر به فرد:**
    1.  **پیکربندی محیط:** دستگاه‌های DOS (مثل درایو `C:`) و ساب‌سیستم‌های مربوط به آن نشست خاص را تنظیم می‌کند.
    2.  **اجرای زوج حیاتی:** این نسخه Slave است که دستور اجرای `csrss.exe` و `winlogon.exe` را در آن نشست جدید صادر می‌کند.
    3.  **خودکشی:** به محض اینکه `csrss` و `winlogon` با موفقیت اجرا شدند و هندل‌های لازم به فرآیند Master منتقل شد، نسخه Slave کارش تمام شده و **خاتمه می‌یابد (Terminates)**.

### سناریوی عملی: ورود کاربر (Logon)

بیایید ببینیم وقتی کامپیوتر را روشن می‌کنید و می‌خواهید وارد شوید چه می‌شود:

1.  **Master (در Session 0):** توسط کرنل اجرا شده و منتظر است.
2.  **درخواست:** کرنل می‌گوید "نیاز به یک نشست تعاملی (Session 1) داریم".
3.  **تولد Slave:** فرآیند Master یک نمونه `smss.exe` (Slave) را در Session 1 اجرا می‌کند.
4.  **اقدام Slave:**
    *   محیط Session 1 را می‌سازد.
    *   `csrss.exe` را برای Session 1 اجرا می‌کند.
    *   `winlogon.exe` را برای Session 1 اجرا می‌کند.
5.  **پایان Slave:** نسخه Slave گزارش می‌دهد "کار انجام شد" و خودش بسته می‌شود.
6.  **نتیجه:** الان در Task Manager:
    *   یک `smss.exe` (Master) دارید.
    *   چندین `csrss.exe` (برای هر نشست یکی).
    *   چندین `winlogon.exe` (برای هر نشست یکی).
    *   **هیچ** `smss.exe` دیگری (Slave) نمی‌بینید چون کارش تمام شده و رفته است.

### خلاصه تفاوت‌ها

| ویژگی | Master Instance | Slave Instance |
| :--- | :--- | :--- |
| **تعداد** | همیشه **۱ عدد** | به تعداد نشست‌های در حال ساخت (معمولاً ۰ چون سریع بسته می‌شوند) |
| **طول عمر** | دائم (تا خاموشی سیستم) | موقت (فقط زمان ساخت نشست) |
| **وظیفه** | مدیریت کلی و انتظار برای درخواست | راه‌اندازی `csrss` و `winlogon` در نشست جدید |
| **نشست** | Session 0 | Session 1, 2, ... (نشست‌های کاربر) |
| **والد (Parent)** | System (Kernel) | `smss.exe` (Master) |

**نکته امنیتی:** اگر در Task Manager خود **دو عدد** `smss.exe` می‌بینید که هر دو به صورت دائم در حال اجرا هستند، احتمال بسیار زیاد سیستم شما به **بدافزار** آلوده شده است (مگر اینکه دقیقاً در لحظه بسیار کوتاه لاگین کردن کاربر جدید باشید که خیلی بعید است با چشم دیده شود).

# winlogon.exe


### ۱. نقش اصلی: دروازه‌بان سیستم
`Winlogon` مسئول مدیریت نشست‌های تعاملی (Interactive Sessions) است. یعنی تمام فرآیند **Logon** (ورود) و **Logoff** (خروج) کاربر تحت کنترل این پروسه است.
*   **نکته حیاتی:** این پروسه "لنگر" نشست کاربری است. اگر `winlogon.exe` به هر دلیلی بسته شود یا کرش کند، ویندوز بلافاصله کاربر را **Log off** می‌کند (نشست بسته می‌شود).

### ۲. مکانیزم امنیتی SAS (Ctrl+Alt+Del)
یکی از مهم‌ترین وظایف Winlogon گوش دادن به **SAS** (Secure Attention Sequence) است.
*   **SAS چیست؟** همان ترکیب کلیدهای `Ctrl+Alt+Del`.
*   **چرا مهم است؟** ویندوز در سطح کرنل طوری طراحی شده که فقط و فقط `Winlogon` بتواند این سیگنال را دریافت کند. این کار باعث می‌شود بدافزارها نتوانند یک صفحه لاگین جعلی بسازند (چون نمی‌توانند `Ctrl+Alt+Del` را بدزدند). وقتی شما این کلیدها را می‌زنید، مطمئن هستید که پنجره‌ای که باز می‌شود متعلق به خود ویندوز است.

### ۳. مدیریت فرآیند احراز هویت (The Authentication Flow)
Winlogon خودش پسورد را چک نمی‌کند یا گرافیک لاگین را نمی‌کشد؛ بلکه مانند یک **مدیر پروژه** کار را بین اجزای دیگر تقسیم می‌کند:

1.  **نمایش گرافیک (GUI):** وقتی نیاز به دریافت پسورد است، Winlogon پروسه‌ی **`LogonUI.exe`** را اجرا می‌کند. این همان پروسه‌ای است که عکس پس‌زمینه و کادر یوزر/پسورد را به شما نشان می‌دهد.
2.  **بررسی امنیت (Logic):** وقتی شما پسورد را در `LogonUI` وارد کردید، Winlogon آن را می‌گیرد و تحویل **`LSASS.exe`** (Local Security Authority Subsystem Service) می‌دهد.
    *   `LSASS` بررسی می‌کند که آیا پسورد درست است یا نه و نتیجه را به Winlogon می‌گوید.
3.  **شروع نشست:** اگر `LSASS` تایید کرد، Winlogon پروفایل کاربر را بارگذاری کرده و شل ویندوز (معمولاً `explorer.exe`) را اجرا می‌کند تا دسکتاپ بالا بیاید.

### خلاصه نموداری
```text
User (Ctrl+Alt+Del) 
       ⬇
  Winlogon.exe  <-- (مدیر کل جریان)
       ⬇
  LogonUI.exe   <-- (نمایش کادر پسورد به کاربر)
       ⬇
   LSASS.exe    <-- (چک کردن درستی پسورد در دیتابیس)
       ⬇
  (اگر صحیح بود)
  Start Session (Explorer.exe)
```

### نکته

به ازای هر smss.exe یک winlogon به وجود میاد و برای اینکه کابر بعد از اینکه حالا به هر طریقی lock کرده دوباره از طریق سشنی که داره میتونه پروسس winlogon به وجود میاد و اجاز ورود به سیستم رو میده 

و در اصل زمانی که ما لاگین میکنیم تحت پروسس winlogon.exe و اون UI که داره میایم و لاگین میکنیم 
پس پروسه winlogon.exe  وظیفه ارسال username و password رئ به پروسسه lsass داره

# LSASS.exe

این بخش تکمیل‌کننده پازل امنیتی ویندوز است. اگر `Winlogon` را "مدیر سالن" در نظر گرفتیم، **`LSASS` (Local Security Authority Subsystem Service)** دقیقاً نقش **"مسئول حراست و صدور کارت شناسایی"** را دارد.

در اینجا وظایف کلیدی ذکر شده در متن را تحلیل می‌کنیم:

### ۱. اجرای منطق احراز هویت (The Brain)
متن می‌گوید: *Calls the appropriate authentication package*.
`LSASS` خودش را محدود به یک روش خاص نمی‌کند. ویندوز از ساختاری ماژولار استفاده می‌کند. وقتی شما پسورد وارد می‌کنید، `LSASS` نگاه می‌کند که شما چه نوع کاربری هستید:
*   **کاربر دامین (Domain User):** پکیج **Kerberos** را صدا می‌زند.
*   **کاربر لوکال (Local User):** پکیج **MSV1_0** را صدا می‌زند.
*   **اثر انگشت/چهره (Windows Hello):** پکیج‌های بیومتریک را درگیر می‌کند.

این یعنی `LSASS` بسته به نوع درخواست، "پیمانکار" (DLL) مناسب را برای چک کردن رمز صدا می‌زند.

### ۲. ساخت توکن امنیتی (The Token Creation) - **بسیار مهم**
متن می‌گوید: *Creates a token representing the user's security profile*.
این حیاتی‌ترین لحظه در فرآیند لاگین است. اگر احراز هویت موفق باشد، `LSASS` فقط نمی‌گوید "اوکی است"؛ بلکه یک شیء کرنلی به نام **Access Token** می‌سازد.

**داخل این توکن چیست؟** (همان Security Profile)
*   **SID کاربر:** شناسه یکتای شما (مثلاً `S-1-5-21...`).
*   **SID گروه‌ها:** لیست گروه‌هایی که عضو هستید (مثلاً Administrators, Users).
*   **Privileges:** کارهایی که اجازه انجامش را دارید (مثلاً `SeShutdownPrivilege` برای خاموش کردن سیستم یا `SeDebugPrivilege`).

**چرا این توکن مهم است؟**
از این لحظه به بعد، **هر** برنامه‌ای که شما اجرا کنید (مثل Chrome, Word, Explorer)، یک کپی از این توکن را دریافت می‌کند. ویندوز با چک کردن این توکن می‌فهمد شما حق دسترسی به فایلی را دارید یا خیر.

### ۳. بازگشت به Winlogon
متن می‌گوید: *Returns information to Winlogon*.
پس از اینکه توکن ساخته شد، `LSASS` یک هندل (Handle) به این توکن را به `Winlogon` برمی‌گرداند.
حالا `Winlogon` که این توکن معتبر را در دست دارد، می‌تواند دسکتاپ شما (`explorer.exe`) را با استفاده از این توکن اجرا کند (با توابعی مثل `CreateProcessAsUser`).

---

### جمع‌بندی جریان لاگین (The Full Picture)

ترکیب متن قبلی و این متن، جریان کامل را می‌سازد:

1.  **Winlogon:** از کاربر (توسط LogonUI) رمز را می‌گیرد و به LSASS می‌دهد.
2.  **LSASS:** رمز را با پکیج مناسب (مثلا Kerberos) چک می‌کند.
3.  **LSASS:** اگر رمز درست بود، یک **Access Token** (حاوی SIDها و دسترسی‌ها) می‌سازد.
4.  **LSASS:** هندلِ توکن را به Winlogon می‌دهد.
5.  **Winlogon:** 
6. با استفاده از آن توکن، پروسه‌ی `userinit.exe` و سپس `explorer.exe` را اجرا می‌کند.

نتیجه: شما دسکتاپی دارید که تمام دسترسی‌های امنیتی شما در آن لحاظ شده است.

# services.exe (SCM)

این متن درباره **SCM** یا **Service Control Manager** است که یکی از مهم‌ترین اجزای هسته ویندوز برای مدیریت کارهای پس‌زمینه (Background) محسوب می‌شود.

در ادامه هر بخش را با دید فنی و سیستمی تحلیل می‌کنیم:

### ۱. فرمانده‌ی سرویس‌ها (`services.exe`)
*   **هویت:** فایل اجرایی آن `\windows\system32\services.exe` است.
*   **نقش:** این پروسه همان SCM است. در زمان بوت شدن سیستم (خیلی زودتر از اینکه صفحه لاگین را ببینید) اجرا می‌شود.
*   **اهمیت حیاتی:** این یکی از پروسه‌های حیاتی ویندوز است. اگر `services.exe` بسته شود یا کرش کند، سیستم عامل دچار خطای بحرانی شده و صفحه آبی (BSOD) می‌دهد.

### ۲. وظایف اصلی SCM
متن می‌گوید: *Responsible for starting, stopping and interacting...*
شما نمی‌توانید مثل برنامه‌های معمولی روی فایل اجرایی یک سرویس (مثلاً `sqlservr.exe`) دابل‌کلیک کنید تا اجرا شود.
*   **مکانیزم:** SCM یک دیتابیس (در رجیستری) دارد که لیست تمام سرویس‌ها در آن است. وقتی سیستم بالا می‌آید یا شما دستور می‌دهید، SCM مسئولیت ساختن پروسه (CreateProcess)، ارسال دستورات کنترلی (Stop, Pause, Continue) و نظارت بر وضعیت آن سرویس را بر عهده دارد.

### ۳. ماهیت سرویس‌ها (Services)
*   **فایل‌های EXE معمولی اما با یک تفاوت:** سرویس‌ها فایل‌های اجرایی استاندارد (PE) هستند، اما کدی داخل خود دارند که باید با SCM "دست بدهد" (Handshake). آن‌ها باید تابع `StartServiceCtrlDispatcher` را صدا بزنند تا به SCM بگویند: "من بالا آمدم و آماده دستورات تو هستم".
*   **بدون نیاز به لاگین (The Key Feature):** مهم‌ترین ویژگی سرویس‌ها این است که مستقل از کاربر هستند.
    *   وب‌سرور (IIS)، دیتابیس (SQL Server) یا آنتی‌ویروس باید کار کنند حتی اگر هیچ‌کس پشت سیستم لاگین نکرده باشد. SCM این امکان را فراهم می‌کند.

### ۴. حساب‌های کاربری خاص (Special Accounts) - **بخش امنیتی مهم**
چون سرویس‌ها معمولاً به یک "کاربر انسانی" متصل نیستند، ویندوز ۳ حساب کاربری داخلی (Built-in) برای اجرای آن‌ها طراحی کرده است که هر کدام سطح دسترسی متفاوتی دارند:

1.  **LocalSystem (سیستم محلی):**
    *   **قدرت:** قدرتمندترین اکانت موجود در سیستم (حتی بالاتر از Administrator).
    *   **دسترسی:** به تمام فایل‌های سیستم و رجیستری دسترسی کامل دارد.
    *   **شبکه:** در شبکه، با هویت "کامپیوتر" (Computer Object) شناخته می‌شود.
    *   *خطر:* اگر سرویسی با این اکانت هک شود، کل سیستم سقوط می‌کند.

2.  **NetworkService (سرویس شبکه):**
    *   **قدرت:** دسترسی‌های محلی محدودی دارد (کمتر از LocalSystem).
    *   **شبکه:** در شبکه، مانند LocalSystem با هویت "کامپیوتر" شناخته می‌شود.
    *   *کاربرد:* برای سرویس‌هایی که نیاز به دسترسی شبکه دارند (مثل RPC یا DNS Client) اما نباید دسترسی کامل ادمین به فایل‌های لوکال داشته باشند.

3.  **LocalService (سرویس محلی):**
    *   **قدرت:** کمترین سطح دسترسی (Least Privilege). تقریباً شبیه به یک کاربر مهمان.
    *   **شبکه:** دسترسی به شبکه ندارد (به صورت Anonymous عمل می‌کند).
    *   *کاربرد:* برای سرویس‌های ساده‌ای که فقط کارهای داخلی سیستم را انجام می‌دهند و نیاز به امنیت بالا یا شبکه ندارند.

### خلاصه فنی
SCM (`services.exe`) مدیر اجرایی Session 0 است. او سرویس‌ها را با اکانت‌های خاص (`LocalSystem/Network/Local`) اجرا می‌کند تا قبل از ورود کاربر، زیرساخت‌های سیستم (شبکه، درایورها، دیتابیس‌ها) آماده به کار باشند.

بله، این یکی از جالب‌ترین و مدرن‌ترین مکانیزم‌های مدیریت حافظه در ویندوز است. این پروسه **Memory Compression** نام دارد (که قبلاً در Task Manager به صورت مخفی یا با نام‌های مبهم دیده می‌شد، اما در ویندوز ۱۰ و ۱۱ حضور پررنگی در تب Performance دارد).

در اینجا توضیحات کامل و فنی آن را برای جزوه‌ات آماده کرده‌ام:

# فرآیند Memory Compression (فشرده‌سازی حافظه)

### ۱. تعریف و ماهیت
پروسه **Memory Compression** (که در ویندوزهای جدیدتر ممکن است بخشی از پروسه سیستم یا جداگانه نمایش داده شود) یک پروسه در سطح **System** و کاملاً مدیریت‌شده توسط **Memory Manager (Mm)** کرنل ویندوز است.
این مکانیزم دقیقاً مشابه ماژول **ZRAM** یا **zSwap** در لینوکس عمل می‌کند. هدف آن بهینه‌سازی استفاده از RAM فیزیکی و کاهش نیاز به Pagefile (هارد دیسک) است.

### ۲. مشکل چه بود؟ (Pagefile کند است)
در گذشته (قبل از ویندوز ۱۰)، وقتی RAM سیستم پر می‌شد و برنامه‌ها به حافظه بیشتری نیاز داشتند، Memory Manager مجبور بود داده‌های کم‌استفاده (Infrequently used pages) را از RAM بردارد و روی هارد دیسک (در فایل `pagefile.sys`) بنویسد.
*   **مشکل:** هارد دیسک (حتی SSD) هزاران بار کندتر از RAM است. وقتی کاربر دوباره به آن داده نیاز پیدا می‌کرد، سیستم دچار کندی (Hard Fault) می‌شد چون باید داده را از دیسک می‌خواند.

### ۳. راه‌حل Memory Compression چگونه کار می‌کند؟
به جای اینکه داده‌ها مستقیماً به دیسک فرستاده شوند، Memory Manager آن‌ها را با الگوریتم‌های سریع (مثل Xpress Huffman) **فشرده** می‌کند و در همان RAM نگه می‌دارد.

**روند کار (Workflow):**
1.  سیستم تشخیص می‌دهد که حافظه کم است.
2.  صفحاتی از حافظه که مدتی دست‌نخورده‌اند (Inactive Pages) شناسایی می‌شوند.
3.  Memory Manager این صفحات را فشرده می‌کند (مثلاً ۱۰۰ مگابایت دیتا تبدیل به ۳۰ یا ۴۰ مگابایت می‌شود).
4.  این دیتای فشرده‌شده در یک فضای مخصوص در RAM (به نام **Compression Store**) ذخیره می‌شود.

**مزیت:**
*   دسترسی به دیتای فشرده در RAM، بسیار سریع‌تر از خواندن از دیسک است.
*   فقط زمانی که فضای Compression Store هم پر شود یا فشار حافظه خیلی زیاد شود، داده‌ها واقعاً به Pagefile روی دیسک منتقل می‌شوند.

### ۴. وضعیت در Task Manager
*   **ظاهر:** در Task Manager ویندوز ۱۰ و ۱۱، اگر به تب **Performance** > **Memory** بروید، بخشی را می‌بینید که نوشته: `In use (Compressed)`. عدد داخل پرانتز نشان می‌دهد چه مقدار از حافظه فشرده شده است.
*   **پروسه:** در لیست پروسه‌ها (Details tab)، معمولاً این فرآیند به صورت جداگانه لیست نمی‌شود چون بخشی از فضای کاری **System process (PID 4)** است، اما در نسخه‌هایی از ویندوز ۱۰ ممکن بود پروسه‌ای به نام `Memory Compression` دیده شود که حالا معمولاً ادغام شده است تا کاربر گیج نشود. در واقع، این یک "Virtual Process" است که برای نگهداری این صفحات فشرده شده استفاده می‌شود.

![[Pasted image 20260127005147.png]]

### ۵. جزئیات فنی برای جزوه (نکات کلیدی)
*   **الگوریتم:** معمولاً از الگوریتم مایکروسافت به نام **Xpress** استفاده می‌کند که تعادلی بین سرعت فشرده‌سازی و نرخ فشرده‌سازی دارد (چون نباید CPU را زیاد درگیر کند).
*   **کاهش I/O:** هدف اصلی کاهش Disk I/O است. کاهش نوشتن روی دیسک نه تنها سرعت را بالا می‌برد، بلکه عمر SSD را هم افزایش می‌دهد.
*   **Soft Faults:** بازیابی داده از حالت فشرده یک "Soft Fault" محسوب می‌شود (چون دیتا در RAM است)، در حالی که خواندن از پیج‌فایل یک "Hard Fault" است.

### خلاصه برای یادداشت:
> **Memory Compression** یک تکنیک مدیریت حافظه در ویندوز است که صفحاتی از حافظه که کمتر استفاده می‌شوند را به جای نوشتن روی هارد دیسک (Pagefile)، فشرده کرده و در RAM نگه می‌دارد. این کار باعث کاهش استفاده از دیسک و افزایش سرعت پاسخگویی سیستم می‌شود. این مکانیزم توسط Memory Manager کنترل شده و معادل قابلیت **ZRAM** در سیستم‌عامل لینوکس است.

# SafeMode

بله، **Safe Mode** (حالت ایمن) یکی از حیاتی‌ترین ابزارهای عیب‌یابی در ویندوز است. اگر بخواهیم فنی صحبت کنیم، Safe Mode یک حالت **Minimal Boot** (بوت حداقلی) است.

در ادامه برای جزوه‌ات، این مفهوم را به صورت ساختاریافته توضیح می‌دهم:

### ۱. Safe Mode چیست؟ (تعریف فنی)
Safe Mode یک حالت راه‌اندازی تشخیصی (Diagnostic Mode) در سیستم‌عامل ویندوز است. در این حالت، سیستم‌عامل با **حداقلِ مطلقِ منابع** مورد نیاز بالا می‌آید.
این یعنی ویندوز تمام تنظیمات سفارشی، نرم‌افزارهای Startup، و درایورهای غیرضروری را نادیده می‌گیرد و فقط هسته اصلی (Kernel) را به همراه درایورهای حیاتی (ماوس، کیبورد، گرافیک پایه، دیسک) بارگذاری می‌کند.

### ۲. فلسفه پیدایش: چرا Safe Mode به وجود آمد؟
این حالت برای حل مشکل **"مرغ و تخم‌مرغ"** در عیب‌یابی سیستم به وجود آمد:
*   **مشکل:** فرض کنید یک درایور کارت گرافیک نصب کرده‌اید که باعث می‌شود ویندوز هنگام بالا آمدن کرش کند (صفحه آبی یا سیاه). شما می‌خواهید درایور را پاک کنید، اما برای پاک کردن آن باید ویندوز بالا بیاید! ولی ویندوز بالا نمی‌آید چون آن درایور خراب است.
*   **راه‌حل (Safe Mode):** مایکروسافت حالتی را طراحی کرد که در آن، آن درایور خراب اصلاً بارگذاری نشود. بنابراین شما می‌توانید وارد محیط ویندوز شوید و عامل خرابی را حذف کنید.

### ۳. تفاوت‌های فنی با بوت معمولی (Under the Hood)
وقتی ویندوز در حالت Safe Mode بالا می‌آید، تغییرات زیر در سطح سیستم رخ می‌دهد:

1.  **درایورهای گرافیک:** درایور اصلی کارت گرافیک (مثلاً NVIDIA یا AMD) بارگذاری نمی‌شود. ویندوز از درایور پایه مایکروسافت (Basic Display Adapter) استفاده می‌کند. به همین دلیل رزولوشن پایین است و انیمیشن‌ها کند هستند.
2.  **سرویس‌ها (SCM):** فقط سرویس‌های حیاتی ویندوز (Core Services) اجرا می‌شوند. هیچ سرویس شخص ثالثی (مثل سرویس آنتی‌ویروس، سرویس SQL Server و ...) اجرا نخواهد شد.
3.  **Startup Programs:** هیچ برنامه‌ای که در پوشه Startup یا کلید `Run` رجیستری قرار دارد، اجرا نمی‌شود.
4.  **فایل‌های سیستمی:** فایل `AUTOEXEC.BAT` و `CONFIG.SYS` (در سیستم‌های قدیمی‌تر) نادیده گرفته می‌شوند.
5.  **رجیستری:** ویندوز به جای خواندن تنظیمات معمول، به کلید رجیستری زیر نگاه می‌کند تا بداند چه سرویس‌هایی مجاز به اجرا هستند:
    `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\SafeBoot`

### ۴. انواع Safe Mode
1.  **Safe Mode:** حالت استاندارد. بدون شبکه. امن‌ترین حالت.
2.  **Safe Mode with Networking:** درایورهای کارت شبکه را هم لود می‌کند. زمانی لازم است که برای رفع مشکل نیاز به اینترنت (دانلود درایور سالم) یا دسترسی به شبکه داخلی دارید.
3.  **Safe Mode with Command Prompt:** رابط گرافیکی (Explorer.exe) بارگذاری نمی‌شود و شما مستقیم وارد محیط CMD می‌شوید. برای متخصصانی که با دستورات خط فرمان راحت‌ترند.

### ۵. چه زمانی باید به Safe Mode برویم؟ (Use Cases)

این لیست را حتماً در جزوه داشته باش:

*   **حذف بدافزار (Malware/Virus):** بسیاری از ویروس‌ها طوری طراحی شده‌اند که به محض بالا آمدن ویندوز اجرا می‌شوند و اجازه نمی‌دهند آنتی‌ویروس آن‌ها را پاک کند. در Safe Mode، ویروس "اجرا نمی‌شود" (چون در Startup است) و می‌توانید فایل غیرفعال آن را راحت پاک کنید.
*   **درایورهای معیوب:** اگر بعد از آپدیت درایور کارت گرافیک یا صدا، سیستم بالا نمی‌آید یا مدام BSOD (صفحه آبی) می‌دهد.
*   **نرم‌افزارهای مشکل‌ساز:** اگر برنامه‌ای نصب کردید که باعث کندی شدید یا قفل شدن سیستم می‌شود و در حالت عادی اجازه Uninstall نمی‌دهد.
*   **مشکلات Windows Update:** گاهی آپدیت‌ها ناقص نصب می‌شوند و سیستم در یک حلقه (Boot Loop) گیر می‌کند. Safe Mode اجازه می‌دهد آپدیت‌های ناقص را حذف کنید.

### خلاصه برای یادداشت:
> **Safe Mode** محیط ایزوله‌ای است که با دور زدن تنظیمات کاربر و درایورهای شخص ثالث، ویندوز را در خالص‌ترین حالت ممکن اجرا می‌کند تا بتوان مشکلات سیستمی را که مانع از بوت شدن عادی می‌شوند، برطرف کرد.
