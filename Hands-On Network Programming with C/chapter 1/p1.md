
### **لیست کردن آداپتورها در ویندوز (Listing network adapters on Windows)**

> **The Windows networking API is called Winsock, and we will go into much more detail about it in the next chapter.**  
> API شبکه در ویندوز به نام **Winsock** شناخته می‌شود.  
> در فصل بعدی، جزئیات بیشتری از آن را بررسی خواهیم کرد.

> **Whenever we are using Winsock, the first thing we must do is initialize it. This is done with a call to WSAStartup().**  
> هر زمان که از Winsock استفاده می‌کنیم، **اولین کاری که باید انجام دهیم، مقداردهی اولیه (Initialization) آن است**.  
> این کار با فراخوانی تابع **`WSAStartup()`** انجام می‌شود.


### **نمونه برنامه‌ی اولیه‌ی Winsock (win_init.c)**

در این برنامه‌ی کوچک، مراحل **راه‌اندازی (initialization)** و **پاک‌سازی (cleanup)** Winsock نشان داده شده است:

- **راه‌اندازی Winsock:** با `WSAStartup()`
    
- **پاک‌سازی Winsock:** با `WSACleanup()`
    

> در واقع، هر برنامه‌ی شبکه‌ای در ویندوز که از Winsock استفاده می‌کند، باید ابتدا Winsock را راه‌اندازی کند و در پایان کار آن را پاک‌سازی کند تا منابع آزاد شوند.

---

### **تابع `WSAStartup()`**

> **The WSAStartup() function is called with the requested version, Winsock 2.2 in this case, and a WSADATA structure.**  
> تابع `WSAStartup()` با **نسخه‌ای که می‌خواهیم استفاده کنیم** فراخوانی می‌شود.  
> در این مثال، نسخه‌ی **Winsock 2.2** درخواست شده است.  
> علاوه بر نسخه، یک ساختار به نام **`WSADATA`** هم به آن داده می‌شود.

- **نسخه Winsock**: مشخص می‌کند برنامه‌ی شما با کدام نسخه‌ی Winsock کار می‌کند.
    
- **ساختار WSADATA**: این ساختار **توسط WSAStartup پر می‌شود** و جزئیاتی درباره‌ی پیاده‌سازی Winsock روی سیستم فراهم می‌کند، مثل نسخه‌ی واقعی نصب شده و قابلیت‌های شبکه.
    

---

> **The WSADATA structure will be filled in by WSAStartup() with details about the Windows Sockets implementation.**  
> همان‌طور که گفتیم، بعد از فراخوانی `WSAStartup()`، **WSADATA پر می‌شود و اطلاعاتی درباره Winsock ارائه می‌دهد**.

---

> **The WSAStartup() function returns 0 upon success, and non-zero upon failure.**  
> نتیجه‌ی تابع:
> 
> - اگر موفق باشد: `0` برمی‌گرداند
>     
> - اگر خطا رخ دهد: **عدد غیر صفر** برمی‌گرداند
>     

با این بازگشت، برنامه می‌تواند بفهمد آیا Winsock با موفقیت راه‌اندازی شده یا نه، و در صورت خطا اقدامات مناسب (مثل چاپ پیام خطا یا خاتمه برنامه) انجام دهد.

---

```c
#include <stdio.h>
#include <winsock2.h>
#pragma comment(lib, "ws2_32.lib")
```

- `#include <stdio.h>`: برای استفاده از توابع استاندارد ورودی/خروجی مثل `printf`.
    
- `#include <winsock2.h>`: این فایل هدر شامل تعاریف **تابع‌ها، ساختارها و ثابت‌های Winsock** است.
    
- `#pragma comment(lib, "ws2_32.lib")`: به **لینکر** می‌گوید که کتابخانه `ws2_32.lib` (کتابخانه‌ی Winsock) را لینک کند. بدون این، توابع Winsock قابل استفاده نیستند.
    

---

```c
int main() {
    WSADATA d;
```

- تعریف یک متغیر از نوع `WSADATA` که قرار است **جزئیات پیاده‌سازی Winsock** توسط `WSAStartup()` در آن ذخیره شود.
    

---

```c
if (WSAStartup(MAKEWORD(2, 2), &d)) {
    printf("Failed to initialize.\n");
    return -1;
}
```

- `WSAStartup(MAKEWORD(2, 2), &d)`:
    
    - `MAKEWORD(2,2)` یعنی درخواست نسخه‌ی **Winsock 2.2**
        
    - `&d` آدرس ساختار WSADATA که توسط تابع پر خواهد شد.
        
- اگر مقدار برگشتی **غیر صفر** باشد (یعنی خطا رخ داده)، پیام `"Failed to initialize."` چاپ شده و برنامه با کد `-1` خاتمه می‌یابد.
    

---

```c
WSACleanup();
```

- این تابع **Winsock را پاک‌سازی می‌کند** و منابع اختصاص داده شده را آزاد می‌کند.
    
- هر برنامه‌ای که Winsock را راه‌اندازی می‌کند، باید در پایان از `WSACleanup()` استفاده کند.
    

---

```c
printf("Ok.\n");
return 0;
```

- اگر همه چیز درست باشد، پیام `"Ok."` چاپ می‌شود و برنامه با موفقیت (`0`) خاتمه می‌یابد.
    

---

✅ **خلاصه عملکرد برنامه:**

1. Winsock را با نسخه 2.2 راه‌اندازی می‌کند.
    
2. بررسی می‌کند که راه‌اندازی موفق بوده یا نه.
    
3. در پایان، Winsock را پاک‌سازی می‌کند.
    
4. نتیجه را به کاربر اعلام می‌کند.
    

---


```
#include <stdio.h>
#include <winsock2.h>
#pragma comment(lib, "ws2_32.lib")
int main() {
    WSADATA d;
    if (WSAStartup(MAKEWORD(2,2), &d)) {
        printf("Failed to initialize.\n");
        return -1;
    }
    WSACleanup();
    printf("ok.\n");
    return 0;
}
```

نکته : تابع `WSAStartup` نسخه‌ی Winsock مورد نظر را به عنوان **یک WORD** می‌گیرد:
### 1️⃣ منظور از `MAKEWORD`

`MAKEWORD`
یک **ماکرو (Macro)** است که در `<windows.h>` یا `<winsock2.h>` تعریف شده و **دو عدد 8 بیتی را ترکیب می‌کند تا یک عدد 16 بیتی (WORD) بسازد**.


---

### 1️⃣ **پاک‌سازی Winsock**
> When a Winsock program is finished, it should call `WSACleanup()`.  
هر برنامه‌ای که از Winsock استفاده می‌کند، پس از اتمام کار باید **تابع `WSACleanup()`** را فراخوانی کند تا منابع اختصاص داده شده آزاد شوند.

---

### 2️⃣ **لینک کردن کتابخانه در Microsoft Visual C**
> If you are using Microsoft Visual C as your compiler, then `#pragma comment(lib, "ws2_32.lib")` tells Microsoft Visual C to link the executable with the Winsock library, ws2_32.lib.  
اگر از **Microsoft Visual C** استفاده می‌کنید، این خط `#pragma comment(lib, "ws2_32.lib")` به **لینکر** می‌گوید که برنامه را با کتابخانه‌ی **Winsock (`ws2_32.lib`)** لینک کند.  
> یعنی لازم نیست کاری دیگری انجام دهید، خود کامپایلر این کار را انجام می‌دهد.

---

### 3️⃣ **لینک کردن کتابخانه در MinGW**
> If you are using MinGW as your compiler, the pragma is ignored. You need to explicitly tell the compiler to link in the library by adding the command-line option, `-lws2_32`.  
اما اگر از **MinGW** استفاده می‌کنید، این `#pragma` نادیده گرفته می‌شود.  
شما باید **به صورت دستی** کتابخانه را لینک کنید با استفاده از **گزینه‌ی `-lws2_32`** در خط فرمان.

**مثال:**
```bash
gcc win_init.c -o win_init.exe -lws2_32
```
- `-lws2_32` به gcc می‌گوید که کتابخانه‌ی Winsock را لینک کند.  
- بدون این گزینه، توابع Winsock مثل `WSAStartup` و `WSACleanup` شناسایی نمی‌شوند و خطای لینک خواهید گرفت.

---

### 1️⃣ کتابخانه‌ها در C

وقتی برنامه‌ای می‌نویسیم و توش از توابعی استفاده می‌کنیم که داخل کتابخانه‌های خارجی تعریف شده‌اند (مثل Winsock)، کامپایلر **تعریف تابع** را می‌شناسد ولی **کد واقعی تابع** در فایل کتابخانه است.  

مثلاً تو داری این‌ها را صدا می‌زنی:

```c
WSAStartup(MAKEWORD(2,2), &d);
WSACleanup();
```

- کامپایلر می‌دونه `WSAStartup` و `WSACleanup` وجود دارند چون هدر `<winsock2.h>` را شامل کردی.  
- اما **کد واقعی این توابع داخل کتابخانه‌ی `ws2_32.lib`** است.  

---

### 2️⃣ Microsoft Visual C

- در Visual C، خط `#pragma comment(lib, "ws2_32.lib")` به **لینکر** می‌گه:  
  > «این کتابخانه را به پروژه اضافه کن.»  
- بنابراین نیازی نیست تو خط فرمان چیزی اضافه کنی، خود Visual C کار لینک کردن را انجام می‌دهد.

---

### 3️⃣ MinGW

- در MinGW، `#pragma comment(lib, ...)` نادیده گرفته می‌شود.  
- بنابراین اگر فقط بنویسی:
```bash
gcc win_init.c -o win_init.exe
```
کامپایلر **کد تابع‌ها را پیدا می‌کند** اما **لینکر نمی‌تواند کد واقعی توابع را پیدا کند** → خطای لینک می‌دهد.  

- با اضافه کردن `-lws2_32` به gcc می‌گویی:  
  > «کتابخانه‌ی ws2_32 را لینک کن تا توابع Winsock درست کار کنند.»

**فرمان کامل:**
```bash
gcc win_init.c -o win_init.exe -lws2_32
```
- `-o win_init.exe` → نام فایل خروجی  
- `-lws2_32` → لینک کردن کتابخانه‌ی Winsock

### 🔹 نکته مهم

در سیستم‌های لینوکس و macOS، برای کتابخانه‌های استاندارد سیستم هم باید بعضی وقت‌ها `-l` بدهی (مثل `-lm` برای math).  
اینجا هم `-lws2_32` همان کار را برای Winsock در ویندوز انجام می‌دهد.

---
## ) خلاصهٔ خیلی کوتاه

- `ws2_32.dll` — فایل **دینامیک** در ویندوز که توابع Winsock (توابع شبکه) را در زمان اجرا فراهم می‌کند.
    
- `Ws2_32.lib` — **"import library"** برای لینک‌کننده. وقتی برنامه‌ت را با توابع Winsock می‌نویسی، لینک‌کننده از این فایل استفاده می‌کند تا بداند هنگام اجرا باید به `ws2_32.dll` مراجعه کند.
    
- `#pragma comment(lib, "Ws2_32.lib")` — یک فرمان برای **MSVC** که به لینک‌کننده می‌گوید این کتابخانه را لازماً به پروژه لینک کند (در عوض تایپ کردن آن در خطِ فرمانِ لینک یا تنظیمات پروژه).
    

---
## ) فرق بین `.lib` و `.dll` و انواع `.lib`

دو نوع `.lib` وجود دارد:

1. **Import library** (مثل `Ws2_32.lib`)
    
    - حاوی _اطلاعاتی_ برای لینک‌کننده است که نشان می‌دهد توابعِ مشخص در زمان اجرا در یک DLL (مثلاً `ws2_32.dll`) وجود دارند.
        
    - این فایل خودش کد تابع را در باینری قرار نمی‌دهد، فقط اشاره می‌کند که هنگام load باید از DLL استفاده شود.
        
    - نتیجه: فایل اجرایی شما هنگام اجرا به `ws2_32.dll` وابسته می‌شود.
        
2. **Static library** (آرشیو از کدهای کامپایل‌شده، مثل `libfoo.a` یا `foo.lib` اگر static باشد)
    
    - توابع واقعاً به باینری تو اضافه می‌شوند؛ نیازی به DLL هنگام اجرا نیست.
        
    - `Ws2_32.lib` **معمولاً import lib است، نه static**.
