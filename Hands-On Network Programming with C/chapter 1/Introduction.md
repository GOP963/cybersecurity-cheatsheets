

امروز تخمین زده میشود که بیش از بیست میلیون دستگاه های مختلف به شبکه اینترنت متصل میشود 
که شامل دستگاه هایی از جمله mobile,laptop,server,pc,router و..... موارد دیگر 
این دستگاه‌ها از **سخت‌افزارهای بسیار متنوعی** استفاده می‌کنند — از **اتصال‌های اترنت (Ethernet)** و **Wi-Fi** گرفته تا **شبکه‌های سلولی، خطوط تلفن، فیبر نوری** و رسانه‌های ارتباطی دیگر.

اما تقریباً همه‌ی این دستگاه‌ها یک ویژگی مشترک دارند:  
احتمال زیاد، **با زبان C نوشته شده‌اند.**


ما در دنیای کامپیوتر یک اصطلاحی داریم به اسم ubiquitous که به این معنی اشاره دارد که اون شی همه جا حاظر است که زبان C یه جورایی یک ubiquitous است یعنی همه جا حاضر است 

وقتی میلیاردها دستگاه مختلف در سراسر جهان (از لپ‌تاپ گرفته تا تلویزیون و چراغ هوشمند) می‌خواهند بدون مشکل با هم ارتباط برقرار کنند، باید مجموعه‌ای از **استانداردها و قوانین مشترک** برای ارتباط بین آن‌ها وجود داشته باشد.

به این استانداردها می‌گوییم **پروتکل‌ها (Protocols)**.  
پروتکل‌ها همه‌چیز را تعریف می‌کنند — از **میزان ولتاژ روی کابل اترنت (Ethernet)** تا نحوه‌ی **فشرده‌سازی تصاویر JPEG در یک صفحه‌ی وب**.


### ⚙️ مفهوم "لایه‌ها" در شبکه

وقتی درباره‌ی شبکه صحبت می‌کنیم، می‌بینیم که موضوعات خیلی متفاوتی درگیر هستند:  
مثلاً یک برنامه‌نویس وب‌سایت اصلاً دوست ندارد درگیر «ولتاژ کابل» یا «فرکانس وای‌فای» شود.  
و در مقابل، کسی که یک **روتر شبکه** می‌نویسد، اصلاً لازم ندارد بداند که JPEG چطور فشرده می‌شود.

برای همین، دانشمندان شبکه تصمیم گرفتند این سیستم پیچیده را **به چند سطح (لایه)** تقسیم کنند، تا هر بخش فقط وظیفه‌ی خودش را انجام دهد و از لایه‌های پایین‌تر خدمات بگیرد، بدون اینکه درگیر جزئیات داخلی آن‌ها شود.

### 🧩 مدل OSI چیست؟

مدل OSI یا **Open Systems Interconnection Model**  
یک **مدل استاندارد ۷ لایه‌ای** برای درک نحوه‌ی ارتباط سیستم‌های کامپیوتری است.  
این مدل در سال ۱۹۷۷ استاندارد شد و با شماره‌ی **ISO 7498** منتشر گردید.


## 🌐 مدل TCP/IP چیست؟

مدل **TCP/IP (Transmission Control Protocol / Internet Protocol)**  
پرکاربردترین مدل ارتباطات شبکه‌ای در دنیای امروز است — یعنی تقریباً **تمام اینترنت با همین مدل کار می‌کند.**

در واقع، مدل TCP/IP نسبت به مدل OSI ساده‌تره؛  
به‌جای ۷ لایه، فقط **۴ لایه** داره.


---

| مدل OSI (7 لایه) | مدل TCP/IP (4 لایه)     |     |
| ---------------- | ----------------------- | --- |
| 7️⃣ Application  | 4️⃣ Process/Application |     |
| 6️⃣ Presentation | 4️⃣ Process/Application |     |
| 5️⃣ Session      | 4️⃣ Process/Application |     |
| 4️⃣ Transport    | 3️⃣ Host-to-Host        |     |
| 3️⃣ Network      | 2️⃣ Internet            |     |
| 2️⃣ Data Link    | 1️⃣ Network Access      |     |
| 1️⃣ Physical     | 1️⃣ Network Access      |     |
یعنی در مدل TCP/IP، چندتا از لایه‌های بالا با هم ترکیب شده‌اند و لایه‌های پایین‌تر خلاصه‌تر بیان شده‌اند.


نکته : مدل OSI **اول تئوری‌اش طراحی شد** و بعد پروتکل‌ها بهش اضافه شدند.  
اما مدل TCP/IP **بر اساس پیاده‌سازی واقعی اینترنت ساخته شد** — یعنی اول پروتکل‌ها ساخته شدند، بعد مدلش تدوین شد.

---

### 🔹 کپسوله‌سازی داده (Data Encapsulation)

مزیت استفاده از مدل‌های لایه‌ای در شبکه این است که هنگام برنامه‌نویسی یک اپلیکیشن، فقط لازم است به **بالاترین لایه** توجه کنیم.  
به‌عنوان مثال، یک مرورگر وب فقط باید پروتکل‌هایی را پیاده‌سازی کند که مربوط به وب‌سایت‌ها هستند — مثل **HTTP، HTML و CSS**.  
مرورگر نیازی ندارد خودش پروتکل‌های TCP/IP را پیاده‌سازی کند و قطعاً نیازی ندارد بفهمد که یک بسته‌ی Ethernet یا Wi-Fi دقیقاً چطور رمزگذاری می‌شود.

این کارها (لایه‌های پایین‌تر) توسط **سیستم‌عامل** انجام می‌شوند — مثلاً در **Windows، Linux یا macOS**.


## حال این فرایند داره به واسطه پرتوکل هایی انجام 

| اصطلاح                                  | معنی                   | توضیح ساده                                                                                           |
| :-------------------------------------- | :--------------------- | :--------------------------------------------------------------------------------------------------- |
| **SAP (Service Access Point)**          | نقطه دسترسی به سرویس   | محلی است که یک لایه می‌تواند از سرویس‌های لایه پایین‌تر استفاده کند. مثل “درگاه ورودی” بین دو لایه.  |
| **SDU (Service Data Unit)**             | واحد دادهٔ سرویس       | داده‌ای که از لایه بالاتر به لایه پایین‌تر فرستاده می‌شود.                                           |
| **PDU (Protocol Data Unit)**            | واحد دادهٔ پروتکل      | داده‌ای است که لایهٔ پایین‌تر پس از افزودن «هدر» (Header) خودش به SDU تولید می‌کند.                  |
| **ICI (Interface Control Information)** | اطلاعات کنترلی رابط    | داده‌های کنترلی و مدیریتی که هنگام ارسال SDU بین لایه‌ها منتقل می‌شود (مثلاً نوع داده یا اولویت آن). |
| **IDU (Interface Data Unit)**           | مجموعه‌ای از SDU و ICI | بستهٔ کامل داده‌ای که از لایه بالاتر به لایه پایین‌تر فرستاده می‌شود.                                |

## 🔹 **سوکت (Socket)**  
سوکت در واقع **یک نقطهٔ انتهایی (End-point)** در ارتباط بین دو سیستم است.  
می‌توان آن را مثل یک **رابط یا درگاه ارتباطی** در نظر گرفت که از طریق آن، برنامه شما می‌تواند داده‌ها را در شبکه ارسال یا دریافت کند.

اگر بخواهیم با مثالی ساده مقایسه کنیم:  
همان‌طور که برنامه شما می‌تواند با استفاده از یک _file handle_ روی یک فایل داده بنویسد یا از آن بخواند،  
با استفاده از _socket handle_ هم می‌تواند داده‌ها را روی شبکه بفرستد یا از شبکه بگیرد.

---

## 🔹 **هویت منحصربه‌فرد یک سوکت (The 5-tuple)**  
هر سوکت باز (فعال) در سیستم به‌صورت یکتا توسط پنج مقدار زیر شناخته می‌شود:

|جزء (Component)|توضیح|
|---|---|
|**Local IP address**|آدرس IP محلی (سیستم شما)|
|**Local port**|پورت محلی که سیستم برای این ارتباط باز کرده است|
|**Remote IP address**|آدرس IP مقصد (سیستم یا سرور مقابل)|
|**Remote port**|پورتی که در سیستم مقصد برای این ارتباط استفاده می‌شود|
|**Protocol (UDP/TCP)**|نوع پروتکل انتقال (TCP یا UDP)|
این پنج‌تایی یا **5-tuple** برای سیستم‌عامل بسیار مهم است، چون با استفاده از همین اطلاعات تشخیص می‌دهد  
که هر بستهٔ دریافتی باید به کدام برنامه (process) تحویل داده شود.


🔹 **مثال:**  
فرض کنید دو مرورگر وب روی سیستم شما باز هستند و هر دو به صورت هم‌زمان به سایت  
`example.com` روی پورت 80 وصل می‌شوند.  
در ظاهر، هر دو ارتباط دقیقاً مشابه‌اند (چون آدرس مقصد، پورت مقصد، و پروتکل TCP یکی هستند).  
اما سیستم‌عامل می‌تواند این دو ارتباط را از هم تفکیک کند چون برای هر اتصال،  
**پورت محلی (Local Port)** متفاوتی انتخاب می‌کند — این پورت‌ها معمولاً توسط سیستم به‌صورت خودکار و موقت (Ephemeral Ports) ایجاد می‌شوند.

---

🔹 **ارتباط با NAT (Network Address Translation):**  
در شبکه‌های خصوصی، چندین سیستم مختلف ممکن است از طریق یک روتر NAT  
به یک منبع خارجی واحد (مثلاً یک سرور در اینترنت) متصل شوند.

روتر NAT برای اینکه بداند هر بستهٔ برگشتی باید به کدام سیستم داخل شبکه خصوصی برگردد،  
برای **هر اتصال** یک نسخه از همان **5-tuple** را ذخیره می‌کند.  
به این ترتیب، وقتی بسته‌ای از اینترنت به روتر می‌رسد،  
روتر با مقایسهٔ این پنج مقدار، تشخیص می‌دهد بسته باید به کدام سیستم درون شبکه ارسال شود.
