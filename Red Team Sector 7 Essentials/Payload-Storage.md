## 1. سکشن `.text`
- **کاربرد اصلی:** نگهداری کد اجرایی (instructions) برنامه
- **ویژگی:** دارای مجوز اجرا (Execute) است، معمولاً Read + Execute
- **در Red Team:** چون این سکشن ذاتاً Executable است، جاسازی shellcode در آن نیازی به تغییر Memory Protection ندارد (مثلاً فراخوانی `VirtualProtect` لازم نیست) — این باعث می‌شود ردیابی آن برای برخی EDRها سخت‌تر باشد، اما در ع
وش تغییر در این بخش، چک‌سام فایل را تغییر داده و باعث هشدار می‌شود.

## 2. سکشن `.data`
- **کاربرد اصلی:** متغیرهای سراسری (Global) و استاتیک که در زمان اجرا مقداردهی می‌شوند.
- **ویژگی:** دارای مجوز Read + Write است (بدون Execute).
- **در Red Team:** برای اجرای شل‌کد در این بخش، حتماً نیاز است در زمان اجرا با استفاده از APIهایی نظیر `VirtualProtect` مجوز Execute به این ناحیه داده شود. این رفتار (تغییر سطح دسترسی حافظه) یکی از بردارهای اصلی شناسایی توسط سیستم‌های امنیتی (EDR) است.

## 3. سکشن `.rsrc` (Resources)
- **کاربرد اصلی:** ذخیره‌سازی داده‌های غیرکد (مانند آیکون‌ها، تصاویر، متن‌ها یا فایل‌های جاسازی شده).
- **ویژگی:** معمولاً Read-only است.
- **در Red Team:** روشی کلاسیک برای پنهان‌سازی بدافزار است. شل‌کد به عنوان یک Resource در فایل قرار می‌گیرد. در زمان اجرا، برنامه ابتدا شل‌کد را از این بخش خوانده، در حافظه (Heap یا بخش جدید) قرار داده و سپس اجرا می‌کند. این روش کمتر از دو روش قبل باعث شکسته شدن امضای کد فایل اصلی می‌شود.

---
**تفاوت کلیدی:**
*   **تغییرات:** `.text` تغییرات را بلافاصله برای اجرا نیاز دارد اما امضای فایل را بهم می‌زند.
*   **امنیت:** `.data` و `.rsrc` برای دوری از detectionهای استاتیک مناسب‌ترند اما برای اجرا نیاز به مراحل میانی (Allocation/Protection Change) دارند که می‌تواند منجر به شناسایی رفتاری شود.

- `.text`
  - کد اجرایی برنامه داخل این بخش قرار می‌گیرد؛ یعنی دستورالعمل‌های ماشین CPU.
  - معمولا این سکشن `read + execute` است و نباید writable باشد.
  - توابع برنامه، روال‌های کامپایل‌شده، و گاهی thunkها یا stubها اینجا هستند.
  - اگر در مهندسی معکوس کار کنی، بیشتر disassembly اصلی را در همین بخش می‌بینی.

- `.data`
  - داده‌های سراسری و static که مقدار اولیه دارند در این بخش قرار می‌گیرند.
  - مثلا `int x = 10;` یا آرایه‌ها و ساختارهایی که از قبل مقداردهی شده‌اند.
  - این سکشن معمولا `read + write` است، چون برنامه هنگام اجرا ممکن است این مقادیر را تغییر دهد.
  - متغیرهای global/state برنامه اغلب اینجا دیده می‌شوند.

- `.rsrc`
  - منابع برنامه در این بخش ذخیره می‌شوند.
  - شامل آیکون، bitmap، منو، dialog، string table، version info، manifest و سایر resourceها است.
  - این بخش معمولا توسط APIهای ویندوز مثل `FindResource` و `LoadResource` خوانده می‌شود.
  - اگر آیکون یک `.exe` را عوض کنی، معمولا تغییر در همین بخش اتفاق می‌افتد.

برای درک بهتر، تفاوتشان این‌طور است:

- `.text` = «برنامه چه دستوراتی اجرا می‌کند»
- `.data` = «برنامه چه داده‌های قابل‌تغییری همراه خود دارد»
- `.rsrc` = «برنامه چه منابع جانبی/UI/metadata همراه خود دارد»

چند نکته مرتبط:

- `.rdata`
  - هرچند شما نپرسیدی، ولی کنار `.data` معمولا این هم هست.
  - داده‌های فقط‌خواندنی مثل string literalها، import tableهای خاص، RTTI و بعضی metadataها آنجا می‌روند.

- `.bss`
  - در PE معمولا به شکل سکشنی مثل داده‌های uninitialized دیده می‌شود یا داخل ساختارهای مشابه مدیریت می‌شود.
  - برای متغیرهایی است که مقدار اولیه ندارند، مثل `int x;`

- از دید امنیتی
  - `.text` ideally writable نیست تا تغییر کد در زمان اجرا سخت‌تر شود.
  - اگر سکشنی هم writable هم executable باشد، ممکن است مشکوک یا از نظر امنیتی ضعیف باشد.
