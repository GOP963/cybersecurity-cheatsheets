


## خلاصه Chapter 1 – Debugging و Error Handling در Windows

### 1. هدف اصلی Chapter 1

این فصل می‌خواهد بهت یاد بدهد که:

- **ویندوز خطاها را چطور تولید و مدیریت می‌کند**
    
- **دیباگرها چطور این خطاها را به متن قابل‌فهم تبدیل می‌کنند**
    
- چرا دانستن این موضوع برای **Debugging، Reverse Engineering و Windows Internals** حیاتی است
    

---

### 2. Error Code چیست؟

- ویندوز بسیاری از خطاها را به‌صورت **عدد (DWORD Error Code)** برمی‌گرداند
    
- این عدد به‌تنهایی معنا ندارد، مگر اینکه به **توضیح متنی (Error Message)** ترجمه شود
    
- مثال:
    
    ```c
    GetLastError()
    ```
    

---

### 3. نقش FormatMessage

تابع **`FormatMessage`** ابزار اصلی تبدیل:

```
Error Code  →  Human Readable Message
```

کاربردهای کلیدی:

- گرفتن توضیح خطاهای **سیستمی ویندوز**
    
- گرفتن پیام خطا از **DLL یا EXE خاص**
    
- استفاده‌ی مستقیم در ابزارهای Debugging
    

---

### 4. فلگ‌های مهم FormatMessage

|فلگ|کاربرد|
|---|---|
|`FORMAT_MESSAGE_FROM_SYSTEM`|جستجوی خطا در پیام‌های داخلی ویندوز|
|`FORMAT_MESSAGE_FROM_HMODULE`|جستجو در پیام‌های یک DLL/EXE خاص|
|`FORMAT_MESSAGE_ALLOCATE_BUFFER`|تخصیص خودکار حافظه توسط ویندوز|
|`FORMAT_MESSAGE_IGNORE_INSERTS`|نادیده گرفتن پارامترهای متغیر پیام|

---

### 5. زبان پیام خطا (Locale)

- پیام‌ها وابسته به زبان سیستم عامل هستند
    
- استفاده از:
    

```c
MAKELANGID(LANG_NEUTRAL, SUBLANG_NEUTRAL)
```

باعث می‌شود پیام در **زبان پیش‌فرض سیستم** نمایش داده شود

- **Hardcode کردن زبان اشتباه است**
    

---

### 6. چرا NetMsg.dll مهم است؟

- همه‌ی Error Codeها سیستمی نیستند
    
- خطاهای مربوط به شبکه در **NetMsg.dll** قرار دارند
    
- هر DLL می‌تواند Error Codeهای اختصاصی داشته باشد
    
- این موضوع پایه‌ی ابزار **Visual Studio Error Lookup** است
