


## 1️⃣ Localization (بومی‌سازی) چیست؟

**Localization** 
یعنی آماده‌سازی یک نرم‌افزار برای اجرا و استفاده در **کشورها، زبان‌ها و فرهنگ‌های مختلف** بدون تغییر منطق اصلی برنامه.

### شامل چه چیزهایی می‌شود؟

- پشتیبانی از **زبان‌های مختلف** (متن، منوها، پیام‌ها)
    
- پشتیبانی از **کاراکترهای غیرانگلیسی** (عربی، فارسی، چینی، ژاپنی و …)
    
- فرمت‌های محلی:
    
    - تاریخ و زمان
        
    - واحد پول
        
    - اعداد
        
- فونت‌ها و جهت نوشتار (LTR / RTL)
    

### مشکل اصلی Localization

بزرگ‌ترین مشکل همیشه **نمایش و پردازش کاراکترها** بوده است، چون:

- ASCII فقط 128 یا 256 کاراکتر دارد
    
- بسیاری از زبان‌ها هزاران کاراکتر دارند
    

---

## 2️⃣ Unicode چیست؟

**Unicode** یک **استاندارد جهانی** برای نمایش تمام کاراکترهای زبان‌های دنیا است.

### ایده‌ی اصلی Unicode

> «هر کاراکتر در هر زبانی، یک شناسه‌ی یکتا (Code Point) داشته باشد»

مثلاً:

- A → U+0041
    
- ب → U+0628
    
- あ → U+3042
    

### Unicode چه کار می‌کند؟

- تعریف می‌کند **چه کاراکترهایی وجود دارند**
    
- به هر کاراکتر یک **Code Point** می‌دهد
    
- مستقل از سیستم‌عامل و زبان برنامه‌نویسی است
    

📌 نکته مهم:  
Unicode خودش **روش ذخیره‌سازی بایت‌ها را مشخص نمی‌کند**  
این کار را UTFها انجام می‌دهند 👇

---

## 3️⃣ UTF چیست؟ (Unicode Transformation Format)

**UTF**
روش‌هایی هستند برای **کدگذاری Unicode در حافظه یا فایل**.

یعنی:

> چطور Code Pointهای Unicode به بایت تبدیل شوند

---

## 4️⃣ انواع مهم UTF

### 🔹 UTF-16 (استاندارد ویندوز)

- هر کاراکتر معمولاً **۲ بایت**
    
- بعضی کاراکترهای خاص → **۴ بایت (Surrogate Pair)**
    
- مزایا:
    
    - سریع در ویندوز
        
    - پیمایش رشته‌ها ساده‌تر
        
    - سازگار با WinAPI و .NET
        
- معایب:
    
    - برای فایل و شبکه بهینه نیست
        

📌 ویندوز و .NET به‌صورت پیش‌فرض از **UTF-16** استفاده می‌کنند

---

### 🔹 UTF-8 (استاندارد وب و لینوکس)

- طول متغیر:
    
    - 1 بایت (ASCII)
        
    - 2، 3 یا 4 بایت برای بقیه
        
- مزایا:
    
    - بسیار کم‌حجم برای متن انگلیسی
        
    - سازگار با اینترنت
        
- معایب:
    
    - محاسبه طول رشته سخت‌تر
        
    - کاراکترها طول متغیر دارند
        

📌 بهترین انتخاب برای:

- فایل‌ها
    
- شبکه
    
- وب
    

---

### 🔹 UTF-32

- هر کاراکتر = **۴ بایت ثابت**
    
- مزایا:
    
    - پردازش بسیار ساده
        
- معایب:
    
    - مصرف حافظه بسیار زیاد
        
- استفاده:
    
    - تقریباً فقط داخل برنامه‌ها (نه ذخیره‌سازی)
        

---

## 5️⃣ چرا Unicode برای Localization حیاتی است؟

بدون Unicode:

- DBCS (کاراکترهای ۱ یا ۲ بایتی) → کابوس برنامه‌نویس
    
- توابعی مثل `strlen` اشتباه می‌کنند
    
- باگ و مشکل امنیتی زیاد می‌شود
    

با Unicode:

- تمام زبان‌ها پشتیبانی می‌شوند
    
- کد ساده‌تر و امن‌تر می‌شود
    
- آماده‌ی بازار جهانی هستی
    

---

## جمع‌بندی خیلی کوتاه

- **Localization** → آماده‌سازی نرم‌افزار برای جهان
    
- **Unicode** → تعریف همه‌ی کاراکترهای دنیا
    
- **UTF** → روش ذخیره‌سازی Unicode در بایت
    
- **Windows + .NET** → UTF-16
    
- **Web / File / Network** → UTF-8

## 1️⃣ کاراکتر و رشته در C (حالت ANSI)

در C کلاسیک:

- نوع داده `char` ⇒ **۸ بیت**
    
- رشته‌ها ⇒ آرایه‌ای از `char` با `\0` در انتها
    

```c
char c = 'A';
char szBuffer[100] = "A String";
```

✔️ این مدل فقط برای **ANSI / ASCII** خوبه  
❌ برای زبان‌هایی مثل فارسی، عربی، ژاپنی، چینی مناسب نیست

---

## 2️⃣ wchar_t و Unicode در کامپایلر مایکروسافت

مایکروسافت یک نوع داده‌ی داخلی معرفی کرده:

### 🔹 `wchar_t`

- نماینده‌ی **کاراکتر Unicode (UTF-16)**
    
- اندازه: **۱۶ بیت (۲ بایت)**
    

```c
wchar_t c = L'A';
wchar_t szBuffer[100] = L"A String";
```

### 🔹 `L` قبل از رشته یا کاراکتر

- به کامپایلر می‌گه:
    
    > «این رشته Unicode (UTF-16) است»
    

📌 بدون `L` → ANSI  
📌 با `L` → Unicode

---

## 3️⃣ چرا /Zc:wchar_t مهم است؟

در نسخه‌های قدیمی:

```c
typedef unsigned short wchar_t;
```

اما با سوییچ:

```text
/Zc:wchar_t
```

- `wchar_t` تبدیل می‌شود به **نوع داده‌ی واقعی (primitive)**
    
- امن‌تر، استانداردتر و قابل‌اعتمادتر
    

✔️ Visual Studio به‌صورت پیش‌فرض این گزینه را فعال می‌کند  
✔️ توصیه‌ی اکید: **همیشه فعال باشد**

---

## 4️⃣ انواع داده‌ی ویندوزی (CHAR / WCHAR)

مایکروسافت برای جدا شدن از C خام، انواع خودش را تعریف کرده:

```c
typedef char    CHAR;   // 8-bit
typedef wchar_t WCHAR;  // 16-bit
```

### اشاره‌گرها:

```c
// ANSI
typedef CHAR*       PSTR;
typedef const CHAR* PCSTR;

// Unicode
typedef WCHAR*       PWSTR;
typedef const WCHAR* PCWSTR;
```

📌 این نام‌ها دقیقاً همان‌هایی هستند که در MSDN می‌بینی  
📌 برای برنامه‌نویسی ویندوز **خواناتر و استانداردترند**

## 6️⃣ ANSI یا Unicode؟ → راه‌حل TCHAR

ویندوز اجازه می‌دهد **یک سورس کد** داشته باشی که:

- هم به‌صورت ANSI کامپایل شود
    
- هم به‌صورت Unicode
    

### شرط:

```c
#ifdef UNICODE
```

### انواع داده‌ی عمومی:

```c
TCHAR   // char یا wchar_t
PTSTR
PCTSTR
```

### ماکرو TEXT

```c
TEXT("Hello")
```

- اگر `UNICODE` تعریف شده باشد → `L"Hello"`
    
- اگر نه → `"Hello"`

```c
TCHAR szBuffer[100] = TEXT("A String");
```

|وضعیت|نتیجه|
|---|---|
|UNICODE تعریف شده|wchar_t / UTF-16|
|UNICODE تعریف نشده|char / ANSI|

## ANSI و Unicode در C Run-Time Library

برخلاف WinAPI:

- در **C Run-Time**:
    
    - توابع ANSI و Unicode **مستقل هستند**
        
    - نسخه‌ی ANSI → Unicode را صدا نمی‌زند
        
    - نسخه‌ی Unicode → ANSI را صدا نمی‌زند
        
- هر کدام **کار واقعی را خودشان انجام می‌دهند**
    

### مثال:

- `strlen` → طول رشته ANSI
    
- `wcslen` → طول رشته

## مشکل بزرگ توابع قدیمی رشته‌ای

توابعی مثل:

- `strcpy`
    
- `wcscpy`
    
- `strcat`
    
- `wcscat`
    

❌ اندازه‌ی بافر را نمی‌دانند  
❌ باعث **Buffer Overflow** می‌شوند  
❌ قابل تشخیص نیست  
❌ ابزار اصلی حملات امنیتی قدیمی

## 4️⃣ راه‌حل: Secure String Functions

مایکروسافت توابع امن معرفی کرده:

	s_ -----> Secure 
### ویژگی‌ها:

- پسوند `_s`
    
- اندازه‌ی بافر را می‌گیرند
    
- قبل از کپی **اعتبارسنجی می‌کنند**
    
- در صورت خطا:
    
    - حافظه را خراب نمی‌کنند
        
    - مقدار خطا برمی‌گردانند


```c
_tcscpy_s(dest, _countof(dest), src);
```
📌 `_countof` = تعداد کاراکتر (نه بایت)


## رفتار توابع _s در خطا

اگر خطا رخ دهد:

- مقدار `errno_t` برمی‌گردد
    
- در Debug:
    
    - assertion
        
    - terminate
        
- در Release:
    
    - auto-terminate
        

⚠️ رفتار سخت‌گیرانه → برای جلوگیری از اجرای برنامه با حافظه‌ی خراب

---


## 6️⃣ نکته‌ی مهم امنیتی

در `_tcscpy_s`:

- اگر بافر کوچک باشد:
    
    - کل رشته مقصد = رشته‌ی خالی
        
    - باقی حافظه = مقدار fill (مثل `0xFD`)
        
- **هیچ truncationی انجام نمی‌شود**
    

📌 یعنی: یا کامل، یا هیچ


- - `0`

## 9️⃣ نسخه‌های Ex (حرفه‌ای‌تر)

توابعی مثل:

- `StringCchCopyEx`
    
- `StringCchCatEx`
    

امکانات اضافه:

- دانستن فضای باقی‌مانده
    
- اشاره‌گر به انتهای رشته
    
- کنترل رفتار در خطا
    

### فلگ‌های مهم:

- `STRSAFE_NULL_ON_FAILURE`
    
- `STRSAFE_NO_TRUNCATION`
    
- `STRSAFE_FILL_BEHIND_NULL`
    
- `STRSAFE_IGNORE_NULLS`
    

## 🔹 تمرین ۱: تفاوت unsafe و secure (عملاً)

### ❌ کد ناامن (قدیمی)

```c
#include <stdio.h>
#include <wchar.h>

int main() {
    WCHAR buf[5];

    wcscpy(buf, L"ABCDE"); // 5 کاراکتر + '\0' → overflow
    wprintf(L"%ls\n", buf);

    return 0;
}
```

### 💣 مشکل:
- بافر 5 تاست
- رشته 6 تا کاراکتر می‌خواد
- حافظه‌ی کناری **خراب می‌شه**
- هیچ اروری هم نمی‌گیری 😐

---

## ✅ تمرین ۲: نسخه‌ی امن (`_s`)

```c
#include <stdio.h>
#include <wchar.h>
#include <tchar.h>

int main() {
    WCHAR buf[5];
    errno_t err;

    err = wcscpy_s(buf, _countof(buf), L"ABCDE");

    if (err != 0) {
        wprintf(L"❌ خطا رخ داد! errno = %d\n", err);
    }

    return 0;
}
```

### ✔️ نتیجه:
- هیچ حافظه‌ای خراب نمی‌شود
- `buf[0] = '\0'`
- برنامه کنترل‌شده fail می‌شود
- دقیقاً چیزی که از کد امن انتظار داریم

---

## 🔹 تمرین ۳: کار با `TCHAR` (ANSI / Unicode مستقل)

```c
#include <stdio.h>
#include <tchar.h>

int _tmain() {
    TCHAR buf[10];

    _tcscpy_s(buf, _countof(buf), TEXT("Hello"));

    _tprintf(TEXT("%s\n"), buf);
    return 0;
}
```

📌 این کد:
- در Unicode → از `wchar_t`
- در ANSI → از `char`
استفاده می‌کند  
بدون تغییر سورس 👌

---

## 🔹 تمرین ۴: الحاق رشته امن (`_tcscat_s`)

```c
#include <stdio.h>
#include <tchar.h>

int _tmain() {
    TCHAR buf[10] = TEXT("Hi ");
    errno_t err;

    err = _tcscat_s(buf, _countof(buf), TEXT("World"));

    if (err != 0) {
        _tprintf(TEXT("❌ بافر جا نداشت!\n"));
    } else {
        _tprintf(TEXT("%s\n"), buf);
    }

    return 0;
}
```

🧠 اگر جا نداشته باشد:
- بافر امن خالی می‌شود
- کرش نداریم
- کنترل دست خودته

## 🔹 تمرین ۵: نسخه‌ی حرفه‌ای‌تر (`StringCchCopy`)

```c
#include <windows.h>
#include <strsafe.h>
#include <stdio.h>

int main() {
    WCHAR buf[5];
    HRESULT hr;

    hr = StringCchCopyW(buf, _countof(buf), L"ABCDE");

    if (FAILED(hr)) {
        wprintf(L"❌ خطا: 0x%08X\n", hr);
    }
    return 0;
}
```

📌 تفاوت مهم:
- **truncate می‌کنه**
- بهت می‌گه truncation رخ داده
- برای UI خیلی خوبه
