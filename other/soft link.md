ما توی سیستم عامل لینوکس یه چیزی داریم به اسم File Discriptor که این مکانیزم در سیستم عامل لینوکس 
یه عددی است که برای ما یک فرایندی رو به وجود می اورد مثلا میتونیم با صدا کردن اون عدد بگیم برو روی پورت USB مثلا یه چیزی رو بنویس 





## **FD** یا **File Descriptor** 
(به فارسی: «توصیف‌گر فایل»)  
در سیستم‌عامل‌های شبه‌یونیکس مثل **Linux** یا **macOS**، یک **عدد صحیح (integer)** هست که برای اشاره به یک فایل باز، سوکت، یا هر نوع جریان ورودی/خروجی (I/O stream) استفاده می‌شه.

به زبان ساده:

> هر وقت یه برنامه فایلی رو باز می‌کنه، سیستم‌عامل یه عدد به اون فایل اختصاص می‌ده — این عدد می‌شه File Descriptor اون فایل.

---

## 📂 مثال ساده

فرض کن برنامه‌ای نوشتی که یه فایل متنی باز می‌کنه:

```c
int fd = open("test.txt", O_RDONLY);
```

اینجا:

- تابع `open()` فایل `test.txt` رو باز می‌کنه.
    
- سیستم‌عامل یه **File Descriptor** بهش می‌ده (مثلاً `3`).
    
- متغیر `fd` عدد ۳ رو نگه می‌داره.
    

حالا اگه بخوای ازش بخونی:

```c
read(fd, buffer, sizeof(buffer));
```

سیستم‌عامل از طریق FD می‌فهمه از کدوم فایل باید بخونه.

---

## 🔢 سه FD پیش‌فرض

وقتی یه برنامه اجرا می‌شه، همیشه **سه فایل از قبل باز هستن**:

|FD|نام|توضیح|
|---|---|---|
|0|`stdin`|ورودی استاندارد (معمولاً کیبورد)|
|1|`stdout`|خروجی استاندارد (نمایش روی صفحه)|
|2|`stderr`|خطای استاندارد (برای پیام‌های خطا)|

مثلاً وقتی در C بنویسی:

```c
printf("Hello");
```

در واقع داره روی FD شماره 1 (stdout) می‌نویسه.

---

## ⚙️ چرا مهمه؟

زیرا **همه چیز در لینوکس فایل است** — حتی سوکت‌ها، pipeها و دستگاه‌ها.  
پس FD فقط برای فایل‌های متنی نیست، بلکه برای:

- فایل‌های معمولی
    
- socket شبکه
    
- pipe بین پردازه‌ها
    
- دستگاه‌های سخت‌افزاری (مثل `/dev/tty`)
    
- و حتی فایل‌های مجازی مثل `/proc/...`
    

---

## 🔍 مثال واقعی از `/proc`

در لینوکس، اگه بخوای ببینی یه برنامه چه فایل‌هایی باز کرده، می‌تونی برید تو مسیر زیر:

```bash
ls -l /proc/<PID>/fd
```

هر عدد داخل این پوشه، یه **File Descriptor** بازه. مثلاً:

```
0 -> /dev/pts/0
1 -> /dev/pts/0
2 -> /dev/pts/0
3 -> /home/martin/test.txt
```

به این معنی که برنامه:

- ورودی، خروجی و خطاش به ترمیناله
    
- و یه فایل `test.txt` هم باز کرده (FD شماره ۳)
    

---

## 🔄 نکته جالب: تغییر مسیر (Redirection)

وقتی می‌نویسی:

```bash
ls > output.txt
```

در واقع داری می‌گی:

> خروجی استاندارد (FD=1) رو بفرست داخل `output.txt`.

---

## 📘 خلاصه

|ویژگی|توضیح|
|---|---|
|نوع|عدد صحیح (int)|
|هدف|اشاره به منبع I/O باز|
|پیش‌فرض‌ها|0 → stdin، 1 → stdout، 2 → stderr|
|کاربرد|فایل، سوکت، pipe، دستگاه|
|مدیریت|با `open()`, `read()`, `write()`, `close()` در C یا معادل‌هایش در Python و ...|
