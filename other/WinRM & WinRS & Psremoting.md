### اشکال‌زدایی WinRM (Windows Remote Management)

**WinRM چیست؟**

از ویندوز ویستا، ویندوز سرور 2003 R2 و ویندوز سرور 2008 (و نسخه Core سرور 2008)، قابلیت‌های جدیدی به نام **WinRM** و **WinRS** معرفی شدند.

- **Windows Remote Management (WinRM)** یک سرویس مدیریت از راه دور است (بخش «سرور»).
    
- **Windows Remote Shell (WinRS)** بخش «کلاینت» این سرویس است که روی کامپیوتری اجرا می‌شود که قصد دارد سیستم مقصد (WinRM Server) را مدیریت کند.
    

⚠️ توجه: برای اینکه **WinRS** کار کند و بتواند اطلاعات را از سیستم مقصد بگیرد، هر دو کامپیوتر (کلاینت و سرور) باید **WinRM نصب و فعال‌شده** داشته باشند.

---

به طور پیش‌فرض **WinRM روی پورت 80 گوش می‌دهد**، اما این به معنای **غیر رمزنگاری‌شده بودن ترافیک** نیست. WinRM فقط ترافیکی را می‌پذیرد که به‌طور پیش‌فرض با استفاده از **Negotiate** یا **Kerberos SSP** رمزنگاری شده باشد.

- WinRM می‌تواند از **HTTP (پورت TCP 80)** یا **HTTPS (پورت TCP 443)** استفاده کند.
    
- WinRM همچنین کد کمکی دارد که به Listener اجازه می‌دهد پورت 80 را با IIS یا هر اپلیکیشن دیگری که از این پورت استفاده می‌کند، به اشتراک بگذارد.
    

---

در استفاده WinRM همراه با **SCVMM (System Center Virtual Machine Manager)**، احراز هویت فقط از طریق **Kerberos** انجام می‌شود و پشتیبانی از NTLM وجود ندارد. اگر Kerberos قابل استفاده نباشد، خطا رخ می‌دهد.

- اگر هیچ اعتباری (Credentials) مشخص نشود، از اعتبارنامه‌های کاربری که روی سیستم لاگین کرده استفاده می‌شود.
    
- این قابلیت باعث ایجاد تجربه **Single Sign-On (ورود یکپارچه)** می‌شود.
    

---

📌 خلاصه: WinRM سرویسی برای مدیریت از راه دوره، روی پورت 80 یا 443 کار می‌کنه، ترافیکش رمزنگاری‌شده‌ست، و با Kerberos بهترین عملکرد رو داره.

### WinRS چیست؟

**Remote Shell (WinRS)** برای اجرای یک برنامه روی یک میزبان راه‌دور استفاده می‌شود.

عملکرد آن مشابه ابزار قدیمی **PSExec** از Sysinternals است. WinRS از **Windows Remote Management (WinRM)** استفاده می‌کند تا بتوانید روی ماشین‌های راه‌دور فرآیندها (Processes) اجرا کنید.

برای مثال، اگر بخواهید روی یک ماشین راه‌دور لیست فایل‌ها و پوشه‌های درایو سیستم را ببینید، می‌توانید دستور `dir` را به شکل زیر از راه دور اجرا کنید:

```
winrs -r:<RemoteHost> dir C:\
```

---

📌 به زبان ساده: WinRS مثل یه **Remote CMD** هست که روی WinRM سوار شده و بهت اجازه می‌ده دستورها رو مستقیم روی سیستم مقصد اجرا کنی.

---

### استفاده از WinRS

مثال ساده:

```
winrs -r:machinename dir
```

این دستور باعث می‌شود روی سیستم راه‌دور (machinename) یک **لیست پوشه‌ها و فایل‌ها** گرفته شود.

---

یک استفاده کاربردی دیگر از **WinRS**، هنگام نصب نرم‌افزار روی سیستم‌های راه‌دور است.

اگر بخواهید یک برنامه را به‌صورت **بی‌صدا (Silent / Quiet)** با استفاده از یک فایل MSI روی یک سیستم راه‌دور نصب کنید، می‌توانید از دستور زیر استفاده کنید (فرض بر این است که فایل MSI قبلاً در مسیر `C:\` قرار داده شده است):

```
winrs -r:machinename msiexec.exe /i c:\install.msi /quiet
```

---

### حالت‌های معتبر برای مشخص کردن سیستم راه‌دور:

- **Localhost**
    
- **نام NetBIOS**
    
- **Fully Qualified Domain Name (FQDN)** (مثل `pc01.example.com`)
    
- **آدرس IP**

### نصب WinRM

- سرویس WinRM به هیچ سرویس دیگری وابسته نیست **به جز WinHttp**.
    
- اگر سرویس IIS Admin روی همان سیستم نصب باشد، ممکن است پیام‌هایی ظاهر شوند که می‌گویند WinRM قبل از IIS نمی‌تواند بارگذاری شود.
    
    - این موضوع به این خاطر است که ترتیب بارگذاری سرویس‌ها طوری طراحی شده که IIS قبل از سرویس HTTP شروع شود.
        
    - اما در واقع WinRM **به IIS وابسته نیست**.
        
- نکته: WinRM نیاز دارد که فایل **WinHTTP.dll** رجیستر شده باشد.
    

---

### وضعیت سرویس WinRM در ویندوزهای مختلف:

- در **Windows Vista** → سرویس باید **دستی (Manually)** شروع شود.
    
- در **Windows Server 2008** → سرویس به صورت **خودکار (Automatic Delayed Start)** اجرا می‌شود.
    
- در **Windows Server 2003** → نیاز به یک **آپدیت** دارد.
    

📌 شماره آپدیت: **936059** – مربوط به Windows Server 2003 و Windows XP که قابلیت WinRM را اضافه می‌کند.

### پیکربندی WinRM

برای تنظیم پیکربندی پیش‌فرض از دستور زیر استفاده می‌شود:

```
winrm quickconfig
```

یا نسخه کوتاه‌تر:

```
winrm qc
```

---

### دستور `winrm qc` چه کارهایی انجام می‌دهد؟

1. سرویس **WinRM** را اجرا می‌کند و نوع راه‌اندازی آن را روی **auto-start** (اجرای خودکار) قرار می‌دهد.
    
2. یک **listener** برای پورت‌هایی که پیام‌های پروتکل **WS-Management** را از طریق **HTTP یا HTTPS** روی هر آدرس IP می‌فرستند و دریافت می‌کنند، پیکربندی می‌کند.
    
3. استثناهایی (ICF exceptions) را برای سرویس WinRM تعریف کرده و پورت‌های **HTTP و HTTPS** را باز می‌کند.
    

📌 (نکته: دستور `winrm quickconfig` تنظیمات پیش‌فرض **WinRS** را هم پیکربندی می‌کند.)

---

### اگر دستور `winrm qc` خطا داد:

اگر فایروال غیرفعال باشد، اجرای دستور **quickconfig** با خطا مواجه می‌شود.

راه‌حل:

- یا باید فایروال را در بخش سرویس‌ها (Services) موقتاً فعال کنید و دوباره `winrm qc` را اجرا کنید،
    
- یا اینکه دستورات زیر را به‌جای آن استفاده کنید:
    

```
sc config "WinRM" start= auto
net start WinRM
winrm create winrm/config/listener?Address=*+Transport=HTTP
netsh firewall add portopening TCP 80 "Windows Remote Management"
```

### پیکربندی از طریق Group Policy

WinRM را می‌توان از طریق **Group Policy** هم پیکربندی کرد:

1. در خط فرمان دستور زیر را اجرا کنید:
    
    ```
    gpedit
    ```
    
    با این کار پنجره **Group Policy Object Editor** باز می‌شود.
    
2. به بخش زیر بروید و تنظیمات مربوط به **Windows Remote Management** و **Windows Remote Shell** را پیدا کنید:
    
    ```
    Administrative Templates → Windows Components
    ```

برای اینکه ما بخواهیم از طریق پاورشل به سیستم های دیگری ریموت بزنیم باید پورت و پروتکلی برای این کار وجود داشته باشند تا ما از آن برای ریموت زدن استفاده کنیم. پاورشل نیز از Windows Server 2012 به بالا از پروتکل WS-MAN استفاده می کند.

Web Services-Management Protocol یا WS-MAN از پورت های زیر استفاده می کند :

HTTP : 5985

HTTPS : 5986

**اما** **PS Remoting** **چگونه کار می کند؟**

وقتی ما با پاورشل از طریق پروتکل WS-MAN به یک سیستم دیگر ریموت می زنیم و یک کامندی را اجرا می کنیم، خروجی کامند در مقصد تبدیل به یک XML می شود و در صفحه نمایش ما از حالت XML خارج شده و نتایج به ما نمایش داده می شود. باید به این نکته توجه داشته باشید که اطلاعات نمایش داده شده مربوط به زمانی است که کامند شما در مقصد اجرا شده است و درواقع آن اطلاعات یک Snapshot هایی هستند که بروزرسانی نمی شوند تا زمانی که شما دوباره دستور را اجرا کنید و نتیجه را دوباره مشاهده کنید.


```
Enable-PSRemoting
```

این کامند برای فعال سازی PSRemoting استفاده میشود و این امکان را فراهم میکند تا بتوانیم دستورات خودمون رو از طریق این پروتوکل اجرا کنیم 


- در ابتدا باید گفت که این دستور باید با دسترسی Administrator انجام شود، پس پاورشل را بصورت Run as administrator باز کنید و این دستور را اجرا کنید.
- سرویس WinRM را Run میکند.
- سرویس WinRM را در حالت Automatic می گذارد.
- یک رول در فایروال برای WS-Management میسازد و اجازه Allow میدهد.

البته چند عملیات دیگر هم برای Permission و اضافه کردن ماژول ها انجام میدهد.

و بعد از اینکار میتونیم دستورات خودمون رو بزنیم 

```
enter-PSsession
new-PSsession
Invoke-PSsession
```
