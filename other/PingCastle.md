

PingCastle
بر اساس یک واقعیت به‌وجود آمد:  
**امنیتی که فقط روی تکنولوژی تکیه کند، کار نمی‌کند.**

به همین دلیل این شرکت تمرکز خود را روی **فرایند (Process)** و **افراد (People)** قرار داده است، نه فقط تکنولوژی.

PingCastle **هیچ محصول امنیتی نمی‌فروشد!**

این شرکت **راه‌حل دفاعی یا حفاظتی** ارائه نمی‌دهد که زیرساخت شما را محافظت کند.  
بلکه ابزارهایی ارائه می‌کند که:

- کمک می‌کنند بفهمید **چه چیزهایی برای محافظت دارید**،
    
- **سطح امنیتی** آن‌ها را ارزیابی کنید،
    
- و نشان می‌دهد **بودجه‌ای که خرج کرده‌اید واقعاً درست استفاده شده یا نه**.
    

هدف PingCastle رسیدن به **امنیت کامل** نیست.  
هدف آن **ایجاد تغییرات مثبت مدیریتی** است.  
و با تلاش کم، احتمالاً حمایت لازم برای بهبود وضعیت امنیتی را به‌دست خواهید آورد


## 🔹 **اکانت Active Directory**

PingCastle
برای اتصال به AD جهت انجام Audit **نیاز به یک حساب AD دارد**.

- هیچ نوع دسترسی ویژه‌ای لازم نیست
    
- حتی یک حساب عادی یا حساب Trust شده از یک دامنه دیگر هم کافی است
    
- این حساب **نیاز ندارد عضو Local Administrators باشد**
    

بنابراین حتی یک کاربر _low-privileged_ هم می‌تواند گزارش‌گیری PingCastle را انجام دهد.


برای **افزایش سرعت** بسیار توصیه می‌شود که کامپوننت زیر روی سرور نصب باشد:

### ✔ **Active Directory Web Services (ADWS)**

ADWS به‌صورت پیش‌فرض روی هر دامنه‌ای نصب است که حداقل یک Domain Controller با سیستم‌عامل **Windows Server 2008 R2 یا نسخه‌های جدیدتر** داشته باشد.

وجود این کامپوننت می‌تواند سرعت PingCastle را **۱۰ برابر** افزایش دهد.

ADWS را می‌توان روی Windows Server 2003 و 2008 نیز نصب کرد (نیازمند .NET Framework 3.5 SP1).  
هات‌فیکس موردنیاز در لینک داده شده در متن موجود است.


## 🔹 **سمت کلاینت (Client Side)**

PingCastle به **.NET Framework 4.0** نیاز دارد  
(که روی تمام ویندوزهای مدرن موجود است).

اما می‌تواند برای اجرا روی .NET 2.0 دوباره کامپایل شود.

### پشتیبانی کامل برنامه از سیستم‌عامل‌ها:

- Windows Vista → Windows 10
    
- Windows Server 2008 → Windows Server 2016
    
- نسخه‌های ۳۲ و ۶۴ بیتی
    

همچنین برنامه روی سیستم‌عامل‌های قدیمی‌تر نیز آزموده شده:

- Windows 2000 (با .NET 2.0)
    
- Windows XP
    
- Windows Server 2003
    

### نیازمندی بخش Analysis Tool (یعنی PingCastle.exe):

- حداقل .NET 3.0 یا بالاتر (که به‌صورت پیش‌فرض از ویندوز ویستا به بعد وجود دارد)
    
- روی .NET 2.0 هم اجرا می‌شود، ولی **با قابلیت‌های کمتر**
    

از نسخهٔ **2.7** به بعد:

PingCastle.exe بدون فایل `.config` هم قابل اجراست.  
اما در این حالت برنامه تحت نسخهٔ .NET Framework اجرا می‌شود که **در زمان کامپایل تعیین شده** است.

اگر نسخهٔ دیگر .NET موردنیاز باشد، Windows یک Popup برای نصب Framework لازم نشان می‌دهد.

## **انجام یک Active Directory Health Check**

گزارش _Health Check_ می‌تواند در حالت **تعامل‌پذیر (interactive)** تولید شود؛ یعنی وقتی ابزار PingCastle را اجرا می‌کنی، می‌توانی گزینه **"healthcheck"** را انتخاب کنی یا حتی فقط **Enter** بزنی، چون این حالت، **حالت پیش‌فرض تحلیل** است.

همچنین می‌توانی این تحلیل را با دستور زیر اجرا کنی:

```
PingCastle --healthcheck --server mydomain.com
```

## **تحلیل سطح ریسک Active Directory**

وقتی Health Check اجرا می‌شود، دو فایل خروجی تولید می‌شود:

1. **فایل HTML**
    
    - این فایل _گزارش اصلی Active Directory_ است.
        
    - برای **کاربران انسانی** طراحی شده و قابلیت مطالعه آسان دارد.
        
2. **فایل XML**
    
    - فقط بخشی از داده‌های پشت‌صحنه HTML را در خود دارد.
        
    - برای **پردازش ماشینی** و جمع‌آوری اطلاعات چندین Active Directory کاربرد دارد.
        
    - این فایل برای تمام تحلیل‌ها (مثل _global overview_ و _cartography_) **الزامی** است.

## **گزارش به ۳ بخش تقسیم می‌شود**

### **1) امتیازات (Scores)**

امتیاز نهایی از **بیشترین مقدار** بین ۴ زیرامتیاز محاسبه می‌شود:

- **Privileged accounts**  
    بررسی حساب‌های ادمین و دسترسی‌های دارای سطح بالا.
    
- **Trusts**  
    بررسی روابط اعتماد بین دامنه‌ها.  
    (یادآوری: یک AD از طریق Trust می‌تواند دیگری را compromise کند.)
    
- **Stale objects**  
    شامل بررسی اشیا قدیمی یا رها شده مثل:
    
    - کاربران قدیمی
        
    - کامپیوترهای قدیمی
        
    - delegationهای غیرضروری
        
- **Security anomalies**  
    موارد امنیتی که در دسته‌های بالا قرار نمی‌گیرند، مثل:
    
    - تنظیمات اشتباه
        
    - misconfiguration
        
    - مشکلات امنیتی پراکنده
        

در ادامه، **قوانینی که فعال شده‌اند (triggered rules)** نمایش داده می‌شود؛ همراه با:

- توضیحات
    
- تعداد امتیازهای داده شده  
    (جمع کل هر بخش نمی‌تواند از 100 بیشتر شود.)
    

وقتی روی هر Rule کلیک می‌کنی:

- توضیح کوتاهی از آن قانون
    
- و روش‌های پیشنهادی برای رفع مشکل  
    نشان داده می‌شود.
    

---

### **2) اطلاعات کلی (General Information)**

این بخش شامل:

- تاریخ تولید گزارش
    
- نام دامنه  
    و اطلاعات پایه‌ای مرتبط است.
    

---

### **3) بخش جزئیات (Details)**

در این قسمت، اطلاعاتی درباره موارد زیر نمایش داده می‌شود:

- کاربران
    
- کامپیوترها
    
- Trustها
    
- Group Policyها
    
- و سایر اجزای AD
    

برخی از این اطلاعات قابلیت باز شدن دارند (لینک‌دار هستند).  
وقتی روی آن‌ها کلیک می‌کنی، جزئیات بیشتری نمایش داده می‌شود تا بتوانی **اشیای مربوطه را شناسایی** کنی.

## **گزینه ۱: انجام چندین گزارش Health Check (توصیه‌شده)**

اگر می‌خوای خیلی سریع وضعیت کلی زیرساخت Active Directory رو ببینی، برنامه رو با حالت **healthcheck** اجرا کن (فقط Enter بزن) و به‌عنوان domain مقدار **ستاره *** رو وارد کن.

- تمام دامنه‌هایی که قابل دسترس باشند اسکن می‌شن.
    
- حالت **reachable mode** فعال می‌شود.
    
- گزارش **consolidation** هم به‌طور خودکار ساخته می‌شود.
    

این کار بین **چند دقیقه تا یک ساعت** زمان می‌برد.

بعد از اتمام، گزارش **cartography** را باز کن (در ادامه توضیح داده شده).

**نکته مهم:**  
فایل‌های XML که از چند نقطه مختلف (multiple point of view) تولید شده‌اند، می‌توانند برای ساخت یک نقشه‌ی یکپارچه و ترکیبی استفاده شوند.

# **نقشه‌ها (Maps)**

در PingCastle دو نوع نقشه (Map) وجود دارد:

### **۱) نقشه کامل (Full Map)**

این نقشه دقیق‌ترین و جامع‌ترین نقشه است، اما ممکن است خواندن آن سخت باشد.

### **۲) نقشه ساده‌شده (Simple Map)**

برای راحت‌تر شدن خواندن، یک نسخه ساده وجود دارد که در آن هر دامنه فقط با **یک Trust** به دامنه‌های دیگر وصل می‌شود.  
این نسخه یک **ساختار سلسله‌مراتبی (Hierarchy)** می‌سازد.

هرجا امکانش باشد، **امتیاز Health Check** دامنه نمایش داده می‌شود و بر اساس مقدارش **رنگ‌بندی** می‌گردد.

Trustها نیز بر اساس وضعیت **SID Filtering** رنگ‌بندی می‌شوند.

# **نقشه کامل دامنه (Full Domain Map)**

فایل‌هایی با نام **xxx_full_node_map.html** نقشه کامل را نشان می‌دهند.

- این نقشه **داینامیک و قابل حرکت** است (Nodeها قابل Drag هستند).
    
- دایره‌های رنگی دامنه‌هایی هستند که گزارش Health Check روی آن‌ها اجرا شده.
    
- رنگ دایره بر اساس امتیاز Health Check تعیین می‌شود.
    
- دایره‌های با کادر بنفش یعنی دامنه‌هایی که اسکریپت روی آن‌ها اجرا نشده، اما از طریق Trust کشف شده‌اند.
    

### **Legend (راهنما):**

وقتی ماوس را روی یک دایره ببری، نام کامل دامنه نمایش داده می‌شود.

وقتی ماوس را روی یک Trust نگه دارید، جزئیات آن به صورت popup نمایش داده می‌شود.

### **رنگ‌ها و معانی:**

- **Intra forest trust** → تراست داخل یک Forest
    
- **Trust بدون SID Filtering**
    
- **Trust همراه با SID Filtering**
    
- **Trust غیرفعال**
    
- **Trust مربوط به مهاجرت (Migration)**
    

### **رنگ امتیاز دامنه‌ها:**

- **امتیاز 100**
    
- **بیشتر از 70 و کمتر از 100**
    
- **بیشتر از 50 و کمتر یا مساوی 70**
    
- **بیشتر از 30 و کمتر یا مساوی 50**
    
- **کمتر یا مساوی 30**
    
- **دامنه بدون گزارش**
    
- **Trust یک‌طرفه بدون اطلاعات SID Filtering**

# **نقشه ساده دامنه (Simple Domain Map)**

- فایل‌ها با نام **xxx_simple_node_map.html** ذخیره می‌شوند.
    
- مشابه نقشه کامل است، اما هر دامنه **فقط یک‌بار** نمایش داده می‌شود و تنها از طریق **یک Trust** وصل می‌شود.
    
- دامنه‌ای که **بیشترین تعداد Trust** را دارد، به‌صورت خودکار مرکز نقشه می‌شود.
    
- می‌توانی دامنه مرکزی را **به صورت دستی نیز مشخص کنی**.

# **نقشه Hilbert (Hilbert Map)**

فایل‌ها با نام **xxx_hilbert_map.html** ذخیره می‌شوند.

### **این نقشه چیه؟**

شبکه‌ها معمولاً بزرگ و پیچیده‌اند، و نمایش بصری‌شان سخت است.  
نقشه Hilbert یک تکنیک فراکتالی استفاده می‌کند:

- یک فضای **یک‌بعدی (IP Address Range)**
    
- به یک فضای **دو‌بعدی** تبدیل می‌شود.
    

هر مربع → نشان‌دهنده یک **شبکه (Network)** است.

این نقشه کمک می‌کند:

- شبکه‌های **بدون استفاده** را ببینی
    
- شبکه‌هایی که **همپوشانی (overlap)** دارند را تشخیص بدهی
    

---

### **این گزارش شامل چهار بخش است:**

1. **نمای کلی تمام شبکه‌ها**
    
2. **بزرگ‌نمایی (zoom) شبکه انتخاب‌شده**
    
3. **لیست کامل شبکه‌ها**
    
4. **لیست Domain Controllerهای شناسایی‌شده**
    

در صفحه نمایش نقشه:

- می‌توان منابع مختلف را انتخاب کرد تا اطلاعات روی هم نیفتد (Overlapping).
    
- با حرکت ماوس روی مربع‌ها، اطلاعات IP و شبکه مرتبط نمایش داده می‌شود.
    
- یک **جستجوی IP** هم وجود دارد.

# **پیاده‌سازی PingCastle**

PingCastle طوری طراحی شده که:

- **مقیاس‌پذیر (Scalable)** باشد
    
- در ساختارهای **غیرمتمرکز (Decentralized)** کار کند
    

برای اینکه PingCastle بیشترین کارایی را داشته باشد، باید **گزارش ریسک تمام دامنه‌ها** را در اختیار داشته باشد.

از آنجایی که PingCastle **نیازی به حساب کاربری داخل دامنه ندارد**،  
می‌توانی از **Trustها** برای اسکن دامنه‌های دیگر استفاده کنی.

PingCastle طوری طراحی شده که:

# **درگیر کردن مدیریت (Management Involvement)**

مشارکت مدیریت یک عامل حیاتی برای موفقیت است. روند پیشنهادی:

### **۱) شروع پروژه بدون اطلاع دادن به Adminها**

می‌توانی ابتدا بدون اطلاع به Adminهای دامنه، ابزار را اجرا کنی:

- با *_healthcheck روی سرورهای Trusted (سرور = _)__
    
- یا **carto mode**
    

این کار یک تصویر کلی (Big Picture) از همه Domainها می‌سازد.

### **۲) سپس اجرای رسمی در یک محدوده کوچک**

بعد از گزارش اولیه:

- ابزار را **به‌صورت رسمی در یک بخش کوچک دپلوی کن**
    
- نتایج را به Adminها نشان بده
    
- با استفاده از Risk Indicatorها یا زمان رفع مشکلات، مدیریت را درگیر کن

این بخش مهم‌ترین قسمت است:

احتمال اینکه یک مهاجم یا ممتحن (Auditor) بتواند AD را نفوذ کند **حدود ۹۰٪** است.

### **• ابزار نیاز به نصب، سرور، پروژه یا هزینه ندارد → بسیار کم‌هزینه است**

### **• Risk Indicatorها می‌توانند نشان دهند وضعیت بهتر شده**

### **• ۸۰٪ مشکلات در کمتر از ۵ دقیقه قابل رفع هستند**

# **تصمیماتی که باید توسط مدیریت گرفته شود**

**۱) دپلوی ابزار روی ۱۰۰٪ دامنه‌ها**

مثلاً:

- ددلاین ۳ ماه
    
- هر Trust کشف‌شده را به مالک AD آن سازمان بسپارید
    

**۲) فعال‌سازی SID Filtering روی ۱۰۰٪ Trustها (به‌جز Trustهای مربوط به Migration)**

برای مثال:

- یک لیست از دامنه‌های مهم
    
- و Trustهایی که روی آن‌ها SID Filtering فعال نیست
    

**۳) پیگیری ماهانه در جلسات مدیریتی**

# **چطور به پوشش ۱۰۰٪ برسیم؟**

برخی سازمان‌ها ممکن است از ارائه گزارش خودداری کنند. دلایل رایج:

- شرکت با سهم کمتر
    
- دامنه‌ای که قرار است در ماه‌های آینده حذف شود
    
- قوانین خاص
    
- وجود "اطلاعات محرمانه" در اسکریپت
    

### **در مورد Migration**

PingCastle حالت Migration را پشتیبانی می‌کند:

- هم برای Audit
    
- هم برای SID Filtering (با تعیین تاریخ پایان)
    

توصیه: Migration نباید بهانه‌ای برای _رفع نکردن مشکلات_ باشد.

---

# **در مورد اطلاعات محرمانه**

فایل XML:

- هیچ اطلاعات شخصی ندارد
    
- هیچ حساب ادمینی داخلش نیست
    

اگر سطح اطلاعات زیاد بود:

- یک گزینه برای کم کردن اطلاعات وجود دارد
    

اگر مشکل ارسال از کانال ناامن باشد:

- ابزار امکان **رمزنگاری فایل XML** را دارد
    

---

# **اگر باز هم گزارشی نمی‌دهند چه کنیم؟**

اگر Trust وجود دارد ولی گزارش نمی‌دهند:

- Trust کار مهاجم را راحت می‌کند (میمیکتز، LLMNR، Kerberoasting و …)
    
- اگر گزارش ندادند → **Trust را حذف کن**
    

اگر دامنه‌ای Trust ندارد:

- مسئولیت آن به سازمان مربوط منتقل می‌شود
    
- وضعیت آن دامنه "خارج از محدوده" (Out Of Scope) می‌شود

# **دپلوی PingCastle در مکان‌های غیرمتمرکز**

در هر دامنه اجرا می‌شود:

```
PingCastle --healthcheck
```

فایل‌ها جمع‌آوری و در مرکز تجمیع می‌شوند.

---

# **دپلوی در ساختار مرکزی (Centralized)**

**اسکن همه دامنه‌ها از یک Bastion Domain Controller:**

```
PingCastle --healthcheck --server *
```

### اسکن فقط ریشه‌ی Forest:

```
PingCastle --healthcheck --server *.forest.root
```

### اسکن فقط Child و دامنه‌های Trusted آن:

```
PingCastle --healthcheck --explore-trust --server child.forest.root
```

### اسکن تمام دامنه‌های همه Forestهای Trusted:

```
PingCastle --healthcheck --explore-forest-trust --server anotherforest.root
```

### استثناء کردن برخی دامنه‌ها:

```
--explore-exception domain1,domain2
```

# **به‌روزرسانی PingCastle**

گزینه‌ها:

# **مرکز‌سازی گزارش‌ها (Centralizing Reports)**

اگر شبکه‌ها به‌هم وصل نیستند، یا Task Scheduler نمی‌تواند فایل‌ها را جمع کند:

### **رمزنگاری (Encryption)**

ابزار می‌تواند گزارش‌ها را با RSA رمز کند.

### تولید کلید RSA:

```
PingCastle.exe --generate-key
```

- **Public Key** را روی همه کلاینت‌ها قرار می‌دهید (برای رمزنگاری)
    
- **Private Key** روی سرور مرکزی قرار می‌گیرد (برای رمزگشایی)
    

### رمز کردن گزارش:

```
PingCastle --reload-report report.xml --encrypt
```

### رمزگشایی:

```
PingCastle --reload-report encrypted-report.xml
```

ابزار می‌تواند با چند کلید، گزارش‌ها را رمزگشایی کند.

# **در نهایت: گرفتن دید کلی از چند گزارش**

PingCastle می‌تواند گزارش‌ها را تجمیع کند و به شما بگوید:

- چند کاربر دارید؟
    
- چند کامپیوتر دارید؟
    
- آیا باید پشتیبانی ویندوز XP یا 2003 بخرید؟
    
- آیا پسورد ۸ کاراکتری اجباری شده؟
    
- آیا نیاز به پاکسازی حساب‌های Admin دارید؟
