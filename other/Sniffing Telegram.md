

Protocol ---> UDP,STUN

```Wireshark
udp && ip.src == 147.135.6.149 && (udp.port >= 10000 || stun)
```



---

پروتکل STUN چیه؟ (به زبان ساده)

STUN = Session Traversal Utilities for NAT  
یعنی: ابزار عبور از NAT برای ارتباط

---

مشکل اصلی: NAT (مثل روتر خونه)

|دستگاه|IP داخلی|IP عمومی|
|---|---|---|
|گوشی|192.168.1.10|185.23.45.67|
|لپ‌تاپ|192.168.1.100|185.23.45.67 (همون اینترنت)|

وقتی از گوشی به لپ‌تاپ زنگ می‌زنی، گوشی نمی‌دونه IP عمومی خودش چیه و نمی‌تونه بگه "صدا رو به این IP بفرست".

---

STUN چیکار می‌کنه؟

1. گوشی به سرور STUN (مثلاً stun.l.google.com:19302 یا سرور تلگرام) می‌گه:
    
    "من کی‌ام؟ IP عمومی من چیه؟"
    
2. سرور STUN جواب می‌ده:
    
    "تو از دید من با IP: 185.23.45.67 و پورت 54321 میای!"
    
3. گوشی این اطلاعات رو به طرف مقابل (لپ‌تاپ) می‌فرسته تا بدونه صدا رو کجا بفرسته.

---

STUN در تماس تلگرام چه نقشی داره؟

|مرحله|توضیح|
|---|---|
|۱. شروع تماس|تلگرام از STUN استفاده می‌کنه تا IP عمومی و پورت هر دو طرف رو پیدا کنه|
|۲. NAT Traversal|حتی اگه پشت روتر باشی، صدا مستقیم بین گوشی و لپ‌تاپ رد و بدل بشه|
|۳. پورت‌های رسانه|بعد از STUN، پورت‌های بالای 10000 (مثل 54321) برای صدا باز می‌شن|

---

چطور STUN رو توی Wireshark ببینی؟فیلتر STUN در Wireshark:

plaintext

```plaintext
udp && stun
```

یا دقیق‌تر:

plaintext

```plaintext
udp && (udp.port == 3478 || udp.port == 5349 || udp.port == 19302) && stun
```

---

پورت‌های معروف STUN:

|پورت|توضیح|
|---|---|
|3478|STUN استاندارد (UDP/TCP)|
|5349|TLS over UDP (تلگرام ازش استفاده می‌کنه)|
|19302|Google STUN (گاهی تلگرام ازش استفاده می‌کنه)|

---

مثال واقعی توی Wireshark:

|Source|Destination|Port|Protocol|Info|
|---|---|---|---|---|
|192.168.1.10|149.154.167.50|54321 → 3478|STUN|Binding Request|
|149.154.167.50|192.168.1.10|3478 → 54321|STUN|Binding Response → Your public IP: 185.23.45.67:54321|

این یعنی: گوشی داره IP عمومی خودش رو می‌پرسه

---

STUN در تماس تلگرام = شروع تماس

|زمان|اتفاق|
|---|---|
|ثانیه ۱|STUN Request (پورت 3478 یا 5349)|
|ثانیه ۱.۱|STUN Response (IP عمومی برمی‌گرده)|
|ثانیه ۱.۲|شروع ارسال صدا روی پورت بالا (مثل 54321)|

---

خلاصه: STUN رو چطور پیدا کنی؟

plaintext

```plaintext
udp && stun
```

این فیلتر تمام پیام‌های STUN رو نشون می‌ده — یعنی لحظه‌ای که تماس داره راه می‌افته

---

فیلتر ترکیبی: STUN + صدا

plaintext

```plaintext
udp && (stun || (udp.port >= 10000 && udp.len > 1000))
```

این فیلتر:

- شروع تماس (STUN)
- جریان صدا (پکت‌های بزرگ)

---

نکته طلایی

اول STUN میاد، بعد صدا شروع می‌شه  
پس اگه توی .pcap دنبال IP گوشی هستی:

1. فیلتر udp && stun بزن
2. توی Binding Response نگاه کن → فیلد XOR-Mapped-Address
3. همون IP عمومی گوشیته!
